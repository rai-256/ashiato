# ST58 の聞かない既定（C）と仮の決定の候補（P）

深掘りで人間に問わずに決めたもの。spec の段が design の D 番号へ写す（P は `D<n>（仮）` と反転条件にして台帳 `provisional.py` に載せる）。
出所の R は `review/deep.md`。

## 仮の決定の候補（P）—— 失わない側が安く、範囲の内で、要件を変えない

### P1. 携帯の収集アプリは、入れ替えの後にアプリを開かなくても収集を再開する（review R11・申し送り st51 R10）

- `ACTION_MY_PACKAGE_REPLACED` の受け手を足し、入れ替えの前に収集が動いていた（設定済みで、本人が止めていない）ときだけ `LocationService` を起こす
- 裏の位置の権限を許されていない端末では、裏から位置の型の前景のサービスを始められない。その端末では「更新の後に収集が止まっています。開いてください」の通知を 1 回出す
  （通知の権限も無い端末では出せない。その端末は今と同じく、開くまで止まる —— 推奨しない側より悪くならない）
- 失わない側（再開する）は受け手 1 つで安い。前は深掘りの Q1（A）として立てたが、P の条件を満たすので問いから外した
- 反転条件: エミュレータで、targetSdk 36 の受け手から位置の前景のサービスを起こせないと分かったら（P6・P7 が確かさ 4 で外れたら）、通知だけにする
- 確かめ: 計測テスト（エミュレータ）で、`adb install -r` の後に `LocationService` が動いていることを見る（P6・P7 を 4 へ）

## 聞かない既定（C）—— 扉を開けたままにする側・申し送りで決まっている

### C1. 更新の手順の順序（review R2・R10・申し送り st48 R21・ST55 D14）

インストーラは、入っている版と自分の版が違えば更新の手順に入る（別の口は作らない）。順は次のとおり:
1. 「更新の途中」の印を状態の置き場に書く
2. サーバのサービスを止める（開始の種類の扱いは Q5）
3. プログラムの置き場を前の版の退け先（`<置き場>\previous`）へ移して退ける
4. 新しい版で置き換える
5. 新しい版の `migrate`（退避 → 移行）
6. 新しい版のサーバを起こす

前の版を退けるのは 1 世代だけ（次の更新で上書き）。

### C2. 戻す退避は「この回に取った退避」と特定できたときだけ（review R1・P18）

インストーラは、`migrate` に回ごとの空の置き場（`backups\pre-migrate\<印の id>\`）を退避の置き場として渡す。終わった後にその置き場に退避があれば「この回の退避がある」とみなす。
退避が無いのに終了コード 1 で終わった回は、DB を戻さず、前の版のまま起動し直す（3・4・2 と同じ向き）。★ spec の段で、取り終えた退避（`.dump`）だけを数え、終了コード 0・2・3・4 以外を戻す対象にした（design D2。review/spec.md R4・R5）。いちばん新しいファイルを選ぶ形は採らない（時計が戻ったときと 2 回目の試みで、前の退避を戻しうる）。

### C3. 戻しは、別の名前の DB に入れてから入れ替える

`pg_restore` は新しい名前の DB（`ashiato_restore`）へ入れ、通ってから元の DB と名前を入れ替える。落ちた DB は `ashiato_failed_<時刻>` の名前で残し、次の更新が通ったときに消す。
戻しの途中で止まっても、元の DB（落ちた状態）は壊れない。

### C4. 更新係（review R7・ST57 の申し送り）

更新係の実行ファイルもプログラムの置き場にあるので、前の版へ戻すときは一緒に戻す。更新係のサービスは止めない（DB に触れず、更新の手順と取り合わない）。
★ spec の段で design D4 に直した: 更新係の実行ファイルもプログラムの置き場にあるので、入れ替えの間だけ止め、最後に（切ってなければ）起こす（review/spec.md R22）。
切った更新の確認（`settings\check.json` の `enabled: false`）は、更新でも戻しでも切ったまま（Scenario にする）。戻した後は、新しい版をまた「更新あり」に出す（同じ版をもう一度入れられる）。

### C5. 同梱の PostgreSQL の大きい版が違う更新は止める（review R8）

DB の置き場は `db\<大きい版>`。大きい版が違う配布物で更新すると、空の DB を新しく作りうる。ST58 は、大きい版が違うときは何も替えずに止まり、そのことを示す（`pg_upgrade` は大きい版を上げる Story で扱う）。
小さい版の違いは、プログラムの置き場と一緒に入れ替え、戻すときは一緒に戻す。

### C6. 戻しで戻すもの（review R9）

戻すのは DB・プログラムの置き場（サーバ・更新係・同梱の PostgreSQL）・「アプリと機能」の版の表示。設定（`server.json`・`owner.json`）と更新係の置き場は、更新で書き換えない（足りない鍵を足すことだけを許す。前の版は知らない鍵を読み飛ばす —— `service.rs:226-233`）ので戻さない。

### C7. PC の収集アプリの古い版への入れ直し（review R13・申し送り ST52 D5・R14）

更新の窓は、見つけた最新の版が入っている版より新しいときだけ入れ替える（古い版を入れる場面は窓に現れない）。本人が手で古い版に置き換えることは止めない。
未送信は行ごとに焼いた送信契約の版で送るので（`contract.rs:401-403`・`outbox.rs:134`）、古い版でも消えず、古い形でも送らない。前は深掘りの Q7 として立てたが、場面が推奨の道に現れないので外した。★ spec の段で直した: 推奨の Q1 の自動の戻しは「新しい版の後に前の版を動かす」場面になる（design D7・D12（仮）。review/spec.md R10）。

### C8. Linux のサーバの更新は扱わない（review R14・ST57 D10）

Linux のサーバは帯を出さないので、FR-114 の「押す」が起きない。Linux の更新と戻しは、Linux の入れ方を持つ Story（ST60。FR-131）で扱う。spec の段で `docs/handoff/ST60.md` に 1 行足す。

### C9. 落とした配布物は指紋と照らす

携帯と PC が落とした配布物は、版の一覧の答え（api.github.com から TLS で読んだもの）の `digest` と照らし、違えば入れない（P2）。`digest` の無い配布物は入れない（厳しい側）。

## 範囲の外として本人に返すもの

### X1. 端末の起動の後も、開くまで収集が止まる（review R15）

携帯の収集アプリは、端末を起動し直した後も `LocationService` を起こさない（P8）。更新の後の再開（P1）と同じ受け手の形で直せるが、更新とは別の振る舞いで、この Story の要件に無い。
change として登録するかを本人に返す（`scripts/hx change`。この段では登録しない）。
