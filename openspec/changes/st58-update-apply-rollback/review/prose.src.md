# ST58 の GO 資料の文（推敲用）

`<!-- prose … -->` の行は変えない・消さない・並べ替えない。各行の下の文だけを推敲する。

<!-- prose purpose -->
画面や収集アプリで「更新あり」を押せば、新しい版を入れる口が開くようになる。携帯は Android のインストール画面、PC は収集アプリ自身の入れ替えの窓、サーバは更新の手順が開く。サーバの更新で移行が落ちても、放っておけば移行の前の退避から DB が戻り、前の版で動き続ける。何が起きたかは窓と画面の帯に出る。

<!-- prose impact.overview -->
3 つの部品で「更新あり」を押すと入れる口が開き、サーバは移行が落ちても前の版へ自動で戻るようになる。自動で戻るのは、移行が落ちたときと新しい版が待ち受けを開く前に落ちたときだけ。待ち受けを開いた後に落ちた新しい版は自動でも rollback の口でも戻さず、ほかに前の版へ移る手順は仕様に無い。更新が通るたびに移行の前の退避は 1 つだけになり、2 つ前より古い更新の前へは戻せなくなる（毎日のバックアップはまだ無い）。戻した後の更新の履歴の「前の版」の読み方に食い違いが見つかった（IMP-07）。

<!-- prose impact.problem -->
本人がサーバの新しい版を入れようとしても、今は道が無い。移行を伴う更新が途中で落ちたまま止まると、その間の記録はサーバに入らず、携帯と PC の手元に上限（90 日・2 GB）まで溜まり続ける。

<!-- prose walkthroughs[W1].title -->
サーバの更新が途中で落ちたとき、何が戻るか

<!-- prose walkthroughs[W1].scene -->
本人が 0.4.0 で動いているサーバに 0.5.0 のインストーラを走らせる。どこで落ちるかによって、戻るものが変わる。

<!-- prose walkthroughs[W1].why -->
待ち受けを開いた後の新しい版は、記録を受け取って 200 を返しているかもしれない。収集アプリはその記録を未送信から消しているので、DB を戻すと捨てることになる。開く前なら、受け取った記録はまだ無い。

<!-- prose walkthroughs[W1].figure.caption -->
落ちた場所と、戻るもの（0.4.0・0.5.0 は説明用の版）

<!-- prose walkthroughs[W1].cases[0].result -->
退避を別の名前の DB に入れてから元の DB と入れ替え、0.4.0 で起きる。退避を取る前にサーバを止めてあるので、失う記録は無い

<!-- prose walkthroughs[W1].cases[1].result -->
DB もプログラムも戻さない。サービスの回復が起こし直しても落ち続け、記録は収集アプリの手元に溜まる

<!-- prose walkthroughs[W1].exceptions[0].text -->
説明用の値。実際の版の組み合わせは確かめていない

<!-- prose walkthroughs[W2].title -->

<!-- prose walkthroughs[W2].why -->
落ちた DB は次に更新が通るまで消さず、戻した回の退避も消さない。戻しは、別の名前の DB に退避を入れてから入れ替えるので、その間は DB が 2 つ分の場所を取る。

落ちた DB と古い退避は、更新が通ったときに消える

<!-- prose walkthroughs[W2].cases[1].result -->
試すたびに落ちた DB と退避が増える。空きが足りないと、戻しの途中で落ちてサーバが止まったままになる（IMP-01）

<!-- prose model.caption -->
サーバの更新の流れ（どこで落ちたら何が戻るか）

<!-- prose features[phone].summary -->
押すとアプリが落として照らし、Android のインストール画面を開く。入れるのは本人

<!-- prose points[phone.1].text -->
最初の画面の「更新あり」の行か、更新の通知を押すと、アプリが新しい版の APK を落とし、版の一覧の指紋と照らしてから Android のインストール画面を開く。通知から開いたときも、行を押したのと同じ処理を 1 回だけ始める

<!-- prose points[phone.2].text -->
アプリに「提供元不明のアプリ」が許されていなければ、落とす前にその許可の画面を開き、行に「許可した後に、もう一度押してください」と出す

<!-- prose points[phone.3].text -->
インストール画面で取り消すと、入っている版のまま動き続ける。落とした APK は、インストール画面を閉じた後か次にアプリを開いたときに消え、置き場に残らない

<!-- prose points[phone.4].text -->
入れ替わった後は、開かなくても収集を再開する。裏の位置の権限が無い端末では起こせないので、「更新の後に収集が止まっています。開いてください」の通知を 1 回出す。送り先の無い端末では起こさない

<!-- prose features[pc].summary -->
本人が y と答えると、収集アプリ自身が新しい版に入れ替える。動き出さなければ前の版に戻す

<!-- prose points[pc.1].text -->
「新しい版」の通知を押すか update の口を使うと、窓が「入っている版 0.4.0 / 新しい版 0.5.0 / 入れ替えますか [y/N]」と聞く。y なら配布物を落として指紋を照らし、前の版を止めてから新しい版を起こす。前の版と新しい版が同時に記録を積むことは無い

<!-- prose points[pc.2].text -->
新しい版が 1 分以内に動き出したことを確かめてから、自動起動の台本を新しい版に向ける。動き出さなければ新しい版を止め、前の版を起こし直し、「新しい版 0.5.0 が動き出さなかったので、0.4.0 に戻しました」と通知する

<!-- prose points[pc.3].text -->
新しい版は、本人が置いた場所ではなく、状態の置き場の版ごとの置き場（versions\<版>）から動く。本人が置いた場所の実行ファイルは前の版のまま残る。版ごとの置き場は今の版と前の版の 2 つだけを残す

<!-- prose points[pc.4].text -->
入れ替えの前に積んだ未送信は、新しい版が続きから送る。前の版に戻しても、新しい版が積んだ未送信は消えない（前の版は知らない形の行を送らずに残す）

<!-- prose points[pc.5].text -->
y 以外の答えでは何も替えない。見つけた最新の版が入っている版より新しくなければ「入っている版が最新です」と出し、配布物を落とさない

<!-- prose points[pc.6].text -->
入れ替えている数秒と、動き出さずに前の版へ戻るまでの間は、窓・入力・アドレスバーの記録が取れない。時刻サーバの検査は、入れ替えた新しい版を起こす決まった 1 つの形だけを新しく許す

<!-- prose features[fetch].summary -->
押したときだけ、決まった 2 つの宛先から落とし、版の一覧の指紋と同じときだけ入れる

<!-- prose points[fetch.1].text -->
押したときに版の一覧を取り直し、配布物を github.com の配布元の下から落とす。転送は release-assets.githubusercontent.com へのものだけを追う。押す前には落とさない。取り直しは 24 時間ごとの確かめの数えに入れない

<!-- prose points[fetch.2].text -->
落とす要求は自分の版・端末の機種・識別子・資格情報を持たない。落とした配布物の SHA-256 が版の一覧の指紋と同じときだけ入れ、指紋の無い配布物は入れない。どの版を落としたかと元の IP は配布元に見える

<!-- prose features[server].summary -->
違う版のインストーラを走らせると、サーバを止めて前の版を退け、新しい版で移行を当てて起こす

<!-- prose points[server.1].text -->
入っている版と違う版のインストーラを走らせると、管理者の確認を 1 回出して更新の手順に入る。印を書く → サーバと更新係を止める → 前の版を previous へ退ける → 新しい版で置き換える → この回の置き場に退避を取って移行 → 新しい版を起こす → 待ち受けを確かめたら印を消す。同じ版なら今までどおり走らせ直しになる

<!-- prose points[server.2].text -->
退避を取る前にサーバを止めるので、更新の移行の間サーバは待ち受けない。秘密・設定・画面の合言葉・更新係の置き場は書き換えない

<!-- prose points[server.3].text -->
移行を当てるのはインストールと更新のときだけ。初めてのインストールで移行が落ちたら、今までどおりサービスを開始せずに止まる（更新のときは前の版へ戻す）

<!-- prose points[server.4].text -->
開発版のインストーラは正式版のインストールを、正式版のインストーラは開発版のインストールを更新しない。同梱の PostgreSQL の大きい版が違う配布物では、何も替えずに止まる

<!-- prose points[server.5].text -->
「更新の途中」の印と更新の記録は、管理者と SYSTEM だけが書ける置き場に置く。サーバのアカウントは読めるが書けない

<!-- prose features[rollback].summary -->
この回の退避があれば DB も戻し、無ければプログラムだけを戻して前の版で起こす

<!-- prose points[rollback.1].text -->
移行が落ち（終了コード 0・2・3・4 以外）、この回の取り終えた退避があれば、退避を別の名前の DB に入れてから元の DB と名前を入れ替え、プログラムの置き場を前の版に戻して前の版で起こす。戻すのは DB・プログラム・「アプリと機能」の版で、設定は戻さない

<!-- prose points[rollback.2].text -->
退避を取る前にサーバを止めてあるので、戻しても受け取った記録は失われない。更新の間に溜まった未送信は、前の版が起きた後に入る

<!-- prose points[rollback.3].text -->
DB に新しい版の知らない版がある・系統が違う・接続先が手元でない（終了コード 2・3・4）と、この回の退避が無い回は、DB を戻さずプログラムだけを前の版に戻す。前の回の退避と書きかけの退避は戻しに使わない

<!-- prose points[rollback.4].text -->
移行が通っても、新しい版が 180 秒以内に待ち受けを開かなければ同じく戻す。待ち受けを開いた後に新しい版が落ちても、DB は戻さない（受け取った記録を捨てない）。その場合は直した版が出るまでサーバは止まる

<!-- prose points[rollback.5].text -->
戻しは DB の管理者でなく、表の所有者の役割で行う。落ちた DB は ashiato_failed_<時刻> の名前で残し、次に更新が通ったときに消す

<!-- prose features[halt].summary -->
更新の間はサーバが自分で起きないようにし、走らせ直すとまず前の版へ戻し終える

<!-- prose points[halt.1].text -->
更新の間はサーバのサービスの開始の種類を「無効」にしておく。電源が落ちても、PC の起動のときに半端な DB でサーバが起きない

<!-- prose points[halt.2].text -->
印が残ったままインストーラ（ST58 以後のどちらの版でも）を走らせ直すと、まず前の版へ戻し終える。走らせた版が前の版と違えば、更新を初めからやり直す。途中から先へは進めない

<!-- prose points[halt.3].text -->
待ち受けを確かめた後に止まった回は、走らせ直しても rollback の口でも戻さず、更新の残りを進めて終える

<!-- prose points[halt.4].text -->
戻しそのものが落ちると、サーバを止めたまま、この回の退避の場所とやり直しの口（ashiato-setup.exe rollback）を示して止まる。印が無ければ rollback の口は「戻すものはありません」と出して何も替えない

<!-- prose features[notice].summary -->
戻した・入らなかったことを、窓と画面の帯と設定に出し、DB の外の記録と更新の履歴に残す

<!-- prose points[notice.1].text -->
戻したときと入らなかったときは、インストーラの窓に、どちらか・新しい版・前の版・理由を出す。理由は落ちた版の名前と SQLSTATE の短い説明（「制約に反した」など）か、止まった種別の短い説明で、DB の誤りの本文は出さない。同じ中身を状態の置き場の更新の記録（DB の外）に 1 行足す。通った更新も 1 行足す

<!-- prose points[notice.2].text -->
画面の「更新あり」の帯を押すと、画面の中にサーバの更新の手順が開く。リンクは配布元のその版のリリースのページだけ（開発版は印 nightly）で、押すまで外へ要求を出さない

<!-- prose points[notice.3].text -->
更新の記録の最後の行が「戻した」か「入らなかった」なら、帯と設定の「更新の確認」にその行を出し、次に更新が通るまで出し続ける。「更新あり」「確かめられていない」と同時なら行を重ねる（360 px でも横に流れない）

<!-- prose points[notice.4].text -->
「確かめられていない」「戻した」「入らなかった」の行は押しても何も起きない。読めない形の記録・1 MB を超える記録は画面に出さない

<!-- prose points[notice.5].text -->
戻したときは、更新の履歴（書き出しにも入る）に 2 行を足す。移行が落ちた回は「落ちた試みの結果（failed）」と「戻した（rolled_back）」。移行は通ったが待ち受けを開かずに戻した回は「当てた結果（applied か nothing_to_apply）」と「戻した」。戻した DB に残る試みの行は書き直さない

<!-- prose points[notice.6].text -->
戻した先の版の表が「戻した」を受け付けない（ST58 より前の版に戻した）ときは、2 行を状態の置き場の控えに書き、次に更新が通ったときに表へ写す。そのため書いた順（seq）では後ろに並び、時刻（at）は戻した時になる。書き出しの説明書にもそう書く

<!-- prose features[keep].summary -->
更新が通ったら、移行の前の退避はその回の 1 つだけにする

<!-- prose points[keep.1].text -->
新しい版が待ち受けを開いたら、移行の前の退避はこの回の 1 つだけを残し、前の回の退避と ST58 より前の版が置いた退避を消す。前の回に残した落ちた DB も消す。2 つ前より古い更新の前の写しは無くなる。仕様は「毎日のバックアップ（30 日分）は別に残る」とするが、毎日のバックアップ（ST30）はまだ作られていない（未解決を参照）

<!-- prose points[keep.2].text -->
戻した回・入らなかった回は、退避を消さない

<!-- prose features[off].summary -->
更新でも戻しでも切ったまま。戻した後も、落ちた新しい版はまた「更新あり」に出る

<!-- prose points[off.1].text -->
サーバの更新係・PC・携帯で切った更新の確認は、更新でも戻しでも切ったまま。切ってあるサーバの更新係は、更新の最後にも起こさない

<!-- prose points[off.2].text -->
前の版に戻した後も、確認が有効なら、落ちた新しい版をまた「更新あり」に出す。同じ版をもう一度入れられる（直した版が出るまで、押しても同じところで落ちうる）

<!-- prose impact.scenarios[S1].result -->
印は消えているか、段が「待ち受けを確かめた」なので、rollback の口は何も戻さない。0.5.0 は落ちては起こし直される。前の版のインストーラで走らせ直したときに何が起きるかは確かめていない

<!-- prose impact.scenarios[S1].lost -->
直した版が出るまでの間、サーバが記録を受け取ること（記録は収集アプリの手元に上限まで溜まる）

<!-- prose impact.scenarios[S2].result -->

<!-- prose impact.findings[IMP-01].title -->
戻すたびに DB 1 つ分の場所を使い、空きが足りないとサーバが止まったままになる

<!-- prose impact.findings[IMP-01].text -->
戻しは退避を別の名前の DB に入れてから入れ替えるので、その間は DB が 2 つ分の場所を取る。落ちた DB は次に更新が通るまで消さず、戻した回の退避も消さないので、同じ版を試すたびに DB 1 つ分と退避 1 つ分が増える。空きが足りないと戻しが落ち、サーバは止まったままになる

<!-- prose impact.findings[IMP-02].title -->
消した記録が、落ちた DB と残した退避に次の更新まで残る

<!-- prose impact.findings[IMP-02].text -->
戻した回の落ちた DB（ashiato_failed_<時刻>）と移行の前の退避は、次に更新が通るまで消えない。その間に本人が消した記録は、この 2 つに残り続ける。更新を長く入れなければ、何か月も残りうる。書き出しはサーバが繋ぐ記録の DB だけを読むので、落ちた DB は書き出しには出ない（毎日のバックアップはまだ無い）

<!-- prose impact.findings[IMP-03].title -->
ST58 より前のサーバは --version に答えず、最初の更新で入っている版を読めない

<!-- prose impact.findings[IMP-03].text -->
design は入っている版を ashiato-server --version で読むとしている。今のサーバは migrate 以外の引数を「知らない引数」で断る。ST58 より前の版から ST58 への最初の更新で、入っている版を読めない。CI の通しは同じ commit の 2 つの zip（どちらも ST58 以後）で見るので、この場面を確かめない

<!-- prose impact.findings[IMP-04].title -->
待ち受けを開いた後に落ち続ける新しい版から前の版へ移る手順を、仕様は定めていない

<!-- prose impact.findings[IMP-04].text -->
待ち受けを開いた後は、自動でも rollback の口でも戻さない。新しい版が落ち続けると、直した版が出るまでサーバは止まり、記録は収集アプリの手元に溜まる。携帯の未送信は 90 日・2 GB を超えると古い方から失われる

<!-- prose impact.findings[IMP-05].title -->
PC で入れ替えた後、置いた場所から開くと前の版が新しい版と同時に動きうる

<!-- prose impact.findings[IMP-05].text -->
新しい版は版ごとの置き場から動き、本人が置いた場所の実行ファイルは前の版のまま残る。PC の収集アプリには 2 つ同時に動くのを止める仕組みが無い。本人がデスクトップのショートカットなどから開くと、前の版と新しい版が同時に記録を積みうる

<!-- prose impact.findings[IMP-06].title -->
ST58 より前の版へ戻した回は、画面の帯に「戻しました」が出ない

<!-- prose impact.findings[IMP-06].text -->
前の版のサーバと画面は更新の記録を読まないので、ST58 を初めて入れる回が落ちて戻ると、帯には出ず、窓にだけ出る。次に ST58 以後の版が入ると、最後の行が「戻した」のままなら帯に出る

<!-- prose impact.findings[IMP-07].title -->
戻した後の次の更新で、更新の履歴の「前の版」が落ちた新しい版になる

<!-- prose impact.findings[IMP-07].text -->
サーバは、書いた順で最後の applied / nothing_to_apply の行から「前の版」を決める。待ち受けを開かずに戻した回は、その回の当てた結果（今の版は新しい版）を書き直してから rolled_back を足すので、次の更新の行の前の版は、実際には動いていない新しい版になる。更新の履歴は凍結した表で、仕様は書いた行を書き直す手順を定めていない（試みの行は書き直さない）
