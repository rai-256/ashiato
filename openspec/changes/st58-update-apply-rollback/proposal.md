# ST58 — 更新を入れ、移行が失敗したら自動で戻る

## Why

ST57 で、サーバ・携帯・PC の収集アプリは新しい版が出たことを知らせるようになった。しかし「更新あり」を押しても何も起きず、サーバのインストーラを新しい版で走らせ直すと「版を替える口はまだ無い」で止まる（premises P10・P11）。本人は新しい版を入れる道を持たない（FR-114）。
サーバの更新は移行を伴う。移行が落ちたまま止まると、その間の記録はサーバに入らず、収集アプリの手元に溜まり続ける（上限 90 日・2 GB）。FR-119・FR-120 は、移行の前の退避から DB を戻し、前の版で動かし続け、そのことを知らせるよう求めている。

## What Changes

> 第 1 回の深掘りは**推奨の答えで先に**書いた（2026-10-20 の流れ）。Q1・Q5・Q6・Q7 は失うものがある問いで、本人は答えを省けない。Q2・Q3・Q4 は仮でよい問い。
> 本人の答えが推奨と違えば `spec --answers` が書き直す。聞かない既定 C1〜C9（`defaults.md`）は design の D1〜D9 に写し、仮の決定の候補 P1 は D10（仮）にした。

- **携帯**（Q2 の推奨・FR-114）: 最初の画面の「更新あり」の行か、更新の通知を押すと、アプリが新しい版の APK を落とし、版の一覧の指紋（`sha256`）と照らしてから Android のインストール画面を開く。入れるのは本人。「提供元不明のアプリ」が許されていなければ、初回だけその許可の画面へ送る。
  入れ替えた後は、アプリを開かなくても収集を再開する（D10（仮）。裏の位置の権限が無い端末では「開いてください」の通知を 1 回出す）
- **PC**（Q1 の推奨）: 「新しい版」の通知を押すか `update` の口を使うと、窓が版を示して「入れ替えますか [y/N]」と聞く。y なら配布物を落として指紋を照らし、前の版を残したまま入れ替えて新しい版を起こす。新しい版が 1 分以内に動き出したことを確かめてから、自動起動の台本を新しい版に向ける。
  動き出さなければ前の版に戻して起こし直し、そのことを知らせる。入っている版より新しい版だけを入れる（D7）
- **収集アプリが落とす宛先**（D9・D11（仮））: 押したときだけ、版の一覧を取り直し（ST57 と同じ決まった形）、配布物を `github.com` から落とし、`release-assets.githubusercontent.com` への転送を追う。指紋が無い・違う配布物は入れない
- **画面**（Q3・Q4 の推奨）: 「更新あり」の帯を押すと、画面の中に「サーバの更新の手順」を開く（版・サーバの PC で行う 3 段・移行が落ちたら自動で前の版に戻ること）。
  更新が入らなかった（移行が落ちて戻した・移行の前に止まった）ときは、帯にそのことと版と理由を出し、次に更新が通るまで出す。設定の「更新の確認」の節にも同じ行を出す
- **サーバのインストーラの更新の手順**（D1〜D6・Q5 の推奨）: 入っている版と自分の版が違えば、更新の手順に入る。
  「更新の途中」の印を書く → サーバのサービスを止めて開始の種類を「無効」にする → プログラムの置き場を前の版の退け先へ退ける → 新しい版で置き換える → 新しい版の `migrate`（回ごとの空の置き場に退避 → 移行）→ 新しい版のサーバを起こす → 待ち受けが開いたら開始の種類を「自動」に戻して印を消す。
  止まった後は、どちらの版のインストーラ（ST58 以後）を走らせ直しても、印を見て、待ち受けを確かめる前に止まった回はまず前の版へ戻し終えてから走らせた版で初めからやり直し、待ち受けを確かめた後に止まった回は戻さずに残りを進める
- **戻し**（FR-119・D2・D3・D6）: 移行が終了コード 1 で落ち、この回の退避があれば、退避を別の名前の DB に入れてから元の DB と入れ替え、プログラムの置き場を前の版に戻し、前の版のサーバで起こし直す。
  この回の退避が無い回・終了コード 2・3・4・それ以外は、DB を戻さず、前の版のまま起こし直す。新しい版が待ち受けを開く前に落ちたときも戻す。開いた後に落ちたときは戻さない
- **戻したことを更新の履歴に残す**（Q6 の推奨）: `outcome` に値 `rolled_back` を足す（移行で CHECK を作り替える）。戻した後に「落ちた試みの結果」と「戻した」の 2 行を書く。前の版の表が受け付けない回は状態の置き場に控え、次に通った移行が控えた時刻のまま表へ写す
- **移行の前の退避**（Q7 の推奨）: 更新が通って新しい版が待ち受けを開いたら、その回の 1 つだけを残し、それより古い退避を消す
- **同梱の PostgreSQL の大きい版が違う配布物**では、何も替えずに止まる（D5）
- **切った更新の確認**は、更新でも戻しでも 3 つの部品とも切ったまま（D4）。戻した後も、新しい版をまた「更新あり」に出す
- **時刻サーバの検査**（`tools/check-no-time-server.sh`）の許可の形に、「入れ替えた新しい自分」を起こす 1 つの形を足す（FR-114 ★ 2026-10-25）

**要件の改訂（record の段で本人の答えを受けてから。この draft では `docs/requirements.md` と `docs/stories/ST58.md` に触らない）**:
- FR-114: 「Windows のインストーラ」は PC の収集アプリには無い（P15）。Q1 の答えで「収集アプリが自分で入れ替える」などに直す
- FR-119: 「移行が失敗する」に「移行は通ったが、新しい版のサーバが待ち受けを開く前に落ちた」を含める（Q5）。戻すのは「この回の退避がある」回だけ（D2）
- FR-120: 「戻した」に加えて「入らなかった（移行の前に止まった）」も知らせる（Q4）

**BREAKING ではない**: 送信の封筒・送信契約の版・取り込みの口は変えない。DB は更新の履歴の CHECK に値を 1 つ足すだけ（今の列と値の意味は変えない）。

## Capabilities

### New Capabilities

（無し）

### Modified Capabilities

- `distribution`: 更新を入れる口（携帯・PC・画面）・配布物を落とす宛先と指紋・PC の入れ替えと戻し・サーバのインストーラの更新の手順・移行の失敗での戻し・途中で止まった後・戻した・入らなかったことの知らせ・「戻した」の行・移行の前の退避の保持・大きい版の違い・切った確認の引き継ぎ・携帯の更新の後の再開を ADDED。
  「インストーラは…インストールのときだけ移行を当てる」「インストールを走らせ直すと…」「画面は…帯に出し…」「更新の履歴は、決めた置き場と列の形で持つ」の 4 つを MODIFIED
- `data-durability`: 書き出しの説明書に「`rolled_back` は移行が落ちて前の版に戻した回」の説明を足す（「書き出しは、更新の履歴と…を、説明つきで持つ」を MODIFIED）

**capability の照合**: INDEX.md は ST58 を `distribution`（「配布と更新（…更新の確認と適用と戻し…）」）に割り当てている。収集アプリと画面の振る舞いも、更新の適用の一部として ST57 と同じく `distribution` に置く（`device-collection`・`desktop-collection`・`browsing-views` には足さない）。
`data-durability` は INDEX の割当に無いが、ST51 が置いた書き出しの説明書（更新の履歴の値の意味）が値の追加で古くなるので、説明の 1 文だけを MODIFIED で直す。振る舞いの前倒しではない。

**requires**: ST57（更新の確認・`GET /update-status`・更新係）・ST48（終了コード 3）・ST51（更新の履歴）・ST54（終了コード 4・系統）はどれも archive 済みで正典にある。ST55（インストーラ）も archive 済み。

## Impact

- インストーラ（`crates/installer`）: 入っている版の読み取り・更新の手順と印（`C:\ProgramData\ashiato\update\`）・前の版の退け先（`<置き場>\previous`）・戻し（`pg_restore` を別の名前の DB へ → 入れ替え）・続きからやり直す口と `rollback` の口・大きい版の検査・退避の保持。今の「版を替える口はまだ無い」の止まり方（`program_version_mismatch_message`）を更新の手順に置き換える
- サーバ（`crates/server`）: `migrate` が回ごとの退避の置き場を受ける（環境変数）・`update-history` の口（「戻した」の 2 行を書く・控えを写す）・`GET /update-status` に `last_update` の欄（状態の置き場の記録を読む）。`docs/openapi.json` を作り直す
- 移行: `migrations/<時刻>_update_history_rolled_back.sql`（と `.down.sql`）・`migrations/ORDER` の末尾へ 1 行
- PC の収集アプリ（`crates/collector-windows`）: `update` の口と窓・更新の通知を押すと窓を開く・配布物を落として指紋を照らす・入れ替えと 1 分の見張り・自動起動の台本の向け直し・戻し
- 携帯の収集アプリ（`collector-android`）: `REQUEST_INSTALL_PACKAGES`・APK を落として照らす・`PackageInstaller` の画面・`FileProvider`・`ACTION_MY_PACKAGE_REPLACED` の受け手
- 画面（`web/src`）: `UpdateBand.tsx`（押すと手順を開く・入らなかった行）・`SettingsView.tsx`・`update.ts`。e2e は `web/e2e/st58-update-apply.spec.ts`
- 道具と CI: `tools/check-no-time-server.sh`（許可の形を 1 つ足す・`--self-test`）・新しい `tools/release/update-apply-install.sh`（Windows の CI の `install-windows` で、2 つの版の zip と落ちる移行の差し込みで更新と戻しを見る）・`tools/release/build.sh`（試験の組み立ての差し込み）
- 文書: `docs/install.md`（サーバの更新と戻し・戻しをやり直す口）・`docs/collector-setup.md`（PC と携帯の更新）
