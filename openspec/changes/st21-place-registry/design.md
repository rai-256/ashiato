# ST21 設計 — 場所を登録し、識別子を変えない

## Context

D-01 に場所を持つ表もコードも無い（`crates/server/src` と `migrations/` に 0 件）。滞在（ST16）は `core.event` の
`logical_source = 's01-stay'`・`origin = 'derived'` の行で、`payload` に代表点（重心）の `lat` / `lon` と `end` を持つ（`crates/server/src/stay_store.rs` の `span_of` / `load_existing`）。
ST19 は「本人が書いた」記録を `/ingest` から入れ、ソースごとの錠を DB に掛ける形（`migrations/202609160220_personal_attributes.sql`）と、
S-6 マスタ管理の骨格（`web/src/MasterView.tsx`。タブ 1 つ）を作った。動機は `proposal.md` の Why。

深掘りで本人が決めた 4 件と、聞かないで決めた C1〜C13 は `deep.md`。**ここで決めるのは、それを実装に落とすときの技術判断だけ**で、
観測可能な振る舞いは `specs/personal-entities/spec.md` に置いてある。（仮）の D 番号は B（計算し直せば戻る）の判断で、反転条件を添える。

## Goals / Non-Goals

**Goals**
- 場所の器と記録を `personal-entities` に足し、FR-49 の「識別子を変えない」と「直すか移ったかを残す」を保存の形で持つ
- 記録の「書き換えない」を DB が強制し、FR-50 / FR-51 の開口部（削除の印・台帳つきの消去）だけを通す（C2 / C13）
- 滞在がどの場所かを読み出しのたびに計算し（FR-48 ★）、場所ごとの合計と名前の無い居た所を返す
- S-6 に「場所」のタブを、本人が proto で選んだ構造（Q1）で置く

**Non-Goals**
- **場所を消す操作**（画面・API）。ST23 が S-6 に足す（C13。`docs/handoff/ST23.md`）。ST21 は錠を開けておき、読み出しが削除の印と消去を効かせるところまで
- **S-2（1 日の一覧）の見出しを場所の名前にすること**（Q4）。ST21・ST22・ST25 の archive 後の `fix/`（`docs/handoff/ST25.md`）
- **滞在を手で場所に付け替える操作**（C8）/ **場所どうしをまとめる操作**（C6）/ **個人属性の住所と場所を結ぶこと**（C12）
- **地図**（C10）/ **緯度経度の欄・この端末のいまの位置**（Q1。居た所から選ぶだけ）
- **感度を変える操作**（ST24）/ **AI への経路**（ST27）/ **呼び出し元ごとの利用者の確かめ**（ST29。ほかの画面と同じく利用者は名乗り）
- **人物**（ST20）。タブの並びに人物を置かない
- **`record-envelope` / `derived-records` / `browsing-views` の要件の変更**

## Decisions

### D1. 器は追記のみの別表。識別子は画面が乱数で決め、`POST /places` で作る

器は記録ではない（本人の出来事ではなく、記録を束ねる識別子）ので `core.event` に入れない（ST19 の種類の表と同じ型。C2）。

```sql
core.place (id uuid PRIMARY KEY, seq bigint GENERATED ALWAYS AS IDENTITY,
            user_id uuid NOT NULL, created_at timestamptz NOT NULL DEFAULT now())
UNIQUE (id, user_id)
```

- **UPDATE / DELETE / TRUNCATE を拒む**（行トリガと文トリガ。**この移行専用の関数** `core.reject_place_change()`。ST03 の `core.reject_truncate()` は使わない —— ST16 / ST19 と同じ理由）
- **識別子は画面が `crypto.randomUUID()` で決めて渡す**（C1）。サーバは名前・座標から計算しない。
  `POST /places`（`{id, user_id}` → `{id}`）は `INSERT … ON CONFLICT (id) DO NOTHING` の後でその行の利用者を読み、**同じ利用者なら 200**（押し直し・送り直しで器を 2 つにしない）、
  **別の利用者なら 400**（`place_id_taken`）
- 並び（「同じ距離なら先に作った場所」・「滞在の無い場所は器を作った順」）は **`seq`** で決める（ST19 D14 —— `now()` はトランザクションの開始時刻なので `created_at` では決まらない）
- **代わりに考えたもの**: 最初の名前の記録を取り込んだときにサーバが器を作る。書き込みの口が 1 本で済むが、器を指し間違えた記録が新しい場所を黙って作る。`unknown_place` で断れる形を採った
- **代わりに考えたもの**: 器を作らず、記録の `place` の値だけで場所を束ねる。識別子が利用者の外と衝突しても検出できず、場所が「ある」ことを記録の有無でしか言えない

器だけ作って記録が 1 件も入らなかった（送る前に閉じた）器は、読み出しに出ない（spec「場所のいまの値と前の値を読める」）。消せない行として残る（Risks）。

### D2. 場所の記録は `core.event` の 1 行。ソースは `s01-place`。取り込み口を通す

**`origin='authored'`、`logical_source='s01-place'` の行として `/ingest` から入れる**（製造準備 A-1。ST19 D1 と同じ）。
エンベロープ・`core.event_live`・削除の印（FR-50）・感度（PERM-2）・書き出し（ST33）が既存のまま掛かる。

| 列 | 入れるもの |
|---|---|
| `id` | 記録の識別子（画面が振る UUID） |
| `event_time` / `tz_offset_min` / `tz_id` | **書いた日時**（画面がその記録の原文を最初に組んだ押下の時刻と地域） |
| `ingest_time` | D-01 に入った時刻（DB の既定） |
| `external_id` / `external_ref` / `device_id` | 持たない（D4 で断る） |
| `crs` | `EPSG:4326`（座標の記録は既定のまま。違えば D4 で断る。FR-28 / C3） |
| `raw` | 画面が組んだ JSON の**文字列**。受け取ったまま（C11） |
| `payload` | **サーバが `raw` から組み直した値**（`nonce` を除き、文字列は NFC） |
| `sensitivity` | 1（外部 AI に出してよい。D11（仮）） |

原文の形（`schema_version = 1`。**1 記録 1 項目**）:

```json
{"record":"<id と同じ UUID>","place":"<器の UUID>","nonce":"<128 bit の乱数を base64url>","field":"name","name":"自宅"}
{"record":"…","place":"…","nonce":"…","field":"coord","lat":35.681236,"lon":139.767125,
 "change":"first"|"fix"|"move",
 "valid_from":{"precision":"year"|"month"|"day"|"unknown","date":"2026"|"2026-04"|"2026-04-01"|null} | null,
 "supersedes":"<直す座標の記録の UUID>" | null}
{"record":"…","place":"…","nonce":"…","field":"radius","radius_m":200}
{"record":"…","place":"…","nonce":"…","field":"note","note":"裏口から入る" | null}
```

- **1 記録 1 項目にする理由**: 名前だけ変えた・広さだけ変えたが行として分かれ、「前の名前」「前の座標」をそれぞれの記録の並びから読める。
  消したことにした記録（ST23）は、その項目だけが 1 つ前に戻る。**代わりに考えたもの**: 名前・座標・広さ・補足を毎回全部持つ「その時点の写し」。
  途中の写しを消すと、前後の写しの座標の違いが「直した」のか「移った」のか分からなくなる
- **座標の変え方（`change`）を原文に持つ**（FR-49 ★「その区別を残す」/ Q2）。`first` は登録のときの 1 件だけ（D4）。
  `fix` は直す先（`supersedes`）を持ち「いつから」を持たない。`move` は「いつから」（精度は ST19 と同じ 4 つ）を持ち直す先を持たない
- `valid_from` の形と検査は ST19 の `attributes.rs` の解釈（精度・暦）を**呼び出して使う**（同じ規則を 2 か所に書かない）。理由の種別も同じ `invalid_valid_from`
- **登録簿の行**: `('s01-place', '場所', 86400, 'none')`。粒度 `none` なので、内容の鍵で同じ原文の再送が 1 件に畳まれる（ST19 D1 と同じ経路）

### D3. 消去の後に値を当てられない —— 原文にだけ乱数を入れる

ST19 D4 と同じ。画面が記録ごとに 128 bit の乱数（`crypto.getRandomValues`）を `nonce` に入れ、**`payload` にも他の列にも写さない**。
サーバは 16 バイト以上（base64url で 22 文字以上）を検査し、乱数を作らない。
乱数の強さと導き方は `web` の単体テスト、「乱数を知らなければ鍵を作り直せない」「解析済みに写らない」は Rust の結合テストで確かめる（ST19 D4 の分け方）。

### D4（仮）. 記録の検査の場所と順、広さの範囲

`crates/server/src/places.rs` に原文の解釈と形の検査を置き、`ingest_one` は `logical_source = 's01-place'` のときだけ呼ぶ。
検査の順は、形（`malformed_place_record`）→ 由来と端末（`place_record_not_authored`）→ 外部識別子 → 名前 / 座標 / 「いつから」/ 広さの値 → DB を見る 3 つ（器・座標の変え方・直す先）。
**DB を見る検査は記録を入れるのと同じトランザクションで行い、座標の記録では先頭で場所ごとの錠**（`pg_advisory_xact_lock(<鍵>, hashtext(place::text))`）を取る ——
`first` を同時に 2 本送ったとき、両方が「まだ座標が無い」を見て 2 本入るのを止める。応答は既存の 1 件ごとの結果の形のまま（値を含まない。製造準備 A-2）。

- `first` は**その場所に座標の記録が 1 件でもあれば**断る（削除の印・消去を問わない）。`move` は 1 件も無ければ断る
- 直す先は ST19 D5 と同じく行錠を取らずに読む（消した記録を直す先に指しても、読み出しがその記録を使わないので害が無い。spec が認めている）
- **本文を消去した直す先**（`raw = ''`）は、本文の代わりに、消去の後も残る `external_ref = coord_marker(place)`（`place-coord:<place>`。取り込みが座標の記録に印し、D5 の錠が凍結する）で「その場所の座標の記録か」を確かめる。
  消去を理由には断らない（spec）が、**別の場所の座標や座標でない記録の消去済みの行は断る**（final review M1。当初は消去済みなら場所も種別も見ずに通していた）
  - **反転条件**: `external_ref` の印を持たない座標の記録を書く経路ができたとき —— 消去済みの行は場所を確かめられなくなるので、「消去済みは通す」に戻す（どちらにしても、使えない直す先を指す fix は D7 で自分の位置に立つだけ）
- **広さの範囲は 10〜5,000 m**（`PLACE_RADIUS_MIN_M` / `PLACE_RADIUS_MAX_M`）。画面の選択肢（50 / 100 / 200 / 300 m。D14）より広く取り、API から書く経路を狭めない
  - **反転条件**: 本人が 5 km より広い場所（「実家の町」など）を持ちたいと言ったとき。範囲を広げるだけで、既存の記録は変わらない

`IngestError` に足す種別と当たる条件は spec「形の合わない場所の記録は受け付けない」の表（**置き場は spec**）。

### D5. 場所の記録の行の錠 —— 新しい関数で、ST03 / ST19 の関数は書き換えない

ST19 D2 の 3 つを、`'s01-place'` を見る**別の関数**として足す（`core.reject_place_record_rewrite()` / `core.require_place_erasure_ledger()` / `core.reject_place_record_delete()`）。
ST19 の関数に `OR logical_source = 's01-place'` を足す形は採らない —— ST19 の `.down.sql` と `tools/check-immutable.sh` の前提が動く。

- 即時の錠: `s01-place` への付け替えを拒み、`id` / `user_id` / `origin` / `logical_source` / `external_id` / `external_ref` / `device_id` / `event_time` / `tz_offset_min` / `tz_id` / `ingest_time` / エンベロープの列の変化を拒む
- COMMIT 時の門: `raw` / `payload` / `content_hash` が変わるなら、**消去の形**（`raw = ''` / `payload = '{}'` / `event_time` と `content_hash` は不変）かつ**同じまとまりにその記録の `core.erasure_ledger` の行**（`event_id = NEW.id AND scope = 'event' AND txid = pg_current_xact_id()`）があるときだけ通す
- 行の削除の拒否。表の切り詰めは ST03 の文トリガが既に拒む

`tools/check-immutable.sh` に場所の記録と器の表の錠の段を足す。既存の「本人が書いた記録は書き換えられる」の段は ST19 で `logical_source = 'immutable-check'` に絞られている（場所の行があっても通る）ことを確かめる。

### D6（仮）. いまの値の読み方

`places.rs` の純粋な関数 `view(places, records, stays, today) -> PlacesView` で組む（DB を持たないので単体テストで固定する）。

1. 削除の印の付いた記録（`core.event_live` で除く）と、本文を消去した記録（`raw = ''`）を除く
2. 名前・広さ・補足は、それぞれ書いた日時（`event_time`）→ D-01 に入った時刻の順で最後の記録がいまの値。広さの記録が無ければ **`PLACE_DEFAULT_RADIUS_M = 100`**（FR-48 ★「既定 100 m」）。補足の記録の `note: null` は補足なし
3. 名前の記録と座標の版（D7）を 1 つ以上ずつ持つ器だけを返す（C7）
4. 前の名前は、いまの名前以外の名前の記録を書いた日時の新しい順。前の座標は、いまの座標の版以外の座標の記録（直されたもの・移る前のもの・未来の移転）

- `PLACE_DEFAULT_RADIUS_M` は `stay::Criteria::default_values().radius_m` と**別の定数**にする（滞在の判定の半径を変えても場所の既定は変わらない。どちらも 100 をテストで名指しで固定する）
- **反転条件**: 名前にも「いつから」を持たせたくなったとき（「旧自宅」と呼ぶ期間を分けたい、など）—— 名前の記録に `valid_from` を足す。既存の記録は書いた日時の順のまま読める

### D7（仮）. 座標の版と、版ごとに当てる期間

FR-49 ★ の「移ったなら、前の座標で居た時間もこの場所」を、**座標の版ごとに当てる期間**で表す。手順は spec「座標の版ごとに当てる期間を決める」で、実装は `places.rs` の純粋な関数 `coord_windows(records) -> Vec<Window>`。

```
版   = 使える座標の記録のうち、使える fix に直されていないもの（fix は直した記録の位置と当て始めを継ぐ）
並び = 版を書いた順（fix の版は直した記録の書いた順。直す先が使えない fix は自分の書いた順）
当て始め start(v) = first → 最も古い時刻 / move(分からない) → 最も古い時刻 / move(年・年月・年月日) → その年の 1/1・その月の 1 日・その日の、どれも Asia/Tokyo 0 時
                  / fix → 直した版の当て始め（直す先が使えなければ最も古い時刻）
区切り   b(v)     = start(v) が最も古い時刻でなければ start(v)、最も古い時刻なら v を書いた日時（fix の版は直した記録を書いた日時）
当て終わり end(v_i) = min { b(v_j) | j > i }（後に書いたどの版の区切りよりも前まで）。後に版が無ければ終わり無し
```

- **後に書いた版が勝つ**（spec-review R15）。当初は「次の版の当て始めまで」だけを見ていたので、後から古い「いつから」の移転（2026-04 の後に 2025-06）を書くと、
  2 つの版が 2025-06〜2026-04 で重なり、間の版は空の期間を持った。`min` にすると、後に書いた版がその区切りから後を占め、前の版はそこで切れる
  （ST19 の「後に書いた主張が勝つ」と同じ向き）。古い「いつから」を断る形（反転の候補）は、位置の記録が無い期間の移転を後から書けなくする
- **今日を含む版が無い場所**（最初の座標を消して未来の移転だけが残った、など）のいまの座標は、書いた順の最後の版（spec-review R15）

- **「いつから分からない」の移転**は、移ったと書いた日まで前の版と新しい版の**両方**が当たる。どちらで居たかを決められないので、どちらも落とさない（照合は D8 で近いほうを選ぶ）
- **「間違いを直す」は直した版の期間をそのまま継ぐ** —— 直された座標はどの期間にも当たらない（Q2「直したなら全期間が新しい座標」）
- **兄弟の fix**（直す先を辿ると同じ記録に行き着く fix が 2 件以上。2 つのタブや 2 つの端末から同じ版に「直す」を送ったとき）は、**最後に書いた 1 件だけを版にする**（final review I2）。
  負けた fix は前の座標に「直した」（`state = fixed`）として出し、`fixed_by` は勝った fix を指す。直された記録の `fixed_by` は、それを直す先に持つ fix のうち最後に書いたもの。
  **取り込みでは断らない** —— 断ると本人の操作を捨てる。読み出しの側なら記録を書き換えずに計算し直せる
  - **反転条件**: 兄弟の fix を本人に誤操作として見せたい・どちらを採るか選ばせたいと言ったとき（読み出しが変わるだけ）/ 取り込みで断る形（`invalid_coord_supersedes`。再送は `is_resend` で先に通る）に変えたいとき —— 既に入った兄弟は読み出しの規則のまま読める
- いまの座標は今日（`Asia/Tokyo`）を含む版で、2 つ以上あれば並びの後の版。今日より後の「いつから」の移転はいまの座標を変えず、前の座標の一覧に**予定**として入る（spec-review R4。画面は「予定（YYYY-MM から）」と出し、「前の名前・座標 N」の N に数える）
- **代わりに考えたもの**: ST19 の「いつから」の比較（分からない = 最も古い）をそのまま使う。「いつから分からない」の移転が最初の座標を全期間で上書きし、FR-49 の「前の座標で居た時間もこの場所」が崩れる
- **代わりに考えたもの**: 版を問わず、使えるどの座標の近くでもその場所とする。期間の区切りが要らず単純だが、引っ越した後に前の家に別の場所（「実家」など）を登録すると、移る前の滞在がどちらにも当たる
- **反転条件**: 本人が「移った」の境目を滞在から決めてほしいと言ったとき（位置の記録がある期間は、前後の座標での滞在の境目から計算し直せる。deep R5）/ 移転の日の境を 0 時以外にしたいとき。どれも記録を書き換えずに計算し直せる

### D8（仮）. 照合

`places.rs` の純粋な関数 `assign(stays, places) -> Vec<Option<PlaceId>>`。

- 滞在は `core.event_live` の `s01-stay`・`origin='derived'` の利用者の全行（`day_view` と同じ絞り方）。代表点は `payload` の `lat` / `lon`、時刻は `event_time`（始まり）、長さは `span_of`。**代表点の無い滞在は当てない**
- 各場所の、滞在の始まりを期間に含む版の座標との距離（`stay::distance_m`。滞在の判定と同じ近似）の最小が、その場所の広さ以下なら候補。候補のうち距離が最小、同じなら `seq` が小さい場所
- **書き込まない**（FR-48 ★）。結果は `GET /places` / `GET /places/candidates` の応答の中だけにある
- **反転条件**: 滞在の始まりでなく真ん中や長さの重みで版を選びたいとき / 1 件の滞在を 2 つの場所に分けたいとき（長い滞在が移転の日をまたぐ）。どれも計算し直せる

読み出しのたびに利用者の全滞在を読む（1 年で千数百件・5 年で 1 万件弱。proto の量）。版の数は場所 22 × 数版で、総当たりで足りる。

### D9（仮）. 場所ごとの合計・最後に居た日・24 時間の帯・並び

- 合計は当たった滞在の `end - start` の和（分）。件数は当たった滞在の数
- 最後に居た日は当たった滞在の `end` の最大の `Asia/Tokyo` の日付。並びはその時刻の新しい順、当たった滞在の無い場所はその後に `seq` の順（Q1「最近居た順」）
- 24 時間の帯は、当たった滞在を `Asia/Tokyo` の時刻で 1 時間ごとに切って、0〜23 時台の分を足した 24 個の整数（分。端数は切り捨てずに秒で足してから分へ丸める）
- **反転条件**: 並びを「最後に居た日」の日付の単位にしたい（同じ日の並びを長く居た順に）とき / 帯を平日と休日で分けたいとき

### D10（仮）. 名前の無い、よく居た所

`places.rs` の純粋な関数 `candidates(stays_unassigned) -> Vec<Candidate>`。**保存しない**（C9）。

1. どの場所にも当たらない滞在を始まり → 識別子の順に並べる
2. 1 件ずつ、中心（属する滞在の代表点の単純平均）が **`CANDIDATE_RADIUS_M = 100`** 以内の最初のまとまりに足す。無ければ新しいまとまり
3. まとまりごとに中心・件数・合計・最初と最後に居た日・24 時間の帯（D9 と同じ数え方）
4. 属する滞在の `end` の最大の新しい順、同じなら合計の大きい順、同じなら中心の緯度・経度の順

- 中心は登録（`first`）と「座標を変える」（`fix` / `move`）で座標として送られる（Q1「居た所から選ぶだけ」）
- `CANDIDATE_RADIUS_M` は場所の広さとも滞在の判定の半径とも別の定数（C9 の 100 m）
- **反転条件**: 同じ所が 2 つに割れる（大学の構内など）と本人が言ったとき —— まとめる半径を広げるか、長さの重みで中心を取る。保存していないので読み出しが変わるだけ

### D11（仮）. 既定の感度はコードの分岐で持つ

`crates/server/src/lib.rs` の `default_sensitivity` に `places::SOURCE` の枝を足し、**`places::DEFAULT_SENSITIVITY = 1`**（外部 AI に出してよい。PERM-3 ★ / Q3）を返す。
**DB の既定と同じ値でも分岐として明示する**（deep.md Q3「黙って既定に乗らない」）。テストは定数を名指しで 1 に固定し、ST19 の `attributes::DEFAULT_SENSITIVITY`（2）が変わらないことも見る。

- **反転条件**: ST24 が登録簿に「ソースごとの既定の感度」を持たせたとき、この分岐を登録簿の値に移す（値は 1 のまま）。本人が締め直すと言ったとき（扉 #15 の代償は選択肢に書いてあった）

### D12. 画面 —— `#/master/places`、登録した場所のカードだけ

`web/src/PlacesView.tsx` と `web/src/places.ts`（型・形の検査・原文の組み立て・時間と日付の書き方）。`Root.tsx` に `#/master/places` を足し、
`MasterView.tsx` のタブを「個人属性」（`#/master`）・「場所」（`#/master/places`）の 2 つにする（`role="tablist"`。押すと hash が変わる）。
**`#/master` はこれまでどおり個人属性を開く**（稼働状況の入口はそのまま）。構造は本人が proto で決めたとおり（Q1 の逐語。`deep.md`）:

- カードは読み出した順に 1 枚ずつ: 名前 / 合計（1 時間以上は「N 時間」、未満は「N 分」）/ 「最後に居た日 YYYY-MM-DD · 広さ N m」（滞在が無ければ「まだ居たことが無い · 広さ N m」）/
  24 区分の帯（濃さ = その時刻台の分 ÷ 24 区分の最大。0 の区分も枠は描く）/ いまの座標（小数 4 桁。表示だけ）/
  「前の名前・座標 N ▸」（`<button aria-expanded>`。N が 0 なら出さない）/「名前を変える」「広さを変える」「座標を変える」
- 前の座標の行は「直した」/「移る前（〜YYYY-MM）」/「予定（YYYY-MM から）」の文字を添える。色だけで区別しない
- 下に「場所を足す」。押すと `GET /places/candidates` を読み、名前の無い居た所を 10 件と「残り N か所 ▸」で出す。各居た所は「名前なし」・合計・帯・「N 回 · 最初 〜 最後」・「名前を付ける」
- **地図・`navigator.geolocation`・外部のフォントや画像を使わない**（C10）。e2e は画面を開いている間の求めの宛先がすべて同じ所であることを数える
- 表面は `tokens.ts`（`SCHEMES` と `tone`）だけから引く。触れる対象は 24 px 以上（ST19 の `control()` を使う）
- 縦の量は D21（仮）

### D13（仮）. 書く流れ —— 器 → 記録の束。押し直しは同じものを送る

`places.ts` に、押した時点で器の識別子・各記録の `id`・`nonce`・書いた日時（`new Date()` と `Intl` の地域）を決めて原文を組む関数を置く。

- **登録**: `POST /api/places`（器）→ `POST /api/ingest` に名前・`first` の座標・広さ（**既定の 100 m でも送る** —— 本人が選んだ値を記録に残す）・補足（入れたときだけ）の記録を 1 回で送る
- **名前・広さ・座標を変える**: `POST /api/ingest` に 1 件
- **入力を変えずに押し直した・届かずに送り直すときは、同じ器の識別子と同じ原文を送る**（器は D1 で同じ利用者なら 200、記録は冪等で 1 件）
- **登録で入力を変えて押し直すときも、器の識別子は保ち、変わった項目の記録だけを組み直す**（変わらない項目は同じ識別子・原文・書いた日時を送り直し、内容の鍵で畳まれる）。
  前に送った補足を空にしたら、補足を消す記録（`note: null`）にする。名前・広さ・座標を変えるフォームは 1 件なので、入力を変えたらその 1 件を組み直す
  - 理由（final review I1）: 束は 1 件ごとに受理されるので、断られた・応答だけが落ちた押下でも一部の記録は入っている。当初は「入力を 1 か所でも変えたら器ごと組み直す」で、
    前の器とそこに受理された位置・補足の記録が消せないごみとして残り、応答だけが落ちたときは同じ座標に名前付きの場所が 2 つ見える形で並んだ
  - **名前が空白だけのうちは「登録する」を押せなくする**（送ると名前だけが `invalid_place_name` で断られ、位置と補足の記録が名前の無い器に残る）
  - **名前・広さを変えるフォームは、いまと同じ値のうちは「変える」を押せなくする**（同じ値の記録が増え、「前の名前: <いまと同じ名前>」が出る。final review M3）
  - **反転条件**: 押し直しで別の場所として登録し直したい（同じ居た所に 2 つの場所を作りたい）と本人が言ったとき —— フォームを閉じて開き直せば新しい器になる。
    名前の無い器に残った記録は、ST23 の「消したことにする」が来たら消せる
- 送っている間は押した操作を押せなくする。受理されたらフォームを閉じ、`GET /places` と（開いていれば）`GET /places/candidates` を読み直す
- 応答は ST19 D9 と同じく **200 でも 400 でも本文の 1 件ごとの結果を読む**。本文が読めない・届かない（`fetch` が投げる / 5xx / 401）ときだけ「届かなかった」

| 種別 | 画面の文 |
|---|---|
| `invalid_place_name` | 名前が空です。名前を入れてください |
| `invalid_radius` | 広さが範囲の外です |
| `invalid_valid_from` | 「いつから」の日付が読めません |
| `unknown_place` | この場所が見つかりません。画面を読み直してください |
| `invalid_coord_supersedes` | 直す座標が見つかりません。画面を読み直してください |
| `invalid_coord_change` | この場所の座標の変え方が合いません。画面を読み直してください |
| `invalid_coordinate` | 座標が読めません |
| `place_id_taken`（器） | 場所を作れませんでした。もう一度「登録する」を押してください（押し直しは識別子を作り直す） |
| それ以外 | 受け付けられませんでした（種別の名前） |
| 届かなかった | サーバに届きませんでした。入力はそのまま残っています |

`place_id_taken` は乱数の衝突でしか起きないので、**その後の押し直しだけは器の識別子と原文を組み直す**（同じ識別子を送り直しても通らない。spec「器の識別子が取られていたら押し直しで識別子を作り直す」）。

- 種別ごとに文を分ける（spec「理由の種別ごとに異なる文」。spec-review R2 —— 当初は 3 種別に同じ文を当てていた）
- **反転条件**: 文言に本人が違和感を言ったとき（表示だけで、送るものは変わらない）

### D14（仮）. 座標を変えるフォームと広さの選択肢

- 新しい座標の選択肢は名前の無い居た所（D10 の順。10 件と「残り N か所」）。**登録した場所の座標は選択肢に出さない**（別の場所の座標へ移す操作は、2 つの場所が同じ所を指すことになる）
- 「前の座標が間違っていた」は **いまの座標の版の記録**（`GET /places` が返す識別子）を直す先にする。前の版を直す選択は置かない
- 「この場所が移った」を選ぶと「いつから」の精度（年・年月・年月日・分からない）を先に選ばせ、選んだ精度の欄だけを出す（ST19 の「書く」と同じ部品）。
  下に「前の座標で居た時間も「<名前>」のまま」を出す（proto の文から時間の数を外した —— 数を出すには版ごとの合計を読む口が要り、本人が選んだ構造の外）
- 広さの選択肢は 50 / 100 / 200 / 300 m（proto のまま）
- **反転条件**: 前の版の座標を直したい（引っ越す前の家の座標の打ち間違い）と本人が言ったとき —— 直す先を前の座標の一覧から選ばせる（API は既にどの座標の記録でも直せる）/
  300 m より広い場所を画面から作りたいとき —— 選択肢を足す（API は 5,000 m まで受ける）

## Risks / Trade-offs

- [読み出しのたびに全滞在を照合する（D8）] → 5 年で 1 万件弱 × 版 100 程度。重くなったら場所ごとの外接矩形で絞る（保存はしない）
- [器だけの行が消せずに残る（D1）] → 送る前に閉じた登録 1 回で 1 行。読み出しに出ないので画面は汚れない。任意の利用者を名乗って器を作れる（ST29）
- [名前の無い居た所の中心は、滞在が増えると動く（D10）] → 登録した座標は登録した時点の中心で固定される（記録）。後で中心がずれて広さの外に出た滞在は名前の無い所に残るので、本人は広さか座標で直せる
- [座標を変えた直後、前の座標の近くの滞在が名前の無い所に戻る（「間違いを直す」のとき）] → spec どおり（全期間が新しい座標）。直す前の座標は前の座標として残るので、間違えて「直す」を選んだら ST23 の消す口で直す記録を消せば戻る（それまでは「移った」の記録を足して戻すことになる）
- [利用者を名乗れる（ST29）] → 他の利用者を名乗って場所を書ける・読める。器と直す先の検査は利用者の中に閉じる（D4）ので、名乗った利用者の外の場所は壊せない
- [ST28 の下流が `testdb.rs` と画面のログインを変えている] → 後から merge する側が追従する。ST28 が先なら、場所の試験は所有者の接続で書き、e2e は既定の `storageState` で通す

## Migration Plan

1. 移行を当てる（起動のたびに全版を当てる既存の形）
2. 既存の行は触らない（場所のソースの行はまだ無い。滞在は読むだけ）
3. 戻すときは `.down.sql`。場所の記録か器が残るうちは登録簿の行と器の表が消えない（D16）
