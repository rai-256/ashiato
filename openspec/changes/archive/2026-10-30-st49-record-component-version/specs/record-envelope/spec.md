## ADDED Requirements

### Requirement: 記録は、作った部品の版と、D-01 に書いた S-01 の版を持つ

THE SYSTEM SHALL 記録 1 件ごとに 3 つの版の欄を持たせる: その記録を作った収集アプリの版、その記録を組んだ画面の版、その記録を D-01 に書いた S-01 の版。
THE SYSTEM SHALL S-01 の版を、すべての記録（収集アプリ・書庫の取り込み・派生・画面・衛星の記録）に、S-01 が自分の組み立ての印から入れる。要求の中身からは決めない。
THE SYSTEM SHALL 収集アプリの版と画面の版は、取り込みの要求の任意の欄（部品の版）で受け取り、どちらの欄に入れるかを要求の資格情報で決める（「部品の版は、要求の資格情報で振り分ける」）。
THE SYSTEM SHALL 版の値を文字列のまま持ち、形を検査しない。部品の版の欄が空・形が違う・無いことを理由に記録を断らない。空の文字列は「不明」として持ち、格納できない文字（U+0000）は取り除いて持つ。
THE SYSTEM SHALL 版を持たない記録（版を残し始める前に入った記録・版の欄を持たない要求）の版を「不明」のまま持ち、取り込みの時刻などから推定して埋めない。
THE SYSTEM SHALL 前の版の履歴にも同じ 3 つの版の欄を持たせ、前の版の読み口にも載せる。

導出元: FR-122, FR-123。扉 #32。深掘り（ST49）Q2・Q4（いずれも推奨で先に書いた）。
記録を作った後から版を足す手段は無い。S-01 は収集アプリの記録にも手を入れる（文字の正規化・内容の鍵・既定の単位と座標系・重複の判定）ので、受け取った S-01 の版も残す。
衛星自身の版は付けない（サーバが確かめられない）。

#### Scenario: 収集アプリの記録は、収集アプリの版と書いた S-01 の版を持つ

- **WHEN** API の合言葉で、部品の版に `0.1.0+<commit A>.debug` を書いた記録を 1 件送る
- **THEN** 格納された記録の収集アプリの版は `0.1.0+<commit A>.debug`、S-01 の版はその S-01 の組み立ての印、画面の版は「不明」

#### Scenario: 記録の S-01 の版は、その S-01 の組み立ての印と同じで、印の形を持つ

- **WHEN** S-01 が記録を 1 件格納する
- **THEN** 記録の S-01 の版は、その S-01 が組み立ての時に埋め込んだ印と一字一句同じで、`<版番号>+<40 桁の 16 進か unknown>` に `.dirty` / `.debug` が 0〜2 個続く形

#### Scenario: 書庫の取り込みの記録は、書いた S-01 の版だけを持つ

- **WHEN** 書庫の取り込みが記録を 1 件格納する
- **THEN** 記録の S-01 の版はその S-01 の組み立ての印で、収集アプリの版と画面の版は「不明」

#### Scenario: 部品の版の欄を持たない要求の記録は、部品の版が「不明」で入る

- **WHEN** API の合言葉で、部品の版の欄を持たない（いまの収集アプリと同じ形の）記録を 1 件送る
- **THEN** 記録は受け付けられ、収集アプリの版は「不明」、S-01 の版はその S-01 の組み立ての印で、結果の形と状態符号は欄を足す前と同じ

#### Scenario: 部品の版が空か形の違う文字列でも、記録は断られない

- **WHEN** API の合言葉で、部品の版に空の文字列を書いた記録と、` not a version ` を書いた記録を送る
- **THEN** 2 件とも受け付けられ、前者の収集アプリの版は「不明」、後者は前後の空白も含めて ` not a version ` のまま残る

#### Scenario: 格納できない文字を含む部品の版は、その文字を取り除いて残る

- **WHEN** API の合言葉で、部品の版に `0.1.0+<commit A>` の途中へ U+0000 を挟んだ値を書いた記録を送る
- **THEN** 記録は受け付けられ（まとめ送りの他の件も入り）、収集アプリの版は U+0000 を除いた `0.1.0+<commit A>`

#### Scenario: 版を残し始める前に入った記録の版は「不明」のまま

- **WHEN** 版の欄を足す移行を、記録が入っている D-01 に当てる
- **THEN** 当てる前に入っていた記録の 3 つの版はすべて「不明」で、移行は値を推定で埋めない

### Requirement: 組み立ての印は、版番号・commit・その部品のソースの未 commit の変更・組み立ての種類を持ち、組み立てのたびに作り直す

THE SYSTEM SHALL S-01・C-01・C-02・V-01 の組み立ての印を `<その部品の宣言した版番号>+<commit>` の形にし、その部品のソースに未 commit の変更があれば `.dirty`、release でない組み立てなら `.debug` を、この順で末尾に足す。
THE SYSTEM SHALL commit を 40 桁の 16 進で持ち、短縮しない。commit を取れなければ `unknown` にする。
THE SYSTEM SHALL 印を、commit が進んだとき・その部品のソースが変わったとき（add していない変更を含む）に、ソースのほかの部分に触れない差分の組み立てでも作り直す。
THE SYSTEM SHALL 「その部品のソース」を、S-01 は自分の crate と印を組む crate と移行と workspace の宣言、C-02 は自分の crate と印を組む crate と workspace の宣言、C-01 は携帯の収集アプリの木、V-01 は画面の木とする。

導出元: FR-122, FR-123。扉 #32。深掘り（ST49）Q1（推奨）。premises の C10・C11。
版番号だけでは、同じ番号の組み立て（開発版の日ごと・手元の組み立て・同じ commit の debug と release）が作った記録を分けられない。記録の版は後から直せない記録に焼き込むので、差分の組み立てで古い印を残さない。
未 commit の印をその部品のソースに限るのは、ほかの部品の木の変更はその部品の組み立てに入らないから（入らない変更で `.dirty` を付けると、同じ中身の組み立てが別のものに見える）。

#### Scenario: 印は版番号・commit・未 commit の印・組み立ての種類を持つ

- **WHEN** 印を組む道具が、部品のソースに未 commit の変更がある git の木で、release でない組み立ての印を組む
- **THEN** 印は `<版番号>+<その木の HEAD の 40 桁>.dirty.debug`

#### Scenario: 綺麗な木の release の組み立ての印は、版番号と commit だけを持つ

- **WHEN** 印を組む道具が、未 commit の変更の無い git の木で、release の組み立ての印を組む
- **THEN** 印は `<版番号>+<その木の HEAD の 40 桁>` で、`.dirty` も `.debug` も持たない

#### Scenario: ほかの部品の木だけが変わっていても、印は .dirty を持たない

- **WHEN** 印を組む道具が、その部品のソースの外（ほかの部品の木）にだけ未 commit の変更がある木で印を組む
- **THEN** 印は `.dirty` を持たない

#### Scenario: commit が取れない場所での組み立ての印は unknown を持つ

- **WHEN** git の木の外で、commit の環境変数も無く印を組む
- **THEN** 印は `<版番号>+unknown` で始まる

#### Scenario: S-01 の組み立ての印は、commit を進めた後の差分の組み立てでも新しい commit になる

- **WHEN** S-01 を組み立てた後に commit を 1 つ足し、ソースに触れずにもう一度組み立てる
- **THEN** 2 回目の組み立てに埋め込まれた印の commit は、足した commit の 40 桁

#### Scenario: S-01 の組み立ての印は、add していないソースの変更の後の差分の組み立てで .dirty になる

- **WHEN** 綺麗な木で S-01 を組み立てた後に、S-01 のソースを 1 つ書き換えて add せずにもう一度組み立てる
- **THEN** 2 回目の組み立てに埋め込まれた印は `.dirty` を持つ

### Requirement: 部品の版は、要求の資格情報で振り分ける

THE SYSTEM SHALL 取り込みの要求が API の合言葉（C-01 / C-02）で来たときだけ、部品の版を収集アプリの版として持つ。
THE SYSTEM SHALL 取り込みの要求が画面のログインの印で来たときだけ、部品の版を画面の版として持つ。
THE SYSTEM SHALL それ以外の書き手（S-01 の中の書庫の取り込み・資格情報が API の合言葉でも画面のログインでもない書き手）の部品の版を、どちらの欄にも入れない。
THE SYSTEM SHALL 振り分けで使わなかった部品の版を、断る理由にしない（記録は入る）。

導出元: FR-122, FR-123, FR-92。深掘り（ST49）Q4（推奨）。premises の C7。
収集アプリと画面は同じ取り込み口に同じ形で送るので、欄の名前ではなく資格情報で書き手を決める（FR-92）。衛星の記録には衛星の版を付けない（FR-123 ★ Q13）。

#### Scenario: 画面のログインの要求の部品の版は、画面の版として入る

- **WHEN** 画面のログインの印で、部品の版に `0.1.0+<commit B>` を書いた記録を 1 件送る
- **THEN** 記録の画面の版は `0.1.0+<commit B>`、収集アプリの版は「不明」、S-01 の版はその S-01 の組み立ての印

#### Scenario: 合言葉でもログインでもない書き手の部品の版は、どこにも入らない

- **WHEN** S-01 の中の格納（書庫の取り込みの口）に、部品の版に `0.1.0+<commit C>` を書いた要求を渡す
- **THEN** 記録は格納され、収集アプリの版と画面の版は「不明」、S-01 の版はその S-01 の組み立ての印

### Requirement: 版は、同じ記録の判定と内容に効かない

THE SYSTEM SHALL 3 つの版を、内容の鍵（同じ記録の判定）・原文・解析済みの内容のどれにも入れない。
THE SYSTEM SHALL 同じ内容の記録が別の版から 2 度届いたら、先に入った行の版を残し、後の到着を重複として扱う（行も版も変えない）。

導出元: FR-122, FR-123, FR-22。壊してはいけないもの「送信契約の既存の欄と重複判定（同じ記録を何度送っても増えない。ST03）」。premises の C3。
版を鍵に混ぜると、同じ記録が版ごとに別の行になる。

#### Scenario: 部品の版だけが違う同じ記録は、1 件のまま

- **WHEN** 外部の識別子を持たない同じ内容の記録を、部品の版 `0.1.0+<commit A>` と `0.1.0+<commit D>` で 1 回ずつ送る
- **THEN** 記録は 1 件だけで、2 回目の結果は重複、記録の収集アプリの版は `0.1.0+<commit A>` のまま

#### Scenario: 部品の版を足しても内容の鍵は変わらない

- **WHEN** 同じ論理ソース・出来事の時刻・原文の記録を、部品の版の欄ありと無しで内容の鍵に通す
- **THEN** 2 つの内容の鍵は同じで、版の欄を足す前の固定値とも同じ

### Requirement: 中身が入れ替わる更新では、版も一緒に動き、前の値は前の版に残る

THE SYSTEM SHALL 外部サービス由来の更新で記録の中身を入れ替えるとき、3 つの版を、届いた要求の部品の版（資格情報で振り分けたもの）と、その更新を書いた S-01 の版に替える。
THE SYSTEM SHALL そのとき、入れ替える前の 3 つの版を前の版の履歴に写す。
THE SYSTEM SHALL 中身が変わらない到着（同じ内容の再到着・更新時刻だけが新しい到着）・古い到着として退けた更新・削除済みの記録への更新では、版を変えない。

導出元: FR-122, FR-123, FR-22。design D1（仮）。review/deep.md R1。
版は今の中身を作った部品の版を指す —— スキーマ版と同じ扱い。前の値は前の版に残るので、どちらの読み方にも後から戻せる。

#### Scenario: 外部サービス由来の更新で、版が新しい到着の版に替わり、前の版が履歴に残る

- **WHEN** 印 `0.1.0+<commit A>` の S-01 が、外部の識別子 `v1` の記録を部品の版 `0.1.0+<commit A>` で入れた後、印 `0.1.0+<commit D>` の S-01 が、同じ `v1` で内容の違う記録を部品の版 `0.1.0+<commit D>` で受け取る
- **THEN** 記録の収集アプリの版と S-01 の版はどちらも `0.1.0+<commit D>` で、前の版の履歴の 1 行目の収集アプリの版と S-01 の版はどちらも `0.1.0+<commit A>`

#### Scenario: 内容の変わらない再到着では、版は変わらない

- **WHEN** 外部の識別子 `v1` の記録を部品の版 `0.1.0+<commit A>` で入れた後、同じ `v1` で同じ内容を、更新時刻だけ新しくして部品の版 `0.1.0+<commit D>` で送る
- **THEN** 記録の収集アプリの版は `0.1.0+<commit A>` のままで、前の版の履歴は増えない

#### Scenario: 古い更新時刻の到着では、版は変わらない

- **WHEN** 外部の識別子 `v1` の記録を更新時刻 10:00・部品の版 `0.1.0+<commit A>` で入れた後、同じ `v1` で内容の違う記録を更新時刻 09:00・部品の版 `0.1.0+<commit D>` で送る
- **THEN** 記録の収集アプリの版は `0.1.0+<commit A>` のままで、前の版の履歴は増えない

#### Scenario: 削除済みの記録への更新では、版は変わらない

- **WHEN** 外部の識別子 `v1` の記録を部品の版 `0.1.0+<commit A>` で入れて削除した後、同じ `v1` で内容の違う記録を部品の版 `0.1.0+<commit D>` で送る
- **THEN** 記録の収集アプリの版は `0.1.0+<commit A>` のままで、前の版の履歴は増えない

#### Scenario: 前の版の読み口と前の版の表は、記録の表と同じ版の列を持つ

- **WHEN** 記録の表・前の版の表・前の版の読み口の列を並べる
- **THEN** 3 つの版の列が、記録の表と前の版の表と前の版の読み口のすべてにある

### Requirement: 収集した記録の版は、前の版を同じまとまりに積むときだけ書き換えられる

THE SYSTEM SHALL 収集した記録の 3 つの版の列の書き換えを、収集した記録の書き換えの門（前の版の履歴か台帳が同じまとまりにあるときだけ通る）の対象にする。
THE SYSTEM SHALL 前の版の履歴の 3 つの版の列を、ほかの列と同じく書き換えられないようにする。
THE SYSTEM SHALL 版の列を足しても、収集した記録の原文・解析済みの内容・出来事の時刻・内容の鍵の書き換えを今と同じに拒む。

導出元: FR-30, FR-122。壊してはいけないもの「収集した記録を書き換えない門（FR-30）」。premises の C8 を design D21（仮）で改めた（review/spec.md R7）。
古い組み立てに残った誤った印は直せるが、直すときも前の値は前の版に残る。前の値を残さずに書き換えられると、D1（仮）の「どちらの読み方にも後から戻せる」が成り立たない。

#### Scenario: 収集した記録の版を、前の版の履歴なしで書き換えると拒まれる

- **WHEN** 収集した記録の収集アプリの版だけを、前の版の履歴を書かずに書き換える
- **THEN** 書き換えは拒まれる

#### Scenario: 前の版を同じまとまりに積めば、収集した記録の版を直せて、前の値が残る

- **WHEN** 同じまとまりで収集した記録の前の版を履歴に積み、収集アプリの版を直す
- **THEN** 書き換えは通り、前の版の履歴の行に直す前の収集アプリの版が残る

#### Scenario: 前の版の履歴の版は書き換えられない

- **WHEN** 前の版の履歴の行の収集アプリの版・画面の版・S-01 の版をそれぞれ書き換える
- **THEN** 3 つとも拒まれる

#### Scenario: 版の列を足しても、収集した記録の原文の書き換えは拒まれる

- **WHEN** 版の列を足した後に、収集した記録の原文を前の版の履歴なしで書き換える
- **THEN** 書き換えは拒まれる

### Requirement: 画面は、本人が書く記録の要求に、読み込まれた画面の組み立ての印を載せる

THE SYSTEM SHALL V-01 が取り込み口へ送る本人の記録（気分・場所・個人属性の主張）の 1 件ごとに、そのとき読み込まれている画面の組み立ての印を部品の版の欄に書く。

導出元: FR-123 ★ 2026-10-25（V-01 から本人が書く記録）。深掘り（ST49）Q4（推奨）。premises の 13。
画面から書く記録の原文・出来事の時刻・TZ は画面の JS が組む。S-01 を更新した後も開いたままのタブは古い画面の JS のままなので、S-01 の版だけではどの画面が組んだかを分けられない。

#### Scenario: 画面が送る気分・場所・個人属性の主張の 1 件は、画面の組み立ての印を持つ

- **WHEN** 組み立てた画面から、気分・場所・個人属性の主張の記録をそれぞれ 1 件送る
- **THEN** 取り込み口に届いた要求のどの 1 件も、部品の版の欄に画面の組み立ての印（印の形を持ち、版番号は画面の宣言した版番号）を持つ
