## MODIFIED Requirements

### Requirement: すべての API 要求は資格情報を要求する

THE SYSTEM SHALL 生存確認（`GET /healthz`）・ログイン（`POST /session`）・ログアウト（`DELETE /session`）の口を除くすべての API 要求に、呼び出し元を識別できる資格情報を要求する。
THE SYSTEM SHALL 資格情報を欠くか一致しない要求を、引数や本文を読む前に 401 で拒否する。
THE SYSTEM SHALL 資格情報の比較を、一致した長さから内容が推測されない方法で行う。

導出元: PERM-10。
PERM-7（外部からの到達を Tailscale 網内に限る）は**網の外を止めるだけ**で、
**同じ PC の中から呼ぶものを何も止めない**。第三者製のプラグインは同じ PC で動く。
★ ST44（深掘りの AI の既定）: 要件（PERM-10）の本文が除く 3 つの口を例外として書いた。生存確認は記録に触れず、ログインの資格情報は画面の合言葉そのもの（data-sensitivity）、
ログアウトは付けてきた印を無効にするだけで、印が無くても何も読めない。資格情報で読める範囲は data-sensitivity が決める。

#### Scenario: 資格情報が無いと拒否される

- **WHEN** 資格情報を付けずに取り込み口または読み出し口を呼ぶ
- **THEN** 401 で拒否される

#### Scenario: 同じ PC の別プロセスからでも拒否される

- **WHEN** 同じ PC 上の別プロセスが資格情報を付けずに呼ぶ
- **THEN** 401 で拒否される

#### Scenario: 資格情報を求めない口は生存確認・ログイン・ログアウトの 3 つだけ

- **WHEN** API の説明に載る全部の口と方法と生存確認を、資格情報を付けず、問い合わせの引数も本文も付けずに 1 回ずつ呼ぶ（ログインは合言葉の欄の無い JSON の本文で呼ぶ）
- **THEN** 生存確認は 200、ログアウトは 204 を返し、ログインは合言葉が無いので 401 で断られ、ほかの口はすべて引数や本文の形にかかわらず 401 で拒否される
