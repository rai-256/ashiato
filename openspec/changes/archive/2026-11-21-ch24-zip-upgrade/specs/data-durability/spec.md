## ADDED Requirements

### Requirement: サーバの版が変わっても、以前の版のサーバが書いた書き出しを同じ中身で読み、新しく書く書き出しは以前と同じ AES の形を持つ

THE SYSTEM SHALL サーバの版が変わった後も、以前の版のサーバが書いた書き出しの zip を、その合言葉で、書いたときと同じ中身で全部の項目を読み、
zip の注記（`ashiato-export <書き出しの id>`）もそのまま読む。
THE SYSTEM SHALL 書き出しの台帳の照合で、以前の版のサーバが書いて置き場に残っている書き出しを、書いたままのファイルと判定する
（新しい書き出しを書き終えたら、それを消して 1 つだけ残す）。
THE SYSTEM SHALL 新しく書く書き出しの zip のどの項目も、以前の版と同じ AES の形で書く: 局所ヘッダと中央ディレクトリの圧縮方式が AES（`99`）、
汎用の印の暗号化の bit が立ち、AES の追加の欄（`0x9901`）の強さが 256 ビット（`3`）、実の圧縮方式が deflate（`8`）で、
同じ名前の項目の AE-1 / AE-2 の別が以前の版と同じ。
この形は、zip を読み書きする部品を使わずに zip のバイト列から読んで確かめる（部品の版が変われば、部品の読み方も一緒に変わりうる）。
導出元: CH24

置き場に残っている書き出しは以前の版で書いたものでありうる。今の試験は書くのも読むのも同じ版の部品なので、版の間の互換は見ていなかった。
試験に埋め込む以前の版の書き出しは、2026-11 のサーバ（zip の部品 2.6.1）で書いたもの（design D2）。

#### Scenario: 以前の版で書いた書き出しの zip を、同じ中身で読める
- **WHEN** 試験が、以前の版のサーバで書いた書き出しの zip のバイト列（試験に埋め込んだもの）を今の版で開き、書いたときの合言葉で全部の項目を読む
- **THEN** 全部の項目が読め、項目の名前の並びと、項目ごとの中身の SHA-256 が、書いたときに記録した値と一致し、zip の注記の書き出しの id が書いたときの値と一致する

#### Scenario: 以前の版で書いた書き出しの zip は、違う合言葉では読めない
- **WHEN** 試験が、埋め込んだ以前の版の書き出しの zip を今の版で開き、書いたときと違う合言葉で各項目を読む
- **THEN** どの項目の中身も読めない

#### Scenario: 以前の版で書いた書き出しは、次の書き出しを書き終えると消える
- **WHEN** 置き場に以前の版で書いた書き出し（埋め込んだバイト列）があり、書き出しの台帳の done の行がその大きさと SHA-256 を持つ状態で、今の版で新しい書き出しを書き終える
- **THEN** 以前の版の書き出しのファイルは消え、置き場には新しい書き出しの 1 つだけが残る

#### Scenario: 新しく書いた書き出しの zip の項目は、以前の版と同じ AES の形で書かれる
- **WHEN** 試験が、埋め込んだ zip を書いたときと同じ記録を置いた試験の DB から今の版で書き出し、書いた zip と埋め込んだ zip の局所ヘッダと中央ディレクトリを、zip を読み書きする部品を使わずにバイト列から読む
- **THEN** 新しく書いた zip のどの項目も、圧縮方式が `99`・暗号化の bit が立ち・追加の欄 `0x9901` の強さが `3`・実の圧縮方式が `8` である
- **AND** 2 つの zip の両方にある名前の項目は、AE-1 / AE-2 の別（vendor version）が同じである
