=== ST52 の深掘り の回答 ===
Q1 [あなたの携帯を、いつ・どう配布版へ移すか] -> 携帯にはまだ入っていない・記録を集めていない
Q2 [携帯の APK を、どこで正式な鍵で署名するか] -> CI が、印と main にだけ開いた Environment の鍵で署名する（扉 34 の置き場に GitHub を足す）
Q3 [携帯の versionCode の付け方] -> 版番号から計算する（上の式）
Q4 [開発版の携帯の APK の識別子] -> ST54 まで、開発版に携帯の APK を入れない
Q5 [最初の公開の印を、いつ誰が打つか] -> ST52 では下書きのリリースで確かめる。最初の本物の印 `v0.1.0-beta.1` と開発版の公開は、ST53 の後に本人が main に打って始める
Q6 [版の出所と、ベータ版・開発版の版の付け方] -> `Cargo.toml` の workspace の `version` を出所にする。ベータは印から、開発版は日付から足す
Q7 [サーバの配布物の OS] -> Windows（x86_64）と Linux（x86_64）の両方
Q8 [サーバが画面を配る形] -> サーバの実行ファイルに組み込む
Q9 [配れる形を、PR ごとに確かめるか] -> コードを触った PR ごとに、公開せずに 3 部品を組み、版がそろうかを見る
Q10 [開発版の印の名前（配った印に数えるか）] -> 開発版の印は `nightly`（`v*` の外）。正式版とベータ版だけを配った印に数える
Q11 [開発版の携帯の APK を、どの鍵で署名するか] -> 開発版は別の鍵（開発版の Environment に置き、控えは USB に 1 部）
IMP-01 [印を push できる人が、main を通さずに正式な鍵を読めるかもしれない] -> 後の Story で扱う
