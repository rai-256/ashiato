## R50. Q23 の台帳は、台帳自身を追記のみにして初めて止まる。いまの答えは「台帳を書けば通す」までで、台帳の保護を誰も書いていない

- 成果物: openspec/changes/st03-idempotent-ingest/design.md（未作成）/ tasks.md（未作成）
- 根拠: 実験 AD4（実測）—— `DELETE FROM core.erasure_ledger;` が **3 行を消した**。
  ① 台帳を書いて消去を通す ② 次のまとまりで台帳を消す、の **2 手で Q23 の保証が消える**
  （R29 が履歴表について、`migrations/202609100000_immutable_origin.sql:5-13` が本表について
  記録したのと同じ形）。Q23 の選択肢 1 の `irreversible` 欄は
  「台帳を持たずに消した分は…復元できない」までで、**台帳が消せることは書いていない**。
  実験 AG3（実測）—— 台帳に追記のみのトリガと `BEFORE TRUNCATE` の文トリガを張ると
  `DELETE` / `UPDATE` / `TRUNCATE` の 3 つとも拒まれ、**実験 AG2 の正規の消去は通ったまま**。
  台帳には**開ける必要のある操作が 1 つも無い**（docs/requirements.md:266 の FR-51 が
  「削除した事実・時刻・件数・範囲を**残す**」と決めている）ので、
  Q10 → Q17 → Q23 と 1 段ずつ外へずれてきた同じ問いは、**ここで止まる**。
  2 点目: 実験 AG6（実測）—— `row_count=1` の台帳 1 行で **4 行を消せた**。
  DB は件数を検算していないので、台帳は実際より少なく申告できる（FR-51 の「件数」と
  FR-52 の「実行前に対象件数を提示」が、残った台帳と食い違いうる）
- kind: technical
- 処置: fixed deep.md — 申し送りへ。台帳自身を追記のみ＋TRUNCATE 禁止にする（実験 AG3 で連鎖が止まることを確認済み）。件数の検算は DB がしないので、台帳の行と実際の消去の突き合わせは tasks の検査でやる
- 提案: 問いにはしない（FR-51 が向きを決めており幅が無い）。design に
  「**台帳は追記のみ。書き換えも削除も TRUNCATE も拒む**」と、その根拠（開ける操作が無いこと）を書く。
  tasks に「台帳の行が消せない / 書き換えられない / TRUNCATE できない」の 3 本の検査を入れ、
  `tools/check-immutable.sh` の作り替え（R38）の対象に台帳を足す。
  併せて**遅延制約トリガで「その txn で消えた行数」と `row_count` が一致することを検算する**。

## R51. 台帳の門は「消去だけ」に絞らないと、0004 が塞いだ迂回がそのまま復活する

- 成果物: openspec/changes/st03-idempotent-ingest/design.md（未作成）
- 根拠: 実験 AD3（実測）—— 門を「同じ txn に台帳行があるか」だけで書くと、
  `BEGIN; INSERT INTO core.erasure_ledger(… scope='うそ', row_count=1); UPDATE core.event SET raw='{"t":"tampered"}' …; COMMIT;`
  が**通り、履歴を 1 行も残さずに原文が改竄された**。Q23 の答えは「**消去**を通す」であって
  「台帳を書けば何でも通す」ではない。実験 AG1（実測）—— 門に
  「`NEW.raw = ''` かつ `NEW.payload = '{}'` かつ `event_time` と `content_hash` が変わらない」を
  足すと同じ攻撃は拒まれ、実験 AG2 の正規の消去は通る。
  消去の印に `raw = ''` を使えるのは、`crates/server/src/ingest.rs:82`
  （`if self.raw.is_empty() || self.raw.contains('\0') { return Err(Invalid::Raw) }`）が
  空の原文を受け口で断っているため —— **正当な記録は `raw = ''` にならない**
- kind: technical
- 処置: fixed deep.md — 申し送りへ。門は「台帳行があるか」ではなく**消去の形（原文が空になる）のときだけ**に絞る。絞らないと 0004 の迂回が復活する（実験 AD3 / AG1）
- 提案: design に「消去の形（`raw` が空・`payload` が `{}`・`event_time` と `content_hash` は据え置き）」を
  定義として書き、門は**その形のときだけ**台帳で通す、と書く。
  tasks に「台帳を書いた改竄が拒まれる」検査を、R38 の 2 本と同じ台本で足す。

## R52. Q23 の台帳は本表と履歴の**両方**の門に効かせないと、R41（消せない DB）が残る
