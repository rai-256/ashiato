=== CH03 の深掘り の回答 ===
Q1 [再発止めの検査をどこに当てるか] -> Rust は crates/ の全体（製品のコードも）、Kotlin は app/src/test だけ。逃げ道は行の印 `tmp-ok: <理由>`
Q2 [検査が拾う書き方] -> 作る書き方の兄弟の全部と、後始末を外す口も落とす
Q3 [Rust と Kotlin 以外（bash の道具・/tmp の固定名・web の試験）] -> この change は Rust と Kotlin の試験だけ。bash も固定名も直さない
Q4 [走っている st09・st13 への響き方] -> 木の全体に当てる。st09・st13 は rebase の後、それぞれの gate → fix で直す
Q5 [「一時フォルダに残るものが増えない」の確かめ方] -> CI の既存の試験の段（ubuntu の `cargo test --workspace` と `:app:testDebugUnitTest`）で、一時フォルダを空のフォルダへ向けて走らせ、終わった後に空であることと走った試験の数が 1 以上であることを見る。手元の台本（`tools/tmp-leak-check.sh`）も同じことをし、下流の Task の検証にする
Q6 [今 /tmp にある残り] -> この change では消さない（仕組みにしない）。要るなら人が手で消すか、再起動
Q7 [殺された試験の残り] -> 残ってよい（再起動か手で消す）。この change は普通に終わる・落ちる試験の後始末だけ
Q8 [失敗した試験の中身を後から見る口] -> 持たない。中身が要るときはもう一度走らせて再現する
QA [仕様への合意] -> 合意する
