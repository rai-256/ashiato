## Purpose

記録に誰がどの経路で届けるかを定める。外からの到達を利用者が許可した私設網の内側に限ること、画面から読む人を合言葉で確かめること、
アプリの DB 接続から記録の門を外せないこと、誰がいつ読んだかを残すこと、記録の写しを拠点外に置かないことを置く。
記録ごとの感度とプラグインの権限も、この capability に積む。

## ADDED Requirements

### Requirement: サーバと画面は loopback でしか待ち受けない

THE SYSTEM SHALL サーバと画面を loopback のアドレスでだけ待ち受けさせる。
WHEN サーバの待ち受けのアドレスとして loopback でないアドレスが与えられる THE SYSTEM SHALL 起動を拒否し、拒否した理由（loopback でない / 全インタフェースを指している）を出す。
THE SYSTEM SHALL 網の内側からの到達を、利用者が選んだ網の手段が loopback の口へ暗号化された接続で中継する形でだけ受ける。

導出元: PERM-7。深掘り Q2（サーバと画面は 127.0.0.1 から動かない）/ C1。
PERM-7 の「利用者が**明示的に**許可した」は、利用者が網の手段に書いた中継の設定で成り立つ。
網のアドレスにサーバが直に口を開けると、その口は暗号化されず（Q2 に反する）、ログインの印（暗号化された接続でだけ送る）も成り立たない。

#### Scenario: 既定では loopback でだけ待ち受ける

- **WHEN** 待ち受けのアドレスを設定せずにサーバを起動する
- **THEN** サーバは loopback のアドレスで待ち受け、loopback 以外のアドレスには口が開いていない

#### Scenario: loopback 以外のアドレスでは起動しない

- **WHEN** 待ち受けのアドレスを loopback でないアドレスにしてサーバを起動する
- **THEN** サーバは起動せず、loopback でないことを理由に出して終わる

#### Scenario: 全インタフェースでは起動しない

- **WHEN** 待ち受けのアドレスを `0.0.0.0` にしてサーバを起動する
- **THEN** サーバは起動せず、全インタフェースを指していることを理由に出して終わる

### Requirement: 網の外に開いていないことを検査で確かめられる

THE SYSTEM SHALL 本システムの口（サーバ・画面・開発用の画面・DB）が網の外に開いていないことを確かめる検査を持つ。
THE SYSTEM SHALL その検査を、本システムの口のいずれかが loopback 以外のアドレスで待ち受けているとき、失敗で終わらせる。
THE SYSTEM SHALL その検査を、網の手段が網の外への公開（網に入っていない相手からの到達）を有効にしているとき、失敗で終わらせる。
THE SYSTEM SHALL その検査を、網の手段が本システムの口を暗号化されていない接続で網へ出しているとき、失敗で終わらせる。
THE SYSTEM SHALL その検査を、網の手段が開発用の画面を網へ出しているとき、失敗で終わらせる。
THE SYSTEM SHALL 検査の失敗の報告に、どの口がどの理由で落ちたかを出す。
THE SYSTEM SHALL 網の手段の設定を読めなかったとき、検査を失敗で終わらせる（読めないことを通ったことにしない）。

導出元: PERM-7。深掘り C2 / Q2。Story の完了の判定「網外からは同じ URL に到達できない」。
網の外の端末を用意せずに、到達できない**状態であること**を判定する。
開発用の画面は応答の指示（写しを保存させない・外部の資源を禁じる）を持たないので、網へ出さない。

#### Scenario: 網の外への公開が有効だと検査が落ちる

- **WHEN** 網の手段の設定で、本システムの口が網の外への公開を有効にしている状態で検査を走らせる
- **THEN** 検査は失敗で終わり、網の外への公開が有効なことを報告する

#### Scenario: loopback 以外で待ち受ける口があると検査が落ちる

- **WHEN** 本システムの口の 1 つが loopback でないアドレスで待ち受けている状態で検査を走らせる
- **THEN** 検査は失敗で終わり、その口とアドレスを報告する

#### Scenario: 網へ平文で出している口があると検査が落ちる

- **WHEN** 網の手段の設定で、本システムの口を暗号化されていない接続で網へ出している状態で検査を走らせる
- **THEN** 検査は失敗で終わり、平文で出している口を報告する

#### Scenario: 開発用の画面を網へ出していると検査が落ちる

- **WHEN** 網の手段の設定で、開発用の画面の口を網へ出している状態で検査を走らせる
- **THEN** 検査は失敗で終わり、開発用の画面の口を報告する

#### Scenario: 網の手段の設定を読めないと検査が落ちる

- **WHEN** 網の手段はあるが、その設定を読み取れない状態で検査を走らせる
- **THEN** 検査は失敗で終わり、設定を読めなかったことを報告する

#### Scenario: loopback と暗号化された網の口だけなら検査は通る

- **WHEN** 本システムの口がすべて loopback で待ち受け、網の手段が暗号化された接続だけでそれを網へ出し、網の外への公開が無効な状態で検査を走らせる
- **THEN** 検査は成功で終わる

### Requirement: 収集側は loopback 以外へ平文で送らない

THE SYSTEM SHALL 携帯端末の収集アプリに、loopback 以外の宛先への暗号化されていない接続を許さない。組み立てに使った接続先の宛先も例外にしない。
THE SYSTEM SHALL 携帯端末の収集アプリを、接続先が loopback 以外で暗号化されていない形のとき組み立てられないようにする。
THE SYSTEM SHALL PC の収集器を、接続先が loopback 以外で暗号化されていない形のとき起動しないようにする。

導出元: PERM-7。深掘り Q2。これまで収集アプリは接続先の宛先に平文を許していた（ST01 の平文の例外）。
網の手段が暗号化するのは網の上だけで、平文の例外を残すと、網の手段を差し替えたときに記録が平文で流れる。
loopback を残すのは、端末の中の試験用サーバへ送る計測テストのため（端末の外へ出ない）。

#### Scenario: 収集アプリは接続先の宛先にも平文を許さない

- **WHEN** 接続先を loopback でない `https://` の宛先にして収集アプリを組み立て、その宛先と、別の loopback でない宛先への暗号化されていない接続が許されるかを通信の設定に問う
- **THEN** どちらも許されない

#### Scenario: 収集アプリは loopback への平文の接続を許す

- **WHEN** 収集アプリの通信の設定で、loopback の宛先への暗号化されていない接続が許されるかを問う
- **THEN** 許される

#### Scenario: 平文の接続先では収集アプリを組み立てられない

- **WHEN** 接続先を loopback でない `http://` の宛先にして収集アプリを組み立てる
- **THEN** 組み立ては失敗し、接続先が暗号化されていないことを理由に出す

#### Scenario: 平文の接続先では PC の収集器が起動しない

- **WHEN** 接続先を loopback でない `http://` の宛先にして PC の収集器を起動する
- **THEN** 収集器は起動せず、接続先が暗号化されていないことを理由に出す

### Requirement: 画面から記録を読むには合言葉のログインが要る

THE SYSTEM SHALL 画面の経路で記録を読み書きするとき、合言葉のログインで得た印を求め、印の無い求めを 401 で断る。
THE SYSTEM SHALL 画面を配る側に、API の合言葉やその他の資格情報を求めへ付け足させない。
THE SYSTEM SHALL ログインの口では、画面の合言葉そのものを資格情報として受け、合言葉の無いか一致しない求めを 401 で断り、印を発行しない。
WHEN 画面の合言葉が一致するログインの求めを受ける THE SYSTEM SHALL ログインの印を発行し、ブラウザに覚えさせる。
THE SYSTEM SHALL ログインの印を、ブラウザのスクリプトから読めず、暗号化された接続でだけ送られ、別のサイトから始まった求めには付かない形で覚えさせる。
THE SYSTEM SHALL 画面の合言葉と API の合言葉を別の値として持ち、画面の合言葉が未設定か、16 文字より短いか、API の合言葉と同じ値なら起動しない。
WHEN 1 分の間にログインの失敗が 10 回を超える THE SYSTEM SHALL その 1 分が過ぎるまで、以後のログインの求めを合言葉の正否にかかわらず 429 で断る。
WHEN ログアウトが求められる THE SYSTEM SHALL その印を無効にし、以後その印での求めを 401 で断る。
THE SYSTEM SHALL API の合言葉による取り込み口と読み出し口の振る舞いを変えない。

導出元: PERM-10。深掘り Q1 / Q4。画面を配る側が API の合言葉を付けていたので、画面に届けば合言葉無しで全記録を読めた。
網の内側に限る（PERM-7）だけでは、本人の端末の上の他のアプリ・同じ PC の別プロセスが画面の URL を叩くのを止めない。
ログインの口も「すべての API 要求は資格情報を要求する」（record-envelope）の例外ではない —— 資格情報が画面の合言葉である。
API の合言葉の読める範囲は変えない（Q4。本人が受け入れた。呼び出し元ごとの範囲は PERM-10 の配り方として後で決める）。
16 文字・1 分 10 回は仮決め（design の D16 / D17）。
ログインの印は同じ機械名の別の口にも送られる（cookie は口で分かれない）。これは主張できないので、画面を他のサービスと同じ機械名に同居させない手順を置く（design）。

#### Scenario: ログインしていないブラウザには記録が 1 件も返らない

- **WHEN** ログインしていないブラウザで稼働状況の画面を開く
- **THEN** 画面が出した記録の読み出しの求めはすべて 401 で断られ、画面に記録の行は 1 つも出ない

#### Scenario: ログインしていないブラウザには合言葉の入力欄が出る

- **WHEN** ログインしていないブラウザで稼働状況の画面を開く
- **THEN** 合言葉の入力欄が見えている

#### Scenario: 合言葉でログインすると画面が記録を読める

- **WHEN** 正しい画面の合言葉でログインし、稼働状況の画面を開く
- **THEN** 画面の経路からの読み出しが通り、記録が画面に出る

#### Scenario: 違う合言葉のログインの求めは断られ、印は発行されない

- **WHEN** 画面の合言葉と違う値でログインを求める
- **THEN** 求めは 401 で断られ、応答はログインの印を発行しない

#### Scenario: 違う合言葉を入れても画面は記録を出さない

- **WHEN** ログインしていないブラウザで、画面の入力欄に違う合言葉を入れてログインする
- **THEN** 入力欄は見えたままで、画面に記録の行は 1 つも出ない

#### Scenario: 合言葉を付けないログインの求めは断られる

- **WHEN** 合言葉を付けずにログインを求める
- **THEN** 求めは 401 で断られ、応答はログインの印を発行しない

#### Scenario: API の合言葉では画面にログインできない

- **WHEN** API の合言葉の値を画面の合言葉としてログインを求める
- **THEN** 求めは 401 で断られる

#### Scenario: 画面を配る側は合言葉を付け足さない

- **WHEN** ログインの印も API の合言葉も持たない求めを、画面を配る側の経路で記録の読み出しへ送る
- **THEN** 求めは 401 で断られる

#### Scenario: ログインの印はスクリプトから読めない

- **WHEN** 正しい合言葉でログインした画面の中のスクリプトから、ブラウザが覚えている cookie を読む
- **THEN** ログインの印は読み出せない

#### Scenario: ログインの印は暗号化された接続でだけ送られる

- **WHEN** 正しい合言葉でログインし、応答が印を覚えさせる指示を見る
- **THEN** 指示は印を暗号化された接続でだけ送る属性（`Secure`）を持つ

#### Scenario: ログインの印は別のサイトから始まった求めには付かない

- **WHEN** 正しい合言葉でログインし、応答が印を覚えさせる指示を見る
- **THEN** 指示は別のサイトから始まった求めに印を付けさせない属性（`SameSite=Strict`）を持つ

#### Scenario: ログアウトすると記録が読めなくなる

- **WHEN** ログインした画面でログアウトし、同じブラウザで稼働状況の画面を開き直す
- **THEN** 記録の読み出しは 401 で断られ、合言葉の入力欄が出る

#### Scenario: ログアウトした印を持ち出しても使えない

- **WHEN** ログインの印の値を控えてからログアウトし、控えた値を付けて記録の読み出しを求める
- **THEN** 求めは 401 で断られる

#### Scenario: 画面の合言葉が API の合言葉と同じだと起動しない

- **WHEN** 画面の合言葉を API の合言葉と同じ値にしてサーバを起動する
- **THEN** サーバは起動せず、2 つの合言葉が同じであることを理由に出して終わる

#### Scenario: 画面の合言葉が無いか短いと起動しない

- **WHEN** 画面の合言葉を設定しないか、15 文字の値にしてサーバを起動する
- **THEN** サーバは起動せず、画面の合言葉が無い・短いことを理由に出して終わる

#### Scenario: 失敗を重ねたログインは一時的に断られる

- **WHEN** 1 分の間に違う合言葉のログインを 10 回求めた後、11 回目に正しい合言葉でログインを求める
- **THEN** 11 回目の求めは 429 で断られ、印は発行されない

#### Scenario: API の合言葉での読み書きは変わらない

- **WHEN** ログインの印を持たず、API の合言葉を付けて記録を送り、記録の読み出しを求める
- **THEN** 送った記録は取り込まれ、読み出しは記録を返す

### Requirement: 画面のログインは期限で切れず、画面の合言葉を変えると全部が無効になる

THE SYSTEM SHALL 既定では、画面のログインの印を時間の経過で無効にしない（ログアウトするまで使える）。
THE SYSTEM SHALL ログインの印を、ブラウザを閉じても残る寿命で覚えさせ、印で認めた応答のたびにその寿命を延ばす。
THE SYSTEM SHALL 画面の合言葉が変わった後の起動で、変わる前に発行したすべてのログインの印を無効にする。
WHERE 利用者が設定でログインの期限を与えている THE SYSTEM SHALL 発行からその期間を過ぎた印を無効にする。

導出元: PERM-10。深掘り Q6（推奨の 30 日を本人が覆した）。
端末を落としたときに、その端末のログインを締め出す手段は、期限の代わりに画面の合言葉を変えることだけになる。
ブラウザは覚える寿命に上限を持つ（design の D18）ので、長く開かなかった端末ではもう 1 度ログインになることがある。

#### Scenario: 既定では日が経ってもログインは切れない

- **WHEN** 期限を設定せずに発行したログインの印で、発行から 400 日後の時刻に記録の読み出しを求める
- **THEN** 読み出しは通る

#### Scenario: ログインの印はブラウザを閉じても残り、使うたびに延びる

- **WHEN** 正しい合言葉でログインし、続けてその印で記録の読み出しを求め、2 つの応答の印を覚えさせる指示を見る
- **THEN** どちらの指示も、ブラウザを閉じても残る寿命（1 日以上の `Max-Age`）を持つ

#### Scenario: 画面の合言葉を変えると、それまでのログインはすべて使えなくなる

- **WHEN** 2 つのブラウザでログインした後、画面の合言葉を変えてサーバを起動し直し、それぞれの印で記録の読み出しを求める
- **THEN** どちらの求めも 401 で断られる

#### Scenario: 期限を設定したときは、過ぎた印は使えない

- **WHEN** ログインの期限を 30 日に設定して発行した印で、発行から 31 日後の時刻に記録の読み出しを求める
- **THEN** 求めは 401 で断られる

### Requirement: 応答はブラウザに記録を残させない

THE SYSTEM SHALL サーバのすべての応答と、画面を配る側のすべての応答に、`Cache-Control: no-store` を付ける。
THE SYSTEM SHALL 画面に、端末の上で記録を見る仕組み（service worker・端末の保存領域への記録の写し）を持たせない。

導出元: NFR-15 / PERM-7。深掘り C4。
網の内側の端末でも、ブラウザのキャッシュに残った記録は網の制限もログアウトも効かない。
開発用の画面はこの指示を持たないので、網へ出さない（網の外に開いていないことの検査が見る）。

#### Scenario: サーバの応答は写しを保存させない

- **WHEN** 記録の読み出し・取り込み・ログイン・ログアウト・断られた求めのそれぞれの応答を見る
- **THEN** どの応答の `Cache-Control` にも `no-store` がある

#### Scenario: 画面の応答は写しを保存させない

- **WHEN** 画面を配る側から画面の本体と、画面の経路を通した記録の読み出しを受け取る
- **THEN** どの応答の `Cache-Control` にも `no-store` がある

#### Scenario: 画面は端末に記録の写しを置かない

- **WHEN** ログインして稼働状況・1 日を見る・マスタ管理の各画面を開いた後、ブラウザの service worker の登録と保存領域を見る
- **THEN** service worker の登録は 0 件で、保存領域（local storage・session storage・IndexedDB）に記録の値は 1 つも無い

### Requirement: 画面は外部の資源を読まない

THE SYSTEM SHALL 画面を、画面を配る側と同じ出所の資源だけで描く。
THE SYSTEM SHALL 画面を配る側の画面の本体の応答に、既定の読み込み先を同じ出所だけに限る `Content-Security-Policy`（`default-src 'self'`）を付ける。

導出元: PERM-7 / NFR-15。深掘り C6。
地図のタイルなどを外から読むと、表示している範囲（＝本人の居場所）が網の外へ出る。いまは 0 件で、それを守る機械が無かった。

#### Scenario: 画面を開いても外部への要求は 0 件である

- **WHEN** ログインして稼働状況・1 日を見る・マスタ管理の各画面を開き、ブラウザが出した要求を数える
- **THEN** 画面を配る側と同じ出所以外への要求は 0 件である

#### Scenario: 画面は外部の資源の読み込みを禁じる指示を持つ

- **WHEN** 画面を配る側から画面の本体を受け取る
- **THEN** 応答の `Content-Security-Policy` の `default-src` は `'self'` だけである

#### Scenario: 画面を開いても読み込みの指示に反した報告は出ない

- **WHEN** ログインして稼働状況・1 日を見る・マスタ管理の各画面を開く
- **THEN** ブラウザは `Content-Security-Policy` に反した読み込みを 1 件も報告しない

### Requirement: 誰がいつ読んだかを、追記のみの読み出しの記録に残す

THE SYSTEM SHALL 記録の読み出しと、ログイン（成功・失敗・一時的な断り）・ログアウトと、資格情報の無いか一致しない求めを、1 件ごとに読み出しの記録に 1 行残す。
THE SYSTEM SHALL 資格情報が認められた取り込み（記録・生存信号・破棄の報告を送る求め）を、読み出しの記録に残さない。
THE SYSTEM SHALL 読み出しの記録の行に、時刻・経路（直接か、網の手段を経て届いたか）・資格情報の種類（画面のログイン / API の合言葉 / 無し）・口の名前・結果だけを持たせ、
記録の中身・求めの引数・合言葉・ログインの印・識別子の文字列を持たせない。
WHEN 読み出しの記録に行を書けない THE SYSTEM SHALL その読み出しの求めに記録を返さず、500 で断る。
THE SYSTEM SHALL 読み出しの記録を追記のみとし、書き換え・行の削除・表の切り詰めのいずれも拒む。
THE SYSTEM SHALL 読み出しの記録の行を、記録の読み出しに出さない。

導出元: PERM-10 / PERM-7。深掘り C5（loss: uncaptured —— 残さなかった期間の読み出しは後から足せない。書けないときに返すと、その読み出しが黙って抜ける）。
製造準備 A-2（中身をログに残さない）。
経路の「網の手段を経て届いた」は中継が付ける印からの判定で、同じ PC のプロセスが偽れる。手がかりとして残す。
取り込みを残さないのは「誰がいつ読んだか」を残すためで、収集は数分ごとに来る。

#### Scenario: 記録の読み出しで読み出しの記録に 1 行増える

- **WHEN** ログインした画面の経路で記録の読み出しを 1 回求める
- **THEN** 読み出しの記録に、資格情報の種類が画面のログインで、口の名前がその読み出しの口の行が 1 行増える

#### Scenario: 断られた求めも読み出しの記録に残る

- **WHEN** 資格情報を付けずに記録の読み出しを求め、続けて違う合言葉でログインを求める
- **THEN** 読み出しの記録に、資格情報の無い読み出しが断られた行と、ログインに失敗した行が 1 行ずつ増える

#### Scenario: 取り込みは読み出しの記録に残らない

- **WHEN** API の合言葉を付けて記録を送り、取り込まれる
- **THEN** 読み出しの記録の行は増えない

#### Scenario: 読み出しの記録には中身も合言葉も残らない

- **WHEN** 引数を付けた記録の読み出し・ログイン・ログアウトを行った後、読み出しの記録の行を全列読む
- **THEN** どの行にも、記録の中身・引数の値・合言葉・ログインの印・利用者や記録の識別子の文字列が含まれていない

#### Scenario: 読み出しの記録に書けないときは記録を返さない

- **WHEN** 読み出しの記録への書き込みが失敗する状態で、正しい資格情報で記録の読み出しを求める
- **THEN** 求めは 500 で断られ、応答に記録は含まれない

#### Scenario: 読み出しの記録の行は書き換えも削除もできない

- **WHEN** 読み出しの記録の行を書き換える、削除する、または表を切り詰めようとする
- **THEN** いずれの操作も拒まれ、行は残っている

#### Scenario: 読み出しの記録は記録の読み出しに出ない

- **WHEN** 読み出しの記録に行がある状態で、記録の読み出しの口で全件を求める
- **THEN** 応答に読み出しの記録の行は含まれない

### Requirement: アプリは DB の管理者でも表の所有者でもない役割で接続し、その接続からは記録の門を外せない

THE SYSTEM SHALL サーバを、DB の管理者でも記録の表の所有者でもない役割で DB に接続させる。
WHEN サーバが接続した役割が DB の管理者であるか、記録の表のいずれかを所有している THE SYSTEM SHALL 起動を拒否し、理由を出す。
THE SYSTEM SHALL 表の作成と移行を、アプリとは別の、所有者の役割の接続で行う。
THE SYSTEM SHALL アプリの役割の接続から、記録の門（書き換えと消去の制限）を外す設定・表の定義の変更・表の切り詰めを拒む。
THE SYSTEM SHALL 移行が後から足した表にも、アプリの役割が取り込みと読み出しに要る権限だけで届くようにする。
THE SYSTEM SHALL DB の管理者・所有者・アプリのいずれの合言葉も、配布物に固定値として持たず、雛形の値のままなら役割を作らない。
THE SYSTEM SHALL サーバの実行時の環境に、DB の管理者と所有者の合言葉を渡さない。

導出元: record-envelope「収集した記録の書き換えと消去は、履歴か台帳が同じまとまりにあるときだけ通る」の
「取り込み口の外から加えられた操作にも適用する」。PERM-10。深掘り Q5。ST03 のレビュー R103。
アプリが管理者で接続していると、門は `session_replication_role` の 1 文で外れ、その管理者の合言葉は公開の固定値だった。
所有者も自分の表のトリガを外せるので、所有者の合言葉も同じ扱いにする。

#### Scenario: アプリの接続からは門を外せない

- **WHEN** アプリの役割の接続で、トリガを止める設定（`session_replication_role` を `replica` にする）を求める
- **THEN** 求めは権限の不足で拒まれる

#### Scenario: アプリの接続からは表の定義を変えられない

- **WHEN** アプリの役割の接続で、記録の表のトリガを無効にする定義の変更を求める
- **THEN** 求めは拒まれ、トリガは有効のままである

#### Scenario: アプリの接続からはどの表も切り詰められない

- **WHEN** すべての移行を当てた後、アプリの役割の接続で、記録の schema のすべての表について切り詰めを求める
- **THEN** どの表の求めも拒まれ、行は残っている

#### Scenario: 管理者の接続ではサーバが起動しない

- **WHEN** DB の管理者の役割の接続先を与えてサーバを起動する
- **THEN** サーバは起動せず、接続した役割が管理者であることを理由に出して終わる

#### Scenario: 所有者の接続ではサーバが起動しない

- **WHEN** 記録の表を所有する役割の接続先を与えてサーバを起動する
- **THEN** サーバは起動せず、接続した役割が表の所有者であることを理由に出して終わる

#### Scenario: アプリの接続で取り込みと読み出しが通る

- **WHEN** アプリの役割で接続したサーバに、API の合言葉を付けて記録を送り、読み出しを求める
- **THEN** 送った記録は取り込まれ、読み出しは記録を返す

#### Scenario: 移行が足したどの表にもアプリの役割が届き、切り詰めの権限は無い

- **WHEN** すべての移行を当てた後、記録の schema のすべての表について、アプリの役割の権限を DB に問う
- **THEN** どの表にも読み・追加・書き換え・削除の権限があり、切り詰めの権限と所有権はどの表にも無い

#### Scenario: 配布物に DB の合言葉の固定値が無い

- **WHEN** 配布物（リポジトリの追跡ファイル）の DB を立てる設定と、試験・台本の DB の接続先を読む
- **THEN** 管理者・所有者・アプリのいずれの合言葉も固定値として書かれておらず、利用者の秘密の設定か実行時に作った値から読まれる

#### Scenario: 雛形の合言葉のままでは役割を作らない

- **WHEN** 秘密の設定の DB の合言葉のいずれかが雛形の値のまま、役割を作る手順を走らせる
- **THEN** 手順は役割を作らずに失敗で終わり、雛形のままの項目の名前を出す

#### Scenario: サーバの実行時の環境に所有者と管理者の合言葉が無い

- **WHEN** 起動の台本でサーバを起動し、動いているサーバのプロセスの環境を読む
- **THEN** DB の管理者と所有者の合言葉も、それを含む接続先も無い

### Requirement: 本システムは記録の写しを拠点外に置かない

THE SYSTEM SHALL 記録の写しを拠点外に置かない。ただし暗号化されたバックアップを除く。
THE SYSTEM SHALL 本人の端末の画面に記録を映すこと・収集側が送る前に端末にためること・感度で許した外部 AI の問い合わせに答えることを、
写しを拠点外に置くことに数えない。
THE SYSTEM SHALL サーバに、外部の宛先へ記録を送る部品（HTTP の送り手・メールの送り手・外部の保管庫の手）を持たせない。
THE SYSTEM SHALL サーバと移行を、DB の接続先が loopback のときだけ動かす。

導出元: NFR-15（★ 2026-09-29 補足）。深掘り Q3（本人の選択）。
文面どおりに「本人の端末以外へ送ること全部」と読むと、既に決めた PERM-3 と扉 15 とぶつかる。
暗号化されたバックアップの送り手を足すときは、この Requirement を MODIFIED にしてその部品だけを開ける。
DB の接続先を拠点外に向けると、記録の写しがまるごと拠点外に置かれる。

#### Scenario: サーバは拠点外へ書き出す部品を持たない

- **WHEN** サーバを組み立てる部品の一覧を、外部の宛先へ送る部品の一覧（HTTP クライアント・メールの送り手・クラウドの保管庫の SDK。一覧は検査の側が持ち、1 つ以上の名前を持つ）と突き合わせる
- **THEN** 一致する部品は 0 件である

#### Scenario: DB の接続先が loopback でなければ起動しない

- **WHEN** DB の接続先を loopback でない宛先にしてサーバ、または移行を起動する
- **THEN** どちらも DB に接続せずに終わり、接続先が loopback でないことを理由に出す
