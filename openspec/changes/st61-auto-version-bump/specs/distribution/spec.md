## ADDED Requirements

### Requirement: main の commit には、CI が通り、前の番号から製品が変わったときだけ次の番号を付ける

WHEN main への push の CI の run が成功で終わる THE SYSTEM SHALL その run の commit に、前に番号を付けた commit からの差分が製品（`docs/`・`openspec/`・名前が `.md` で終わるファイル以外。道具・CI・試験を含む）に触れていれば、次の番号を 1 つ付ける。
THE SYSTEM SHALL 差分が `docs/`・`openspec/`・`*.md` だけの commit には番号を付けない。
THE SYSTEM SHALL 前の番号の commit との差分が空の commit（間の変更が戻され、木が同じ）には番号を付けない（製品は変わっていない）。
THE SYSTEM SHALL 取り消された・落ちた run の commit には番号を付けない。その commit の中身は、後で番号が付く子孫の commit の番号に入る（番号は前の番号から 1 つ進む）。
THE SYSTEM SHALL 番号の付いていない commit で、番号を付けた commit の祖先（main の first-parent の上で、それより前の commit）には、後からその run が成功しても番号を付けない。
THE SYSTEM SHALL 1 つの commit に番号を 2 つ付けず、既に番号の印がある commit の run を走らせ直したときは、それが最新の番号でなくても、付けた番号のまま返す（欠けた配布物の続きを置く）。
IF 番号の印がまだ 1 つも無い THEN THE SYSTEM SHALL 製品が変わったかを、その commit の first-parent の親からの差分で決める。
THE SYSTEM SHALL main に commit を積まずに番号を付ける（番号を記録するのに main のファイルを書き換えない）。
THE SYSTEM SHALL PR の run・fork の run・main 以外の枝の run では番号を付けない（PR の組み立ては自分の番号を持たない）。

導出元: FR-134。deep.md Q1（答え待ち・推奨: CI が通り、前の番号から製品が変わった commit に付ける）・Q6（差分が空の commit に番号を付けない）・D4（仮）。premises P2・P3・P12・P13。review/deep.md R1・R2。
「製品が変わった」の見分けは、PR の CI が配る形の組み立てを走らせるかの判定（`tools/release/changes.sh code`）と同じにする。

### Requirement: 番号は、左の数字を本人のファイルから読み、真ん中と右の数字を機械が決める

THE SYSTEM SHALL 番号を `<左>.<真ん中>.<右>` の 3 つの数字にし、左の数字を repo のファイル `tools/release/MAJOR`（数字 1 つ。本人が PR で変える）から読む。
THE SYSTEM SHALL 次の番号を、前に付けた番号（番号の印のうち最も大きいもの）から次のとおり決める:
(1) まだ番号が 1 つも無ければ `<左>.2.0`（今の形で使った 0.1.0・0.1.1 より大きいところから始める）、
(2) 左の数字のファイルの値が前の番号の左より大きければ `<左>.0.0`、
(3) 前の番号の commit を除き、番号を付ける commit を含む main の first-parent の commit のうちに、確認バッチの merge（枝 `verify/` の PR の merge）が 1 つでもあれば、真ん中を 1 上げて右を 0 にする、
(4) どれでもなければ右を 1 上げる。
IF 左の数字のファイルの値が前の番号の左より小さい・数字 1 つでない THEN THE SYSTEM SHALL 番号を付けずに止まり、理由を示す。
IF 次の番号の真ん中が 999 を超える・右が 9,999 を超える・左が 209 を超える THEN THE SYSTEM SHALL 番号を付けずに止まり、超えた数字を示す（携帯の versionCode に収まらない番号を作らない）。
THE SYSTEM SHALL 一度付けた番号を、別の commit に付けない（付けた番号の組み立てが落ちても、その番号を次の commit に回さない）。
IF 番号付けの判定を走らせる木が浅い THEN THE SYSTEM SHALL 番号を付けずに止まり、出力に「履歴が浅い」を示す。
THE SYSTEM SHALL 次の番号を、番号の印と左の数字のファイルと main の履歴だけから決める（付けた番号を数え直さない）。

### Requirement: 番号を付けた組み立ては、番号の印と配布元の下書きのリリースに残し、上書きしない

WHEN 番号を付ける THE SYSTEM SHALL 組む前に、その commit を指す番号の印 `build-<番号>` を配布元に作り（同じ名前の印が既にあれば作らず、別の commit を指していれば止まる）、その後で、その commit から版番号に番号を渡して 4 つの配布物（サーバの Windows 向けと Linux 向け・携帯の APK・PC の収集アプリ）と、署名していない携帯の APK `ashiato-collector-<番号>-unsigned.apk` を組む。署名していない APK は、debug の鍵で署名した APK と同じ組み立ての印と versionCode を持つ。
THE SYSTEM SHALL 置く前に配布物の検査（組み立ての印・`.dirty`・資格情報・名前・版番号）を通し、落ちれば配布元へ何も書かない。
THE SYSTEM SHALL 組んだ配布物を、印 `build-<番号>` の下書き（draft）のリリース 1 つに置き、説明文に `ashiato-build: <番号> <commit の 40 桁>` の行を書く。下書きは公開せず、印 `v*` を作らない。
IF 同じ番号の下書きの説明文の commit が、置こうとする commit と違う THEN THE SYSTEM SHALL 何も置かずに止まる。
THE SYSTEM SHALL 番号を付けた組み立てを、どれも消さずに残す（番号ごとに 1 つの下書き）。
WHEN 同じ番号の下書きに決めた配布物が揃っている THE SYSTEM SHALL 何も組み直さず、何も置き直さない（置いた配布物を上書きしない）。揃っていなければ、欠けた配布物だけを同じ commit から組んで足す。
THE SYSTEM SHALL 番号を付けた組み立てに、CI のキャッシュの前の組み立てを使い回さず、番号を付けた組み立てを CI のキャッシュに保存しない。
THE SYSTEM SHALL 番号の印 `build-*` を、配った印（`v[0-9]*`）にも開発版の印にも数えない。
THE SYSTEM SHALL 番号を付ける job にだけ配布元へ書く権限を与え、その job は配布元の公開と印 `v*` の操作をしない。

| 種別・SQLSTATE の級 | 短い説明 |
|---|---|
| `db_ahead` | DB に新しい版の知らない版がある |
| `ledger_unreadable` | 版の記録を読めない |
| `channel_mismatch` | DB の系統が違う |
| `db_not_loopback` | DB の接続先が手元でない |
| `backup_failed` | 移行の前の退避に失敗した |
| `connect_failed` | DB に繋げない |
| `server_not_listening` | 新しい版のサーバが起きない |
| `aborted` | 移行が途中で終わった |
| `pg_major_mismatch` | 同梱の PostgreSQL の大きい版が違う |
| SQLSTATE `23…` | 制約に反した |
| SQLSTATE `42…` | 定義が当たらない |
| SQLSTATE `53…` | 資源が足りない |
| SQLSTATE `57…` | 止められた |
| SQLSTATE `08…` | 繋がらない |
