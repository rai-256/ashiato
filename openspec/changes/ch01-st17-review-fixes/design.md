## Decisions

### D1（仮）. `*.d/` を読む口を戻しの前へ動かし、ST17 の錠の節を自立した 1 本にして移す（Q1）

- 読む口のかたまり（見出し `# ====… Story ごとの節（tools/check-immutable.d/）` から `done` まで）を `# --- 戻し手順が当たること（R117）` の直前へ動かす。
  見出しの行と `for … done` の行は一字一句変えない（見出しの文字列は `tools/check-shared-appends.sh` の `MARK` が探す鍵）。かたまりの中の注記（`tools/check-immutable.sh:1503-1506` の「末尾を取り合い」「途中の既存の節を直すのは通す」）は
  動かした後の事実に直す —— D2 の例外は見出しと `for … done` の行だけを比べるので、注記を直しても CH01 の PR は通る
- ST17 の節（`# ==== ST17: 主観の記録の錠と、2 つの台帳` から、その節の「戻し手順（D16）」の検査まで）を `tools/check-immutable.d/<作成時刻>_st17-feeling-locks.sh` へ移す。
  「戻し手順を逆順に当てる」の中の ST17 の段（主観の版を戻す・当て直す・2 回目に戻す）は本体に残す（全版の戻しの並びの一部で、ST17 だけを抜くと並びが崩れる）
- 節は**前の節の状態に依らない**: 利用者の id は節の中で決め（ST19 の節の `$AU` を使わない。節の変数と関数は `ST17_` / `st17_` を頭に付ける）、「主観以外の本人が書いた記録は従来どおり」の検査に使う本人が書いた行は、
  節が自分の論理ソースを登録簿に足して自分で置く（`immutable-check` の行を使わない）。主観の版が当たっていることを節の頭で確かめ、当たっていなければ NG を出す
- `# Scenario: …` の印と `echo` の文言は移す前と一字一句同じにする（`scripts/check_scenarios.py` が印を数える）
- `tools/check-immutable.d/README.md` と読む口の注記の「末尾が読む」を「戻しの前に読む。DB は本体の節を全部走らせた状態で、版は全部当たっている」に直す。
  あわせて「節の後ろに本体の検査（戻しの並び・読み出しの記録・`app-role`）が続くので、本体の変数（`fail` を NG で 1 にする以外。`MIGS` `ST03_UP` `down_fail` `AU` など）と関数（`psql` `app_psql`）を上書きしない。節の変数は `ST<NN>_` を頭に付ける」を書く
- 選ばなかった案: 読む口を末尾に残し、節の頭で戻した版を当て直す —— 戻しの後は ST17 より前の版（ST19・ST16 など）も戻っているので、節が当て直す版が Story ごとに増え、後の Story の節も同じ負担を持つ
- 反転条件: 本人が Q1 で「本体に残す」か「全部移す」を選んだら、この D を書き直す。読む口を動かすと本体の後ろの節（読み出しの記録・`app-role`）が崩れるなら、読む口を末尾に戻して節の頭で版を当て直す案に移る

### D2（仮）. `check-shared-appends.sh` は本体の途中への節の見出しも落とし、読む口の移動だけは通す（Q2）

- 足した行（`git diff -U0` の `+` 行）が Story の節の見出しで、その ST 番号が同じファイルの差分の `-` 行の見出しのどれにも出ていない（＝既存の見出しの言い直しでない）なら、本体のどこでも落とす。見出しとみなすのは
  `^# *[=-]{3,}.*ST[0-9]{2}`（`# ====… ST17: …` / `# --- ST22: …` / `# ------… ST12（…）`）・`^echo "== (Scenario: )?ST[0-9]{2}`（`echo "== ST17: …"`）・
  `^echo "== [0-9]+[a-z]?\. .*ST[0-9]{2}`（smoke.sh の `echo "== 41. …（ST16 …）"`）。既存の節の中身を直す変更（見出しを足さない）と、既存の見出しの文言を直す変更（`+` 行の ST 番号が `-` 行の見出しに出ている）は通す
- 守る末尾を「読む口の見出しの直前の空でない行から、読む口のかたまりの `done` まで」と「ファイルの最後の空でない行の 1 つ前の空でない行より後ろ」の 2 つにする（review/spec.md R2）。
  読む口が末尾にある木（今の `smoke.sh` `seed.sh` と、動かす前の `check-immutable.sh`）では、2 つ目が読む口の `done` より後ろになり今と同じ範囲を守る。
  読む口を動かした木（D1 の後の `check-immutable.sh`）では 2 つ目が最後の検査の `done` より後ろになり、読む口より後ろの戻しの並びの途中を直すのは通す
- 読む口のかたまりを別の位置へ動かすだけの変更（基準の木と HEAD で、かたまりの見出しの行と `for … done` の行が同じで、守る範囲に足した行がかたまりの行だけ）は通す。かたまりの中の注記の行は比べない
- `--self-test` に足す（各 1 件）: 途中に `# ==== ST99: …` を足す → 落とす / 途中に `echo "== ST99: …"` を足す → 落とす /
  smoke.sh の途中に `echo "== 45. …（ST99）"` を足す → 落とす / 既存の小見出しの文言を直す → 通す / 読む口のかたまりを（注記を直して）前へ動かす → 通す /
  動かした後の木で読む口の直後に節を足す → 落とす / 動かした後の木でファイルの最後に書き足す → 落とす / 動かした後の木で戻しの並びの途中の行を直す → 通す /
  `done` と最後の判定の行の間に 1 行足す → 落とす（動かす前の木と動かした後の木で 1 件ずつ）。計 10 件。既存の 11 件はそのまま通る
- 規則の文言を持つ文書（`AGENTS.md` の「テスト」・`docs/testing.md` §4・`tools/smoke.d/README.md`・`tools/seed.d/README.md`・`tools/check-immutable.d/README.md`）を「末尾への書き足しと、本体の途中への新しい節の見出しを落とす」に直す。
  動かさない読む口の中の注記（`tools/smoke.sh:1123`・`tools/seed.sh:604`）は守る範囲の中なので CH01 では直さない（正本は各 `*.d/README.md`）
- 反転条件: 既存の節の中に小見出しを足すのが正当な Story が出て、見出しの検査が誤って落とすなら、見出しの型を `# ====`（最上位の節）と `echo "== ST<NN>:` に狭める

### D3. 錠の節の検査は NG の後に同じ検査の OK を出さない（指摘 2。問わずに決めた）

- 「戻しても台帳と登録簿の行と主観の記録が残る」の検査を `if …; then OK; else NG; fi` の形にする（D1 で `*.d/` へ移すときに直す）。
  rc は今も正しく 1 になるので、変わるのは記録に NG と OK が並ばないことだけ
- 同じ節のほかの検査で、`|| { NG; }` の次の行に無条件の OK があるものも同じ形にする

### D4. 録画の環境は Android のトークンと利用者の id を追跡されないファイルから渡す（指摘 3。問わずに決めた）

- `collector-android/app/build.gradle.kts` は、`ashiato.apiToken` / `ashiato.userId` が gradle の property に無ければ `collector-android/local.properties`（`.gitignore:29` で追跡されない）から読む
- `tools/record-env.sh` は `collector-android/gradle.properties`（追跡されている）に書かず、一時 worktree の `collector-android/local.properties` に書く。書いた後に戻す処理は要らなくなる
- 止められても（`record-run` は TERM の後に KILL を送り、KILL では trap が走らない。`scripts/record-run:555-556`）、トークンは追跡されないファイルにしか無いので、`git add -A` でも commit に入らない。
  一時 worktree は片付けの `worktree remove --force` で消える
- 選ばなかった案: trap で戻す —— KILL では走らない。コマンド行の `-P` —— `ps` に見える。環境変数 `ORG_GRADLE_PROJECT_ashiato.apiToken` —— 名前に「.」があり gradlew（sh）が子へ渡さない（2026-10-14 実測）

### D5（仮）. 滞在の行は、断られたら押された印を最新の記録の値に戻し、届かなかったら残す（Q4）

- 振る舞いは spec（`subjective-log` の「主観入力の画面で、その日の滞在ごとの気分を書く」）。滞在の行の押された印は「保存した値か、送り直しを待っている値」だけになる
- 戻す先は、画面が最後に読んだその滞在の最新の記録の値（読み直さない）。断られた後に読み直すと、別の失敗（読み出しの失敗）が押された印を消す経路が増える
- 日の欄（`pick`）は変えない。spec が「送れなかったとき（断られたときも）選んだ値とひとことを消さない」と決めている（ST17）
- 日の欄の SHALL は「日の欄で送れなかったとき」と欄を名指しし、滞在の行の SHALL と区別する（review/spec.md R16）
- 反転条件: 本人が Q4 で「どちらも戻す」「日の欄も戻す」を選んだら書き直す。日の欄も戻すなら spec の日の欄の文と Scenario「届かなかったとき選んだ値とひとことが残る」を MODIFIED にする

### D6（仮）. 日の欄は送るたびに記入の日時で前/後を決め直し、またいでいたら読み直して知らせる（Q5）

- 振る舞いは spec（「主観入力の画面で、押した瞬間に保存する」）。決め直しは押した時点の記入の日時（端末の時計。サーバも同じ値で決める）で行う
- またいでいたら、保存したことの文に「振り返りとして残しました」を添え、画面の「いま」を記入の日時に進めて読み直す（読み直しは D8 の 1 回）
- 時計のタイマーで日の終わりに画面を切り替える案は採らない（端末が眠る・タブが後ろに回るとタイマーが遅れ、その間に押すとまた食い違う）
- 知らせの条件は「押したときに画面が『前』を出していて、記入の日時の前/後が『後』」だけにする。送り直しが届いたときは知らせない（送り直しの原文は押したときの記入の日時を持つので、
  届いた時刻で判定すると、日をまたいでから「前」の記録が届いたときに誤って知らせる。review/spec.md R14）。届かなかった・断られたときも知らせを足さない
- 反転条件: 本人が Q5 で「時計で切り替える」「いまのまま」を選んだら書き直す。「いまのまま」なら spec の delta からこの SHALL と 2 本の Scenario を外す

### D7（仮）. 取り込みの「人が書いた記録」の規則を 1 つの関数にまとめる（Q7）

- 共通の関数は 1 件の受け取り（由来・端末 id・外部識別子・地域のずれ）を見て、「由来か端末が違う」「外部識別子を持つ」「地域のずれが範囲の外」のどれに当たったかを返す。
  理由の種別への写しは種類ごと（主張は `claim_not_authored` / `claim_has_external_id` / `malformed_claim`、場所は `place_*`、主観は `feeling_*`）
- 順はいまのまま: 主張と場所は 形 → 由来と端末 → 外部識別子 → 地域のずれ。主観は 形と地域（`Asia/Tokyo` の +9:00 に限る）を先に見て → 由来と端末 → 外部識別子。
  主観の「東京に揃える」と「形と一緒に先に見る」は主観の側に残す（`subjective-log` の「形の合わない主観の記録は受け付けない」の表の順と、地域の決定。前提 7 —— 食い違いではない）
- まとめる前に、いまの拒み方を固定する: 主張と場所は `personal-entities` の delta の Scenario（順と地域のずれの範囲。今の正典に無い）、主観は既存の Scenario と順の組み合わせのテスト
- 反転条件: 本人が Q7 で「まとめない」を選んだら、この D を「まとめない。主観の地域の違いは spec の決定であることを `lib.rs` のコメントに残す」に書き直し、`personal-entities` の delta を外す
  （CH01.md の `capability` からも外す）

### D8（仮）. 主観の画面の主観の読み出しを 30 日の 1 回にまとめる（Q6）

- `/api/feelings?from=<対象の日の 29 日前>&to=<対象の日>` を 1 回読み、日の欄・暦・滞在の行の値をその応答から取る。押して受理された後の読み直しも 1 回
- 読み出しが失敗したら、日の欄と暦の両方が「読み出しに失敗した」を出す（spec の「読み出しの失敗と未記入を区別する」はそのまま成り立つ）。滞在の行そのものは `/api/stays` から出す（今と同じ）
- 読み出しを 1 回にすることと、失敗が日の欄と暦の両方に出ることは spec に書く（「主観入力の画面の読み出しの失敗と下限」。archive の後に 2 回へ戻っても落ちないように。review/spec.md R15）。勘定は jsdom の試験で固定する（開いて 1 回・受理の後 1 回）
- 反転条件: 本人が Q6 で「いまのまま」を選んだら、spec の delta からこの SHALL と Scenario を外し、分けている理由（片方の失敗が他方を巻き込まない）を `FeelView.tsx` のコメントに残すだけにする

### D9（仮）. 終わりの読めない滞在の受け付け方は直さず、コメントを正確にし、ST23 へ申し送る（Q3）

- `crates/server/src/feelings.rs` の紐づけ先の検査の「消した滞在も通す」のコメントを、
  「削除の印の付いた滞在は通す。終わりの読めない滞在は、読み方（ST16 の `span_of`）と同じく始まりの一点とみなす」に直す
- いまの振る舞いをテストで固定する: 本文に終わりを持たない滞在の行を DB に直接置き、記録の区間が始まりの一点を含めば受け付け、含まなければ `invalid_feeling_target` で断る
- 製品のコードに滞在の本文を消す経路は無い（消す操作は印だけ、作り直しは同じ id の本文を書き換える。`review/deep.md` R3）。本文の消去を作る ST23 が、消した滞在に気分を付ける受け付け方を決める。
  `docs/handoff/ST23.md`（既にあり、他の Story からの申し送りが 10 節ある）の末尾に 1 節足す
- 反転条件: 本人が Q3 で「いま直す」を選んだら、spec の拒む理由の表に「終わりが分からない滞在は、記録の区間が始まりと同じ日（`Asia/Tokyo`）にかかれば受け付ける」を足して書き直す

### D10. 始まりの日の求め方は直さず、理由をコードに残す（指摘 9。問わずに決めた）

- `crates/server/src/feelings.rs` の `min(event_time)` の上に、既存の索引 `event_by_source_time (logical_source, event_time)`（`migrations/202609112113_source_lifecycle.sql:71`）に乗ること、

- 反転条件: 利用者が複数になり、他人の主観が古い場合に読みが増えることが実測で問題になったら、利用者の列を先頭に持つ索引を足す

## Risks / Trade-offs

- [読む口を動かすと、`*.d/` の節が本体の後ろの検査（読み出しの記録・`app-role`）より先に走る] → 本体の後ろの検査は版を戻した後の DB を前提にしており、`*.d/` の節が残す行に依らない。
  `tools/check-immutable.sh` rc=0 と、ST17 の節の OK の行が移す前と同じであることで確かめる（tasks Task 2）
- [D2 の見出しの型が既存の木の正当な変更を落とす] → 見出しの検査は、ST 番号が差分の `-` 行の見出しに出ていない `+` 行だけを見る。self-test で既存の 11 件と「既存の小見出しの文言を直す → 通す」が通ることを確かめる
- [`*.d/` の節が本体の変数を上書きし、後ろの検査が黙って変わる] → 読む口の注記と README に上書きしないことを書き、節の変数に `ST<NN>_` を付ける（D1）
- [CH01 の PR 自身が `check-shared-appends.sh` を変えて自分を通す] → CI は HEAD の台本で走るので、自分を通す規則を自分で足すことになる。通すのは「読む口のかたまり（見出しと `for … done` が同じ）の移動」だけに絞り、
  self-test が「動かした後に読む口の直後へ節を足す」を落とすことで、抜け道になっていないことを示す
- [Q6 で読み出しを 1 回にすると、読み出しの失敗が日の欄と暦の両方に出る] → 同じ口を同じ時に読むので、片方だけ失敗することはほぼ無い（Q6 の why）
- [e2e は主観の行を消せない] → ST17 と同じく、乱数で選んだ遠い日を `page.clock` の今日にして書き、件数は書く前との差で数える
