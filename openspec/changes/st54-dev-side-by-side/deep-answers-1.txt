=== ST54 の深掘り の回答 ===
Q1 [PC の収集アプリが開発版だと知る方法] -> 組み立てのときの版番号で決める（携帯と同じ）
Q2 [PC の収集アプリの置き場と端末識別子] -> 開発版は自分で分ける（置き場の下に `dev` を掘り、端末識別子の末尾に `-dev` を付ける）。除外の登録は正式版の置き場のものを読む
Q3 [開発版のサーバを正式版の DB に繋がない守り] -> DB に開発版か正式版かの印を残し、違う側のサーバは何も書かずに止まる
Q4 [開発版の DB が main の移行とずれたとき] -> 止まったら原因を示し、DB は書き換えない。main 側で直す
Q5 [開発版の印の動かし方] -> 動かす方式のまま。手順書に `git fetch --tags --force` を書く
Q6 [開発版の収集アプリの送り先] -> 開発版のサーバにだけ送る（送る前にサーバが開発版かを確かめ、違えば送らずに手元に積む）
Q7 [開発版の見分け方] -> 名前に「開発版」を付ける（「あしあと。開発版」「ashiato 開発版」）
Q8 [「サポートしない」をどこに書くか] -> 開発版のリリースの説明文の先頭に書き、公開のたびに書き直す
Q9 [この Story の完了を何で確かめるか] -> 下書きのリリースと使い捨ての鍵で確かめる（ST52 と同じ）。完了の判定にこの 3 つを足す
Q10 [開発版の携帯の収集アプリが動かす収集] -> 全部を動かす（正式版と同じ）
IMP-01 [PC の開発版で、ブラウザの履歴の除外が効かない恐れ] -> 仕様を直す
IMP-02 [更新の失敗からの戻し（ST58）が、終了コード 4 を知らない] -> 仕様を直す
QA [仕様への合意] -> 合意する
