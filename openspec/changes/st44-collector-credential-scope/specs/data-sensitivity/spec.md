## REMOVED Requirements

### Requirement: 画面から記録を読むには合言葉のログインが要る

**Reason**: 「API の合言葉による取り込み口と読み出し口の振る舞いを変えない」と Scenario「API の合言葉での読み書きは変わらない」が、ST44 の深掘り Q1（API の合言葉を送るだけに締める）で成り立たなくなった。
**Migration**: 「記録を読むには画面の合言葉のログインが要り、API の合言葉では読めない」（この change の ADDED）に、その 1 文・導出元の 2 行・1 つの Scenario のほかは同じ中身で置き直した。API の合言葉で記録を読んでいた道具は、画面の合言葉でログインして読む。

## MODIFIED Requirements

### Requirement: 画面のログインは期限で切れず、画面の合言葉を変えると全部が無効になる

THE SYSTEM SHALL 既定では、画面のログインの印を時間の経過で無効にしない（ログアウトするまで使える）。
THE SYSTEM SHALL ログインの印を、ブラウザを閉じても残る寿命で覚えさせ、印で認めた応答のたびにその寿命を延ばす。
THE SYSTEM SHALL 画面の合言葉が変わった後の起動で、変わる前に発行したすべてのログインの印を無効にする。
THE SYSTEM SHALL ログインの印の鍵（「画面のログインの印の鍵はサーバだけが持つ」）が変わった後の起動で、変わる前に発行したすべてのログインの印を無効にする。
THE SYSTEM SHALL API の合言葉が変わっても、ログインの印を無効にしない。
WHERE 利用者が設定でログインの期限を与えている THE SYSTEM SHALL 発行からその期間を過ぎた印を無効にする。

導出元: PERM-10。深掘り Q6（推奨の 30 日を本人が覆した）。
端末を落としたときに、その端末のログインを締め出す手段は、期限の代わりに画面の合言葉を変えることだけになる。
ブラウザは覚える寿命に上限を持つ（design の D18）ので、長く開かなかった端末ではもう 1 度ログインになることがある。
★ ST44（深掘りの AI の既定・design D7）: 前は API の合言葉を変えてもログインが全部切れた（印の鍵が API の合言葉だった）。鍵をサーバだけが持つ値に替えたので、
収集アプリの合言葉を替えても画面のログインは続く。ログインを締め出す手段は、画面の合言葉か印の鍵を変えること。

#### Scenario: 既定では日が経ってもログインは切れない

- **WHEN** 期限を設定せずに発行したログインの印で、発行から 400 日後の時刻に記録の読み出しを求める
- **THEN** 読み出しは通る

#### Scenario: ログインの印はブラウザを閉じても残り、使うたびに延びる

- **WHEN** 正しい合言葉でログインし、続けてその印で記録の読み出しを求め、2 つの応答の印を覚えさせる指示を見る
- **THEN** どちらの指示も、ブラウザを閉じても残る寿命（1 日以上の `Max-Age`）を持つ

#### Scenario: 画面の合言葉を変えると、それまでのログインはすべて使えなくなる

- **WHEN** 2 つのブラウザでログインした後、画面の合言葉を変えてサーバを起動し直し、それぞれの印で記録の読み出しを求める
- **THEN** どちらの求めも 401 で断られる

#### Scenario: 期限を設定したときは、過ぎた印は使えない

- **WHEN** ログインの期限を 30 日に設定して発行した印で、発行から 31 日後の時刻に記録の読み出しを求める
- **THEN** 求めは 401 で断られる

#### Scenario: API の合言葉を変えてもログインは切れない

- **WHEN** ログインした後、API の合言葉だけを変えてサーバを起動し直し、その印で記録の読み出しを求める
- **THEN** 読み出しは通る

#### Scenario: ログインの印の鍵を変えると、それまでのログインはすべて使えなくなる

- **WHEN** 2 つのブラウザでログインした後、ログインの印の鍵だけを変えてサーバを起動し直し、それぞれの印で記録の読み出しを求める
- **THEN** どちらの求めも 401 で断られる

### Requirement: 誰がいつ読んだかを、追記のみの読み出しの記録に残す

THE SYSTEM SHALL 記録の読み出しと、ログイン（成功・失敗・一時的な断り）・ログアウトと、資格情報の無いか一致しない求めと、衛星の資格情報で断った求めと、API の合言葉で許可の一覧の外の口に届いて断った求めを、1 件ごとに読み出しの記録に 1 行残す。
THE SYSTEM SHALL 資格情報が認められた取り込み（記録・生存信号・破棄の報告を送る求め）を、読み出しの記録に残さない。衛星の資格情報で取り込みの口に届いた求めは、断ったものとして残す。
THE SYSTEM SHALL 読み出しの記録の行に、時刻・経路（直接か、網の手段を経て届いたか）・資格情報の種類（画面のログイン / API の合言葉 / 衛星 / 無し）・口の名前・結果だけを持たせ、
資格情報の種類が衛星の行にはさらに、どの衛星か・どの 1 本の資格情報かを本体の中の番号で持たせる。
記録の中身・求めの引数・合言葉・ログインの印・衛星の資格情報の値・衛星の識別子の文字列・記録と利用者の識別子の文字列を持たせない。
THE SYSTEM SHALL 衛星の資格情報で断った求めと、API の合言葉で許可の一覧の外の口に届いて断った求めの行の結果を、実際に返した応答（403）のとおりに書く。
WHEN 読み出しの記録に行を書けない THE SYSTEM SHALL その読み出しの求めに記録を返さず、500 で断る。
THE SYSTEM SHALL 読み出しの記録を追記のみとし、書き換え・行の削除・表の切り詰めのいずれも拒む。
THE SYSTEM SHALL 読み出しの記録の行を、記録の読み出しに出さない。

導出元: PERM-10 / PERM-7 / PERM-14。深掘り C5（loss: uncaptured —— 残さなかった期間の読み出しは後から足せない。書けないときに返すと、その読み出しが黙って抜ける）。
製造準備 A-2（中身をログに残さない）。
経路の「網の手段を経て届いた」は中継が付ける印からの判定で、同じ PC のプロセスが偽れる。手がかりとして残す。
取り込みを残さないのは「誰がいつ読んだか」を残すためで、収集は数分ごとに来る。
★ ST29（深掘り C9 / C12・D1（仮）・D4（仮））: 資格情報の種類に「衛星」を足し、衛星と 1 本の資格情報の番号を残す。1 つの衛星に何本でも資格情報を
発行できる（PERM-14）ので、漏れた 1 本を後から特定する手がかりは、求めごとの行にその 1 本の番号があるときだけ残る（最後に使われた時刻は上書きされる）。
「識別子の文字列を持たせない」が禁じるのは記録と利用者の識別子（PERM-13 ★ C6。衛星が何を読んだかは別の台帳（ST45）に残す）で、衛星と資格情報の番号は呼び出し元を指すもの。
衛星の求めは承認（ST38）までどの口でも断るので、ST29 の衛星の行の結果はどれも 403 になる。
★ ST44（深掘りの AI の既定）: API の合言葉で許可の一覧の外の口に届いた求めを、資格情報の種類が API の合言葉・結果が 403 の行で残す。落とした電話の値で読もうとした跡が残る。
許可の一覧の中の取り込み（記録・生存信号・破棄の報告）は今どおり残さない。

#### Scenario: 記録の読み出しで読み出しの記録に 1 行増える

- **WHEN** ログインした画面の経路で記録の読み出しを 1 回求める
- **THEN** 読み出しの記録に、資格情報の種類が画面のログインで、口の名前がその読み出しの口の行が 1 行増える

#### Scenario: 断られた求めも読み出しの記録に残る

- **WHEN** 資格情報を付けずに記録の読み出しを求め、続けて違う合言葉でログインを求める
- **THEN** 読み出しの記録に、資格情報の無い読み出しが断られた行と、ログインに失敗した行が 1 行ずつ増える

#### Scenario: 取り込みは読み出しの記録に残らない

- **WHEN** API の合言葉を付けて記録を送り、取り込まれる
- **THEN** 読み出しの記録の行は増えない

#### Scenario: 衛星の資格情報で断った求めは、衛星と 1 本の番号つきで残る

- **WHEN** 衛星「読書ログ」の 2 本の資格情報のうち 1 本を付けて記録の読み出しを求める
- **THEN** 読み出しの記録に、資格情報の種類が衛星で、「読書ログ」の衛星の番号と付けた 1 本の資格情報の番号を持ち、結果が 403 の行が 1 行増え、その行のどの列にも衛星の識別子の文字列（`dev.example.booklog`）も資格情報の値も含まれていない

#### Scenario: 衛星の資格情報で取り込みの口に送った求めも残る

- **WHEN** 衛星の資格情報を付けて記録を取り込みの口に送る
- **THEN** 求めは 403 で断られ、読み出しの記録に、資格情報の種類が衛星で、口の名前がその取り込みの口で、結果が 403 の行が 1 行増える

#### Scenario: 読み出しの記録には中身も合言葉も残らない

- **WHEN** 引数を付けた記録の読み出し・ログイン・ログアウトと、衛星の資格情報を付けた記録の読み出しを行った後、読み出しの記録の行を全列読む
- **THEN** どの行にも、記録の中身・引数の値・合言葉・ログインの印・衛星の資格情報の値・衛星の識別子の文字列・利用者や記録の識別子の文字列が含まれていない

#### Scenario: 読み出しの記録に書けないときは記録を返さない

- **WHEN** 読み出しの記録への書き込みが失敗する状態で、正しい資格情報で記録の読み出しを求める
- **THEN** 求めは 500 で断られ、応答に記録は含まれない

#### Scenario: 読み出しの記録の行は書き換えも削除もできない

- **WHEN** 読み出しの記録の行を書き換える、削除する、または表を切り詰めようとする
- **THEN** いずれの操作も拒まれ、行は残っている

#### Scenario: 読み出しの記録は記録の読み出しに出ない

- **WHEN** 読み出しの記録に行がある状態で、記録の読み出しの口で全件を求める
- **THEN** 応答に読み出しの記録の行は含まれない

#### Scenario: API の合言葉で断った読み出しは、API の合言葉・403 の行で残る

- **WHEN** API の合言葉を付けて記録の読み出しを求める
- **THEN** 求めは 403 で断られ、読み出しの記録に、資格情報の種類が API の合言葉で、口の名前がその読み出しの口で、結果が 403 の行が 1 行増える

## ADDED Requirements

### Requirement: 記録を読むには画面の合言葉のログインが要り、API の合言葉では読めない

THE SYSTEM SHALL 画面の経路で記録を読み書きするとき、合言葉のログインで得た印を求め、印の無い求めを 401 で断る。
THE SYSTEM SHALL 画面を配る側に、API の合言葉やその他の資格情報を求めへ付け足させない。
THE SYSTEM SHALL ログインの口では、画面の合言葉そのものを資格情報として受け、合言葉の無いか一致しない求めを 401 で断り、印を発行しない。
WHEN 画面の合言葉が一致するログインの求めを受ける THE SYSTEM SHALL ログインの印を発行し、ブラウザに覚えさせる。
THE SYSTEM SHALL ログインの印を、ブラウザのスクリプトから読めず、暗号化された接続でだけ送られ、別のサイトから始まった求めには付かない形で覚えさせる。
THE SYSTEM SHALL 画面の合言葉と API の合言葉を別の値として持ち、画面の合言葉が未設定か、16 文字より短いか、API の合言葉と同じ値なら起動しない。
WHEN 1 分の間にログインの失敗が 10 回を超える THE SYSTEM SHALL その 1 分が過ぎるまで、以後のログインの求めを合言葉の正否にかかわらず 429 で断る。
WHEN ログアウトが求められる THE SYSTEM SHALL その印を無効にし、以後その印での求めを 401 で断る。
THE SYSTEM SHALL API の合言葉で通る口を、「API の合言葉で通る口は、送る口と通知に要る読みの許可の一覧だけ」の一覧に限る（記録の読み出しは画面のログインでだけできる）。

導出元: PERM-10。深掘り Q1 / Q4。画面を配る側が API の合言葉を付けていたので、画面に届けば合言葉無しで全記録を読めた。
網の内側に限る（PERM-7）だけでは、本人の端末の上の他のアプリ・同じ PC の別プロセスが画面の URL を叩くのを止めない。
ログインの口は「すべての API 要求は資格情報を要求する」（record-envelope）の例外の 1 つで、資格情報の代わりに画面の合言葉そのものを受ける（★ ST44 で record-envelope に例外として書いた）。
ST28 の深掘り Q4 では API の合言葉の読める範囲を変えなかった（呼び出し元ごとの範囲は PERM-10 の配り方として後で決める、とした）。
★ ST44（深掘り Q1 / Q3）: API の合言葉を送る口と通知に要る読みだけに締めた。全部を読めるのは画面のログインだけになる。
前の名前は「画面から記録を読むには合言葉のログインが要る」。Scenario「API の合言葉での読み書きは変わらない」が成り立たなくなり、OpenSpec は MODIFIED で Scenario を落とせないので、名前を替えて置き直した（中身はその 1 文・導出元の 2 行・1 つの Scenario のほかは同じ）。
16 文字・1 分 10 回は仮決め（design の D16 / D17）。
ログインの印は同じ機械名の別の口にも送られる（cookie は口で分かれない）。これは主張できないので、画面を他のサービスと同じ機械名に同居させない手順を置く（design）。

#### Scenario: ログインしていないブラウザには記録が 1 件も返らない

- **WHEN** ログインしていないブラウザで稼働状況の画面を開く
- **THEN** 画面が出した記録の読み出しの求めはすべて 401 で断られ、画面に記録の行は 1 つも出ない

#### Scenario: ログインしていないブラウザには合言葉の入力欄が出る

- **WHEN** ログインしていないブラウザで稼働状況の画面を開く
- **THEN** 合言葉の入力欄が見えている

#### Scenario: 合言葉でログインすると画面が記録を読める

- **WHEN** 正しい画面の合言葉でログインし、稼働状況の画面を開く
- **THEN** 画面の経路からの読み出しが通り、記録が画面に出る

#### Scenario: 違う合言葉のログインの求めは断られ、印は発行されない

- **WHEN** 画面の合言葉と違う値でログインを求める
- **THEN** 求めは 401 で断られ、応答はログインの印を発行しない

#### Scenario: 違う合言葉を入れても画面は記録を出さない

- **WHEN** ログインしていないブラウザで、画面の入力欄に違う合言葉を入れてログインする
- **THEN** 入力欄は見えたままで、画面に記録の行は 1 つも出ない

#### Scenario: 合言葉を付けないログインの求めは断られる

- **WHEN** 合言葉を付けずにログインを求める
- **THEN** 求めは 401 で断られ、応答はログインの印を発行しない

#### Scenario: API の合言葉では画面にログインできない

- **WHEN** API の合言葉の値を画面の合言葉としてログインを求める
- **THEN** 求めは 401 で断られる

#### Scenario: 画面を配る側は合言葉を付け足さない

- **WHEN** ログインの印も API の合言葉も持たない求めを、画面を配る側の経路で記録の読み出しへ送る
- **THEN** 求めは 401 で断られる

#### Scenario: ログインの印はスクリプトから読めない

- **WHEN** 正しい合言葉でログインした画面の中のスクリプトから、ブラウザが覚えている cookie を読む
- **THEN** ログインの印は読み出せない

#### Scenario: ログインの印は暗号化された接続でだけ送られる

- **WHEN** 正しい合言葉でログインし、応答が印を覚えさせる指示を見る
- **THEN** 指示は印を暗号化された接続でだけ送る属性（`Secure`）を持つ

#### Scenario: ログインの印は別のサイトから始まった求めには付かない

- **WHEN** 正しい合言葉でログインし、応答が印を覚えさせる指示を見る
- **THEN** 指示は別のサイトから始まった求めに印を付けさせない属性（`SameSite=Strict`）を持つ

#### Scenario: ログアウトすると記録が読めなくなる

- **WHEN** ログインした画面でログアウトし、同じブラウザで稼働状況の画面を開き直す
- **THEN** 記録の読み出しは 401 で断られ、合言葉の入力欄が出る

#### Scenario: ログアウトした印を持ち出しても使えない

- **WHEN** ログインの印の値を控えてからログアウトし、控えた値を付けて記録の読み出しを求める
- **THEN** 求めは 401 で断られる

#### Scenario: 画面の合言葉が API の合言葉と同じだと起動しない

- **WHEN** 画面の合言葉を API の合言葉と同じ値にしてサーバを起動する
- **THEN** サーバは起動せず、2 つの合言葉が同じであることを理由に出して終わる

#### Scenario: 画面の合言葉が無いか短いと起動しない

- **WHEN** 画面の合言葉を設定しないか、15 文字の値にしてサーバを起動する
- **THEN** サーバは起動せず、画面の合言葉が無い・短いことを理由に出して終わる

#### Scenario: 失敗を重ねたログインは一時的に断られる

- **WHEN** 1 分の間に違う合言葉のログインを 10 回求めた後、11 回目に正しい合言葉でログインを求める
- **THEN** 11 回目の求めは 429 で断られ、印は発行されない

#### Scenario: API の合言葉では記録を送れるが読めない

- **WHEN** ログインの印を持たず、API の合言葉を付けて記録を送り、記録の読み出しを求める
- **THEN** 送った記録は取り込まれ、読み出しは 403 で断られて記録を返さない

### Requirement: API の合言葉で通る口は、送る口と通知に要る読みの許可の一覧だけ

THE SYSTEM SHALL API の合言葉（収集アプリの資格情報）を付けた求めを、次の許可の一覧の口と方法にだけ通す:
記録を送る（`POST /ingest`）・生存信号を送る（`POST /heartbeat`）・破棄の報告を送る（`POST /drops`）・原本の欠けを送る（`POST /media/missing`）・写真の原本を置く（`PUT /media/originals/{sha256}`）・
送信契約の版を確かめる（`GET /contract`）・原本を受け取り済みかを確かめる（`HEAD /media/originals/{sha256}`）・気分の通知を出すかを判断する（`GET /feelings/reminder`）・途絶の判定を読む（`GET /outages`）。
THE SYSTEM SHALL 許可の一覧の外の口と方法に API の合言葉で届いた求めを、ハンドラを呼ばず本文も読まずに 403 で断る。
THE SYSTEM SHALL 新しく足した口を、許可の一覧に足すまで API の合言葉では通さない。
THE SYSTEM SHALL API の合言葉とログインの印の両方を付けた求めを、API の合言葉の求めとして扱う。
THE SYSTEM SHALL 画面のログインの印で通る口の範囲を変えない（送信契約の版の口は今どおり断り、ほかの口は全部通る）。
THE SYSTEM SHALL 衛星の形でない、API の合言葉と一致しない `Bearer` と有効なログインの印を両方付けた求めを、ログインの印の求めとして扱う。

導出元: PERM-10。ST44 の深掘り Q1（いまの API の合言葉を締める）・Q3（画面のログインはいまのまま）・`docs/handoff/ST44.md`（気分の通知と途絶の判定の 2 つの読みを残す）。
携帯の APK と PC の自動起動の台本は同じ API の合言葉を持つ。落とした電話や入れ直す前の古い APK に残った値で読まれた記録は戻らない。締めた後に、その値でできるのは送ることと、上の 4 つの読みだけになる。
4 つの読みはどれも記録の中身を返さない（送信契約の版の整数・原本の有無・通知の時刻と記録の有無の真偽・途切れたソースの表示名と最後に生きていた時刻）。
気分の通知の判断と途絶の判定を塞ぐと、通知が鳴りすぎる・鳴らなくなる（ST17 の D10・ST14 の Q1）。
既定は厳しい側に置く（新しい口は断る）。一覧に足す判断は、その口を収集アプリが使う Story がする。
両方を付けた求めを API の合言葉として扱うのは、資格情報の判定が API の合言葉を先に見る今の順を変えないため（design D11（仮））。読む道具は印だけを付ける。
一致しない `Bearer` と印の組を印で通すのは今の振る舞いのまま（design D10（仮）。読めるのは本人の画面と同じ範囲。ST29 の申し送りを閉じる）。
配り方は共有の 1 本のまま（深掘り Q2）。端末ごとの発行と取り消しは ST56 が作る。

#### Scenario: API の合言葉で記録・生存信号・破棄の報告・原本の欠けを送れる

- **WHEN** ログインの印を持たず、API の合言葉を付けて、記録・生存信号・破棄の報告・原本の欠けをそれぞれ送る
- **THEN** どの求めも 200 で、送った 1 件ずつが受け付けられた結果として返り、403 で断られる求めは無い

#### Scenario: API の合言葉で写真の原本を置き、受け取り済みかを確かめられる

- **WHEN** API の合言葉を付けて、記録が参照する写真の原本を置き、続けて同じ原本の有無を確かめる
- **THEN** 原本は置かれ、有無の確かめは受け取り済みを答える

#### Scenario: API の合言葉で送信契約の版を確かめられる

- **WHEN** API の合言葉を付けて送信契約の版を問い合わせる
- **THEN** 求めは 200 で、受け付ける一番新しい契約の版を答える

#### Scenario: API の合言葉で気分の通知の判断を読める

- **WHEN** API の合言葉を付けて、日付を指定して気分の通知の判断を求める
- **THEN** 求めは 200 で、通知の時刻と記録の有無の真偽を返す

#### Scenario: API の合言葉で途絶の判定を読める

- **WHEN** 判定を待つ時間が過ぎたサーバに、API の合言葉を付けて途絶の判定を問い合わせる
- **THEN** 求めは 200 で、途切れたソースの一覧を返す

#### Scenario: API の合言葉では許可の一覧の外の口はすべて断られる

- **WHEN** API の説明に載る口と方法のうち、許可の一覧の外のものすべてに、API の合言葉だけを付けて求める
- **THEN** どの求めも 403 で断られ、記録も滞在も気分も書き出しも返らず、記録・滞在・場所・属性・衛星・書き出しの状態は変わらない

#### Scenario: API の合言葉では気分の中身は読めない

- **WHEN** ひとことと尺度を持つ気分の記録がある日について、API の合言葉を付けて日ごとの気分の読み出しを求める
- **THEN** 求めは 403 で断られ、応答にひとことの文字列も尺度の値も含まれない

#### Scenario: API の合言葉ではログインの状態も読めない

- **WHEN** API の合言葉だけを付けてログインの状態を問い合わせる
- **THEN** 求めは 403 で断られ、読み出しの記録に資格情報の種類が API の合言葉で結果が 403 の行が 1 行増える

#### Scenario: API の合言葉とログインの印を両方付けた読み出しは断られる

- **WHEN** 有効なログインの印と API の合言葉の両方を付けて記録の読み出しを求める
- **THEN** 求めは 403 で断られる

#### Scenario: ログインの印だけを付けた読み出しは通る

- **WHEN** 有効なログインの印だけを見出しで付けて、画面を配る側を通さずに記録の読み出しを求める
- **THEN** 読み出しは通り、記録を返す

#### Scenario: 画面のログインは許可の一覧の外の口も通る

- **WHEN** 有効なログインの印を付けて、記録・滞在・日ごとの気分の読み出しと、記録を送る求めをそれぞれ求める
- **THEN** どの求めも 2xx で応える

#### Scenario: 一致しない Bearer とログインの印を両方付けた読み出しは印で通る

- **WHEN** 衛星の形でなく API の合言葉とも一致しない `Bearer` と、有効なログインの印の両方を付けて記録の読み出しを求める
- **THEN** 読み出しは 2xx で記録を返し、読み出しの記録の行の資格情報の種類は画面のログインである

#### Scenario: API の合言葉で通知に要る読みをすると、読み出しの記録に 1 行残る

- **WHEN** API の合言葉を付けて、送信契約の版・気分の通知の判断・途絶の判定をそれぞれ 1 回読む
- **THEN** 読み出しの記録に、資格情報の種類が API の合言葉で、口の名前がそれぞれの口で、結果が 200 の行が 1 行ずつ増える

### Requirement: 画面のログインの印の鍵はサーバだけが持つ

THE SYSTEM SHALL ログインの印が画面の合言葉の変わる前のものかを見分ける印を、サーバだけが持つ鍵（ログインの印の鍵）で作り、API の合言葉を鍵にしない。
THE SYSTEM SHALL ログインの印の鍵が未設定か、16 文字より短いか、API の合言葉か画面の合言葉と同じ値なら起動せず、どれに当たるかを理由に出して終わる。
THE SYSTEM SHALL ログインの印の鍵の値を、ログ・読み出しの記録・応答・DB に出さない。

導出元: PERM-10。ST44 の深掘りの AI の既定（review/deep.md R2）。
前は API の合言葉を鍵にしていたので、収集アプリに残る API の合言葉と DB の写し（ログインの印の行）がそろうと、画面の合言葉の候補を手元で確かめられた（全部を読める合言葉を総当たりできた）。
鍵をサーバだけが持てば、収集アプリの値と DB の写しがそろっても確かめられない。鍵の持たせ方は design D8（仮）。
鍵を入れ替えた最初の起動で、それまでのログインは 1 回だけ全部切れる（記録は失わない）。

#### Scenario: ログインの印の鍵が無いと起動しない

- **WHEN** ログインの印の鍵を設定せずにサーバを起動する
- **THEN** サーバは起動せず、ログインの印の鍵が無いことを理由に出して終わり、出力のどこにも API の合言葉と画面の合言葉の値が無い

#### Scenario: ログインの印の鍵が短いか、ほかの合言葉と同じだと起動しない

- **WHEN** ログインの印の鍵を 15 文字の値・API の合言葉と同じ値・画面の合言葉と同じ値にして、それぞれサーバを起動する
- **THEN** どれもサーバは起動せず、短い・API の合言葉と同じ・画面の合言葉と同じ、をそれぞれ理由に出して終わり、出力のどこにもログインの印の鍵の値が無い

#### Scenario: API の合言葉と DB の写しだけでは画面の合言葉を確かめられない

- **WHEN** ログインした後のログインの印の行と API の合言葉から、API の合言葉を鍵にして画面の合言葉の印を作り、行の印と比べる
- **THEN** 2 つの印は一致しない
