これらは ST50 の後も古い側として残り、直せない。

失われるものを持つ決定の推奨は、確かさ 4 以上の前提（P1・P3・P4・P5・P7）に載せる。確かさ 2〜3 で残るのは P2・P6・P8・P9:
P2 は外れても C2 で手元に残る（下）。P9 は「409 を使わない」側の根拠で、推奨（426）は P3 の「200 / 400 以外は残す」と P9 の else（試し直す）に載る。
P2 が外れても（古い S-01 が 404 以外を返しても）、新しい収集アプリは「受け付ける版の答えとして読めないものは、受け付けないものとして扱う」（C2）ので、記録は手元に残る。

## 聞かない既定（C。扉を開けたままにする側。spec の段で design の D 番号に写す）

- **C1** 契約の版を名乗らない要求（ST50 より前の収集アプリ）は**版 1** とみなして受け付ける（FR-124）。版 1 は今の封筒の全部と、
  最初の正式版までに足す欄（走っている ST41 の終わりの時刻・ST49 の `client_version`）を含む（FR-130 の★）
- **C2** 新しい収集アプリは、問い合わせの答えが**受け付ける版として読めない**とき（404・読めない本文・版が無い）は、受け付けないものとして
  送らずに手元に残す（FR-125「口を持たない S-01 は受け付けないものとして扱う」を、404 だけに絞らない）。到達できない・5xx・401 は今どおり
  一時的な失敗（手元に残し、「サーバを更新してください」は出さない —— 原因が更新ではない）
- **C3** FR-130 の検査の基準点は**最後に配った印（タグ `v*`）の版の契約**。印が無い間は何も落とさない（ST48 の
  `tools/check-released-migrations.sh` と同じ「配った」の定義）。main の前の commit と比べると、最初の正式版の前の足し方まで版を上げさせる。
  `v*` はベータ版（`-beta.N`）の印にも当たる。ベータ版を「配った」に入れるかは Q8（review/deep.md R1）
- **C4** 契約の版は**整数を 1 つ**。S-01 は自分の版以下の全部を受け付ける（FR-124。正式版で出した版を外さない）。版の数は 1 か所に置き、
  S-01・携帯・PC の 3 つの値が食い違えば CI が落ちる（機械の検査。片方だけ直す事故を防ぐ。`docs/collector-contract.md` の冒頭と同じ理由）
- **C5** PC の収集アプリの未送信には上限を足さない（FR-8 の★「上限は C-01 だけ」。premises P6）。止まっている間は溜め続け、Q5 の通知で知らせる。
  FR-125 の★（「手元に残した記録には FR-8 / FR-9 の上限を掛ける」）と NFR-7 の★が食い違う（review/deep.md R10）—— 失わない側なので問わず、
  spec の段で `D<n>（仮）` として台帳に載せ、FR-125 の★に「上限は FR-8 の主語（C-01）に掛かる」を足す訂正を「要件へ戻すもの」に挙げる
- **C6** S-01 を更新して受け付けるようになったら、手元に残していた記録は**今の送り方のまま**（溜めた順・まとめ送り）送る。
  止まっていた間に覚えた「飛ばす」印は捨てる（受け付けるようになった 1 件が先頭で待たされないように）
- **C7** 確かめる口は取り込みと同じ資格情報（API の合言葉）で守る。版は私的データではないが、合言葉の無い相手に S-01 の版を明かさない
- **C8** 画面（V-01）と衛星の要求は契約の版の対象にしない。V-01 は S-01 が配る（FR-104 の★）ので常に同じ版、衛星の契約は別に作る（`docs/collector-contract.md` の冒頭）
- **C9** 断りの応答の新しい種別（例: `unknown_field`・`contract_unsupported`）は、携帯の `PERMANENT_ERRORS` に**入れない**（捨てない側。premises P4）
