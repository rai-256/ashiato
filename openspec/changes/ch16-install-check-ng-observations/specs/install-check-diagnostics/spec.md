## Purpose

Windows のインストールの試験の台本（`tools/release/install-check.sh` と `tools/release/update-check-install.sh`）は、判定が落ちたときに、
NG の理由の 1 行だけでなく、その判定が見た観測を CI のログに出す。観測を足すためだけに CI をもう 1 周回さずに、製品の誤りか判定の誤りかを
1 回のログで切り分けられるようにするための、開発の道具の約束。

## ADDED Requirements

### Requirement: Windows のインストールの試験の判定が NG になると、その判定が見た観測を CI のログに出す

THE SYSTEM SHALL `tools/release/install-check.sh` と `tools/release/update-check-install.sh` の判定が NG になったとき、
標準エラーの `NG: <理由>` の行に続けて、`== 観測（ここから）` の行と `== 観測（ここまで）` の行で挟んだ観測の塊を出してから、終了コード 1 で終わる。
観測の塊は次を持つ:

- 判定が渡した値（判定が受けた命令の出力など）
- その判定より前に台本が走らせた観測の命令（`sc.exe`・`icacls.exe`・`netstat.exe`・`reg.exe`・`curl`。`System32` の場所から呼ぶものも含む）の、名前・引数・終了コード・生の出力の直近のもの
- Windows の実地の確かめの中では、共通の様子: `ashiato-db`・`ashiato-server`・`ashiato-updater` の状態と構成、サーバの healthz の HTTP の番号、
  設定のファイルのキーの名前（値は出さない）、台本が書いた命令の記録とサーバのログの末尾

観測の塊の量には上限があり（命令の記録の件数・1 件の行数・ファイルの末尾の行数）、観測を取る命令の 1 つずつに時間の上限がある。
観測を取る命令が無い・落ちる・時間の上限を超えるときも、`NG: <理由>` の行と終了コード 1 は変わらず、その命令について `（取れない: <命令> rc=<n>）` の 1 行を観測の塊に書く。
観測の塊は標準エラーにだけ出し、標準出力（`== Scenario:` の行）には出さない。

観測の塊に秘密の値を出さない。伏せるのは、設定のファイルの秘密の値・台本が使う画面の合言葉・`Authorization:` の見出しの値・`ashiato_session=` の値で、
出す前に `***` に置き換える。伏せる値を集められない（設定のファイルを読めない）ときは、命令の記録とファイルとログの末尾を出さず、
`（伏せる値を読めないので出さない）` の 1 行を書く（サービスの状態と healthz の番号は出す）。

この約束は、台本が `NG:` を出して終わる道についてのもので、`set -e` によって判定の外の命令の失敗で止まる道は含まない。
判定が OK / NG を出す条件と `--list` の出力は変えない。
導出元: CH16

#### Scenario: 判定が NG になると、NG の行に続けて判定が見た命令の出力が出る
- **WHEN** 自己試験が、`sc.exe query` の偽の出力（4 行目に `        STATE              : 4  RUNNING`）を返す命令を置き、状態が 1 であることを求める判定を走らせる
- **THEN** 判定は終了コード 1 で終わり、標準エラーの最初の行は `NG: ` で始まる判定の理由である
- **AND** 標準エラーの `NG: ` の行より後に `== 観測（ここから）` の行があり、その後に偽の出力の `        STATE              : 4  RUNNING` の行がそのまま出て、最後に `== 観測（ここまで）` の行がある
- **AND** 標準出力に観測の塊の行は無い

#### Scenario: 判定が渡した値は、命令を走らせない判定でも観測に出る
- **WHEN** 自己試験が、受けた icacls の出力の行を見る判定に、余計な主体を持つ偽の行を渡す
- **THEN** 標準エラーの `NG: ` の行より後に、判定に渡した偽の行が出る

#### Scenario: 実地の確かめの中の NG は、サービスの状態・healthz・設定のキー・命令の記録とサーバのログの末尾を出す
- **WHEN** 自己試験が、実地の確かめの中と同じ置き場（状態の置き場・設定のファイル・命令の記録・サーバのログ）と偽の `sc.exe` と偽の `curl` を置き、判定を NG にする
- **THEN** 標準エラーの `NG: ` の行より後に、3 つのサービスそれぞれの偽の `sc.exe` の出力・healthz の番号・設定のキーの名前・命令の記録の末尾の行・サーバのログの末尾の行が出る

#### Scenario: 観測に秘密の値が出ない
- **WHEN** 自己試験が、設定のファイルの秘密（API の合言葉・ログインの印の鍵・照らすための値・2 つの DB の合言葉）と台本の画面の合言葉を、命令の記録と命令の出力と判定が渡す値に混ぜて、判定を NG にする
- **THEN** 標準エラーにそのどの値も現れない
- **AND** 設定のキーの名前は出る

#### Scenario: 設定に無い秘密も、見出しの形で伏せる
- **WHEN** 自己試験が、設定のファイルに無い値を `Authorization: Bearer <値>` と `Cookie: ashiato_session=<値>` の形で観測の命令の引数と出力に混ぜて、判定を NG にする
- **THEN** 標準エラーにその値が現れない

#### Scenario: 伏せる値を読めなければ、命令の記録とファイルの末尾を出さない
- **WHEN** 自己試験が、設定のファイルを読めないようにして、命令の記録と命令の記録のファイルを置いたまま判定を NG にする
- **THEN** 標準エラーに `（伏せる値を読めないので出さない）` の行があり、命令の記録とファイルとログの末尾の行は無い
- **AND** 終了コードは 1 で、標準エラーの最初の行は `NG: ` で始まる

#### Scenario: 観測を取る命令が無い・落ちても、NG の行と終了コードは変わらず、取れなかったことを書く
- **WHEN** 自己試験が、要る道具だけを並べた置き場を `PATH` にして `sc.exe` と `curl` を無くした環境と、偽の `sc.exe` が終了コード 5 で落ちる環境で、それぞれ判定を NG にする
- **THEN** どちらも終了コード 1 で終わり、標準エラーの最初の行は `NG: ` で始まる判定の理由である
- **AND** 観測の塊に `（取れない: sc.exe rc=` で始まる行がある

#### Scenario: 観測を取る命令が戻らなくても、時間の上限で打ち切って NG で終わる
- **WHEN** 自己試験が、戻らない偽の `sc.exe` を置き、観測の時間の上限を 1 秒にして判定を NG にする
- **THEN** 判定は 30 秒より前に終了コード 1 で終わり、観測の塊に `（取れない: sc.exe rc=` で始まる行がある

#### Scenario: 観測の命令を記録しても、判定が見る出力は変わらない
- **WHEN** 自己試験が、行末に CR を持つ標準出力と標準エラーを出して終了コード 3 で終わる偽の `sc.exe` を、記録しながら呼ぶ呼び出しと記録しない呼び出しで受ける
- **THEN** 2 つの標準出力・標準エラー・終了コードはそれぞれ同じである

#### Scenario: 記録する命令の出力をパイプが途中で閉じても、終了コードは命令のものになる
- **WHEN** 自己試験が、`set -o pipefail` のもとで、64 KiB を超える出力を出して終了コード 0 で終わる偽の `sc.exe` を記録しながら呼び、その出力を最初の行で終わる `grep -q` で受ける
- **THEN** パイプ全体の終了コードは 0 である

#### Scenario: CI の Windows で、観測の塊を本物の命令で一度出してから実地の確かめに入る
- **WHEN** `tools/release/install-check.sh` の実地の確かめが Windows で始まる
- **THEN** 本物の `sc.exe` と `curl` で観測の塊を一度作り、`== 観測（ここから）`・`== 観測（ここまで）` の行と 3 つのサービスそれぞれの `sc.exe` の答えの行（サービスがまだ無ければ無いという答え）があることを確かめる
- **AND** 無ければ、それを理由に NG で終わる

### Requirement: 観測を出さずに NG で終わる道を、自己試験が落とす

THE SYSTEM SHALL `tools/release/check-ng-observations.sh <台本>…` で、名指しした台本を静的に見て、次の決まりに外れる行を、決まりの名前と行の番号を付けて出し、終了コード 1 で終わる:

1. `NG:` の行を出すのは観測を出す口だけである
2. 0 でない終了コードの `exit` は、観測を出す口と使い方を示す口の中だけにある
3. 観測の命令を `System32` の下の場所を直に書いて呼ぶのは、記録する口の中だけである
4. 台本は観測を出す部品を読み込み、観測を出す口を自分で定義し直さない

ヒアドキュメントの中は見ない。同じ行に `# ng-observations: <理由>` の印がある行は 1〜3 の決まりから除き、理由が空の印は外れとする。
`tools/release/install-check.sh --self-test` と `tools/release/update-check-install.sh --self-test` は、自分にこの検査を当てる。
導出元: CH16

#### Scenario: 観測の口の外で NG の行を出す台本を、検査が落とす
- **WHEN** 検査の自己試験が、ほかの決まりには外れず、観測の口の外に `echo "NG: x" >&2` の行だけを持つ台本の写しに検査を当てる
- **THEN** 検査は終了コード 1 で終わり、決まり 1 の名前とその行の番号を出す

#### Scenario: 観測の口の外で 0 でない exit をする台本を、検査が落とす
- **WHEN** 検査の自己試験が、ほかの決まりには外れず、観測の口の外に `exit 3` の行だけを持つ台本の写しに検査を当てる
- **THEN** 検査は終了コード 1 で終わり、決まり 2 の名前とその行の番号を出す

#### Scenario: 記録しない口で観測の命令を呼ぶ台本を、検査が落とす
- **WHEN** 検査の自己試験が、ほかの決まりには外れず、記録する口の外で `System32` の下の `sc.exe` の場所を直に書いて呼ぶ台本の写しに検査を当てる
- **THEN** 検査は終了コード 1 で終わり、決まり 3 の名前とその行の番号を出す

#### Scenario: 観測を出す部品を読まない・口を定義し直す台本を、検査が落とす
- **WHEN** 検査の自己試験が、観測を出す部品を読み込まない台本の写しと、読み込んだ後に観測を出す口を定義し直す台本の写しに、それぞれ検査を当てる
- **THEN** どちらも検査は終了コード 1 で終わり、決まり 4 の名前を出す

#### Scenario: 理由の印を付けた行は除き、理由の無い印は外れにする
- **WHEN** 検査の自己試験が、`exit 2 # ng-observations: 使い方の誤り` の行だけを持つ写しと、`exit 2 # ng-observations:` の行だけを持つ写しに、それぞれ検査を当てる
- **THEN** 前の写しは終了コード 0、後の写しは終了コード 1 で終わる

#### Scenario: 2 つの台本は検査を通る
- **WHEN** `tools/release/install-check.sh --self-test` と `tools/release/update-check-install.sh --self-test` が、自分に検査を当てる
- **THEN** 検査は終了コード 0 で終わり、2 つの自己試験も終了コード 0 で終わる
