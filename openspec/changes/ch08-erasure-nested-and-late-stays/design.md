### D2（仮）. 作り直しが隠した重なる滞在の見分けと消し方（Q8・C1〜C4）

`rebuild_day` の中、`assign` の後・書き込みの前に、次をすべて満たす既存の滞在 L を「隠れて本文を消す滞在」とする:

1. `Mark::Live`（作り直しの前に一覧に出ていた。C2）
2. L の作り直しの前の時間（`load_existing` が読んだ `start`・`end`）が、本文ごと消した時間帯のどれかと**重なる**（`a.start < b.end AND b.start < a.end`。端が触れるだけは含めない。C1）。
   本文ごと消した時間帯は `load_existing` が足す本文を消した滞在（`raw = ''` の `Mark::UserDeleted`）の時間。操作の識別子を引けるように `PurgedStay` に `operation_id` を足す
3. この作り直しが隠す: (a) `plan.absorbed` に入っている、または (b) 引き継ぐ新しい滞在 `f` が `touches_erased` で隠れる

(b) のときは **L を引き継がせない**（`inherits[i] = None` にして `f` を新しい行として隠して作る）。L を新しい本文で書き換えてから消すと、書き換えの前の版を積んでから消すことになり、
`f` の隠れた行（消した時間帯の「消した」の行になる時間）が次の作り直しまで無くなる。新しく作った行は `f` の生きた位置だけから作るので、P の座標を持たない（C2）。

**(b) が起きる場面**（spec review R5）: 作り直しは位置を読む前に P の時間帯（両端を含む）の生きた位置へ後着の印を付ける（`mark_late_arrivals`）ので、`f` は P 自身には触れない。
`f` が隠れるのは、P と別の、本文を消していない消した時間帯に触れるとき（例: 10 分未満の消した滞在 B2 をまたぐ `f`。spec の Scenario「作り直しで消した時間帯と重なるとして隠れた…」の場面）。
L は P と重なる時間を持ったまま `f` に引き継がれ、`f` が B2 に触れて隠れる。

L ごとに `deletion::purge_hidden_overlap(tx, …)`（新しい。`purge_late_arrival` と同じ並びで、D3 の行を書く）を呼ぶ。`absorb` は呼ばない（`core.stay_absorbed` に行を書かない —— L は吸収されたのではなく本文ごと消された）。
同じトランザクションの中なので、消去の台帳が書けなければ `rebuild_day` 全体が巻き戻る（C4）。派生の門（ST23 D7）は commit の時に台帳の行を見る。

時刻は比べない（C2）。新しく作って初めから隠す行（`insert_stay(hide = true)`）と、`Mark::ErasedRange` / `Mark::Absorbed` の行は 1 で外れる。

**（仮）の中身**: (b) で引き継がせない形。反転条件: 引き継がせないことで、`f` の行の識別子が作り直しのたびに変わって困る読み手（気分・場所の付け先など）が見つかったら、
引き継いで書き換えた後に、書き換えの前の版を含めて消す形にする。

### D3（仮）. L の印・台帳・範囲の行と、元の操作の選び方（C7）

`purge_hidden_overlap` が 1 つのトランザクションの中で書くもの（順は ST23 D3 と同じ。門が commit の時に見る）:

1. `core.erasure_operation` に `kind = 'late'`・`parent_id` = 元の操作・`stay_id` = 元の操作の指定した滞在・`start_at` / `end_at` = 元の操作の時間帯・`stays = 1`・ほかの組 0・`versions` = L の本文の残る前の版の数
2. `core.erasure_ledger` に L（`scope = 'event'`）と前の版ごと（`scope = 'version'`）の行（`reason = 'stay-purge'`・`operation_id`）
3. `core.erasure_span` に L の作り直しの前の時間（`scope = 'event'`）と前の版それぞれの時間（`scope = 'version'`・`version_no`）
4. 本文の消去（`erase_bodies`。前の版 → 記録）
5. L の印を `deleted_at = now()`・`deleted_by = 'user:purged'` に（読んだときの印が `NULL` の行だけ。`SAME_MARK` と同じ確かめ）、`core.deletion_ledger` に `erase`・原因 = 元の操作の指定した滞在・`mark = 'user:purged'`

`user:purged` は `core.stay_erased` に出ないので、L の時間は消した時間帯の窓を広げない（探り B1・B2。spec「作り直しで本文を消した滞在は消した時間帯を広げない」）。

**元の操作**: L と重なる本文ごと消した時間帯が 2 つ以上あれば、重なりのいちばん大きいもの → 時間帯の始まりの早いもの → 操作の識別子の順（C5 の B の置き場と同じ規則）。
**（仮）の中身**: 元の操作の選び方。どれを選んでも消す範囲は同じで、1 日の行の「後から N 件」がどの行に出るかだけが変わる。反転条件: 本人が「重なるすべての行に数える」を選んだら、操作の行を重なる時間帯ごとに 1 行にする。

### D4（仮）. 戻す口の断り方 —— 戻した結果を同じまとまりの中で作り直して確かめる（Q2）

`deletion::restore` の印を外した後、commit の前に:

1. 求めた滞在のうち、本文ごと消した時間帯と重なる（端が触れるだけは含めない）ものがあるかを見る。**無ければいまのとおり**（commit → 呼び出し側が日ごとに作り直す）
2. あれば、戻した滞在の日（いまの `rebuild_days` と同じ計算）を**同じトランザクションの中で**作り直し（`rebuild_day` の本体を `rebuild_day_in(tx, …)` に切り出す。錠は同じ鍵を取り直すだけ）、
   重なる滞在がどれも `deleted_at IS NULL` で残っているかを見る
3. 1 つでも残っていなければ、巻き戻して 409（理由 `not_restorable`。ST23 の `purged_restore` と区別する）。残っていれば commit し、呼び出し側は作り直し済みの日を作り直さない
4. 2 の作り直しが落ちたら（`RangeUnsettled`・`MarkChanged`・DB の誤り）、巻き戻して 503（理由 `restore_rebuild_failed`）。いまの「作り直しが落ちても 200 でログだけ」（`lib.rs` の `stays_restore`）は、
   重ならない求めには残す。重なる求めで commit してしまうと、戻した B が一覧に戻るかを誰も確かめないまま次の作り直しで隠れ、D2 が本文を消す。試験は作り直しに失敗を差し込む口（`rebuild_day_in` の試験用の差し込み）で落とす

先に規則で決める（入れ子か・はみ出しの長さが最短のとどまり以上か）形は採らない: 滞在になるかは位置の並び・半径・引き継ぎの距離（`assign` の半径の 2 倍）で決まり（探り A2）、規則を書き写すと作り直しとずれる。
同じまとまりの中で作り直すと、作り直しの中の D2 が戻した B を隠して本文を消しうるが、そのときは 3 で巻き戻すので B の本文は消えない。

すっぽり入る B（D6 の入れ子の項目）は画面に「戻す」を出さない（spec）。口はそれでも 2 の作り直しで断る（画面を通らない求めのため）。

**（仮）の中身**: 確かめ方（作り直して見る）。反転条件: 戻す口の応答が遅くなり、作り直しの所要が `stay.rebuild_slow` のログで閾値を超えるなら、本文ごと消した時間帯と重なる求めだけを規則（入れ子なら断る）で先に断り、残りを作り直して見る。

### D5（仮）. 起動時の手当ての対象の見分け方 —— 時刻を比べない（Q5）

対象は、次をすべて満たす滞在 R（`s01-stay`・`origin = 'derived'`）:

1. `deleted_by IN ('rebuild:absorbed', 'rebuild:erased-range')`・`raw <> ''`
2. R の**いまの**時間が、`kind = 'user'` の操作 P の時間帯（`start_at`・`end_at`）と重なる（端が触れるだけは含めない）
3. `core.deletion_ledger` に R の行が 1 つも無い（本人が R を消したことも戻したことも無い）
4. `R.ingest_time <> R.deleted_at`（作り直しが初めから隠して作った行ではない。`insert_stay` は両方を同じ `now()` にする。等しいかだけを見て、前後は比べない）

元の操作の選び方は D3 と同じ。見つけた R を、利用者ごとに錠を取ったトランザクションで D2 の `purge_hidden_overlap` に渡す（規則を移行の SQL に書き写さない）。
起動時の処理は `deletion::purge_hidden_overlap_remedy(&pool) -> usize`（残った件数）1 つにまとめ、失敗を飲み込んで `warn`（`kind = "purge_remedy"`・残った件数・SQLSTATE だけ）を出すところまで持たせる。
`run()` はそれを `purged_without_span` のログの隣・待ち受けの前で 1 回呼ぶだけ（`?` で伝えない）。各トランザクションに `lock_timeout`（5 秒）を掛ける。
本文を消した R は `raw = ''` になって対象から外れるので、何度走っても行は増えない。

**なぜこの 4 つで「P の時点で一覧に出ていて、P の後に隠れた」と言えるか**（時刻を比べない。deep.md Q5 の帰結のとおり。spec review R2〜R4）:

| R の来歴 | どの条件で | 向き |
|---|---|---|
| P の時点で一覧に出ていて、P の後に作り直しで吸収された（Q8 の L）| 1〜4 を満たす | 消す（対象） |
| P の時点で作り直しの印で隠れていて、P と重なっていた | ST23 の本文ごと消す範囲（ST23 D2 の 3）がすでに `user:purged` にしているので 1 で外れる | 来ない |
| P の時点で作り直しの印で隠れていて、端が触れるだけ | 2 で外れる。隠れたまま書き換わっても、P の後の本文は生きた位置だけから作る —— P の時間帯の位置には後着の印が付いて読まれない（`mark_late_arrivals`）ので、書き換わった後の時間は P と重ならない | 残す |
| P の後に作り直しが初めから隠して作った | 4 で外れる（同じ理由で 2 でもふつう外れる） | 残す |
| P の時点で本人が消していて（B）、P の後に戻され、作り直しで吸収された | 3 で外れる | 残す（B の本文を消すのは本人が「本文ごと消す」を押したときだけ。Q2） |
| P の時点で一覧に出ていて、P の後に作り直しが引き継いで隠し（`rebuild:erased-range`）、書き換わった | 書き換わった後のいまの時間は P と重ならないので 2 で外れる | **残す**（P の座標は前の版に残る。下の Risks） |
| P の前に本人が消して戻した L が、P の後に吸収された | 3 で外れる | 残す（同上） |

**（仮）の中身**: 3 と、最後の 2 行を残す側に倒すこと。どちらも失う側には倒れない（見つけ損ねた本文が残るだけ）。
反転条件: 残した行に P の座標が残ることが確認バッチで問題になったら、前の版の時間が P と重なることも 2 に足す —— そのときは「P の前から隠れていた端の滞在は入れない」（Q5）を崩さないよう、
前の版を積んだのが P の後であることを見分ける列（`core.event_version` の `txid`）を移行で足してから行う。

### D6（仮）. 1 日の並びの入れ子の項目（Q7・C5）

`DayEntry` に `nested: Option<Vec<NestedEntry>>`（本文ごと消した区間だけ。空なら出さない）を足す。`NestedEntry` は `start`・`end`・`stay_ids`・`purged: bool`。既存の項目は変えない。

`day_view` の中で:

1. **本文を消していない B**: いまの「消した」の断片（`subtract_spans` の前の、その日の中に切った B の時間）から本文ごと消した区間を差し引いて**空になる**もの。
   いまはここで捨てている断片を、親の区間に添える
2. **本文ごと消した B**: 本文を消した滞在で、その日の中に切った時間が、**ほかの**本文ごと消した区間の和に覆われるもの。互いに覆う（時間が同じ）ときは、
   先に本文ごと消した方（操作の `txid` の小さい方。本文ごと消す口は最初の書き込みの前に利用者の錠を取るので、`txid` の順が消した順）を親、後の方を入れ子にする（spec に写した）。入れ子にした B は区間を作らず（`purged_spans` にも入れない）、その操作の後からの件数を親の区間の件数に足す
3. **親の選び方**: B と重なりのいちばん大きい本文ごと消した区間 → 始まりの早い区間（D3 と同じ）
4. 親ごとに、入れ子の項目を始まりの順に並べ、時間が重なるか隣り合う（いまの「消した」の行のまとめ方と同じ）本文を消していない B どうしを 1 つにまとめて識別子をすべて持たせる（spec に写した）。
   本文ごと消した B はまとめない（戻す口が無く、行ごとに「本文ごと消した」を出す）

1 は日ごとに判定する: 日をまたぐ B は、空になる日では入れ子の項目、残る日では「消した」の断片（「戻す」が出て、口が D4 で断ることがある）。

**（仮）の中身**: 2 の時間が同じときの親の決め方と、4 で本文ごと消した B をまとめないこと（どちらも spec の Scenario で固定した）。反転条件: 本人が確認バッチで「本文ごと消した入れ子もまとめたい」と返したら、4 で同じ扱いにする。

### D7（仮）. 確認の口の「一覧に出ている重なる滞在」（Q4）

`PurgeScope` と確認の口の応答に `visible_overlaps: u32` を足す。数えるのは、`s01-stay`・`origin = 'derived'`・`deleted_at IS NULL` で、指定した滞在の時間（範囲の行があればそこ。いまの `range` と同じ）と重なる（端が触れるだけは含めない）行。
`counts`・消す口の `expected` の比べ・範囲（D2 の和集合）は変えない。消す口は `visible_overlaps` を比べない（一覧に出ている L は消さないので、確認の後に増えても失うものが無い。spec に写した）。

**（仮）の中身**: 消す口で比べないこと。反転条件: 確認を見てから消すまでに L が増えたことを本人に知らせたい、と確認バッチで返ったら、`counts_changed` と同じく比べて出し直す。

### D8（仮）. 画面の形と文面（Q2・Q3・Q4・C5）

文字列は `web/src/messages.ts` に置く（いまの `purgedLate` の隣）。

| 所 | 形 |
|---|---|
| 入れ子の行 | 「本文ごと消した」の行のすぐ下に、左に 1 段の字下げ。見出しは「消した 10:15 – 10:45」（本文ごと消した後は「本文ごと消した 10:15 – 10:45」）。行の高さと文字は「消した」の行と同じ |
| 入れ子の行の口 | 「本文ごと消す」だけ（44×44 px 以上）。添える文「本文ごと消した時間の中なので戻せません」。本文ごと消した後は口も文も出さない |
| 確認 | 「消した」の行と同じ確認（ST23 D16）。対象は入れ子の項目の `stay_ids` の先頭（いまの「消した」の行と同じ。Non-Goals） |
| 戻す口の 409 `not_restorable` | その行の下に「戻しても一覧に戻らないため、戻せません」。行は「消した」のまま、「戻す」も残す |
