## Why

**Chrome 系のブラウザは、90 日を過ぎた閲覧履歴を手元の DB から削除する**（Chromium の
`history_backend.h`: `kExpireDaysThreshold = 90`「is considered "old" and is deleted」。2026-09-15 確認）。
放置した日数ぶん、閲覧した URL は永久に遡れなくなる。

ST07 のウィンドウの記録は「その瞬間どれを前景に置いていたか」を残すが、**「いつ訪問したか」は残さない** ——
背景のタブで開いたページ・訪問の正確な時刻・遷移の種類（入力した / リンク / 再読み込み）・どこから来たかは、
ブラウザの履歴 DB にしか無い。成功条件 2 の QS-7 / QS-10（いちばん時間を使ったサイト / 関心の移り変わり）が
直接これに乗る。

いま作れる理由: 先行の ST01 と、同じ capability を作った ST07 がどちらも archive 済みで、
`desktop-collection` の正典（`openspec/specs/desktop-collection/spec.md`）に `MODIFIED` を書ける。

## What Changes

深掘りは **1 巡・3 問（すべて A）**。本人が 3 問すべてを選択肢から明示的に選んだ（未回答 0 件・推奨のまま 0 件）。
渡す前の独立レビュー（`deep-review`）は **10 件** —— 問いを 2 問 → 3 問にした（Q3 を新設、Q2 を絞った）。
**レビューが前提の誤りを 1 件見つけた**: 「訪問の番号は再利用されない」は事実と違い、全期間の削除で表が作り直され
番号が 1 から振り直される（R2）。これで「読み直したときの見分け方」を design から問いへ上げた。

- **C-02 が 24 時間ごとに、PC で見つかったブラウザ（Chromium 系 5 つと Firefox）の全プロファイルから履歴を取る**（FR-13）
- **訪問 1 件ごとに 1 件**。訪問時刻は**マイクロ秒**で持ち、ブラウザ・プロファイル・遷移の種類・どこから来たか・滞在時間・
  同期で入った訪問の発生元の印を載せる
- **訪問ごとの識別子で同じ訪問を見分ける**。題名や滞在時間が後から書き換わっていたら**更新して前の版を残す**（FR-22 の経路に乗る）。
  そのため**登録簿の `c02-browser-history` を「記録ごとの識別子がある」に変える**（移行 1 本。このソースの行が 0 件のときだけ当てる）
- **一度取った訪問が次の取得で消えていたら、「消えた」事実を記録として残す**（ashiato からは消さない）。経路の手がかりを載せ、判定はしない
- **除外（FR-83）を履歴にも効かせる**。登録の形に**URL の部分一致**と**ブラウザ + プロファイル**を足す（URL の部分一致はウィンドウの記録にも効く）
- **履歴のソースにも生存信号を送る**（想定間隔 24 時間）。見つかった対象の 1 つでも読めなければ「取得できない」

**BREAKING は無い。** 取り込み口・エンベロープ・受け口の形は変えない。
C-02 が送る本文に `external_id` と `source_updated_at` が載るのは**履歴のソースだけ**で、ウィンドウの記録の形は 1 文字も変えない。

成果物の独立レビュー（`spec-review`）は **20 件**。うち 2 件は識別子の形で本人に返した（**第 2 回 Q4 / Q5。本人が 2 問とも推奨を明示的に選んだ**）。
残りは第 1 回の答えのとおりに spec / design / tasks を直した（Scenario は 49 本 → 75 本。ST08 で足したものは 62 本）。
