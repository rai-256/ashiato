## ADDED Requirements

### Requirement: YouTube のファイルの項目は、視聴・検索・その他に 1 件ずつ分かれる

THE SYSTEM SHALL マイアクティビティの形のファイルのうち、**項目の最初の製品の名前がどれも「YouTube」のもの**を YouTube のファイルとして読む。製品の名前を持つ項目が 1 件も無く、URL で YouTube の視聴・検索と見分けた製品側の履歴のファイルも YouTube のファイルとして読む。
THE SYSTEM SHALL 項目の最初の製品の名前に「YouTube」とそれ以外が混ざるファイルを、マイアクティビティとして製品ごとの論理ソースに入れる（YouTube の項目は `c03-myactivity-youtube`）。
THE SYSTEM SHALL YouTube のファイルではないマイアクティビティの項目を、YouTube の動画の URL を持っていても YouTube の視聴・検索の論理ソースに入れない。
THE SYSTEM SHALL YouTube のファイルの項目の行き先を、**1 件ずつ次の順で最初に当たったもの**で決める ——
(1) `details` の欄を持つ（広告）→ その他 /
(2) `watch?v=` の URL を持ち、題名が、**そのファイルで当たった言語の**評価の決まり文句（日本語・英語の表）に当たる → その他 /
(3) `watch?v=` の URL を持つ → 視聴（`c03-youtube-watch`）/
(4) `results?search_query=` の URL を持つ → 検索（`c03-youtube-search`）/
(5) それ以外（URL を持たない項目を含む）→ その他。
THE SYSTEM SHALL その他を、他の製品のマイアクティビティと同じ名付けの `c03-myactivity-youtube`（見出し「マイアクティビティ: YouTube」）に入れ、行為の種類で論理ソースを分けない（行為は原文に残る）。
THE SYSTEM SHALL 広告を `details` の欄の**有無**で見分け、欄の値（訳される。空の配列も含む）を見ない。
THE SYSTEM SHALL マイアクティビティ経由のファイルと製品側の履歴（`watch-history.json` / `search-history.json`）に**同じ規則**を当て、経路を見分けない。
THE SYSTEM SHALL `c03-myactivity-youtube` を、登録簿に想定間隔 60 日・外部サービス上の識別子の粒度「無し」で、印を置く前から登録しておく。

導出元: FR-14, FR-16, FR-17。ST47 の深掘り Q1・Q2・Q3・Q4・Q6（本人の決定）/ C2 / C5。
**論理ソースは内容の鍵の入力で、格納した時点で凍結される**（FR-17 ★）。行き先の規則が外れた行は後から分け直せないので、見分けられないものは視聴にも検索にも入れず、その他へ寄せる。
2 経路の両方を書き出すと、原文が違えば同じ視聴が同じソースの中に 2 行になる（同じソースの中の内容の鍵。畳むのは読む側）。ST12 の design D3（2 経路とも別々のソースに入れる）を Q1 で覆した。

## MODIFIED Requirements

### Requirement: Takeout の書庫の中身は、形の確認の印を置くまで格納しない

THE SYSTEM SHALL Takeout の書庫の中身（YouTube の視聴履歴・検索履歴・マイアクティビティ・Chrome の履歴）を、**利用者が形の確認の印を置くまで記録として格納しない**。
THE SYSTEM SHALL 確認を待っている書庫を台帳に「形の確認待ち」として残し、その書庫の読んだ製品のファイルの**写しを、写しの設定に関わらず作る**。
THE SYSTEM SHALL 形の確認のために、書庫の中のファイルの種類・最上位の鍵・項目の欄の名前・件数・製品の名前の種類だけを出す手段を用意し、**記録の値（題名・URL・検索語・座標）を出さない**。
THE SYSTEM SHALL YouTube のファイルについては、形の確認の出力に**行き先ごとの件数**（視聴・検索・その他と、その他のうち広告・評価）と、**決まり文句の表（評価・視聴・検索）が当たった言語**も出す（★ ST47 C3 / Q4）。製品の名前に「YouTube」を含むマイアクティビティの形には、YouTube の項目のうち視聴・検索に入らずにその他へ入る件数を出す（★ ST47 D2）。
WHEN 利用者が形の確認の印を置く THE SYSTEM SHALL 確認を待っていた書庫を写しから読み直して格納する。
THE SYSTEM SHALL 形を、**論理ソースの名前を決めるもの**（ファイルをどの中身と見分けたか・マイアクティビティの各項目の最初の製品の名前・**YouTube のファイルなら項目の最初の製品の名前と、決まり文句の表（評価・視聴・検索）が当たった言語**）だけで比べ、項目の欄の名前・書庫の中のパスの名前・2 つ目以降の製品の名前・**行き先ごとの件数**の違いでは確認待ちにしない（★ ST47 Q4 / Q6）。
WHEN YouTube のファイルの題名に、決まり文句の表（評価・視聴・検索）が 1 件も当たらない THE SYSTEM SHALL そのファイルを確認待ちにし、**その形には印を置かせない**（表に言語を足して解析器の版を上げるまで入らない。★ ST47 Q4 / D6）。
THE SYSTEM SHALL YouTube のファイルの見分け方を変える前の形（YouTube の視聴・検索を URL だけで見分け、製品の名前を形に持たなかったもの）に置いた印を、YouTube のファイルに効かせない（★ ST47 C6）。
THE SYSTEM SHALL YouTube のファイルではない種類の形の比べ方を変えず、それらに置いた印を効いたままにする（★ ST47）。
WHEN 解析器の版が上がる THE SYSTEM SHALL 確認待ちのファイルの形を写しから取り直し、確認待ちの一覧には新しい版の形だけを出し、**取り直した形に印が無ければ、旧い版の形に置いた印では格納しない**（★ ST47 C4 / C6）。
WHEN 解析器の版が上がって読み終えた書庫を読み直す THE SYSTEM SHALL その書庫のうち、新しい版の形に印の無いファイルを黙って飛ばさず、確認待ちにする（★ ST47 C4）。
WHEN 後から置かれた書庫のファイルに、**印を置いたときに無かった中身、または印を置いた形に無い製品の名前**がある THE SYSTEM SHALL そのファイルだけをまた確認待ちにし、同じ書庫の他のファイルは格納する（★ 第 3 回 Q12 で本人に確かめている。design D16）。
THE SYSTEM SHALL 確認待ちの書庫について、1 回の読みに台帳の行を 1 つだけ足し、置き場に残り続けても走査のたびに行を足さない。
WHEN 印を置く THE SYSTEM SHALL 確認待ちだった書庫を、同じ中身・同じ解析器の版でも読み直し、台帳に読み直した行を 1 つ足す。
THE SYSTEM SHALL 端末から書き出したタイムラインと移行前のロケーション履歴を、確認を待たずに格納する。

導出元: FR-14, FR-22, FR-23。深掘り 第 2 回 Q10（本人の決定）/ spec R12 / deep-r2 R5 / R6。ST47 の深掘り Q4 / Q6 / C3 / C6。
**書庫の中身を振り分ける論理ソースは、格納した時点で書き換えられない。** 振り分けの規則が本物の書庫で外れていたと分かっても、既に入った行は直せない。
写しを設定に関わらず作るのは、写しを残さない設定のとき確認待ちの書庫が読み直せなくなるのを防ぐため。
YouTube の製品の名前（「YouTube」）は書き出しの言語で訳されないので、製品の名前だけでは言語の変化に気づけない。決まり文句は訳されるので、表の当たった言語を形に持たせ、言語が変わったら印を置き直すまで入れない（表の外の言語で評価が視聴に凍結されるのを防ぐ）。

- **THEN** そのファイルは確認待ちになり、視聴の論理ソースに記録が増えない

#### Scenario: YouTube 以外の形に置いた印は効いたままになる

- **WHEN** ST12 の版の形のバイト列 `{"kind":"MyActivity","products":["検索"]}` と `{"kind":"ChromeHistory","products":[]}` の sha256 を直に入れた印だけがある状態で、製品「検索」のマイアクティビティと Chrome の履歴を含む書庫を置く
- **THEN** その 2 つのファイルは確認待ちにならずに格納される

#### Scenario: 解析器の版が上がると確認待ちのファイルは新しい形で一覧に出る

- **WHEN** 旧い版で YouTube のマイアクティビティが形 `{"kind":"YouTubeWatch","products":[]}` の確認待ちになっている状態で、解析器の版を上げて走査が来る
- **THEN** 形の確認の一覧に、そのファイルが製品の名前「YouTube」と言語を持つ新しい形で出て、旧い形は出ない

#### Scenario: 評価を持たない日本語の YouTube のファイルは日本語の形の印で格納される

- **WHEN** 当たった言語 `ja` の YouTube のマイアクティビティの形に印を置いた後に、評価の項目を 1 件も持たず、題名が「を視聴しました」「を検索しました」で終わる項目だけの YouTube のマイアクティビティを含む書庫を置く
- **THEN** そのファイルは確認待ちにならずに格納される

#### Scenario: 行き先ごとの件数が変わっただけでは YouTube のファイルは確認待ちにならない

- **WHEN** YouTube のマイアクティビティの形に印を置いた後に、製品の名前と当たった言語が同じで、視聴・検索・その他の件数だけが違う YouTube のマイアクティビティを含む書庫を置く
- **THEN** そのファイルは確認待ちにならずに格納される

#### Scenario: 決まり文句の当たらない YouTube の形には印を置けない

- **WHEN** 題名がどれも表の言語の決まり文句に当たらない YouTube のファイルが確認待ちの状態で、その形に `tools/archive-shape.sh --confirm` で印を置こうとする
- **THEN** 道具は 0 以外で終わって理由を出し、印の表に行が増えず、そのファイルは確認待ちのままである

#### Scenario: 旧い形の印があっても確認待ちの YouTube のファイルは版の上げの後に新しい形の印を待つ

- **WHEN** 旧い版の確認待ちの行（形 `{"kind":"YouTubeWatch","products":[]}`）と、その形に置いた印がある状態で、解析器の版を上げて走査が来る
- **THEN** 視聴・検索・その他のどの論理ソースにも記録が増えず、そのファイルは新しい形で確認待ちの一覧に出る

#### Scenario: 読み終えた書庫の新しい形に印の無いファイルは版の上げで確認待ちになる

- **WHEN** 旧い版で YouTube のマイアクティビティが旧い形の印で読み終えられた書庫がある状態で、解析器の版を上げて走査が来る
- **THEN** その YouTube のファイルは新しい形で確認待ちの一覧に出て、新しい形に印を置くまで視聴・検索・その他の記録が増えない

#### Scenario: 版の上げの後に印を置いて読み直した台帳の行は元の書庫の名前と作られた時刻を持つ

- **WHEN** 旧い版で名前の時刻を持つ書庫が確認待ちになって取り込み済みへ移った後に、解析器の版を上げ、新しい形に印を置いて読み直す
- **THEN** 台帳のその書庫の読み直した行は、元の読みと同じ書庫の名前と作られた時刻を持つ

#### Scenario: YouTube の項目を含むマイアクティビティの形の出力にその他へ入る件数が出る

- **WHEN** 最初の製品が「YouTube」の項目 2 件と「検索」の項目 1 件が混ざったマイアクティビティを含む書庫の形を出す
- **THEN** 出力に、YouTube の項目 2 件がその他へ入る件数が出る
