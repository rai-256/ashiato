## Context

動機は `proposal.md` の Why。いまのコードの形（深掘りの手順 5 で読んだもの。`deep.md`）:

- `crates/server/src/archive/classify.rs` の `kind_of` は、配列のファイルの種類を「`titleUrl` を持つ最初の項目」の URL で決める。`watch?v=` なら `YouTubeWatch`、`results?search_query=` なら `YouTubeSearch`、
  どちらでもなければ `products` / `header` / `time` を持つかで `MyActivity`。YouTube のマイアクティビティ（`マイ アクティビティ/YouTube/マイアクティビティ.json`）は丸ごと `YouTubeWatch` になる
- `archive/worker.rs` の `takeout_items` は、`YouTubeWatch` / `YouTubeSearch` のファイルの項目を URL で視聴・検索に分け、どちらでもない項目（広告・投票・URL の無い項目）は**見分けた種類の側**へ落とす
- `worker.rs` の `shape_for_file` は `products` を `MyActivity` のときだけ形に入れ、`hash_shape` は `{"kind", "products"}` だけをハッシュにする。YouTube の形は `{"kind":"YouTubeWatch","products":[]}`（`f3e578ff…`）
- 位置の印付け（`stay_store.rs`）は、登録簿の `c03-myactivity-*` と固定名の `archive::ITEM_SOURCES` を、原文の `locationInfos` の有無で見る（ST12 D22-d）
- 本物の書庫の件数（形だけ。`deep.md`）: 全 118,895 / `watch?v=` 109,334（広告 19,770 のうち URL を持つもの・評価 196 を含む）/ `results?search_query=` 5,643 / URL の無い項目 303（うち「〜を視聴しました」98 件は全部が広告）/ 位置の欄 0

## Goals / Non-Goals

**Goals**: YouTube の項目を本人の決めた規則（Q1〜Q4・Q6）で 1 件ずつ振り分ける。形の確認が、YouTube の言語と製品の名前の変化に気づく。YouTube 以外の形の印・論理ソース・行を変えない。

**Non-Goals**:
- 2 経路（マイアクティビティと製品側）で同じ視聴が 2 行になったときに畳むこと（読む側。ST25 の後）
- 既に `c03-youtube-watch` に入った行を分け直すこと（凍結。作業用の DB にだけありうる。Risks）
- 他の製品のマイアクティビティの行為を分けること（ST12 のまま、製品ごとに 1 本）
- 画面の変更（書庫のソースの格子に `c03-myactivity-youtube` の行が 1 本増えるだけ。並び・高さの規則は ST12 のまま）

## D1. YouTube のファイルは製品の名前で見分け、種類を 1 つにする（Q6 / Q1。本人の決定）

- `KnownKind::YouTubeWatch` / `YouTubeSearch` を **`KnownKind::YouTube` の 1 つ**にする。視聴か検索かはファイルではなく項目で決まる（D3）ので、ファイルの種類に持たせない
- 配列のファイルの見分けは次の順:
  1. `products` を持つ項目があり、**その最初の製品の名前の集合がちょうど `{"YouTube"}`** → `YouTube`
  2. `products` を持つ項目があり、`header` / `time` / `products` を持つ項目がある → `MyActivity`（並びに依らない。`docs/handoff/ST13.md` の `st12-archive-ingestion R28` と同じ所。D2）
  3. `products` を持つ項目が 1 件も無く、`titleUrl` が `watch?v=` か `results?search_query=` の項目がある → `YouTube`（製品側の履歴の古い形。D2）
  4. それ以外 → 読まない
- 「YouTube」の文字列は訳されない（本物の書庫で YouTube のファイルの 118,895 件がすべて `YouTube`、他の製品のファイルには 0 件）。比べ方は完全一致
- 製品側の `watch-history.json` / `search-history.json` も同じ `YouTube` の種類（Q1: 経路を見分けない）。ファイル名・フォルダ名は見ない（訳される。ST12 D3）

代わりに考えたもの: 種類を `YouTubeMyActivity` と製品側の 2 つに分ける —— Q1 で経路を見分けないと決めたので要らない。分けると形の印も 2 回置くことになる。

## D2（仮）. 製品が混ざったファイルと、製品の名前を持たないファイル

- **製品が混ざったファイル**（最初の製品が「YouTube」の項目と、それ以外の項目が同じファイルにある）は `MyActivity` として読み、項目ごとに製品の名前で論理ソースを決める（ST12 D2）。
  YouTube の項目は `c03-myactivity-youtube`（その他）に入り、視聴・検索には入らない。**見分けがつかないものは凍結の害が小さい側（その他）へ寄せる**（扉を開けたままにする既定の「既定は厳しい側」）。
  本物の書庫には混ざったファイルが無い。混ざったファイルの形は `products` の集合が YouTube だけのものと違うので必ず確認待ちになり、**その形の一覧には YouTube の項目のうちその他へ入る件数を出す**（D7。本人は視聴がその他へ入ることを見てから印を置く。spec R9）
- **製品の名前を持たないファイル**（D1 の 3）は、ST12 の合成の材料と製品側の古い形のため。`products` が無いので形の製品の名前は `[]` になり、`["YouTube"]` の形とは別に印を置く（D5）
- 反転条件: 本物の書庫に混ざったファイルが出て、その YouTube の項目を視聴・検索に入れたいと本人が言ったとき（そのときは混ざったファイルの YouTube の項目だけに D3 を当てる）。
  製品の名前を持たない YouTube の履歴が本物に無いと分かったとき（3 の枝を消し、材料に `products` を足す）

## D3. 項目の行き先の規則と、行き先ごとの payload（Q1〜Q4。本人の決定 / C5）

`YouTube` のファイルの項目ごとに、spec の順（(1) `details` → (2) 評価の決まり文句 → (3) `watch?v=` → (4) `results?search_query=` → (5) その他）で最初に当たったもので決める。

| 行き先 | 論理ソース | payload の欄（ST12 D6 の全記録の欄に足すもの） |
|---|---|---|
| 視聴 | `c03-youtube-watch` | `title` / `url` / `channel_name` / `channel_url`（ST12 と同じ） |
| 検索 | `c03-youtube-search` | `title` / `url` / `query`（ST12 と同じ） |
| その他 | `c03-myactivity-youtube`（`myactivity::source_name("YouTube")` と同じ名前） | `product` / `title` / `url` / `details`（ST12 のマイアクティビティと同じ） |

- 広告は `details` の欄が**あるか**だけを見る（値「Google 広告から」は訳される。Q3）。`details` が空の配列でも欄があれば広告に数える（本物では `details` を持つ項目は全部が広告だった）
- URL の無い項目は、題名が「〜を視聴しました」でもその他（C5。本物では URL の無い「視聴」は全部が広告で、広告は (1) で先に分かれる。削除された動画として視聴へ入れる規則は、合成の材料にしか根拠が無かった）
- payload は原文から作り直せる（内容の鍵は論理ソース・時刻・原文）。欄の過不足は解析器の版で直せる
- **ST12 D3 の「2 経路とも別々のソースに入れる」を覆す**（Q1）。2 経路の同じ視聴は同じ `c03-youtube-watch` に入り、原文が同じなら 1 行、違えば 2 行

## D4（仮）. 評価と言語の決まり文句の表

`archive/youtube.rs` に表を 1 つ置く。題名の比べ方は決まり文句の組ごとに決まる —— 日本語の評価は**先頭**・視聴と検索は**末尾**、英語はどれも**先頭**の一致（決まり文句は題名の頭か尾に固定で付くので、題名の動画名に決まり文句が含まれても当たらない）。日本語の評価が先頭なのは本物の書庫で確かめた形（deep.md 第 2 回 Q9 の前提の訂正。先頭が `高く評価しました ` 190 件・`低く評価しました ` 6 件。末尾の `を高く評価しました` はコミュニティ投稿の 1 件だけで、評価に数えない）。

| 言語 | 評価（視聴から外す） | 言語の見分けだけに使う |
|---|---|---|
| `ja` | 先頭が `高く評価しました ` / `低く評価しました `（後ろに空白） | 末尾が `を視聴しました` / `を検索しました` |
| `en` | 先頭が `Liked ` / `Disliked ` | 先頭が `Watched ` / `Searched for ` |

- **当たった言語** = ファイルの中で、その言語の表のどれかに 1 件以上当たった言語の集合（並べて重複を除く）。**1 件の題名は、表の上から順（`ja` → `en`）に最初に当たった言語にだけ数える**（日本語の書き出しの「Liked by the Sea を視聴しました」を英語の当たりに数えない。spec R8。反転条件: 1 つの題名が複数の言語の表に正当に当たる言語が表に加わったとき。全部に数える形へ直し、解析器の版を上げる（D9））。視聴・検索の決まり文句も表に入れるのは、評価が 1 件も無いファイルでも言語が分かるようにするため
  （評価だけで見ると、評価の無い書き出しのたびに「表が当たらない」になって確認待ちに戻る）
- 評価の判定（D3 の (2)）は、**そのファイルで当たった言語の表だけ**で行う（言語をまたがない。日本語の書き出しで「Liked by the Sea を視聴しました」のような題名が英語の評価に当たらないように。spec R8）
- 反転条件: 本物の書庫で、評価の題名の形がこの表と違う（日本語の評価の頭の語が違う・英語の動詞が違う）とき。表を直し、解析器の版を上げる（D9）。
  確認バッチの realdata の確認（tasks）で、形の一覧の「評価」が 196 件前後、「視聴」が約 8.9 万件になることで確かめる。
  **英語の表は本物の書き出しで確かめていない**（本人の書庫は日本語の 1 冊）。英語の書き出しは `languages: ["en"]` の新しい形として必ず確認待ちになるので、本人は印を置く前に `destinations` の `rating` の件数を見られる（0 なら表が外れている合図。印を置かずに表を直す）
- 残る一方通行（本人が Q4 の選択肢で読んだもの）: 表の言語のうちで言い回しだけが変わると、その分は視聴に入ったまま凍結される

## D5. 形の同一性（Q4 / Q6 / C6。本人の決定）

- `shape_for_file` は `YouTube` の種類にも `products`（最初の製品の名前の集合）を入れ、`languages`（D4 の当たった言語の集合）を足す
- `hash_shape` の同一性:
  - `YouTube` の種類: `{"kind":"YouTube","products":[…],"languages":[…]}`
  - **それ以外の種類: いまと同じ `{"kind","products"}` を、いまと同じバイト列で**（`kind` の文字列 `MyActivity` / `ChromeHistory` なども変えない）。変えると、本人が印を置いた 26 種類の形がすべて確認待ちに戻る
- 旧い YouTube の形（`{"kind":"YouTubeWatch","products":[]}` = `f3e578ff…`）は、新しい同一性と必ず違うハッシュになるので、そこに置いた印は効かない（C6）。印の表は追記のみのまま、何も消さない（ST12 D16）
- 他の製品のファイルが YouTube の形と同じハッシュになる経路は無くなる（D1 で種類が製品の名前で決まり、`products` がハッシュに入る）

## D6. 言語の当たらない YouTube の形には印を置かせない（Q4 の帰結。既定は厳しい側）

- 当たった言語が `[]` の YouTube の形に `tools/archive-shape.sh --confirm` を当てると、道具は印を置かずに 0 以外で終わり、「決まり文句の表に当たる言語が無いので、評価を視聴から外せない」と出す
- 理由: 表に無い言語はどれも同じ `languages: []` のハッシュになるので、1 回印を置くと、後から来た別の言語のファイルもその印で通り、その言語の評価が視聴に凍結される（Q4 の「表が当たらない言語は確認待ちに戻す」を覆す。spec R1）
- 入れたいときは、表にその言語を足して解析器の版を上げる（D9 で確認待ちの形が取り直され、新しい言語の形に印を置ける）。本人のファイルは置き場・取り込み済みに残り、写しも残る（確認待ちの写しは設定に関わらず作る）ので、待っている間に失われるものは無い
- 決まり文句を持たない合成の材料（`tools/smoke.sh` の `watch-history.json`）には、日本語の決まり文句の題名を付ける（D10）

## D7. 形の一覧に行き先ごとの件数を出す（C3）

- `shape_for_file` の形に `destinations`（`watch` / `search` / `other` と、`other` のうち `ad` / `rating`）を足す。`YouTube` の種類のときと、`products` に「YouTube」を含む `MyActivity` の形（そのときは YouTube の項目の `other` の件数だけ。D2）
- `hash_shape` は `destinations` を見ない（件数は書き出しのたびに変わる。ST12 第 3 回 Q12 の「件数の変化では確認待ちにしない」）
- `tools/archive-shape.sh` の一覧は形の JSON をそのまま出しているので変えない。`--confirm` だけが D6 の断りを持つ。値（題名・URL・検索語）は出さない（ST12 の Scenario のまま）

## D8. その他のソースを移行で登録する（C2）

- 移行 1 本（名前は作成時刻 `YYYYMMDDHHMM_youtube_myactivity_source.sql` と `.down.sql`。`MIGRATIONS` の末尾）で、
  `core.source` に `('c03-myactivity-youtube', 'マイアクティビティ: YouTube', 5184000, 'none')` を `ON CONFLICT (logical_source) DO NOTHING` で足す（本人が変えた想定間隔を戻さない。ST12 の Requirement）
- 見出しの文字列は `worker::ensure_myactivity_source` が作るものと同じ。印を置く前から登録しておくのは、格子に「まだ無い」と出して、分けた行き先があることを本人が見られるようにするため
- down は、`c03-myactivity-youtube` の記録が 1 件も無いときだけ登録を消す（記録があれば残す。記録を消す down は書かない）

## D9. 解析器の版を上げ、確認待ちと読み終えた書庫の形を取り直す（C4 / C6）

`archive::PARSER_VERSION` を `"1"` → `"2"`。ST12 D8 の読み直しのほかに、いまのコードには版の上げで穴が 3 つある（spec R4〜R7）ので、ここで塞ぐ。

1. **確認待ちの形を取り直す**。`core.archive_pending_shape` は版の列を持たないので、**台帳の `pending_shape` の行の版**で見分ける —— 確認待ちの行を持つ書庫のうち、いまの版の `pending_shape` の行が無いものを、
   写し（`core.archive_file`）から読んで形を取り直し、`archive_pending_shape` の行の `shape_hash` / `shape` を新しい形に置き換える（`record_pending_file` の `ON CONFLICT` も `shape_hash` / `shape` を更新する）。
   取り直した書庫には、**いまの版の `pending_shape` の行を 1 つ足す**（1 回の読みに 1 行。元の読みの書庫の名前・作られた時刻・置き場の種類を写す。`ledger_meta` がいまの版でその行を引けるので、印を置いた後の `read` の行が名前と時刻を引き継ぐ。FR-16 / final review R58 の型）
2. **順序**: 走査の輪で、1 の取り直しを `ingest_confirmed_pending`（印のある確認待ちを読む）**より先**に回す。加えて `ingest_confirmed_pending` は、読む直前に**いまの形のハッシュ**で印を照らし、無ければ読まない（旧い形 `f3e578ff…` の印が新しい分類器の読みを通さない。C6）
3. **読み終えた書庫の読み直し**（`reparse_older_versions` → `reread_archive(..., true)`）で、新しい版の形に印の無いファイルを `continue` で黙って飛ばさず、`archive_pending_shape` に積んで確認待ちにする
   （ST12 の「印を置いた形に無いものはそのファイルだけ確認待ち」の規則を、読み直しにも当てる。**捨てるより確認待ちに入れる**）。旧い形の印で YouTube のファイルが既に入った書庫（Q5 の「覚えていない」の場合）では、
   本人が新しい形に印を置くと、検索・その他が新しい論理ソースに入り、`c03-youtube-watch` の旧い行は残る（凍結。Risks の 1 つ目）
- 読み終えた書庫の YouTube 以外のファイルは、同じ論理ソース・同じ原文なので内容の鍵で既存の行に当たり、行は増えない（spec `読み直しても YouTube 以外の論理ソースの行は増えない`）
- 移行は足さない（版は台帳の既存の列で見分ける。`archive_pending_shape` は書き換えてよい表）

## D10. 試験の材料を本物の形に合わせる（C5）

- `archive_tests.rs` の「URL を持たない＝削除された動画」の材料（`削除された動画を視聴しました` を視聴に入れる試験）を、本物の形（URL の無い項目はその他、広告は `details` を持つ）に書き直す
- `products` を持たない YouTube の合成の材料は、D1 の 3 の枝でそのまま読める。行き先を確かめる新しい試験の材料は `products: ["YouTube"]` と題名を持つ本物の形で書く
- `tools/smoke.sh` の形の一覧の照合（`grep -q 'YouTubeWatch'`）を、種類の欄を名指しする `grep -Eq '"kind": ?"YouTube"'` に変える（`YouTube` だけだと製品の名前にも当たる）。smoke の `watch-history.json` の項目には日本語の決まり文句の題名と `products: ["YouTube"]` を付ける（D6 で言語の当たらない形には印を置けない）

## D11. その他のソースも位置の印付けの対象（C1）

- `stay_store` の印付けは登録簿の `c03-myactivity-*` を対象にしている（ST12 D22-b / D22-d）。`c03-myactivity-youtube` は D8 で登録されるので、コードを足さずに対象に入る
- 判定は項目の `locationInfos` の有無のまま（ソースの名前では決めない）。いまの本物の書庫の位置の欄は 0 件
- `classify.rs` の見張り（`every_archive_logical_source_is_classified_as_location_or_item`）の材料を `KnownKind::YouTube` に合わせ、3 つの行き先をすべて通す

## Risks / Trade-offs

- **[確認バッチの DB に、旧い形で入った YouTube の行があるかもしれない]**（Q5。本人は覚えていない）→ その DB は確認バッチの作業用（`tools/stack.sh`）で、本人の運用の DB ではない。
  旧い形の印は D5 で効かなくなるので、この Story の後に入る行は新しい規則でしか入らない。確かめる手順（共有の資源を変えるので、本人か確認バッチの準備の段でやる）:
  docker volume `1dd5c7e5…`（更新 2026-10-12 23:31。確認バッチ 2 回目の日）を別の名前の volume に写して PostgreSQL を起こし、
  `select count(*) from core.archive_shape_confirmation where shape_hash like 'f3e578ff%';` を引く。1 以上なら、その DB の `c03-youtube-watch` には検索・広告・その他が混ざっている（作業用なので捨ててよい）。
  本人の運用の DB に同じ印が見つかったときだけ、扱いを深掘りで問う
- **[表の言語のうちで言い回しが変わる]** → その分の評価は視聴に凍結される（Q4 で本人が受け入れた残り）。確認の一覧の `rating` の件数が 0 に落ちることで気づける（D7）
- **[2 経路の両方を書き出す]** → 原文が違えば同じ視聴が `c03-youtube-watch` に 2 行（Q1 で本人が受け入れた）。いまの本人の書庫は製品側を含まない
- **[URL を持たない本物の視聴（削除された動画）が将来の書き出しに出る]** → その他に入る（視聴には凍結されない側）。原文は残るので読む側で拾える
- **[解析器の版の上げで、全部の書庫を読み直す]** → 読み直しの時間がかかる（本物の書庫で数分）。行は増えない（D9）

## Migration Plan

1. 移行を当てる（`c03-myactivity-youtube` が登録される）
2. サーバを入れ替える（解析器の版 2）。読み手が次の走査で、確認待ちの形を取り直し、覚えている書庫を読み直す。YouTube のファイルは、確認待ちだったものも読み終えていたものも、新しい形で確認待ちに積まれる（D9）
3. 本人が `tools/archive-shape.sh` で YouTube の形（`products: ["YouTube"]`・`languages: ["ja"]`・行き先ごとの件数）を見て `--confirm` で印を置く → 写しから読み直して格納

戻すとき: サーバを戻し、down の移行を当てる。印を置いた後に入った行は戻らない（凍結。論理ソースの規則そのものが一方通行）。
