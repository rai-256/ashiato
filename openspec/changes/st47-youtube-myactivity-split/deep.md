## 問うた項目

### Q1. 視聴と検索をどの論理ソースに入れるか（A / rewrite-all。R3）

- **本人の答え**: 同じソースに入れ、製品側にも同じ分け方を当てる（c03-youtube-watch / c03-youtube-search）
- **帰結**: マイアクティビティの YouTube も製品側の `watch-history.json` / `search-history.json` も、同じ `c03-youtube-watch` / `c03-youtube-search` に入る。Q2〜Q4 の分け方（広告・評価・その他）は**製品側のファイルにも同じく当てる**（製品側の読み方も変わる）。経路は見分けない
- **ST12 design D3 を覆す**（下の「当初案を覆したもの」）

### Q2. 視聴でも検索でもない項目の行き先（A / rewrite-all）

- **本人の答え**: 他の製品と同じ規則で c03-myactivity-youtube に入れる
- **帰結**: 視聴でも検索でもない項目（コミュニティ投稿の表示・投票・回答・チャンネルの登録・評価など）は `c03-myactivity-youtube`。行為の種類はソースに分けず、原文に残す。格子の見出しは「マイアクティビティ: YouTube」
- Q1 により、製品側のファイルの「その他」も同じ所へ入る

### Q3. 広告の視聴（約 2 万件）を視聴に数えるか（A / rewrite-all）

- **本人の答え**: 視聴から外し、Q2 の「その他」に入れる
- **帰結**: `details` を持つ項目（広告。この書庫で 19,770 件、URL の無い 98 件を含む）は `c03-myactivity-youtube`。**この判定を Q4 より先に当てる**（広告なら URL や決まり文句に関係なく「その他」へ）
- 見分けは `details` の欄の**有無**で行い、値（「Google 広告から」。訳される）は見ない

### Q4. 評価を視聴から外すか —— 題名の決まり文句を見るか（A / rewrite-all。R4）

- **本人の答え**: 決まり文句の表（日本語・英語）で評価を外し、表が 1 件も当たらない言語のファイルは確認待ちに戻す
- **帰結**: `watch?v=` の URL を持つ項目のうち、題名が評価の決まり文句（日本語・英語の表）に当たるものは視聴から外し、`c03-myactivity-youtube` へ（Q2）
- 形の確認のハッシュに「表が当たった言語」を入れる。表が 1 件も当たらないファイルは形が変わり、印を置き直すまで確認待ちに戻る（ST12 第 3 回 Q12 と同じ向き）
- 残る一方通行（本人が選択肢の `irreversible` で読んだもの）: 表の言語のうちで言い回しだけが変わると、その分は視聴に入ったまま凍結される

### Q5. YouTube の形にもう印を置いたか（A / premise。R6）

- **本人の答え**: 覚えていない
- **前提の扱い**: 本人の選んだ選択肢は「確認バッチの DB を起こして `core.archive_shape_confirmation` を引いて確かめる」。記録の段で試した結果:
  - いま動いている `ashiato2-db-1` は 2026-10-13 01:53 に作り直された別の DB（印は 0 件）で、確認バッチの DB ではない
  - 使われていない docker volume を読むだけで探すと、更新が 2026-10-12 23:31 の volume（`1dd5c7e5…`。確認バッチ 2 回目の日）の中に、旧い形のハッシュ `f3e578ff…` の文字列が**ある**。ただし文字列が印の表（`archive_shape_confirmation`）にあるのか、確認待ちの表（`archive_pending_shape`）にあるのかは区別できていない
  - その volume を写して DB として起こす操作は、この段の権限（共有の資源を変えない）で止められた。**確かめきれていない**
- **答えに依らず決まること**（C6 に写す）: Q6 で YouTube の形のハッシュが変わるので、旧い形に置いた印があっても、この Story の後の書庫は新しい形として確認待ちに戻る（旧い印は効かない）。残るのは「確認バッチの DB に、既に `c03-youtube-watch` へ入った行があるかもしれない」ことだけで、その DB は確認バッチの作業用（`tools/stack.sh`。本人の運用の DB ではない）
- spec の段は、確認バッチの DB の印の有無を確かめる手順（volume `1dd5c7e5…` を写して起こし、`select count(*) from core.archive_shape_confirmation where shape_hash = 'f3e578ff…'`）を tasks か design の Risks に残す。印があったときに作業用の DB の行をどうするかは、本人の運用の DB に印が無い限り問わない

### Q6. YouTube のファイルかどうかの見分け方（A / rewrite-all。R1）

- **本人の答え**: 製品の名前で決め、形のハッシュにも製品の名前を入れる
- **帰結**: マイアクティビティのファイルが YouTube かどうかは、項目の `products` の「YouTube」で決める（URL を持つ最初の項目では決めない）。YouTube の種類の形のハッシュにも製品の名前を入れる
- 副作用: 形のハッシュが変わるので、旧い形（`{"kind":"YouTubeWatch","products":[]}` = `f3e578ff…`）に置かれた印は新しい形に効かない（Q5 の前提の扱いに効く）

  2 経路とも `c03-youtube-watch` / `c03-youtube-search`（とその他は `c03-myactivity-youtube`）に、同じ分け方で入れる。
  2 経路を両方書き出すと、原文が違えば同じ視聴が 2 行になる（同じソースの中の内容の鍵。読む側で畳む —— ST25）
- **ST12 の製品側の読み方**（視聴でも検索でもない項目と広告を視聴に入れる）を Q1・Q3 で覆した。製品側にも Q2〜Q4 の分け方を当てる
- **ST12 の種類の見分け**（URL を持つ最初の項目でファイル全体の種類を決める）を Q6 で覆した。製品の名前で決める
