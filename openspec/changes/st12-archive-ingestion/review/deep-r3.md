## R1. Q12 は「知らない製品の名前が出たら」と問うが、design の判定は形のハッシュの完全一致で、名前が変わらない場合も確認待ちになる
- 成果物: openspec/changes/st12-archive-ingestion/deep-questions-r3.json（Q12 の context と 1 つ目の選択肢の detail）
- 根拠: design.md:93 / tasks.md:104（論理ソースの名前は `products[0]` だけから作る）/ design.md:329、tasks.md:138（形は「`products` の値の**集合**」）/ design.md:332-334（印は形のハッシュに置き、「印を置いた形の集合に無い形」を確認待ち）/ spec.md:153（「印を置いた形に無い製品の名前**がある**」= 含まれるかの判定）。
  design のとおりに作ると、(a) 既に確かめた製品のファイルの項目に 2 つ目以降の `products` の値が 1 つ増えただけ（名前は変わらない）、(b) 値が 1 つ減っただけ（古い項目が消えた書庫）でもハッシュが変わり、そのファイルは確認待ちになる。
  Q12 の context「比べるのは振り分けを決めるものだけ（…マイアクティビティの製品の名前）」と選択肢 1 の detail「**新しい製品が出た回だけ**」は、spec の読みでは正しいが design / tasks の読みでは頻度を少なく見せている。本人が手作業の頻度を読んで選ぶ問いなので、前提の違いが答えに効く
- kind: premise
- 提案: 判定の式は計算し直せば戻る（確認待ちにするかの引き金で、格納されるものは変わらない）ので C/B として先に揃える —— 「`products[0]` の値のうち、印を置いた値の集合に**含まれない**ものがあるときだけ」に design D16 / tasks 7b.1 を合わせ、Q12 の context に「名前を作る `products[0]` の値だけ、含まれるかで比べる」と 1 行足す
- 処置: fixed D16 — design D16 の形を「各項目の products[0] から作る名前の集合」にし、比べ方を「印を置いた名前・種類に無いものが含まれるか」に揃えた。spec の SHALL を同じ言い方に直し、Q12 の context に 1 行足した

## R2. 印の後に初めて出る「見分けた種類」（例: 最初の書庫に無かった Chrome の履歴、後から来た `-002.zip`）も確認待ちになるのに、Q12 は製品の名前だけを問う
- 成果物: openspec/changes/st12-archive-ingestion/deep-questions-r3.json（Q12 の範囲）
- 根拠: design.md:329（形は `(見分けた種類, マイアクティビティなら products の値の集合)`。種類だけでも形になる）/ design.md:332-333（印を置いた形の集合に無い形は確認待ち）/ spec.md:152（見分けた中身は比べるものに入る）/ spec.md:153 は「製品の名前」の場合だけを書く / spec.md:69-72（分割書庫は 1 本ずつ読まれる）。
  最初の Takeout に YouTube の視聴履歴しか無く、後の書庫で Chrome の履歴やマイアクティビティが初めて出る（書き出しの対象を足した・`-002.zip` だけ後から来た）と、design ではそのファイルが確認待ちになる。これも「最初に 1 回」を越える読み取りで、spec-r2 R4 と同じ型。
  待たずに入れる側は、第 2 回 Q10 の (2)（マイアクティビティの中の YouTube の項目が `c03-youtube-watch` に入る）と同じく凍結される。Q12 の答えがどちらでも、この場合の扱いは決まらない
- kind: irreversible
- loss: rewrite-all
- 提案: Q12 の問いと選択肢の対象を「印を置いたときに無かった形（知らない製品の名前・知らない種類）」に広げるか、同じ形の選択肢で Q13 を立てる。spec.md:153 を答えに合わせて種類の場合も書く
- 処置: escalated — Q12 の対象を「印のときに無かった中身・製品の名前」に広げ、spec の SHALL にも初めて出る中身を入れた。deep.md の Q12 に R2 を記録

## R3. 選択肢に「規則が外れた兆しのあるファイルだけ待ち、それ以外は待たずに入れる」が無い
- 成果物: openspec/changes/st12-archive-ingestion/deep-questions-r3.json（Q12 の options）
- 根拠: 選択肢 2 の `irreversible` が名付ける外れ方は「訳された名前・欠けた名前」。D2 の規則ではそれぞれ機械で見分けられる —— 訳された名前は ASCII に畳めず `u` + ハッシュの枝に入る（design.md:93）、欠けた名前は `products` が無い / 空（design.md:95 が反転条件に挙げる。規則には枝が無い）。
  いまの 3 択は「毎回待つ / 一切待たない / 1 本にまとめる」で、選択肢 2 の不可逆が名指しした場合だけを止めて手作業を減らす中間が無い。この中間にも残る不可逆がある（ASCII に畳める名前で外れる —— Google が製品の英語名を変えて同じ製品が 2 本に割れる、など）ので、それを書いて並べる必要がある
- kind: irreversible
- loss: rewrite-all
- 提案: 選択肢を 1 つ足す —— 「印の後の知らない製品は、`products` が無い・ASCII に畳めない（`u` + ハッシュになる）ときだけ確認待ち、それ以外は待たずに入れる」。`irreversible` に「ASCII の名前のまま外れた（製品名の変更など）ときは、その製品の行が別の論理ソースに割れて直せない」と書く
- 処置: escalated — Q12 に選択肢「外れの兆しがあるファイルだけ待つ」と、その不可逆（兆しの無い外れは凍結され、同じ製品が 2 本に割れる）を足した。deep.md の Q12 に R3 を記録

## R4. 推奨の選択肢の「名前は確かめてから凍結される」は、確かめて外れていたときに本人ができることを書いていない
- 成果物: openspec/changes/st12-archive-ingestion/deep-questions-r3.json（Q12 の 1 つ目の選択肢の detail）
- 根拠: design.md:334（`tools/archive-shape.sh` は一覧と `--confirm <形のハッシュ>` だけ。名前の付け替え・別名の手段は無い）/ design.md:95（外れていたときの道は「規則を直して解析器の版を上げてから印を置く」= コードの変更）/ Q12 の detail「`archive-shape.sh` を見て印を置く手順が増える。名前は確かめてから凍結される」。
  再確認で本人が名前の外れに気づいても、その場でできるのは「印を置かない（その製品は写しに残ったまま入らない）」までで、入れるには規則の変更と版の上げが要る。選択肢 1 の手作業の中身と、選択肢 2 / 3 と比べて何を守っているかが detail から読めない
- kind: daily
- 提案: 選択肢 1 の detail に「外れていたら印を置かずに止めておける（写しに残る）。入れるには名前の規則を直して解析器の版を上げる」を 1 行足す
- 処置: escalated — Q12 の推奨の選択肢と context に「外れていたら名前の規則を直して解析器の版を上げるまで確認待ちのまま（何も凍結されない）」を書いた。deep.md の Q12 に R4 を記録

## 確かめて指摘にしなかったこと

- **分類**: `kind: irreversible` / `loss: rewrite-all` は妥当。待たない側（選択肢 2 / 3）で論理ソースの名前が格納時に凍結される（spec.md:159、第 2 回 Q10 の出典 `migrations/202609120944_gates.sql:55-58`）。推奨の側に失われるものは無い（確認待ちのファイルは写しの設定に関わらず写す。spec.md:149）
- **`recommended`**: 1 つ目にある
- **選択肢 3 の不可逆**: 「後から製品ごとの論理ソースに分けられない」は第 2 回 Q10 の選択肢 4 と同じ根拠で正しい（製品は解析済みの内容に残るので読むときに絞れる点は、第 2 回で書いてある）
- **context の「同じ書庫の他のファイルは待たずに入る」**: spec.md:153 と Scenario（spec.md:202-205、tasks.md:142 の「知らない製品があっても同じ書庫の他のファイルは格納される」）に合う
