<!-- prose purpose -->
携帯を落としたときに、本人がログインしたままの画面の設定から、画面の合言葉と収集アプリの値（携帯と PC で共有する 1 本の値）を変えて、拾った人を締め出せるようになる。どちらも今の画面の合言葉を入れ直したときだけ変わるので、ログインしたままの携帯を拾った人には変えられない。

<!-- prose impact.overview -->
Windows にインストールした形のサーバなら、ログインした画面の設定で、今の合言葉を入れ直して、画面の合言葉と収集アプリの値を変えられるようになる。合言葉を変えるとほかの端末のログインはその場で切れ、収集アプリの値を変えると前の値の送信はその場で断られる。できなくなること・手間が増えることもある。本人の PC の収集アプリも貼り直すまで送れず、本人のほかのブラウザもログインし直しになる。.env で起こした開発の形のサーバでは、この分析の範囲では画面から変えられない（断る）。

<!-- prose impact.problem -->
携帯を落としたとき、携帯のブラウザは画面にログインしたままで、収集アプリは共有の値を持っている。サーバをサービスにした後は、設定がサービスのアカウントだけが書ける置き場にあり、本人は画面からも手でも締め出せない。

<!-- prose impact.findings[IMP-01].text -->

<!-- prose impact.findings[IMP-02].title -->

<!-- prose impact.findings[IMP-02].text -->
失敗の数えは誰の失敗かを区別しない 1 つの窓（1 分に 10 回）で、ログインと 2 つの変える口で共有する。拾った人が間違え続けると、本人の正しい合言葉も 429 で断られる。ログインの口は前から同じ数えで、ST59 は変える口もそこに入れる。網からノードを外した後も、最後の失敗から最大 60 秒は断られる

<!-- prose impact.findings[IMP-03].title -->
画面で変えた後に、インストーラの password で決め直せるかは CI で確かめるまで分からない

<!-- prose impact.findings[IMP-03].text -->
インストーラの一時の書きは「中のファイルの持ち主もインストーラ」を前提に書かれている。サーバが名前の付け替えで置いた設定のファイルの持ち主はサーバのアカウントになる。そこへインストーラの書きが届くかは、まだ実物で見ていない

<!-- prose impact.findings[IMP-04].title -->
インストーラの password の入力を待つ間に画面で収集アプリの値を変えると、取り消したはずの前の値が黙って有効に戻る

<!-- prose impact.findings[IMP-04].text -->
インストーラの password は、設定のファイルを読んでから合言葉の入力を待ち、その後でサービスを止めて、読んだ設定を丸ごと書き戻す。その間に画面から収集アプリの値を変えると、書き戻されるのは前の値、つまり落とした携帯の値になる。起動し直すと落とした携帯の送信が通り、新しい値を貼り直した収集アプリは断られる。収集アプリは 401 を本人にすぐ知らせないので、本人は気づきにくい

<!-- prose impact.findings[IMP-05].title -->
試験のサーバの待ち受けが、ほかの台本と同じ番号を使う

<!-- prose impact.findings[IMP-05].text -->
