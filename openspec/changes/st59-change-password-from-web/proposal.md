# ST59 — 合言葉を画面から変えられる

## Why

サーバを Windows のサービスにした（ST55）ので、画面の合言葉の照らす値と収集アプリの共有の値（`API_TOKEN`）は、サービスのアカウントだけが書ける `settings\server.json` にある（FR-109）。
いまそれを変える口は、インストールの最後と、忘れたときのインストーラの `password`（PC の管理者）しか無い。共有の値を変える口はどこにも無い。
そのため、携帯を落としたときに、拾われた携帯のログインと収集アプリの値を本人が締め出す手段が無い（FR-133。`docs/audit/2026-11-03-native-postgres-consistency.md` の C9）。

## What Changes

> 第 1 回の深掘りは**推奨の答えで先に**書いた（2026-10-20 の流れ）。Q1〜Q3 はどれも「仮でよい」問い。本人の答えが推奨と違えば `spec --answers` が書き直す。
> 聞かない既定（`review/deep.md` の C1〜C7）は design に写した（C1 → D9、C2 → D1、C3 → D2、C4 → D3、C5 → D4、C6 → D6、C7 → D7）。

- **画面の設定に「画面の合言葉を変える」の節を足す**（Q2 の推奨）: 今の合言葉・新しい合言葉・新しい合言葉（もう一度）を入れて「変える」を押す。
  今の合言葉が合えば、サーバは新しい照らす値を設定のファイルに書き、止まらずにその場で差し替える（C2・C3）。
  ほかの端末のログインはその場で全部切れ、変えた画面だけは新しいログインの印を受け取ってログインしたまま（Q1 の推奨）。新しい合言葉は、インストーラの決め直しと同じ 5 つの検査を通す（C5）
- **画面の設定に「収集アプリの値を変える」の節を足す**（Q2 の推奨）: 今の合言葉を入れて「変える」を押す。サーバが OS の暗号の乱数で新しい値を作り（C6）、設定のファイルに書いてその場で差し替える。
  古い値は変えた瞬間から断る（C7・FR-128）。変えた直後に「収集アプリの設定」と同じ形の設定の文字列とコピーのボタンを出し、全部の収集アプリに貼り直すよう案内する。
  2 つの節の近くに「携帯を落としたときは両方を変える」と書く
- **どちらの操作も、今の画面の合言葉を入れ直させる**（FR-133）。照合はログインと同じ照らし方・同じ失敗の遅れ・同じ回数の制限で、失敗の数えをログインと「収集アプリの設定」と共有する。
  有効なログインの印が要り、API の合言葉と衛星の資格情報では通らない
- **設定のファイルを指して起こしたサーバでだけ変えられる**（Q3 の推奨）: `.env` の元の合言葉で起こした開発の形では、押すと「この形のサーバでは画面から変えられません。.env を書き換えて起動し直してください」と断り、何も変えない
- **画面の合言葉を変えたら、ログインはその場で無効になる**（`data-sensitivity` の MODIFIED）: 今の正典は「変わった後の起動で」無効にする。画面から変えたときは、起動し直さずにその場で無効にする
- **変える求めを読み出しの記録に残す**（C1・`data-sensitivity` の MODIFIED）: 成功も断りも 1 求め 1 行。値と入れた合言葉は残さない
- **画面で変えた後も、忘れたらインストーラの `password` で決め直せる**ことを、Windows の CI で確かめる（C4・premises の 5 行目）
- **手順書**: `docs/network.md` §4（携帯を落としたとき）を、配る形では画面の設定から変える手順に直す。`docs/install.md` と `docs/collector-setup.md` に、画面から変えたあとの手順を足す

**BREAKING ではない**: 送信の封筒・送信契約の版・取り込みの口・ログインの口は変えない。開発の形（`.env` で起こすサーバ）は今どおり動く（画面から変えようとすると断るだけ）。

**やらないこと**（要件と正典で決まっている。`review/deep.md` R7・R8）:
- 収集アプリの値を端末ごとにする・落とした携帯だけを締め出す（FR-128 ★ 2026-11-02 で本人が共有の 1 本を選んだ。要るなら /requirements から）
- 古い収集アプリの値を変えた後も一定の時間受ける猶予（同じ ★。変えた瞬間から断る）
- 衛星の資格情報を一緒に取り消す（ST38 へ申し送り済み。`docs/handoff/ST38.md`）
- Linux の配る形での画面からの変更（FR-131。サービスの形は ST60 が作る。`docs/handoff/ST60.md` へ申し送る）

## Capabilities

### New Capabilities

（無し）

### Modified Capabilities

- `data-sensitivity`: 画面の合言葉を変える口と、収集アプリの値を変える口（ADDED 2 本）。ログインの無効化を「変わった後の起動で」から「画面から変えたときはその場で」へ（MODIFIED）。読み出しの記録に残すものに変える求めを足す（MODIFIED）

**capability の照合**: INDEX.md は ST59 を `data-sensitivity` にだけ割り当てている。画面の合言葉と収集アプリの値を変える口・その守り・ログインの無効化・読み出しの記録は、どれもアクセス制御で、割り当てと合っている。
サーバが `settings\server.json` に書き戻すこと・画面で変えた後もインストーラの `password` が使えることは、`data-sensitivity` の ADDED の Requirement の振る舞い（変えた値が起動し直しても残る・忘れたときの戻り道）として書き、`distribution` には delta を持たない。
`distribution` の「状態の置き場は、2 つのサービスのアカウントだけが書け…」（サーバのサービスのアカウントは `settings` に書ける）と「インストールを走らせ直すと…既にある秘密・設定を上書きしない」（画面で変えた値を走らせ直しが戻さない）は、今の文のまま成り立つ。
「秘密はインストーラが自動で作り、状態の置き場の設定にだけ置き、人に見せない」の「画面に出さない」は、共有の値を本人の画面に出す ST56 の `/collector-setup` と既に食い違っており、ST59 の `/collector-token`（サーバが作り直した値を出す）もそれを広げる。
`distribution` は ST59 の割り当ての外なので、ここでは直さず、`distribution` を次に MODIFIED する Story へ「共有の値は、ログインして合言葉を入れ直した本人の画面にだけ出す」例外を足すよう申し送る（Task 8.2。review/spec.md R13）。前倒しは無い。

**requires**: ST55（照らす値と `server.json`・インストーラの `password`）と ST56（「収集アプリの設定」の節・合言葉の入れ直しの口・断られ続けた知らせ）は、どちらも archive 済みで正典にある。

## Impact

- サーバ（`crates/server`）: `web_session.rs`（照らす値・印の材料・共有の値をまとめて差し替えられる持ち方にし、照合と印の発行は同じ版を 1 つ取って使う。変える 2 つの口）・`lib.rs`（`App` の持ち方・`decide` が今の共有の値を読む・router に 2 つの口）・
  `service.rs`（設定のファイルへの書き戻し）・`access_log.rs`（素通しの口に 2 つを足す）。`docs/openapi.json` を作り直す。移行は無い（読み出しの記録の結果の語は今あるものを使う。D9（仮））
- 画面（`web/src`）: `SettingsView.tsx` に 2 つの節と新しい部品（`WebPasswordChangePanel.tsx`・`CollectorTokenChangePanel.tsx`）・`messages.ts`。e2e は `web/e2e/st59-change-secrets.spec.ts`
- 試験と道具: 設定のファイルを指してサーバを起こす台本 `tools/settings-server.sh`（新しい。Linux の e2e と試験が使う。D8（仮））・`tools/release/install-check.sh`（Windows の CI の `install-windows` に ST59 の Scenario を足す）
- 文書: `docs/network.md` §4・`docs/install.md`・`docs/collector-setup.md`
- 申し送り: `docs/handoff/ST60.md`（Linux の配る形でも画面から変えられるよう、設定のファイルから起こす形にする）。`docs/handoff/ST38.md` は深掘りの段で書いた
- インストーラ（`crates/installer`）のコードは変えない。サーバが書き直した `server.json` を `password`・走らせ直し・`repair` が今どおり扱えることを Windows の CI で確かめ、届かなければ直す（premises 5 行目。D4 の反転条件）
- **走っている change との重なり**: 無い（`openspec/changes/` に archive 以外の change はこの Story だけ）
