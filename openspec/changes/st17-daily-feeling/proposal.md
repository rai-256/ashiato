## Why

**その日どう感じたかを残す場所が無い。** D-01 にあるのは端末と PC が集めた記録・そこから作った滞在・個人属性の主張だけで、
主観を書く口も表も無い（`deep.md` の手順 5）。扉 #1 は「day one から持つ」と決まっているのに、書く口が無い日の気分は後から思い出せない ——
3 年前の今日をどう感じていたかは、そのときに書いていなければ残らない（Story の価値）。

いま作る理由は 2 つ。

1. **書き始めが遅いほど、取れない日が増える。** 主観は収集できない（本人しか書けない）ので、口が無い日は全部 `uncaptured`
2. **後続が主観の形を前提にする。** ST18（紐づけ先の種類を足す）・ST24（感度）・ST26（語で探す。主観記述が対象）が、この Story の器と錠の上に積む

## What Changes

深掘りは **1 巡・13 問**（A 6 / B 7）。本人がすべて選択肢から明示的に選んだ（未回答 0・推奨のまま 0）。**Q9 だけ推奨と違う選択肢**、Q1 は proto の初期値から 1 軸を動かした。
聞かないで決めた C1〜C10 は `deep.md` に番号つきで並べ、答えを貼り戻すときに異論が無かった。

- **`subjective-log` を新しい capability として作る**
- **主観の記録を「本人が書いた」記録として取り込み口（`/ingest`）から受け付ける。** 快–不快（-2〜+2）は必須、元気さ（-2〜+2）とひとことは任意（Q2 / Q3）。
  尺度は（識別子・版・値）の並びで持つ（C4）。紐づけ先は「日」か「滞在」を種類の登録簿つきで指す（C5 / Q4）
- **2 つの時刻を別々に持つ。** 出来事の時刻の列には**対象の時刻**（日は Asia/Tokyo の 0:00、滞在は書いた時点の始まり）、記入の日時は本文に（Q12 / C3）。
  前/後は記入の日時と対象の終わりから**機械で決め、本人は選ばない**（Q5）。**未来の日にも書ける**（FR-42 ★）
- **主観は書き換えられない。DB が強制する**（C2）。書くたびに 1 件増え、同じ値でも畳まない。消したことにする（FR-50）と本文の消去（FR-51）の開口部だけを通す（ST19 の主張と同じ形）
- **主観の既定の感度は「ローカル AI まで」**（PERM-4 / C6）
- **主観入力の画面（S-3）を作る**（Q1 の proto のとおり）: 快–不快の 5 つのボタンを押した瞬間に保存 / ひとことと元気さは常に出す / 見出しの日付と ‹ › / 1 か月の暦 / その日の滞在ごとの気分。
  **開いたときの対象の日はいつも暦の今日**（Q9。推奨と違う選択）。同じ対象に何度も書いたら最後の 1 件を出し、前の記録は「書き直した履歴」で見る（Q11）
- **主観の無い日を区別して出す**（FR-57 ★ / Q13）: S-3 の暦と**1 日の画面（S-2）の頭**の両方に、破線と文字「未記入」で。最初の記録より前の日は「使い始める前」、未来の日は数えない
- **S-2 の滞在の行に、その滞在の気分を 1 行添える**（ST16 の Q4 で本人が決めた「行の中に主観の本文を出す。置き場は ST17」。書く口は S-3 のまま）
- **携帯の収集アプリが 1 日 1 回、その日の記録が無いときだけ通知を出し、押すと Web の S-3 を開く**（Q6 / Q7 / Q8）。既定 21:00、時刻は Web で変える。確かめられないときは鳴らす（FR-43 ★）
- **滞在に付けた気分は、吸収先の滞在に出す。消した滞在の気分は画面では滞在と一緒に隠れる**（Q10）

**BREAKING は無い。** 取り込みの契約の形・エンベロープ・登録簿の形は変えない。取り込みの結果の「理由の種別」に主観の検査の値を足し、登録簿に行を 1 本足す。

## Capabilities

### New Capabilities

- **`subjective-log`** —— 主観の記録（尺度・ひとこと・紐づけ先・2 つの時刻・前/後）、形の検査、書き換えの禁止、既定の感度、読み出し（対象ごとの最新と履歴・未記入の日）、
  主観入力の画面（S-3）、通知（携帯の収集アプリが鳴らす条件と開く先）。`docs/stories/INDEX.md` の割当どおり（ST17 / ST18）。
  **通知は `device-collection` に置かない** —— 収集ではなく主観の入口なので（Q6 の context）。携帯側のファイルも収集と分ける（design）

### Modified Capabilities

- **`browsing-views`** —— 1 日の画面（S-2）の頭に、その日の気分か「気分 未記入 — 書く」を出す（Q1 の軸 4）。滞在の行にその滞在の気分を 1 行添える（ST16 の Q4）。**ADDED の要件 2 本**で、既存の要件は変えない。
  `docs/stories/INDEX.md` は record の段で ST17 を `browsing-views` に足してある（capability の前倒しではなく、本人の選択の帰結）

`record-envelope` は変えない —— 主観は既存の約束（原文・2 つの時刻・出自・冪等・削除済みは戻らない）のまま入る。
**主観のソースだけに掛ける検査と錠は `subjective-log` に書く**（ST19 が `personal-entities` に置いたのと同じ）。
`record-deletion` も変えない —— 消す・消去は既存の経路が主観にも及ぶ（錠が開口部を通す）。主観を消す画面の操作は作らない。

**要件の側の前倒しはある** —— PERM-4（ST24）/ FR-50（ST22）/ FR-51（ST23）/ FR-35（ST14。★ 2026-10-07）/ 画面の下限 NFR-17〜23（ST25）の、主観と S-3 にかかる条項だけを満たす（ST19 と同じ扱い。`docs/stories/INDEX.md` の 2026-10-07 の追記に表）。

## Impact

- **移行を 1 本足す**（名前は作成時刻）: 紐づけ先の種類の登録簿（日・滞在）、主観の行の錠（即時の錠・COMMIT 時の門・行の削除の拒否）、登録簿に主観のソースを 1 行、通知の時刻の設定の台帳
- `crates/server`: 取り込み口に主観のソースの検査と既定の感度、主観の読み出しの口（対象ごとの最新・履歴・未記入の日）、通知の判断の口、通知の時刻の設定の口。OpenAPI に載せる
- `web`: 主観入力の画面（S-3。新しい経路）、1 日の画面の頭の気分の欄と滞在の行の気分、通知の時刻の設定
- `collector-android`: 1 日 1 回の通知の予約（再起動の後も）と、押して Web の S-3 を開く経路（**収集の経路と別のファイル**）。`RECEIVE_BOOT_COMPLETED` を足す
- `tools/check-immutable.sh` に主観の行の錠を足す。`tools/smoke.sh` / `tools/seed.sh` に主観を足す
- 要件: FR-36 / FR-39 / FR-40 / FR-41 / FR-42 / FR-43 / FR-57 に ★（record の段で済み）、FR-35 に ★（spec の段。spec-review R4）
- 後続へ（`docs/handoff/` に書いた）: **ST14** —— 本人が書くソースを途絶の判定から外す / **ST18** —— 紐づけ先の種類の登録簿に行を足す（既存の主観の行は触らない）/ **ST24** —— 主観の既定の感度はコードの分岐で持つ /
  **ST26** —— ひとことは NFC で解析済みに入る（検索の対象）/ **ST29** —— 収集側の合言葉は ST29 まで主観の中身も読める。範囲を絞るとき収集アプリに残すのは通知の判断の口だけ
