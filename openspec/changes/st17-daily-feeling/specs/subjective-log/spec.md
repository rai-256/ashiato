## Purpose

本人がその日（またはその滞在）をどう感じたかを、快–不快を必須の軸とする主観の記録として毎日 30 秒で残し、書き換えずに積む。
記入の日時と対象を別々に持ち、前に書いたか後に書いたかを時刻から導き、主観の無い日を区別して見せ、書き忘れを 1 日 1 回の通知で促す。

## ADDED Requirements

### Requirement: 主観の記録を積む

THE SYSTEM SHALL 主観の記録を、取り込み口から「本人が書いた」記録として受け付ける。
THE SYSTEM SHALL 各記録に、尺度の並び・紐づけ先・記入の日時とその地域を持たせ、ひとことを任意で持たせる。
THE SYSTEM SHALL 尺度を（尺度の識別子・版・値）の組で持ち、快–不快（識別子 `valence`・版 1・-2〜+2 の整数）を必須、元気さ（識別子 `energy`・版 1・-2〜+2 の整数）を任意とする。
THE SYSTEM SHALL 紐づけ先を（種類・鍵）で持ち、種類「日」の鍵を `Asia/Tokyo` の日付、種類「滞在」の鍵を滞在の識別子とする。
THE SYSTEM SHALL 種類「滞在」の記録に、書いた時点のその滞在の始まりと終わりを持たせる。
THE SYSTEM SHALL 記録の出来事の時刻に**対象の時刻**（種類「日」はその日の 0:00 `Asia/Tokyo`、種類「滞在」は書いた時点のその滞在の始まり）を持たせ、記入の日時は本文に持たせる。
THE SYSTEM SHALL 今日より後の日を紐づけ先にする記録と、過去の日を紐づけ先にする記録を受け付ける。
THE SYSTEM SHALL 記録を書くたびに 1 件増やし、尺度・ひとこと・紐づけ先が既存の記録と同じでも畳まない。
THE SYSTEM SHALL 同じ記録の再送（原文が同じ）では記録を増やさない。
THE SYSTEM SHALL 記録の原文を受け取ったまま保持する。
THE SYSTEM SHALL 記録の解析済みの値（尺度・ひとこと・紐づけ先・記入の日時）を、送り主の解析済みではなく原文から作り、文字列を NFC にする。

導出元: FR-36, FR-37, FR-40, FR-41, FR-42, FR-18, FR-19, FR-21, FR-22, FR-25, FR-27。扉 #1 / 扉 #2。深掘り Q2 / Q3 / Q4 / Q5 / Q12 / C2 / C3 / C4 / C5 / C10。
出来事の時刻に対象の時刻を入れるのは、翌朝に書いた昨日の分を、時刻で日を引く読み手（1 日の画面・AI）に昨日として見せるため（Q12。この列は凍結されるので後から入れ替えると全行の書き直し）。
滞在の始まりと終わりを書いた時点の値で持つのは、作り直しで滞在の時刻が動いても、前/後の計算と出来事の時刻が動かないようにするため。

#### Scenario: 快–不快だけで記録が 1 件入る

- **WHEN** 2026-10-07 の日に、快–不快 +1 だけを持つ記録を書く
- **THEN** その記録が格納され、読み出すと快–不快 +1 を持ち、元気さとひとことを持たない

#### Scenario: 元気さとひとことを添えた記録が入る

- **WHEN** 快–不快 -1・元気さ +2・ひとこと「久しぶりに走った」を持つ記録を書く
- **THEN** 読み出した記録は、快–不快 -1・元気さ +2・ひとこと「久しぶりに走った」を持つ

#### Scenario: 尺度は識別子と版とともに残る

- **WHEN** 快–不快と元気さを持つ記録を書いて読み出す
- **THEN** 各尺度の値は、尺度の識別子（`valence` / `energy`）と版（1）とともに返る

#### Scenario: 日の記録の出来事の時刻はその日の 0 時

- **WHEN** 2026-10-08 08:10（`Asia/Tokyo`）に、2026-10-07 の日を紐づけ先にする記録を書く
- **THEN** 格納された記録の出来事の時刻は 2026-10-07T00:00:00+09:00 である

#### Scenario: 記入の日時は出来事の時刻と別に残る

- **WHEN** 2026-10-08 08:10（`Asia/Tokyo`）に、2026-10-07 の日を紐づけ先にする記録を書いて読み出す
- **THEN** 読み出した記録は、記入の日時として 2026-10-08T08:10+09:00 を、出来事の時刻とは別の欄に持つ

#### Scenario: 滞在の記録の出来事の時刻は書いた時点の滞在の始まり

- **WHEN** 9:12 に始まり 11:40 に終わる滞在を紐づけ先にする記録を書く
- **THEN** 格納された記録の出来事の時刻はその日の 9:12 で、記録はその滞在の識別子と、始まり 9:12・終わり 11:40 を持つ

#### Scenario: 滞在の時刻が作り直しで動いても記録の時刻は動かない

- **WHEN** 滞在に記録を書いた後、基準を変えて作り直し、同じ識別子の滞在の始まりが変わる
- **THEN** その記録の出来事の時刻と、記録が持つ滞在の始まりと終わりは、書いた時点の値のままである

#### Scenario: 昨日の分を後から書ける

- **WHEN** 2026-10-08 に、2026-10-07 の日を紐づけ先にする記録を書く
- **THEN** その記録は格納され、2026-10-07 の記録として読み出せる

#### Scenario: 未来の日を紐づけ先にする記録を受け付ける

- **WHEN** 今日より後の日を紐づけ先にする記録を書く
- **THEN** その記録は格納される

#### Scenario: 同じ値を書き直しても 1 件増える

- **WHEN** 同じ日に、既存の記録と尺度もひとことも同じ記録を改めて書く
- **THEN** その日の記録が 1 件増える

#### Scenario: 同じ記録の再送は増えない

- **WHEN** 同じ原文の記録を 2 回送る
- **THEN** 記録は 1 件のままで、2 回目の結果は受理を示す

#### Scenario: 主観の原文が 1 バイトも変わらずに残る

- **WHEN** 主観の記録を書く
- **THEN** 格納された原文は送った原文とバイト単位で一致する

#### Scenario: 合成済みでないひとことは合成済みで読み出される

- **WHEN** ひとことを NFD（分解された形）の文字列で持つ記録を書く
- **THEN** 読み出したひとことは NFC の文字列である

#### Scenario: 原文と食い違う解析済みの主観を送っても原文の値で格納される

- **WHEN** 原文の快–不快が +2 で、送り主の解析済みの快–不快が -2 の記録を送る
- **THEN** 読み出した快–不快は +2 である

### Requirement: 形の合わない主観の記録は受け付けない

THE SYSTEM SHALL 次の表のいずれかに当たる主観の記録を、その 1 件だけ受け付けず、表の理由の種別を返す。

| 理由の種別 | 当たるもの |
|---|---|
| `malformed_feeling` | 原文が JSON でない / 必須の欄が欠ける / 原文の記録の識別子が記録の識別子と違う / 原文の乱数が 128 bit に満たない / 記入の日時が地域のずれつきの日時として読めない / 記録の地域が `Asia/Tokyo`（+9:00）でない |
| `feeling_not_authored` | 由来が「本人が書いた」でない / 端末識別子を持つ |
| `feeling_has_external_id` | 外部サービス上の識別子か対象の識別子を持つ |
| `invalid_scale` | 快–不快が無い / 尺度の値が -2〜+2 の整数でない / 識別子と版の組が知らないもの / 同じ識別子の尺度が 2 つある |
| `invalid_note` | ひとことが NFC にして 2,000 文字（Unicode のコードポイントの数）を超える |
| `invalid_feeling_target` | 紐づけ先の種類が登録簿に無い / 日の鍵が暦に無い日付 / 滞在の鍵がその利用者の滞在に無い / 滞在の始まりが終わりより後 / 記録が持つ滞在の始まりと終わりの区間が、その滞在のいまの区間と重ならない / 出来事の時刻が対象の時刻と違う |

THE SYSTEM SHALL 表の上の行から順に確かめ、2 つ以上に当たる記録には、最初に当たった行の種別を返す。

THE SYSTEM SHALL 空のひとこと（前後の空白を除いて空）を「ひとこと無し」として受け付ける。
THE SYSTEM SHALL 長すぎるひとことを切り詰めて格納しない。
THE SYSTEM SHALL 削除の印の付いた滞在と、作り直しで吸収された滞在を紐づけ先にする記録を、その理由では断らない。
THE SYSTEM SHALL 記録が持つ滞在の始まりと終わりが、その滞在のいまの値と一致しないことを、区間が重なる限りその理由では断らない。
THE SYSTEM SHALL 主観の記録を受け付けなかった応答に、尺度の値・ひとことを含めない。

導出元: FR-36, FR-37, FR-40, FR-41, FR-23, FR-25。深掘り C2 / C4 / C5 / C10。design D5。
切り詰めないのは、黙って切ると書いた分が消えるから（C10。捨てるより断る）。
消した滞在・吸収された滞在を断らないのは、画面を開いてから書くまでの間に作り直しや消す操作が挟まりうるからで、そのような記録の読み方は「日ごとの主観を、対象ごとの最新と履歴で読める」が決める。
滞在の区間が重なることを求めるのは、主観の行は消せない（「主観の記録は書き換えられない」）ので、まったく別の時刻を持つ記録が入ると、その記録が別の日に数えられ続けるから。一致まで求めないのは、作り直しで区間が少し動いても断らないため。

### Requirement: 前に書いたか後に書いたかは時刻から決まる

THE SYSTEM SHALL 各主観の記録の前/後を、記入の日時が対象の終わりより前なら「前」、それ以外なら「後」と、読み出すたびに記録の時刻から導く。
THE SYSTEM SHALL 対象の終わりを、種類「日」はその日の翌日 0:00 `Asia/Tokyo`、種類「滞在」は記録が持つ書いた時点の滞在の終わりとする。
THE SYSTEM SHALL 前/後を本人に選ばせず、記録の本文に持たせない。

導出元: FR-39。深掘り Q5。
本人は「当日の夜に書いた記録も時刻の上では『前』になる」ことと、本人のつもりが残らないことを承知で選んだ。
前/後を本文に持たせないのは、記入の日時と対象が両方残るので、数え方を後から何度でも計算し直せるから。

#### Scenario: 翌朝に書いた昨日の記録は後

- **WHEN** 2026-10-08 08:10（`Asia/Tokyo`）に 2026-10-07 の日の記録を書く
- **THEN** その記録は「後」として読み出される

#### Scenario: 当日の夜に書いたその日の記録は前

- **WHEN** 2026-10-07 21:30（`Asia/Tokyo`）に 2026-10-07 の日の記録を書く
- **THEN** その記録は「前」として読み出される

#### Scenario: 未来の日に書いた記録は前

- **WHEN** 2026-10-07 に 2026-10-10 の日の記録を書く
- **THEN** その記録は「前」として読み出される

#### Scenario: 滞在が終わった後に書いた記録は後

- **WHEN** 9:12–11:40 の滞在に、12:00 に記録を書く
- **THEN** その記録は「後」として読み出される

#### Scenario: 前後は格納した記録に持たない

- **WHEN** 主観の記録を書き、格納された原文と解析済みを見る
- **THEN** どちらにも前/後を表す欄が無い

#### Scenario: 日付が変わった直後に書いた前の日の記録は後

- **THEN** その記録は「後」として読み出される

### Requirement: 主観の記録は書き換えられない

THE SYSTEM SHALL 格納された主観の記録の、原文・解析済み・内容の鍵・出来事の時刻とその地域・D-01 に入った時刻・識別子・利用者・由来・論理ソース・外部識別子・端末識別子の書き換えを、DB の側で拒む。
THE SYSTEM SHALL 主観の記録の行の削除を DB の側で拒む。
THE SYSTEM SHALL 他の記録を主観の論理ソースへ付け替える書き換えを、DB の側で拒む。
THE SYSTEM SHALL 主観の記録の削除の印（削除時刻と削除した者）と感度の書き換えを通す。
THE SYSTEM SHALL 主観の記録の本文の消去を、原文と解析済みを空にし出来事の時刻と内容の鍵を変えない形で、かつ同じまとまりに**その記録の**消去の台帳の行があるときだけ通す。
THE SYSTEM SHALL これらの制限を、取り込み口の外から加えられた操作にも適用する。
THE SYSTEM SHALL 主観以外の記録に、この制限を広げない。

導出元: FR-36, FR-30, FR-50, FR-51, PERM-2。深掘り C2。

### Requirement: 主観の無い日を数える

THE SYSTEM SHALL 削除の印の付いた記録と本文を消去した記録を数えない。
THE SYSTEM SHALL 今日を `Asia/Tokyo` の日付で決める。

### Requirement: 日ごとの主観を、対象ごとの最新と履歴で読める

WHEN 資格情報を持つ呼び出し元が日付の範囲（始まりと終わり。`YYYY-MM-DD`、最大 62 日）を指定して主観を求める THE SYSTEM SHALL

THE SYSTEM SHALL 各日の記録を、紐づけ先（その日の「日」と、その日に紐づく各滞在）ごとに、前/後ごとの最新の 1 件と、その紐づけ先の記録の全部（記入の日時の新しい順）に分けて返す。
THE SYSTEM SHALL 「最新」を記入の日時が最も後の記録とし、記入の日時が同じなら D-01 に入った時刻が後の記録とする。
THE SYSTEM SHALL 各記録の尺度（識別子・版・値）・ひとこと・記入の日時（地域のずれつき）・D-01 に入った時刻・前/後を別々の欄で返す。
THE SYSTEM SHALL 作り直しで吸収された滞在に紐づく記録を、吸収の台帳をたどった先の滞在の記録として返し、元の滞在の識別子を添える。
THE SYSTEM SHALL 本人が消した滞在（1 件を消した・範囲を消して隠れた）に紐づく記録と、吸収をたどっても生きた滞在に着かない記録を、滞在ごとの記録として返さず、その日の「表示しない滞在の記録の数」として数だけを返す。
THE SYSTEM SHALL 滞在ごとの記録を、記録のある滞在についてだけ返す（記録の無い滞在は返さない）。
THE SYSTEM SHALL 各日に「記録のある滞在の数」（滞在ごとの記録を返した滞在の数と、表示しない滞在の数の和。同じ滞在の書き直しは 1 と数える）を返す。
THE SYSTEM SHALL 削除の印の付いた記録と本文を消去した記録を返さない。
THE SYSTEM SHALL 感度で記録を絞らずに返す。
THE SYSTEM SHALL 別の利用者の記録を返さない。
THE SYSTEM SHALL 日付として解釈できない指定と 62 日を超える範囲を 400 で断り、資格情報の無い求めを 401 で断る。

THE SYSTEM SHALL 暦の日を押すと、その日を対象にする。

導出元: FR-57。深掘り Q1 の軸 3・軸 4 / Q13 / C1。design D14（仮）。
30 日の暦は proto で本人が見た長さ。対象の日が未来なら、その日までの「これから」の日も並ぶ。

#### Scenario: 暦に未記入の日が破線と未で出る

- **WHEN** 30 日のうち 9 日が「未記入」の状態で主観入力の画面を開く
- **THEN** 暦の 9 日に破線の枠と文字「未」があり、残りの日には無い

#### Scenario: 暦に記入ありの日の値が出る

- **WHEN** 「日」の最新が快–不快 +1 の日を含む暦を出す
- **THEN** その日の欄に +1 が出る

#### Scenario: 使い始める前の日は未記入と出ない

- **WHEN** 最初の記録が 10 日前の状態で主観入力の画面を開く
- **THEN** 暦の 11 日前より前の日に破線の枠と「未」が無い

#### Scenario: 前と後がある日の暦は後の値を出す

- **WHEN** 「日」に前の記録（+2）と後の記録（-1）がある日を含む暦を出す
- **THEN** その日の欄に -1 が出る

#### Scenario: これからの日は暦で未記入と出ない

- **WHEN** 3 日後の日を対象にして主観入力の画面を開く
- **THEN** 暦の今日より後の日に破線の枠と「未」が無い

#### Scenario: 暦は対象の日で終わる 30 日

- **WHEN** 2026-10-07 を対象にして主観入力の画面を開く
- **THEN** 暦は 2026-09-08 から 2026-10-07 までの 30 日を出す

#### Scenario: 暦の日を押すとその日を書ける

- **WHEN** 暦の 3 日前の日を押す
- **THEN** 見出しの日付が 3 日前になる

### Requirement: 通知の時刻を画面で変えられる

THE SYSTEM SHALL 主観入力の画面に、いまの通知の時刻を出し、時:分を変えて保存する操作を置く。
THE SYSTEM SHALL 保存できたとき新しい時刻を出し、できなかったとき入れた値を消さずにそれと分かる文を出す。

導出元: FR-43。深掘り Q6 / Q7。design D10（仮）。

#### Scenario: 画面で通知の時刻を変えられる

- **WHEN** 主観入力の画面で通知の時刻を 22:30 にして保存する
- **THEN** 画面のいまの通知の時刻が 22:30 になる

#### Scenario: 画面で変えた通知の時刻が通知の判断に効く

- **WHEN** 主観入力の画面で通知の時刻を 22:30 にして保存した後、通知の判断を求める
- **THEN** 応答の通知の時刻は 22:30 である

#### Scenario: 通知の時刻を保存できなかったとき入れた値が残る

- **WHEN** サーバに届かない状態で通知の時刻を 22:30 にして保存する
- **THEN** 保存できなかったことが出て、時刻の欄は 22:30 のままである

### Requirement: 主観入力の画面の読み出しの失敗と下限

THE SYSTEM SHALL 読み出しに失敗したとき、記録が無い状態（未記入）と区別できる形で失敗を出す。
THE SYSTEM SHALL 快–不快の 5 つのボタンの高さを 64 CSS px 以上にし、すべての触れる対象を 24 × 24 CSS px 以上にする。
THE SYSTEM SHALL 幅 360 px で、快–不快の 5 つのボタンを横 1 列に、横のスクロール無しで出す。
THE SYSTEM SHALL 本文と背景のコントラスト比を 4.5:1 以上にする。
THE SYSTEM SHALL 意味を担う非テキスト（押された状態・未記入の破線）を、隣の色に対して 3:1 以上にする。
THE SYSTEM SHALL キーボードのフォーカスの位置に、隣の色に対して 3:1 以上の輪郭を出す。
THE SYSTEM SHALL OS の明暗設定に追従し、取得できないときはダークにする。
THE SYSTEM SHALL 画面の色を `docs/ui-direction.md` の確定値からだけ引く。

導出元: NFR-17, NFR-18, NFR-19, NFR-22, NFR-23。深掘り Q1（proto の 64 px は高さ。幅は 360 px を 5 つで分ける）。`docs/ui-direction.md`。

#### Scenario: 読み出しの失敗と未記入を区別する

- **WHEN** 主観の読み出しが失敗した状態で主観入力の画面を開く
- **THEN** 読み出しに失敗したことが出て、暦に「未」は出ない

#### Scenario: 快不快のボタンは高さ 64 px 以上

- **WHEN** 幅 360 px で主観入力の画面を開き、快–不快の 5 つのボタンを測る
- **THEN** どれも高さが 64 CSS px 以上で、幅が 24 CSS px 以上である

#### Scenario: 快不快のボタンは 1 列に並ぶ

- **WHEN** 幅 360 px で主観入力の画面を開き、快–不快の 5 つのボタンの上端を測る
- **THEN** 5 つの上端がそろっている

#### Scenario: 幅 360 px で横のスクロールが出ない

- **WHEN** 幅 360 px で主観入力の画面を開く
- **THEN** ページの横幅は 360 CSS px を超えない

#### Scenario: 主観入力の画面は触れる対象の下限を満たす

- **WHEN** 主観入力の画面のボタン・暦の日・滞在の行のボタン・入力欄を測る
- **THEN** どれも幅と高さが 24 CSS px 以上である

#### Scenario: 主観入力の画面は文字のコントラストの下限を満たす

- **WHEN** 明と暗のそれぞれで、本文と補助の文字の色を背景と比べる
- **THEN** コントラスト比は 4.5:1 以上である

#### Scenario: 押された状態と未記入の破線は 3:1 以上

- **WHEN** 明と暗のそれぞれで、押された快–不快のボタンの面と、未記入の日の破線の色を、隣の面の色と比べる
- **THEN** コントラスト比は 3:1 以上である

#### Scenario: 主観入力の画面はフォーカスの輪郭が見える

- **WHEN** 明と暗のそれぞれで、キーボードでフォーカスを快–不快のボタンに移す
- **THEN** 輪郭が出て、その色は隣の面の色に対して 3:1 以上である

#### Scenario: 主観入力の画面は OS の明暗に追従する

- **WHEN** OS の明暗設定を明にして画面を開き、設定が取得できない状態でも開く
- **THEN** 前者は明の面で、後者は暗の面で描かれる

#### Scenario: 主観入力の画面は確定した色だけを使う

- **WHEN** 主観入力の画面のコードに書かれた色を集める
- **THEN** どれも `docs/ui-direction.md` の確定値から引いたものである
