## MODIFIED Requirements

### Requirement: 組み立ての印は、版番号・commit・その部品のソースの未 commit の変更・組み立ての種類を持ち、組み立てのたびに作り直す

THE SYSTEM SHALL S-01・C-01・C-02・V-01 の組み立ての印を `<その部品の版番号>+<commit>` の形にし、その部品のソースに未 commit の変更があれば `.dirty`、release でない組み立てなら `.debug` を、この順で末尾に足す。
THE SYSTEM SHALL commit を 40 桁の 16 進で持ち、短縮しない。commit を取れなければ `unknown` にする。
THE SYSTEM SHALL 印を、commit が進んだとき・その部品のソースが変わったとき（add していない変更を含む）に、ソースのほかの部分に触れない差分の組み立てでも作り直す。
THE SYSTEM SHALL 「その部品の版番号」を、4 つの部品とも同じ 1 つの出所の版（distribution「3 つの部品の版番号は、1 つの出所から決まる」）にし、組み立ての時に版番号が渡されたときだけ、渡された版番号にする。
THE SYSTEM SHALL 「その部品のソース」を、S-01 は自分の crate と印を組む crate と移行と workspace の宣言、C-02 は自分の crate と印を組む crate と workspace の宣言、C-01 は携帯の収集アプリの木と出所の版を持つ根の `Cargo.toml`、V-01 は画面の木と根の `Cargo.toml` とする（出所の版を書き換えて commit していない組み立てが、`.dirty` の無い印で別の版番号を名乗らないように）。

導出元: FR-122, FR-123。扉 #32。深掘り（ST49）Q1（推奨）。premises の C10・C11。ST52: FR-104（版の出所は 1 つ）・深掘り（ST52）Q6（推奨）。
版番号だけでは、同じ番号の組み立て（開発版の日ごと・手元の組み立て・同じ commit の debug と release）が作った記録を分けられない。記録の版は後から直せない記録に焼き込むので、差分の組み立てで古い印を残さない。
未 commit の印をその部品のソースに限るのは、ほかの部品の木の変更はその部品の組み立てに入らないから（入らない変更で `.dirty` を付けると、同じ中身の組み立てが別のものに見える）。

#### Scenario: 印は版番号・commit・未 commit の印・組み立ての種類を持つ

- **WHEN** 印を組む道具が、部品のソースに未 commit の変更がある git の木で、release でない組み立ての印を組む
- **THEN** 印は `<版番号>+<その木の HEAD の 40 桁>.dirty.debug`

#### Scenario: 綺麗な木の release の組み立ての印は、版番号と commit だけを持つ

- **WHEN** 印を組む道具が、未 commit の変更の無い git の木で、release の組み立ての印を組む
- **THEN** 印は `<版番号>+<その木の HEAD の 40 桁>` で、`.dirty` も `.debug` も持たない

#### Scenario: ほかの部品の木だけが変わっていても、印は .dirty を持たない

- **WHEN** 印を組む道具が、その部品のソースの外（ほかの部品の木）にだけ未 commit の変更がある木で印を組む
- **THEN** 印は `.dirty` を持たない

#### Scenario: commit が取れない場所での組み立ての印は unknown を持つ

- **WHEN** git の木の外で、commit の環境変数も無く印を組む
- **THEN** 印は `<版番号>+unknown` で始まる

#### Scenario: S-01 の組み立ての印は、commit を進めた後の差分の組み立てでも新しい commit になる

- **WHEN** S-01 を組み立てた後に commit を 1 つ足し、ソースに触れずにもう一度組み立てる
- **THEN** 2 回目の組み立てに埋め込まれた印の commit は、足した commit の 40 桁

#### Scenario: S-01 の組み立ての印は、add していないソースの変更の後の差分の組み立てで .dirty になる

- **WHEN** 綺麗な木で S-01 を組み立てた後に、S-01 のソースを 1 つ書き換えて add せずにもう一度組み立てる
- **THEN** 2 回目の組み立てに埋め込まれた印は `.dirty` を持つ

#### Scenario: 版番号を渡した組み立ての印は、渡した版番号で始まる

- **WHEN** 印を組む道具が、未 commit の変更の無い git の木で、版番号 `0.4.0-beta.2` を渡されて release の組み立ての印を組む
- **THEN** 印は `0.4.0-beta.2+<その木の HEAD の 40 桁>`

#### Scenario: 携帯と画面の印の版番号も、根の出所の版から読む

- **GIVEN** 出所の版を `0.9.0` に書き換えて commit した木
- **WHEN** 版番号を渡さずに携帯の収集アプリと画面の組み立ての印を組む
- **THEN** どちらの印も `0.9.0+` で始まる

#### Scenario: 根の Cargo.toml を書き換えて commit していなければ、携帯と画面の印は .dirty を持つ

- **WHEN** 出所の版を書き換えて add せずに、携帯の収集アプリと画面の組み立ての印を組む
- **THEN** どちらの印も `.dirty` を持つ

### Requirement: 封筒の形が変わったのに送信契約の版が上がっていなければ CI が落ちる

THE SYSTEM SHALL 封筒の形 —— S-01 が受ける要求の型の最上位の欄と、収集アプリ 2 本が実際に直列化する最上位の欄の、名前・型・必須か任意か —— を 1 つの写しに、送信契約の版と一緒に持つ。
THE SYSTEM SHALL 写しが今のコードと食い違えば CI を落とす。
WHEN 最後の配った印（タグ `v[0-9]*`。ベータ版の印を含み、開発版の印 `nightly` を含まない）の写しと比べて、欄の追加・削除・型の変化・必須と任意の入れ替わりがある THE SYSTEM SHALL 送信契約の版が印の版より大きくなければ CI を落とす。
THE SYSTEM SHALL 「最後の配った印」を、配った印のうち今の木の HEAD の祖先にあるものの中で、版番号が最も大きいもの（同じ MAJOR.MINOR.PATCH ではベータ版より正式版が大きく、ベータ版どうしは N の大きい方）にする。印を打った日時では選ばない。
THE SYSTEM SHALL 配った印が 1 つも無い間は、版の比較で CI を落とさない。
IF 配った印があるのに、その印の版から写しを取り出せない THEN THE SYSTEM SHALL CI を落とす（印が無いものとして通さない）。
IF 検査する木が浅い（履歴が途中で切れていて、どの印が祖先かを決められない）THEN THE SYSTEM SHALL 印を数える前に CI を落とし、履歴が浅いことを示す（配った印が 0 個に見えても通さない）。
THE SYSTEM SHALL S-01・携帯・PC の 3 つの送信契約の版の値が写しの版と食い違えば CI を落とす。
THE SYSTEM SHALL 送信契約の文書（`docs/collector-contract.md`）の版の履歴に今の版の行が無ければ CI を落とす。

導出元: FR-130（機械の検査で固定する）。ST52: FR-105（緊急の修正の枝）・D1。深掘り Q12（祖先の印だけを数え、CI はその job を完全な履歴で取る）。深掘り Q7（欄の追加・削除・型・必須を、S-01 の型と収集アプリ 2 本の両方で落とす。意味だけの変化は版の履歴に理由を書く規則）。C3・C4。

意味だけの変化は機械では止まらない（どの選択でも同じ）。版の履歴の行に「版を上げた理由」を書くことで規則にとどめる。

#### Scenario: 収集アプリだけが欄を足して版を上げないと CI が落ちる

- **WHEN** 配った印の後に、携帯の収集アプリの記録に最上位の欄を 1 つ足し、送信契約の版を上げずに検査を走らせる
- **THEN** 検査は欄の追加と、版が上がっていないことを出して落ちる

#### Scenario: 既存の欄の型や必須を変えて版を上げないと CI が落ちる

- **WHEN** 配った印の後に、S-01 の記録の型の欄の型を変える・必須の欄を任意にする変更を、版を上げずに検査する
- **THEN** 検査は落ちる

#### Scenario: 欄を消して版を上げないと CI が落ちる

- **WHEN** 配った印の後に、S-01 の生存信号の型から最上位の欄を 1 つ消し、版を上げずに検査する
- **THEN** 検査は欄の削除と、版が上がっていないことを出して落ちる

#### Scenario: ベータ版の印も配った印として比べる

- **WHEN** ベータ版の印（`v0.1.0-beta.1`）だけがある木で、記録に欄を足し、版を上げずに検査する
- **THEN** 検査は落ちる

#### Scenario: 版の履歴に今の版の行が無いと CI が落ちる

- **WHEN** 版を 2 に上げ、3 つの値と写しをそろえたが、送信契約の文書の版の履歴に版 2 の行を書かずに検査する
- **THEN** 検査は、版の履歴の行が無いことを出して落ちる

#### Scenario: 配った印の写しを取り出せないと CI が落ちる

- **WHEN** 配った印はあるが、その印の版から封筒の形の写しを取り出せない木で検査する
- **THEN** 検査は、印の写しを取り出せないことを出して落ちる（黙って通らない）

#### Scenario: 版を上げれば欄を足しても通る

- **WHEN** 配った印の後に欄を足し、3 つの版の値と写しの版と版の履歴の行をそろえて 1 つ上げて検査する
- **THEN** 検査は通る

#### Scenario: 配った印が無い間は欄を足しても通る

- **WHEN** 配った印が 1 つも無い木で、記録に欄を足して写しを作り直し、版を 1 のまま検査する
- **THEN** 検査は通る

#### Scenario: 3 つの版の値が食い違うと CI が落ちる

- **WHEN** PC の収集アプリの送信契約の版だけを 2 にして検査する
- **THEN** 検査は、どの値が食い違っているかを出して落ちる

#### Scenario: 写しがコードとずれていると CI が落ちる

- **WHEN** PC の収集アプリの記録に欄を足し、写しを作り直さずに検査する
- **THEN** 検査は、写しを作り直す手順を出して落ちる

#### Scenario: 最後の配った印は、打った日時でなく祖先の中で版番号の最も大きい印

- **GIVEN** main の上で送信契約の版を 2 に上げた後に打った印 `v0.4.0-beta.1`（写しは版 2）と、その後に別の枝 `release/0.3` の上に打った印 `v0.3.1`（写しは版 1）がある木
- **WHEN** main の HEAD で、封筒に欄を 1 つ足し、送信契約の版を 2 のまま検査する
- **THEN** 検査は、印 `v0.4.0-beta.1` と比べて版が上がっていないことを出して落ちる

#### Scenario: 最後の配った印は、ベータ版の番号を数として比べて選ぶ

- **GIVEN** どちらも main の祖先にある印 `v0.4.0-beta.10` と、その後に打った印 `v0.4.0-beta.9`
- **WHEN** 最後の配った印を選ぶ
- **THEN** 選ばれるのは `v0.4.0-beta.10`

#### Scenario: 同じ版のベータ版と正式版では、正式版を最後の配った印に選ぶ

- **GIVEN** 同じ commit に付いた印 `v0.4.0` と、その後に付けた印 `v0.4.0-beta.2`
- **WHEN** 最後の配った印を選ぶ
- **THEN** 選ばれるのは `v0.4.0`

#### Scenario: 開発版の印 nightly は、最後の配った印に数えない

- **GIVEN** 配った印 `v*` が 0 個で、開発版の印 `nightly` だけがある木
- **WHEN** 記録に欄を足して写しを作り直し、版を 1 のまま検査する
- **THEN** 検査は通る

#### Scenario: 浅い木では、送信契約の版の検査は通らない

- **GIVEN** 印 `v0.1.0` を HEAD の 1 つ前の commit に持つ木を、深さ 1 で clone し、印だけを取り寄せた木（印は見えるが、祖先かどうかを辿れない）
- **WHEN** 送信契約の版の検査を走らせる
- **THEN** 終了コードは 0 でなく、出力に「履歴が浅い」を含む（印が 0 個として通らない）
