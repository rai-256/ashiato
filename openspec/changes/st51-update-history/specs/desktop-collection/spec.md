## MODIFIED Requirements

### Requirement: PC の収集アプリは、記録を未送信に積む時点で自分の版を焼き込み、溜めた行の欄を落とさない

THE SYSTEM SHALL C-02 が記録を未送信に積むとき、その時点の C-02 の組み立ての印を部品の版の欄に書き込む。
THE SYSTEM SHALL C-02 が生存信号を未送信に積むとき、その時点の C-02 の組み立ての印を、生存信号の欄 `client_version` と原文の `client_version` の両方に書き込む（★ ST51）。
THE SYSTEM SHALL 未送信を送るとき、積んだときの部品の版をそのまま送る（送る時点の版で書き換えない）。
THE SYSTEM SHALL 溜めた行を読み戻したとき、部品の版の欄が無ければ、今の版を入れずに欄の無いまま送る。
THE SYSTEM SHALL 溜めた行が今の C-02 の知らない欄を持っていても、その欄を捨てずに送る。
THE SYSTEM SHALL ブラウザ履歴を読み直して送る記録には、読み直した時点の C-02 の版を書き込む（中身を作った版。外部サービス由来の更新で版が動く）。
THE SYSTEM SHALL C-02 の組み立ての印を、組み立てのたびに作り直す（「組み立ての印は、版番号・commit・その部品のソースの未 commit の変更・組み立ての種類を持ち、組み立てのたびに作り直す」の形）。

導出元: FR-122、FR-121（★ ST51）。扉 #32・#33。FR-122 ★ 2026-10-25 訂正（送った時の版ではなく作った時の版）・FR-121 ★ 2026-10-25 訂正（収集アプリの版の変化は生存信号の申告で知る）。深掘り（ST49）Q1（推奨）。design（ST49）D1（仮）・D3（仮）・D13。深掘り（ST51）premises の C1・C3（design（ST51）D1（仮）・D6・D12）。
未送信は更新の後に送られるので、送る時点の版を付けると取り違えた版が作った記録に直した版が付く。
生存信号も同じく未送信に溜めて後から送る（premises（ST51）2）ので、積む時点の版を焼き込み、原文にも入れる（premises（ST51）3・4）。

#### Scenario: PC の収集アプリを更新した後に送った未送信は、積んだときの版で届く

- **WHEN** 組み立ての印 `0.1.0+<commit A>` の C-02 がウィンドウの記録を未送信に積み、送る前に印 `0.1.0+<commit D>` の C-02 で置き場を開き直して送る
- **THEN** 送った要求の部品の版は `0.1.0+<commit A>`

#### Scenario: PC の版の欄を持たない未送信の行は、版の欄の無いまま送られる

- **WHEN** 版の欄を足す前の形で積まれた未送信の行を、版の欄を知る C-02 が読み戻して送る
- **THEN** 送った要求に部品の版の欄は無く、壊れた行として退避されない

#### Scenario: PC の未送信の行が知らない欄を持っていても、送るときに落ちない

- **WHEN** 今の C-02 の知らない欄 `future_field` を持つ未送信の行を読み戻して送る
- **THEN** 送った要求に `future_field` が同じ値で載っている

#### Scenario: PC の生存信号は、積んだときの版を欄と原文に持つ

- **WHEN** 組み立ての印 `0.1.0+<commit A>` の C-02 がウィンドウの生存信号を未送信に積み、送る前に印 `0.1.0+<commit D>` の C-02 で置き場を開き直して送る
- **THEN** 送った生存信号の `client_version` は `0.1.0+<commit A>` で、原文の `client_version` も `0.1.0+<commit A>`

#### Scenario: PC の版の欄を持たない溜めた生存信号は、版の無いまま送られる

- **WHEN** 版の欄を足す前の形で積まれた生存信号を、版を載せる C-02 が読み戻して送る
- **THEN** 送った生存信号に `client_version` は無く、原文は積んだときのまま

#### Scenario: PC の収集アプリの組み立ての印は、commit を進めた後の差分の組み立てでも新しい commit になる

- **WHEN** C-02 を組み立てた後に commit を 1 つ足し、ソースに触れずにもう一度組み立てる
- **THEN** 2 回目の組み立てに埋め込まれた印の commit は、足した commit の 40 桁

#### Scenario: PC の収集アプリの印は、add していないソースの変更の後に .dirty になり、release では .debug を持たない

- **WHEN** 綺麗な木で C-02 を release で組み立てた後に、C-02 のソースを 1 つ書き換えて add せずに release でもう一度組み立てる
- **THEN** 1 回目の印は `<版番号>+<40 桁>` で終わり、2 回目の印は `.dirty` で終わる

#### Scenario: ブラウザ履歴を読み直して送る記録は、読み直した時点の版を持つ

- **WHEN** 印 `0.1.0+<commit A>` の C-02 が送ったブラウザ履歴の訪問を、印 `0.1.0+<commit D>` の C-02 が読み直して、題名の変わった記録を積む
- **THEN** 積んだ要求の部品の版は `0.1.0+<commit D>`
