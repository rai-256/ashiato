# ST51 の前提（外の形式・既存の振る舞い）

ST51 の決定は外のサービスの書き出しの形式には依らない。依るのは**この repo の収集アプリとサーバの今の振る舞い**（生存信号の送り方・溜め方・端末識別子・
S-01 の起動と移行の検査）と、OS の更新の振る舞い（アプリを上書きで入れ直しても手元のデータが残るか）。

**失われるもの（`loss`）のある問いが載る前提**: Q1 は 6・7・10、Q2 は 6・7 と `crates/server/src/lib.rs:305`（migrate は当てる前に退避を取る）。どれも既存のコードか正典を読んで辿った（確かさ 3）。
tasks の試験で 4 に上げる。
C1（すべての生存信号に今の版を載せる。旧 Q1）は 1〜5 に載る。**5 は確かさ 2**（走っている ST49 の版の印）で、ST51 は ST49 の実装の上に積む（C7。requires は spec の段で足す）。
C1 は失わない側（載せる回がいちばん多い）なので、5 が外れても選択は変わらない（載せる値の形が変わるだけ）。
8・9 は「同じ端末の版の変化として見えるか」の前提で、外れても生存信号の行と原文に版が残るので、**後から数え直せる**（Q3 の推奨が生存信号から導く形なのはこのため）。

## 聞かずに決めるもの（C。spec の段で design の D にする）

失わない側を選んだ C1・C2・C5・C6 は `provisional.jsonl` に D1〜D4 で載せた（独立検査が A と見たため。別の席の確かめはグラフの `provisional_review` が書く）。
Q3 の推奨は D5（仮）にする（R6）。

- **C1**（design D1（仮）。旧 Q1。review/deep.md R2 で P の条件を満たすと分かった）収集アプリ（C-01・C-02）は**すべての生存信号に、その信号を積んだ時に動いていた版**を載せる。
  送った時の版にしない（溜まった古い信号に新しい版が付き、偽の変化になる。FR-121 ★）。失わない側で、1 件 60 バイトほど。生存信号は端末の溜めの上限の対象外
  （`LocationService.kt:314`・`docs/collector-contract.md:525`）なので、捨てられて版が欠けることもない
- **C2**（design D2（仮）。旧 Q5。R5 で P と分かった）S-01 は **migrate の終わり（通った・落ちた）**と **S-01 の起動のとき**の両方で版の変化を知る。起動では、**版の検査（ST48）を通った後・待ち受けを開く前**に書く
  （検査より前に書くと、古い S-01 が新しい D-01 に書き、FR-117 に反する。R4）。どちらも直前の行の版と自分の版が違うときだけ書く。migrate が終了コード 3 で止まった回は書かない（正典 distribution）
- **C3** 版は生存信号の**任意の欄**（ST49 の取り込み口と同じ名前 `client_version`）と**原文**の両方に入れる。原文に入れるのは冪等キーが原文から作られるため（前提 4）と、
  ST51 より前の S-01 が欄を読み飛ばしても版が残るため（前提 3。R7）。導くときは欄を先に、無ければ原文を読む。値は文字列のまま、形を検査しない・断らない。版を持たない信号も今までどおり受け付ける
- **C4** 移行が落ちた行の後の「前の版」は、直前の**通った**行（か起動の行）の今の版にする。落ちた版は D-01 を動かしていない（R4）
- **C5**（design D3（仮））S-01 の版の変化の行は、記録の schema（`core`）の**追記のみの表**に置く（書き換えの門・実行時の役割には足すことだけを許す）。全記録の書き出しに分類して入れる（前提 10。R3）。
  ST51 の S-01 が初めて動いた回は、前の版を「不明（記録の始まり）」として 1 行書く
- **C6**（design D4（仮）。R11）S-01 の版の変化の表の列と、生存信号の版の欄の名前は、ST48 の版の記録と同じく **Requirement の表で名前・型・NULL の可否を固定**し、版をまたいで変えない（凍結した行の形は後から書き直せない）
- **C7**（R8）ST51 は ST49 の版の印（`<版番号>+<commit 40 桁>[.dirty][.debug]`）を読むだけで、印を作らない。ST49 の実装の上に積むので、spec の段で requires に ST49 を足す
- **C8** 収集アプリの版は申告で、S-01 は確かめない（ST49 の C2 と同じ）。S-01 の中の書庫の取り込み器が積む生存信号には版を載せない（取り込み器は S-01 の一部で、S-01 の版の変化は C5 の行が持つ）
- **C9** 稼働状況の格子の状態の判定・途絶の判定（FR-80）・途切れの通知は変えない（壊してはいけないもの）。更新の間の途絶を「途絶」でなくする規則は作らない
- **C10** 申し送り: ST58（更新の後に C-01 を起き直させる —— R10。戻した後に落ちた試みと戻したことの行を書き直す —— Q2 の推奨）、ST54（同じ PC に正式版と開発版の C-02 を並べるときに端末識別子を分ける —— 前提 9）。
  どちらもまだ tasks.md が無いので deferred
