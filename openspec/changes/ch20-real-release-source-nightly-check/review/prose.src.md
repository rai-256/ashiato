<!-- prose purpose -->
毎晩、サーバの更新係と PC の収集アプリが本物の配布元（GitHub の rai-256/ashiato のリリース）と話したときの振る舞いを機械が確かめ、食い違えば翌朝までに赤で分かるようになる。2026-11-19 に本人が見たエラーを直すことも、その種類を捕まえることも、この change は約束しない。

<!-- prose impact.overview -->
毎晩 1 回、別の workflow がサーバの更新係（配る形）と PC の収集アプリ（試験の組み立て）を本物の配布元に当て、正典の期待と食い違えば赤にする。本物が見せない状態はその晩の答えを流し直して作り、答えの形は偽の配布元の形の写しと比べる。直しの change が入るまでは、既に分かっている 3 つの食い違いで初日から毎晩赤になる。赤にするのは正典と食い違ったときだけで、開発版の道の 404 を記録し続けること（推奨の Q7）や、部品だけが配布元に届かない晩（3 晩続くまで）は赤にならない。PR ごとの CI は今のまま本物に問い合わせない。この分析では、今できていてできなくなることを見つけていない。

<!-- prose impact.problem -->
本人が配る形を入れて普通に使ったら、更新の確認がエラーを出し続けた。自動の試験はどれも偽の配布元を相手にしていて、本物の配布元と組み合わせた振る舞いは一度も機械で試されていなかった。問いを立てる中で、偽の配布元と本物はすでに 3 つずれていた。

<!-- prose impact.findings[IMP-01].title -->
直しの change が入るまで毎晩赤で、直しの change はまだ無い

<!-- prose impact.findings[IMP-01].text -->
既知の 3 つの食い違いで、初日から毎晩赤になる。直しの change は登録されておらず、申し送りの先も決まっていない（design の Risks は番号が決まってから申し送るとしている）。赤が当たり前になると、GitHub の失敗の知らせが毎朝届き、新しい赤を見落としやすくなる

<!-- prose impact.findings[IMP-02].title -->
共有の runner の IP で上限に当たる晩が多いと、本物の段がほとんど判定されないかもしれない

<!-- prose impact.findings[IMP-02].text -->
部品は資格情報なしで問い合わせるので、共有の runner の IP の 1 時間 60 回を他の利用者と分け合う。上限に当たる晩が多ければ、本物の今の状態の段は注意ばかりになり、続けば「3 晩続けて届かない」の赤になる。届かない晩が断続する（2 晩届かず 1 晩届く、の繰り返し）と、3 晩続かないので赤にならず、本物の段がほとんど見られないまま緑が続く

<!-- prose impact.findings[IMP-03].title -->
runner で配る形のインストーラを対話なしに通す手順は、まだ確かめていない

<!-- prose impact.findings[IMP-03].text -->
collect は install-check.sh の呼び方に合わせて配る形を入れるが、install-check.sh は呼ばない。合言葉の渡し方などがずれると、配る形の更新係の段が毎晩「記録が無い」の赤になる。更新係の配る形の段は依頼の中心で、確かめるのは merge の後の最初の実行になる

<!-- prose impact.findings[IMP-04].title -->
検査の側にだけ下書きのリリースが見えると、一覧の大きさの比べが部品と違う

<!-- prose impact.findings[IMP-04].text -->

<!-- prose impact.findings[IMP-05].title -->
既知の食い違いを部品と場合の組だけで名指しするので、同じ組の新しい赤が既知の節に埋もれる

<!-- prose impact.findings[IMP-05].text -->
要約の「既に分かっている食い違い」は、部品と場合の組（collector の status-503・shape の 1 件の道など）で名指しする。同じ組で実際が変わった赤（503 に記録が無い・時間切れになった）や、1 件の道で本物の項目が消えた赤も既知の節に入り、「それ以外の赤が空」を見る読み方では見落とす。1 件の道の形の変化は、この検査が拾いたいものそのもの

<!-- prose impact.findings[IMP-06].title -->
開発版の部品が 404 を記録し続けても、この検査では緑（Q7 の答えで変わる）

<!-- prose impact.findings[IMP-06].text -->
推奨の Q7 では、開発版の道の 404 に「配布元が見つからない」と記録すれば緑で、要約に食い違いの 1 行が出るだけ。依頼の「エラーを記録し続けない」は、この検査では赤にならない。本人が見たエラーに近い種類（失敗を記録し続ける）が緑で通る

<!-- prose impact.findings[IMP-07].title -->
検査の側が 200 を取れた晩に部品だけが届かないと、製品の通信の不具合が 3 晩まで注意に隠れる

<!-- prose impact.findings[IMP-07].text -->
PC の収集アプリは、証明書の確かめの失敗・別の宛先への転送・知らない状態コードなどもまとめて「配布元に届かない」と記録する。部品がそう記録した本物の段は、検査の側が同じ晩に 200 を取れていても比べずに注意にする。製品の側の通信の不具合（本人の「エラーが出続ける」に近い種類）が、3 晩続くまで赤にならず、断続すれば赤にならない

<!-- prose impact.findings[IMP-08].title -->
毎晩の検査そのものが止まっても、何も知らせない

<!-- prose impact.findings[IMP-08].text -->
