# 仮で進めた決定の確かめ（ST23 st23-record-erasure）

## D2
- 判定: 否
- 根拠: 条件 2（`cost` が成り立たない）。`cost` は「その滞在の本文を消したければ、本人がその行の『本文ごと消す』をもう 1 回押す」だが、別に消した滞在 B が指定した滞在 P の時間に**すっぽり入る**とき（例: P 10:00–11:00・B 10:15–10:45）、押す行が無い。
  1 日の行は重なる部分を「本文ごと消した」が持ち、「消した」の区間はその分を差し引く（design.md:215、browsing-views spec:54-56、Scenario「…重なる消した時間は差し引いて出る」spec:101）。B の区間を引くと何も残らないので、B の識別子を持つ「消した」の行が出ず、「本文ごと消す」も「戻す」も押せない。
  B を本文ごと消す口（`POST /stays/purge`、design.md:52）は API にはあるが、画面から届く道が無い。このため B の本文（P の場面の重心の座標）は DB に残り続け、Q2 で本人が選んだ答えの detail「消した場面の座標は DB の本文に残らない」（deep-questions.json Q2 推奨）が成り立たない。
  B ⊂ P の Scenario は spec にも tasks.md:134-142 にも無い。道を足す（差し引いて空になった B の行を残す・P の確認で B も名指す、など）と、design D12 と画面を変えることになり、仮の範囲を越える。広く取る側（B も入れる）は R2 の失い方（B の連鎖が戻せず、本文ごと消すこともできない）を持つので、どちらの側にも費用がある。
  ほか: 条件 1（`chosen` で失うもの）は無い。B の連鎖の位置は、原因 P の行を持つ分が P と一緒に消え、B を戻すと `blocked_by_other_cause` として 409 の数から除かれる（design.md:150-151、deletion.rs:133-146）。
  条件 4: 土台の D12（区間の差し引き）が `rests_on` に無い。
  付記（D2 の向きに依らない）: 吸収された滞在 A を `user:purged` に付け替えると `Mark::of` が `UserDeleted` と読み（stay_store.rs:258-266）、`feelings::resolve_stay` が None を返す（feelings.rs:457-459）。A から吸収先の生きた滞在へたどって出ていた気分が出なくなる。気分の行も吸収の台帳も残るので、戻しようはある。

## D13
- 判定: 確か
- 根拠: 条件 1（失わない）: 広げない側では、はみ出しの時間に後から届いた位置は印の無い生きた記録として入り、本文を消さない。`user:purged` は消した時間帯のどの読み手にも窓として入らない。
  入らないことは design と tasks が押さえている。消した時間帯のビューは出さない（design.md:123、tasks.md:70）。`user_erased_stay_sql` を使う `mark_late_*` はビュー越しに読む（tasks.md:69）。作り直しは、いまは `Mark::UserDeleted` を窓にしている（stay_store.rs:574-578。`user:purged` もここに入る）が、`load_existing` が `raw = ''` を候補から外す（design.md:148、tasks.md:69）。書き出しの除外はビューから読む（export/excluded.rs:197-204）。試験は spec:318 の Scenario。
  条件 2（費用）: 安く、範囲を越えず、要件の本文を変えない。spec:303 の文言は Q3 の問い「本文ごと消した滞在の時間帯」と同じ向き。
  条件 3: `follows` は無い。
  条件 4: 土台の D5 / D6（`user:purged` を窓から外す）は design の中にあり、仮の中身ではない（D6 の仮の中身は戻す口の断り方。design.md:154）。
  直すもの（D13 の向きには効かない）: design.md:108 の `core.erasure_operation.end_at`「（D13 の和の外側）」が、D13 の「和にしない」と食い違っている。追記のみの行に何を凍結するかを design で揃えること。値は `core.erasure_span` から計算し直せるので、失うものは無い。

## D17
- 判定: 否
- 根拠: 条件 2（`cost` が成り立たない）。`cost` は「本人がその滞在を消して本文ごと消せば消える」だが、本人がそうする前に次の作り直しが通ると、その道は閉じる。
  作り直しが通ると、消した位置から作られた印の無い滞在 L は、点が消えているので新しい滞在に割り当てられない。このため `rebuild:absorbed` か `rebuild:erased-range` が付いて隠れる（stay_store.rs:574-616 の `assign` → `absorb`、`touches_erased`）。
  隠れた後は 3 つの道がすべて閉じている:
  (a) 一覧に出ないので押せない（browsing-views spec:50-56。行は本人が消した滞在の識別子だけを持つ）
  (b) ST22 の消す口は削除済みの滞在に 0 件で返す（deletion.rs:258-266）
  (c) 本文ごと消す口は作り直しの印だけの滞在を 409 `not_erased` で断る（design.md:56）。P をもう一度本文ごと消しても、範囲を集め直さず 0 件で返る（design.md:57）
  このため L の本文（消した場面の座標）は残り続け、Q2 で本人が選んだ答えの「消した位置から作られていた滞在も消す・座標は DB の本文に残らない」（deep-questions.json Q2 推奨の detail）が成り立たない。
  消せるようにするには、隠れた後に重なる滞在の本文を消す道（D8 / D9 の後着の位置と同じ見回りを滞在にも掛ける、など）を足すことになり、design と spec の Requirement（spec:139-148）を変える。仮の範囲を越える。入れる側（D17 の反転）は R5 の失い方（一覧に見えている滞在の本文を消す）を持つので、本人に問うのが筋。
  ほか: 条件 1（`chosen` で失うもの）は無い。条件 3: `follows` は無い。
  条件 4: 土台の D1（2 度押しは 0 件、作り直しの印だけの滞在は 409）と、作り直しが割り当てられない滞在を隠すこと（ST16 の吸収）が `rests_on` に無い。
