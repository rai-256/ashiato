# ST23 の深掘り — 聞かずに決めるもの（C）

第 1 回の問い（`deep-questions.json`）と一緒に本人に見せる。どれも「片方の選択肢が扉を開けたままにし、費用が小さい」か、
既に本人が決めたことの帰結で、問いにしない。異論があれば問いの HTML の補足に番号で書く。
`record` の段がこの表を `deep.md` の「確かめたが問わなかったこと」に写し、`spec` の段が `design.md` の D 番号に残す。

| # | 論点 | 当てた既定 | 聞かない理由 |
|---|---|---|---|
| C1 | 本文を消した後に何を残すか | **識別子・ソース・出来事の時刻・内容の鍵（`content_hash`）・端末・取り込みの時刻は残す**。原文と解析済みだけを空にする（ST03 の消去の形のまま） | 壊してはいけないもの「消したものが再流入しない」。鍵を消すと再送と書庫の読み直しが生きた記録として戻る。鍵は塩の無い SHA-256 なので、候補の原文を持つ人は照らせる（premises.md）が、鍵に塩を足すと全ソースの鍵が変わる（全行の書き直し）。残す側は何も失わない |
| C2 | 「消した」でない記録を本文ごと消せるか | **本文を消す記録には、必ず削除の印も付ける**（画面の口がどこにあっても、中では「消した」にしてから消す）。ST22 の「戻す」は、本文ごと消した記録を含む時間帯を断る。**本文を消した滞在の印は本人の印（`rebuild:` で始まらない値）に付け替え**、作り直しは本文を消した滞在を一致の候補にしない（吸収された滞在・時間帯で隠した滞在も同じ。review R18） | 削除の印があれば、再流入・外部の更新・作り直しを止める既存の規則（ST03 / ST16 / ST22）がそのまま効く。印の無い空の記録は、どの規則も想定していない |
| C3 | 台帳に何を残すか（FR-51 の「事実・時刻・件数・範囲」） | **1 操作 1 行の「消去の操作」の行を、追記のみの台帳に足す**（指示した対象（滞在の識別子と時間帯）・ソースごとの件数・前の版の件数・時刻）。記録ごとの既存の消去の台帳（`core.erasure_ledger`）の行を、その操作に結ぶ。台帳を見る画面は作らない（一覧の「本文ごと消した」行が事実を出す）。**範囲は始まりと終わりを `timestamptz` のまま持つ**（丸めない）。行の形は固定の値で試験し、読めない行は「0 件・範囲なし」と読まず厳しい側（除く・数えられない）に倒す（review R6） | 「台帳は追記のみ」「細かい粒度で持つ」の既定。いまの台帳は記録ごとの行だけで、範囲と操作のまとまりを持たない |
| C4 | 途中で落ちたら | **本文の消去・前の版の消去・台帳の行は 1 つのまとまり**（DB の門が強制する）。落ちたら何も消えない。作り直しと同じ錠を取る（ST22 の C6） | FR-51 と ST03 の門のまま |
| C5 | 滞在（派生）の本文の消去 | **滞在の本文を空にする書き換えにも、台帳の行を要る門を掛け、親を消すなら全部の前の版も同じまとまりで消すことを求める**（ST03 の R40 と同じ形）。作り直しの書き換えは今までどおり通すが、**本文を消した行（`raw = ''`）へ本文を書き戻すことは拒む**（review R14 / R18） | いまは派生の行が門を素通しする（premises.md）。FR-51「台帳の行が無い消去は DB が拒む」が滞在に及んでいない |
