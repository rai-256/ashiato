## ADDED Requirements

### Requirement: zip の部品の版を上げても、前の版で書いた書き出しの zip を同じに読み、同じ AES の形で書く

THE SYSTEM SHALL zip の部品の版を上げた後も、上げる前の版（zip 2.6.1）で書いた書き出しの zip を、その合言葉で全部の項目を書いたときと同じ中身で読み、
zip の注記（`ashiato-export <書き出しの id>`）もそのまま読む。違う合言葉ではどの項目の中身も読めない。
THE SYSTEM SHALL 上げた後に書く書き出しの zip の各項目を、上げる前の版と同じ AES の形で書く: 中央ディレクトリの AES の追加の欄（`0x9901`）の
強さが 256 ビット（`3`）、実の圧縮方式が deflate（`8`）、AE-1 / AE-2 の別が同じ内容の同じ項目で上げる前の版と同じ。
この形は、zip の部品を使わずに zip のバイト列から読んで確かめる（部品の版が変われば、部品の読み方も一緒に変わりうる）。
導出元: CH24

置き場に残っている書き出しは上げる前の版で書いたものでありうり、書き出しの台帳の照合（注記を読む）もそれを読む。
今の試験は書くのも読むのも同じ版の部品なので、版の間の互換は見ていなかった。

#### Scenario: 前の版の zip の部品で書いた書き出しの zip を、上げた後の版で同じ中身に読める
- **WHEN** 試験が、上げる前の版（zip 2.6.1）の書き出しで書いた zip のバイト列（試験に埋め込んだもの）を、上げた後の版で開き、決まった合言葉で全部の項目を読む
- **THEN** 全部の項目が読め、項目の名前の並びと、項目ごとの中身の SHA-256 が、書いたときに記録した値と一致する
- **AND** zip の注記は `ashiato-export ` で始まり、続く書き出しの id が書いたときの値と一致する
- **AND** 違う合言葉では、どの項目の中身も読めない

#### Scenario: 上げた後に書いた書き出しの zip の項目は、前の版と同じ AES の形で書かれる
- **WHEN** 試験が、埋め込んだ zip を書いたときと同じ記録を置いた試験の DB から上げた後の版で書き出し、書いた zip と埋め込んだ zip の中央ディレクトリの各項目の AES の追加の欄（`0x9901`）を、zip の部品を使わずにバイト列から読む
- **THEN** 2 つの zip の項目の名前の集まりは同じで、どの項目も強さが `3`（256 ビット）・実の圧縮方式が `8`（deflate）である
- **AND** 同じ名前の項目の AE-1 / AE-2 の別（vendor version）が 2 つの zip で同じである
