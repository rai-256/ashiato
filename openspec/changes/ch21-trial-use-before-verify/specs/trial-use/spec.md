## Purpose

確認バッチの手順書が人間に渡る前に、確認バッチの準備が配る形をまっさらな Windows に入れ、Claude が筋書きなしで普通の利用者として使ってみる席を走らせること。
何を組み・何を渡し・どこで止め・何を手元に残し・手順書に何を載せ、何を外に出さないかの約束。人間が最初の利用者にならないための開発の道具で、製品の振る舞いではない。

## ADDED Requirements

### Requirement: 確認バッチの準備は使ってみる席を呼び、席がどう終わっても準備を続ける

WHEN 確認バッチの準備（`tools/verify-prep.sh <tag>`）が、いまの成果物（サーバ・画面・携帯の APK・`run.sh`）と manifest の既存の段落を作り終えたとき、
THE SYSTEM SHALL 使ってみる席の入口を呼び、その結果を manifest の 1 段落（語「使ってみた」で始まる）として、既存の段落の後に足す。
THE SYSTEM SHALL 席の入口を、本体が非 0 で終わっても・途中で止まっても rc=0 で終わらせ、manifest の既存の段落を変えさせない。そのとき足す段落は、席が走らなかった・落ちた理由を 1 つ名指しする警告にする。
THE SYSTEM SHALL 準備の台本に、入口の失敗を受け止めさせ（入口が非 0 でも準備を止めない）、`run.sh` と manifest の既存の段落をいまと同じに残させる。
THE SYSTEM SHALL 手元に Windows Sandbox が無い（Windows の PowerShell が無い・Sandbox の実行ファイルが無い）ときは席を走らせず、その理由を警告の段落に書く。
導出元: CH21（依頼「落ちても確認バッチは止めない（警告として手順書に書く）」・深掘り Q9 の族）

#### Scenario: 席の本体が落ちても、入口は rc=0 で既存の段落を変えず警告の段落を足す
- **WHEN** 既存の形の manifest を置いた一時の木で、本体を必ず非 0 で終わる偽のものに替えて席の入口を呼ぶ
- **THEN** 入口は rc=0 で、manifest の既存の段落は呼ぶ前とバイト単位で同じである
- **AND** manifest の最後の段落は「使ってみた」で始まり、本体が落ちたことと本体の rc を含む

#### Scenario: Windows Sandbox が無い機械では、席を走らせず理由を書く
- **WHEN** Windows の PowerShell が見つからない環境と、PowerShell はあるが Sandbox の実行ファイルが無い環境で、それぞれ席の入口を呼ぶ
- **THEN** どちらも、Sandbox を起こす命令も配る形を組む命令も打たずに rc=0 で終わる
- **AND** どちらの段落も「使ってみた」で始まり、Windows Sandbox が無いので走らせていないことを書く

#### Scenario: 準備の台本は、席を既存の段の後に 1 か所でだけ呼び、その失敗で止まらない
- **WHEN** `tools/verify-prep.sh` を読む
- **THEN** 席の入口を呼ぶ行はちょうど 1 つで、manifest の既存の段落を書く段より後にあり、同じ行で入口の非 0 を受け止めている（`||` で続く）

#### Scenario: 本物の確認バッチで、手順書の冒頭に使ってみた段落が載る
- **WHEN** 手元の機械で確認バッチ（`scripts/hx verify`）が作られる
- **THEN** 手順書の冒頭の manifest の段落に「使ってみた」で始まる段落があり、件数と題（0 件なら巡った目的）と手元の報告の場所か、走らせなかった・落ちた理由が書かれている
- **AND** 手元の報告の場所を開くと、報告の HTML がある

### Requirement: 席が入れて使うのは、確認バッチの木から組んだサーバの zip と PC の収集アプリの zip

THE SYSTEM SHALL 席に、確認バッチの木（準備が走っている木の HEAD）から Windows のサーバの zip と PC の収集アプリの zip の 2 つを組ませ、その 2 つだけを Sandbox に渡させる。
THE SYSTEM SHALL 組み立てに上限（既定 60 分）を設けさせる。2 つのどちらかを組めなかった・上限を越えたときは、Sandbox を起こさずに席を終え、組めなかったことと理由（組み立ての rc か上限）を警告の段落に書かせる。
THE SYSTEM SHALL 携帯の収集アプリ（APK）を Sandbox に渡させない。
導出元: CH21（依頼「Claude が配る形（Windows の配る zip）を入れ」「携帯の収集アプリはこの change の外」・深掘り Q1・Q2）

#### Scenario: 席が Sandbox に渡すのは、この木から組んだ 2 つの zip だけ
- **WHEN** 配る形の組み立てを、呼ばれた木の commit を書き留めて決まった名前の zip を 2 つ置く偽のものに替えて席を走らせる
- **THEN** 書き留めた commit は準備が走っている木の HEAD である
- **AND** Sandbox に読みだけで渡す材料の置き場の zip は、サーバの zip と PC の収集アプリの zip の 2 つだけで、`.apk` は無い

#### Scenario: 配る形を組めなければ、Sandbox を起こさずに警告を書く
- **WHEN** 配る形の組み立てを必ず非 0 で終わる偽のものに替えて席を走らせる
- **THEN** Sandbox を起こす命令は 1 回も打たれない
- **AND** 段落は「使ってみた」で始まり、配る形を組めなかったことと組み立ての rc を含む

#### Scenario: 組み立てが上限を越えれば、組めなかったとして終える
- **WHEN** 組み立ての上限を 2 秒にし、眠り続ける偽の組み立てで席を走らせる
- **THEN** 席は上限から 60 秒以内に rc=0 で終わり、Sandbox を起こす命令は打たれない
- **AND** 段落は、組み立てが上限を越えたので組めなかったことを書く

### Requirement: 席は自分の Sandbox だけを起こして閉じ、網を開けて起こす

THE SYSTEM SHALL 席が同時に 1 つしか走らないよう、手元の置き場の錠を取らせる。取れなければ（別の席が走っている）Sandbox を起こさず、そのことを警告の段落に書かせる。
THE SYSTEM SHALL 席が Sandbox を起こす前に、手元で Windows Sandbox が既に動いていないかを確かめさせる。動いていれば、起こさず・閉じず（本人や録画のものかもしれない）、そのことを警告の段落に書かせる。
THE SYSTEM SHALL 席が起こした Sandbox を、席が正常に終えたときも・失敗したときも・時間の上限で打ち切ったときも、席の終わりまでに閉じさせる（直後の録画が「別の Sandbox が動いている」で止まらないように）。閉じた後にも残っていれば、そのことを段落に書かせる。
THE SYSTEM SHALL 席の Sandbox を、網を開けた設定で起こさせる（本人の PC と同じに、更新の確認が配布元に問い合わせられる）。
導出元: CH21（依頼「場所は Windows Sandbox」・深掘り Q10・Q12・deep-review R6・R7）

#### Scenario: 別の席が走っていれば、Sandbox を起こさず警告を書く
- **WHEN** 手元の置き場の錠を別のプロセスが持っている状態で席を走らせる
- **THEN** Sandbox を起こす命令は 1 回も打たれず、席は rc=0 で終わる
- **AND** 段落は「使ってみた」で始まり、別の席が走っていたので走らせていないことを書く

#### Scenario: Sandbox が既に動いていれば、起こさず閉じず警告を書く
- **WHEN** 動いている Sandbox を 1 つ返す偽の問い合わせのもとで席を走らせる
- **THEN** Sandbox を起こす命令も閉じる命令も 1 回も打たれず、席は rc=0 で終わる
- **AND** 段落は「使ってみた」で始まり、別の Sandbox が動いていたので走らせていないことを書く

#### Scenario: 席が起こした Sandbox は、どう終わっても閉じる
- **WHEN** 偽の Sandbox と偽の Claude で、Claude が正常に終わる・非 0 で終わる・時間の上限を越える、の 3 通りに席を走らせる
- **THEN** 3 通りとも、席が終わった時点で偽の Sandbox は動いていない（閉じる命令が席の起こした 1 つに打たれている）

#### Scenario: 閉じても残った Sandbox は、段落に書く
- **WHEN** 閉じる命令を受けても動き続ける偽の Sandbox で席を走らせる
- **THEN** 席は rc=0 で終わり、段落は Sandbox が閉じずに残っていることを書く

#### Scenario: 席の Sandbox の設定は網を開けている
- **WHEN** 席が Sandbox を起こすのに書いた設定（`.wsb`）を読む
- **THEN** `Networking` は `Disable` でない

### Requirement: 席が Claude に使わせる時間の上限は 45 分で、越えたらそこまでの候補で閉じる

THE SYSTEM SHALL 席が Claude に使わせる時間に上限（指定が無ければ 2700 秒 = 45 分）を設けさせ、越えたら Claude を止め、それまでに Claude が書いた候補と見たものから報告を作らせ、Sandbox を閉じさせる。
THE SYSTEM SHALL 打ち切ったときの段落に、時間の上限で打ち切ったことと、そこまでの件数を書かせる。
THE SYSTEM SHALL Claude が動けなかった（非 0 で終わり候補が 1 件も無い。利用上限・認証切れ・起動できない）ときは、そのことを警告の段落に書かせ、同じ回の中で Claude を起こし直させない。
THE SYSTEM SHALL Claude が使っている間、Sandbox の中のサーバが応えるか（`healthz`）を席の道具に定期に問わせて記録させ、回の間に一度も応えなかったときは「インストールまで届かなかった」を段落に書かせる（候補とは別の警告。候補の数に入れない）。一度でも応えた回は、後でアンインストールしても届いたとみなす。
導出元: CH21（深掘り Q9 とその落ち方の族・deep-review R5・R7）

#### Scenario: 時間の上限を越えると、それまでの候補で報告を作って閉じる
- **WHEN** 上限を 2 秒にし、根拠の揃った候補を 1 件書いてから眠り続ける偽の Claude で席を走らせる
- **THEN** 席は上限から 60 秒以内に rc=0 で終わり、偽の Claude は動いていない
- **AND** 段落は時間の上限で打ち切ったことを書き、候補の件数は 1 である

#### Scenario: 上限を指定しなければ、Claude に許す時間は 2700 秒である
- **WHEN** 上限を指定せずに、受け取った上限を書き留める偽の時間の包みで席を走らせる
- **THEN** 書き留めた上限は 2700 秒である

#### Scenario: Claude が動けなければ警告を書き、起こし直さない
- **WHEN** 候補を書かずに非 0 で終わる偽の Claude で席を走らせる
- **THEN** 席は rc=0 で終わり、偽の Claude が使うために起こされたのは 1 回だけである
- **AND** 段落は「使ってみた」で始まり、Claude が動けなかったことを書く

#### Scenario: インストールまで届かなければ、候補とは別の警告として書く
- **WHEN** サーバが回の間に一度も応えなかったと記録する偽の Sandbox と、根拠の揃った候補を 1 件書く偽の Claude で席を走らせる
- **THEN** 段落はインストールまで届かなかったことを書き、候補の件数は 1 である

#### Scenario: 一度応えた後に消された回は、インストールまで届いたとみなす
- **WHEN** サーバが一度応え、その後は応えなくなった（アンインストールした）と記録する偽の Sandbox で席を走らせる
- **THEN** 段落はインストールまで届かなかったことを書かない

### Requirement: Claude に渡すのは利用者の目的と配る形と合成の書き出しだけ

THE SYSTEM SHALL 席が Claude に渡す材料を、利用者の目的の一覧・配る 2 つの zip・取り込みに渡す合成の書き出しだけにさせる。Sandbox の中で動く席の道具は、材料とは別の置き場に置く。
仕様（`openspec/`）・Scenario・コード（`crates/`・`web/`・`collector-android/`）・試験・前の回の報告・開いている issue の一覧は、材料の置き場にも Claude の作業場所にも置かない（既知の印の照合は Claude が使い終えた後に行う）。
THE SYSTEM SHALL Claude を、リポジトリの外の作業場所で、リポジトリのパスを引数に持たせず、許す道具をブラウザを操る道具・Sandbox への頼みの道具・候補の置き場への書き込みに限って起こさせる。
THE SYSTEM SHALL 目的の一覧に、手順・巡る順・押す場所を書かせず、依頼の対象ごとの札（`install` `password` `login` `import` `browse` `settings` `update-check` `uninstall` `reinstall` `pc-collector`）を 1 つずつ持つ目的を、利用者の言葉で含ませる。
THE SYSTEM SHALL 数日分の記録を、利用者の口（取り込みに合成の書き出しを渡す・PC の収集アプリを動かす）だけで作らせる。DB へ直に入れる道具（偽データの台本）は材料に入れず、Sandbox の時計やタイムゾーンを変える頼み（`Set-Date`・`Set-TimeZone`・`w32tm`・`tzutil`・コマンドプロンプトの `date` / `time` の命令）は断る。時刻を読むだけの頼みは届ける。
導出元: CH21（依頼「何を触るかは筋書きにしない（Scenario の写しにならないこと）」・深掘り Q4・Q5）

#### Scenario: 材料の置き場と Claude の作業場所には、目的と zip と合成の書き出しのほかに何も無い
- **WHEN** 偽の Sandbox で席を走らせ、Claude に渡した材料の置き場と、偽の Claude が起こされた作業場所のファイルを全部並べる
- **THEN** どちらにあるのも目的の一覧・2 つの zip・合成の書き出し（と、作業場所では Claude が書いた候補）だけで、`openspec`・`crates`・`web`・`collector-android`・`seed` の名前を持つものも、`spec.md` も、前の回の報告も無い

#### Scenario: Claude はリポジトリの外で、限った道具だけで起こされる
- **WHEN** 起こされた引数と作業場所を書き留める偽の Claude で席を走らせる
- **THEN** 作業場所はリポジトリの外で、引数にリポジトリのパスは無い
- **AND** 許す道具の指定にあるのは、ブラウザを操る道具・Sandbox への頼みの道具・候補の置き場への書き込みだけで、Read と任意の Bash は無い

#### Scenario: 目的の一覧は、依頼の対象の札を全部持ち、手順を書かない
- **WHEN** 席が渡す目的の一覧を読む
- **THEN** `install` `password` `login` `import` `browse` `settings` `update-check` `uninstall` `reinstall` `pc-collector` の札がそれぞれちょうど 1 回ある
- **AND** 番号つきの手順の行（`1.` `2.` …）も、`/` で始まる URL の道も、「」で囲んだ画面の文言も無い

#### Scenario: Sandbox の時計を変える頼みは断る
- **WHEN** Sandbox への頼みの道具に、`Set-Date`・`Set-TimeZone`・`w32tm`・`tzutil`・コマンドプロンプトの `date` の命令をそれぞれ 1 つずつ含む頼みを渡し、続けて `Get-Date` と `Invoke-WebRequest -TimeoutSec 5` を含む頼みを渡す
- **THEN** 前の 5 つは Sandbox に届けられずに非 0 で終わり、時計を変える頼みは断ると書く
- **AND** 後の 2 つは Sandbox に届けられる

### Requirement: 違和感の候補は利用者に見えたものだけで、根拠の欠けたものは数えない

THE SYSTEM SHALL 席に、Claude が書いた候補を 1 件ずつ機械で確かめさせ、次の 4 つの根拠が全部ある候補だけを「候補」として数えさせる:
画面の写し（手元の置き場にあるファイル）・直前の操作の列（1 つ以上）・期待したことと見えたこと（どちらも空でない）・同じ操作をもう 1 回したときに起きたか（起きた / 起きなかった）。
根拠が欠けた候補は数えず、報告の別の節（根拠が欠けたもの）に残させる。
THE SYSTEM SHALL もう 1 回で起きなかった候補に「1 回だけ」の印を、開いている「違和感」の issue と同じだと照合した候補に「既知: #<番号>」の印を付けさせ、既知の候補は数に入れさせない。
THE SYSTEM SHALL Claude が Sandbox に固有の違い（ダウンロードの印が無い・Tailscale が無い・遅い・書き出しが小さい）に依ると書いた候補に「Sandbox だから」の印を、待ち時間の候補の題に「（Sandbox で測った）」を付けさせる。
THE SYSTEM SHALL 候補の題を 1 行・60 文字までにさせ、私的な値の形（`tools/check-private.sh` が拾う形）に当たる部分は伏せ字にさせる（元の題は手元の報告にだけ残す）。
THE SYSTEM SHALL 候補を「1 回だけ」でないもの、次に「1 回だけ」のものの順に並べ、手順書に出す候補を上から 10 件までにさせる。10 件を越えた分も、手元の報告には全件を残させる。
導出元: CH21（依頼「誤検知で人間を疲れさせないよう、候補には根拠を添える」・深掘り Q6・Q5 の context・Q7）

#### Scenario: 4 つの根拠のどれが欠けても、候補は数えず報告の別の節に残す
- **WHEN** 根拠の揃った候補 1 件と、画面の写し・操作の列・期待と見えたこと・もう 1 回の結果をそれぞれ 1 つずつ欠いた候補 4 件を書く偽の Claude で席を走らせる
- **THEN** 段落の件数は 1 で、手元の報告の「根拠が欠けたもの」の節に 4 件ある

#### Scenario: もう 1 回で起きなかった候補には「1 回だけ」の印が付く
- **WHEN** もう 1 回で起きた候補と起きなかった候補を 1 件ずつ書く偽の Claude で席を走らせる
- **THEN** 段落の件数は 2 で、起きなかった候補の題にだけ「1 回だけ」の印がある

#### Scenario: 既知と照合した候補は数えず、印を付けて手元に残す
- **WHEN** 2 件の候補のうち 1 件を開いている issue #900 と同じと返す偽の照合で席を走らせる
- **THEN** 段落の件数は 1 で、手元の報告にもう 1 件が「既知: #900」の印で残る

#### Scenario: 「1 回だけ」でない候補が先に並ぶ
- **WHEN** 「1 回だけ」の候補を先に、もう 1 回で起きた候補を後に書く偽の Claude で席を走らせる
- **THEN** 段落の題の並びは、もう 1 回で起きた候補が先である

#### Scenario: Sandbox に固有の違いと待ち時間には印が付く
- **WHEN** Sandbox に固有の違いに依ると書いた候補と、待ち時間の候補を 1 件ずつ書く偽の Claude で席を走らせる
- **THEN** 前の候補の題には「Sandbox だから」の印があり、後の候補の題には「（Sandbox で測った）」がある

#### Scenario: 題は 1 行 60 文字までで、私的な値の形は伏せる
- **WHEN** 改行を含む 120 文字の題と、私設の IP の形を含む題の候補を書く偽の Claude で席を走らせる
- **THEN** 段落のどの題も 1 行・60 文字以下で、私設の IP の形は段落に無い
- **AND** 手元の報告には元の題が残る

#### Scenario: 候補が 10 件を越えても、手順書には 10 件、手元には全件
- **WHEN** 根拠の揃った候補を 13 件書く偽の Claude で席を走らせる
- **THEN** 段落に並ぶ題は 10 行で、件数は 13 と書かれている
- **AND** 手元の報告には 13 件の候補がある

### Requirement: 見たものと候補の全件は手元に置き、手順書には件数と題と場所だけを載せる

THE SYSTEM SHALL 席に、画面の写し・Sandbox を閉じる前に取り出したログ（サーバ・同梱の DB・更新係・インストーラ）・候補の全件の本文と根拠・Claude の操作の記録を、手元の置き場（`C:\dev\ashiato2-trial-use\<tag>\`。リポジトリの外）に置かせ、報告を 1 枚の HTML にさせる。取り出せなかったログは、報告に取り出せなかったと書かせる。
THE SYSTEM SHALL Sandbox を起こした回は、警告で終わったときも、そこまでの写しとログで報告の HTML を作らせる。
THE SYSTEM SHALL manifest の段落（手順書では 1 行に潰れる）に、件数・各候補の題（区切り記号で並べる）・巡った目的の札（目的の一覧の札だけ。Claude の書いた文ではない）・所要の分・終わり方（決まった語）・手元の報告の場所だけを載せさせる。
候補の本文・根拠・画像・ログの中身・Claude の書いた自由な文（題を除く）は、manifest にもリポジトリの追跡するファイルにも書かせない。
THE SYSTEM SHALL 候補が 0 件のときも、0 件であることと巡った目的の札を段落に書かせる（走ったのに何も見なかったのか、見て何も無かったのかを分ける）。
導出元: CH21（依頼「出すもの: 見たもの（画面の写し・ログ）と『違和感の候補』の一覧」・深掘り Q7・Q13。このリポジトリは公開で、手順書は commit され PR の本文にも写る）

#### Scenario: 手順書の段落には件数と題と札と場所だけが載る
- **WHEN** 本文・根拠・巡った目的の説明に決まった目印の文字列を入れた候補を 2 件書く偽の Claude で席を走らせる
- **THEN** 段落に件数 2・題 2 行・巡った目的の札・手元の報告の場所がある
- **AND** 段落にも、リポジトリの追跡するファイルの差分にも、目印の文字列と画像のファイル名は無い

#### Scenario: 見たものとログは、手元の置き場に残る
- **WHEN** 偽の Sandbox がサーバ・DB・更新係・インストーラのログと画面の写しを出力の置き場に書いて終わる
- **THEN** 手元の置き場の `<tag>` の下に、報告の HTML と 4 つのログと画面の写しがある

#### Scenario: 取り出せなかったログは、報告に書く
- **WHEN** 偽の Sandbox が更新係のログだけを書かずに終わる
- **THEN** 手元の報告は、更新係のログを取り出せなかったことを書く

#### Scenario: 警告で終わった回も、そこまでの写しで報告を作る
- **WHEN** 画面の写しを 1 枚書いてから非 0 で終わる偽の Claude で席を走らせる
- **THEN** 手元の置き場に報告の HTML があり、その写しを載せている

#### Scenario: 候補が 0 件でも、巡った目的を書く
- **WHEN** 目的の札を 3 つ巡ったと書き、候補を書かずに終わる偽の Claude で席を走らせる
- **THEN** 段落は件数 0 と、巡った目的の札 3 つを書く

### Requirement: 席は issue を作らず、各候補に /iwakan に貼れるメモを添える

THE SYSTEM SHALL 席に issue を作らせない。席が打つ GitHub の命令は、開いている「違和感」の issue の一覧を読むこと（`gh issue list`）だけにする。どの候補を「違和感」の issue にするかは人間が選ぶ。
THE SYSTEM SHALL 一覧を読めなかった（網・`gh` が無い）ときは照合を飛ばし、報告にそう書かせる。
THE SYSTEM SHALL 手元の報告の各候補に、そのまま /iwakan に貼れる違和感メモ（`=== 違和感メモ ===` で始まり、`ページ:`・`表題:`・`場所:`・`日時:`・`何が引っかかったか:`・`こうなってほしい:` の行を持つ）を添えさせる。`場所:` には手元の報告と写しの場所を書く。
導出元: CH21（依頼「残すべきものは『違和感』の issue にする」・深掘り Q8。ラベル「違和感」の意味は「人間が見て・触って感じたもの」のまま）

#### Scenario: 席が打つ GitHub の命令は、一覧を読むことだけ
- **WHEN** 打たれた引数を書き留める偽の `gh` を置き、候補を 3 件書く偽の Claude で席を走らせる
- **THEN** 書き留めた `gh` の命令は 1 つ以上あり、すべて `issue list` で始まる

#### Scenario: 一覧を読めなければ、照合を飛ばして報告に書く
- **WHEN** 必ず非 0 で終わる偽の `gh` で、候補を 1 件書く偽の Claude の席を走らせる
- **THEN** 席は rc=0 で終わり、段落の件数は 1 で、手元の報告は既知の照合を飛ばしたことを書く

#### Scenario: 各候補に、そのまま貼れる違和感メモが付く
- **WHEN** 候補を 2 件書く偽の Claude で席を走らせる
- **THEN** 手元の報告の 2 件の候補それぞれに、`=== 違和感メモ ===` で始まり、`ページ:`・`表題:`・`場所:`・`日時:`・`何が引っかかったか:`・`こうなってほしい:` の行を持つメモがある
- **AND** 各メモの `場所:` の行に、報告の場所とその候補の写しのファイル名がある

### Requirement: 配る形の出所が前の回と同じなら走らず、前の回の結果を写す

THE SYSTEM SHALL 席に、配る形の出所（配る 2 つの zip の組み立てに入る、追跡するファイルの中身）を前の回と比べさせ、同じなら Sandbox を起こさず、前の回の段落を「前の回（<前の tag>）の結果」と分かる形で写させる。
THE SYSTEM SHALL 出所が変わったとき・前の回の結果が無いときは走らせる。前の回が、Claude が使い終えた（一通り終えた・時間の上限で打ち切った）回でなければ（組めなかった・Sandbox が動いていた・Claude が動けなかった など）、同じ出所でも走らせる。
THE SYSTEM SHALL tag が `probe-` で始まる回（手で試す回）には、前の回の記録を読ませも書かせもしない（確認バッチの回を写しで済ませないように）。
導出元: CH21（深掘り Q11。確認バッチは Story が gate を通るたびと fix・CI の直しの後に作り直される）

#### Scenario: 出所が同じなら、走らずに前の回の結果を写す
- **WHEN** 同じ木で、別の tag の席を続けて 2 回走らせる
- **THEN** 2 回目は Sandbox を起こす命令を打たず、段落は 1 回目の tag を名指して前の回の結果と書き、件数と題は 1 回目と同じである

#### Scenario: 出所が変われば走る
- **WHEN** 1 回目の後に、一時の repo で配る形の組み立てに入るファイルを 1 つ変えて commit し、2 回目を走らせる
- **THEN** 2 回目は Sandbox を起こす命令を 1 回打つ

#### Scenario: 前の回が走れていなければ、同じ出所でも走る
- **WHEN** 1 回目を Sandbox が動いていた警告で終え、同じ木で 2 回目を走らせる
- **THEN** 2 回目は Sandbox を起こす命令を 1 回打つ

#### Scenario: 手で試す回は、前の回の記録に触らない
- **WHEN** tag が `probe-` で始まる回を走らせた後に、同じ木で確認バッチの tag の回を走らせる
- **THEN** 確認バッチの回は Sandbox を起こす命令を 1 回打つ
- **AND** 前の回の記録には probe の tag が無い
