## 聞かないで決めるもの（C —— 扉を開けたままにする既定）

design の D 番号に残す。**異論があれば、答えを貼り戻すときに番号で書いてください。**

- **C1. 主張の行に DB の錠を足す。** 書き換え（値・いつから・種類・訂正先・主張した日時）と行の削除と表の切り詰めを DB が拒む
  （既定は厳しい側。FR-30 が凍結をアプリ層に置かなかった理由と同じ —— 同じ PC の psql やプラグインが素通りする）。
  通すのは感度の列と、Q1 の答えに応じた削除の印・台帳つきの消去だけ。
  `tools/check-immutable.sh` の「本人が書いた記録は書き換えられる」は、**主張以外の**本人が書いた記録（ST17 の主観など）について残す
- **C2. 書くたびに新しい主張として積み、内容で畳まれない形にする。** 同じ値・同じ「いつから」をもう一度書いても 1 件増える
  （「その日にまだそうだと確かめた」が残る。捨てるより入れる）。
  **形（答えを受けて design で直した）**: 主張は取り込み口（`/ingest`）から「本人が書いた」記録として入り、**原文に主張ごとの識別子と乱数を、出来事の時刻に主張した日時（C4）を入れる**。
  内容の鍵は SHA-256(ソース, 出来事の時刻, 原文) なので、**主張ごとに必ず違う鍵になる**。再送（同じ原文）は同じ鍵で 1 件に畳まれる（二重送信はこれで 1 件）。
  **FR-22 / FR-50 の文面のまま成り立つので、要件は改訂しない**（当初は「FR-22 を覆すので要件へ戻す」と書いていた。R1 / R2）。
  ソースの外部識別子の粒度は「無し」にする —— 送り主が外部識別子を付けても重複の判定にも更新の経路にも乗らない（`crates/server/src/lib.rs:344-356`。**R9** はこれで閉じる）。
  実測の根拠（**R6 で直した**）: 内容の鍵には出来事の時刻が入るので、A → B → A と戻った 3 件目は「いつから」が違えば畳まれない。
  畳まれるのは**同じ値・同じ「いつから」を、同じ原文で書き直したとき**（`INSERT 0 0` で黙って消える）
- **C3. 「いつから」は精度ごと持つ**（年 / 年月 / 年月日 / 分からない）。2019 年とだけ分かっている値を 2019-01-01 に丸めない
  （細かい粒度で持つ・丸めない）。「分からない」も値として受け付ける
- **C4. 「主張した日時」は画面が「積む」を押した時刻（出来事の時刻。タイムゾーンつき）とし、本人が入力する欄を置かない。** FR-45 の 2 軸のうち
  「いつそう書いたか」を本人が過去にずらせると、2 軸を分けた意味（後から直したことが分かる）が消える。D-01 に入った時刻（FR-19）も別に残る（**R5 で直した**。当初は「D-01 が受け取った時刻」）
- **C5. 訂正は「どの主張を取り消すか」を指して積む。** 取り消された主張も行は残り、印は訂正した側が持つ（追記のみ）。
  指さずに積むと、「いつから」を直す訂正（2019 年 4 月 → 10 月）で古い開始が導出に残り続ける
- **C6. 未来の「いつから」を受け付ける**（来月から新しい住所）。今日を過ぎるまで「いまの値」にはしない
- **C7. 種類は本人が足せる。** 種類は識別子で持ち、名前を変えても識別子は変えない（扉 #17 と同じ型）。最初に「住所」「職業」を置く
- **C8. 値は本人が打った文字列をそのまま持つ**（NFC。FR-27）。住所を場所（ST21）に結ぶ・構造にするのは後から足す
- **C9. 主張に任意の補足（文）を持たせる。** 「なぜ変わったか」は後から書き足せても、その時点の言葉は戻らない
- **C10. 「なし」（その属性が終わった）も主張として積める。** 置き換える値が無い終わり方（副業をやめた）を表すため
- **C11. 主張も受け取った要求の原文を文字列のまま残す**（FR-18 を主張にも当てる。列を持つ既定）。「いつから」を 1 つの欄から読み取る場合に、
  読み違えても打ったままの文字列から直せる（**R4**）
- **C12. 本文を消したあとに残る列から値を当てられないようにする。** 原文に**他の列へ写さない乱数**を入れる（識別子は `id` の列に残るので鍵を守らない。消去は原文と解析済みを空にするので、乱数は消去で消える）
  （いまの鍵は塩の無い SHA-256(ソース, 出来事の時刻, 原文) で、消去は鍵を残す。住所は候補が少ないので総当たりで確かめられる。**R3**）
- **C13. 主張は「本人が書いた」記録として、記録の約束（FR-19 / FR-20 / FR-24〜FR-29 / PERM-2）に乗る。** 出来事の時刻には主張した日時（C4）を入れ、
  **「いつから」は精度つきの別の欄に置く**（出来事の時刻に入れると「分からない」を置く値が要り、その値が鍵に入る）。
  旧設計（`reference/skeleton/entities.md:30`）の「2 軸を event_time / ingest_time と混ぜない」とも揃う。消せるかどうか（FR-50 / FR-51）は Q1 が決める（**R5**）
