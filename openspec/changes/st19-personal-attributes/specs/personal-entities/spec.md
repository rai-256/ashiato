## Purpose

本人が自分について書く個人属性（住所・職業など）を、上書きせずに主張として積み、「いつそう書いたか」と「いつからそうだったか」の 2 つの時刻で履歴を残す。人物と場所も後から同じ置き場に積む。

## ADDED Requirements

### Requirement: 個人属性の主張を積む

THE SYSTEM SHALL 個人属性の主張を、取り込み口から「本人が書いた」記録として受け付ける。
THE SYSTEM SHALL 各主張に、種類・値・「いつから」・主張した日時を持たせ、取り消す主張と補足を任意で持たせる。
THE SYSTEM SHALL 主張した日時を記録の出来事の時刻として持ち、D-01 に入った時刻とは別に保持する。
THE SYSTEM SHALL 「いつから」を、年・年月・年月日・分からない のいずれかの精度とその精度の日付の組として持ち、精度を丸めない。
THE SYSTEM SHALL 値の代わりに「なし」（その属性が終わった）を持つ主張を受け付ける。
THE SYSTEM SHALL 今日より後の「いつから」を持つ主張を受け付ける。
THE SYSTEM SHALL 主張を書くたびに記録を 1 件増やし、値と「いつから」が既存の主張と同じでも畳まない。
THE SYSTEM SHALL 同じ主張の再送（原文が同じ）では記録を増やさない。
THE SYSTEM SHALL 主張の原文を受け取ったまま保持する。
THE SYSTEM SHALL 主張の解析済みの値（値・補足・「いつから」・種類・取り消す主張）を、送り主の解析済みではなく原文から作り、文字列を NFC にする。

導出元: FR-44, FR-45, FR-18, FR-19, FR-21, FR-22, FR-25, FR-27。扉 #3。深掘り C2 / C3 / C4 / C6 / C8 / C9 / C10 / C11 / C13。
主張した日時を本人が入力する欄は持たない —— ずらせると 2 つの時刻を分けた意味（後から直したことが分かる）が消える。
同じ値をもう一度書いたことは「その日にまだそうだと確かめた」を残すので、畳まずに積む。

#### Scenario: 住所を 2 回変えると 3 つの主張が残る

- **WHEN** 種類「住所」に主張を 1 件書き、続けて別の値の主張を 2 件書く
- **THEN** 種類「住所」の主張が 3 件読み出せる

#### Scenario: 主張した日時といつからが別々に入る

- **WHEN** 2026-09-15 に「いつから」を 2019 年 10 月とする主張を書く
- **THEN** 読み出した主張は、主張した日時として 2026-09-15 の時刻を、「いつから」として 2019 年 10 月（精度: 年月）を、別々の欄に持つ

#### Scenario: D-01 に入った時刻も別に残る

- **WHEN** 主張を書く
- **THEN** 読み出した主張は、主張した日時とは別の欄に D-01 に入った時刻を持つ

#### Scenario: 年だけ分かるいつからは年のまま残る

- **WHEN** 「いつから」を精度「年」・2019 とする主張を書く
- **THEN** 読み出した主張の「いつから」は精度「年」・2019 で、月と日を持たない

#### Scenario: いつからが分からない主張を受け付ける

- **WHEN** 「いつから」を精度「分からない」とする主張を書く
- **THEN** その主張は格納され、読み出すと精度「分からない」で日付を持たない

#### Scenario: 未来のいつからを受け付ける

- **WHEN** 今日より後の日を「いつから」とする主張を書く
- **THEN** その主張は格納される

#### Scenario: なしの主張を受け付ける

- **WHEN** 値の代わりに「なし」を持つ主張を書く
- **THEN** その主張は格納され、読み出すと値が「なし」であることが分かる

#### Scenario: 同じ値といつからを書き直しても 1 件増える

- **WHEN** 既存の主張と値も「いつから」も同じ主張を、改めて書く
- **THEN** 主張が 1 件増える

#### Scenario: 同じ主張の再送は増えない

- **WHEN** 同じ原文の主張を 2 回送る
- **THEN** 主張は 1 件のままで、2 回目の結果は受理を示す

#### Scenario: 補足が残る

- **WHEN** 補足つきの主張を書く
- **THEN** 読み出した主張はその補足を持つ

#### Scenario: 主張の原文が 1 バイトも変わらずに残る

- **WHEN** 主張を書く
- **THEN** 格納された原文は送った原文とバイト単位で一致する

#### Scenario: 合成済みでない値は合成済みで読み出される

- **WHEN** 値を NFD（分解された形）の文字列で持つ主張を書く
- **THEN** 読み出した値は NFC の文字列である

#### Scenario: 原文と食い違う解析済みを送っても原文の値で格納される

- **WHEN** 原文の値が「東京都」で、送り主の解析済みの値が「大阪府」の主張を送る
- **THEN** 読み出した値は「東京都」である

### Requirement: 形の合わない主張は受け付けない

THE SYSTEM SHALL 次の表のいずれかに当たる主張を、その 1 件だけ受け付けず、表の理由の種別を返す。

| 理由の種別 | 当たるもの |
|---|---|
| `malformed_claim` | 原文が JSON でない / 必須の欄が欠ける / 原文の主張の識別子が記録の識別子と違う / 原文の乱数が 128 bit に満たない |
| `claim_not_authored` | 由来が「本人が書いた」でない / 端末識別子を持つ |
| `claim_has_external_id` | 外部サービス上の識別子か対象の識別子を持つ |
| `unknown_attribute_kind` | その利用者に無い種類 |
| `invalid_claim_value` | 値が、前後の空白を除いて空で、「なし」でもない |
| `invalid_valid_from` | 精度と日付の形が合わない / 暦に無い日付 |
| `invalid_supersedes` | 取り消す主張が無い / 個人属性の主張でない / 別の利用者 / 別の種類 / 自分自身 |

THE SYSTEM SHALL 削除の印の付いた主張や本文を消去した主張を取り消し先に指す主張を、その理由では断らない。
THE SYSTEM SHALL 1 つの主張を複数の主張が取り消すことを、その理由では断らない。
THE SYSTEM SHALL 主張を受け付けなかった応答に、主張の値・補足を含めない。

導出元: FR-44, FR-45, FR-23, FR-25。深掘り C5 / C7 / C12。design D5。
取り消す主張の検査が無いと、別の種類の主張を取り消して「いまの値」が黙って変わる。
由来を見ないと、「派生させた」や「収集した」として入った主張に、主張の錠ではなく別の規則が掛かる。
消した主張を取り消し先に指しても、読み出しがその取り消しを効かせる相手はいない（「種類ごとのいまの値と履歴を読める」）ので害が無い。

### Requirement: 主張は書き換えられない

THE SYSTEM SHALL 格納された主張の、原文・解析済み・内容の鍵・主張した日時とその地域・D-01 に入った時刻・識別子・利用者・由来・論理ソース・外部識別子・端末識別子の書き換えを、DB の側で拒む。
THE SYSTEM SHALL 主張の行の削除を DB の側で拒む。
THE SYSTEM SHALL 他の記録を主張の論理ソースへ付け替える書き換えを、DB の側で拒む。
THE SYSTEM SHALL 主張の削除の印（削除時刻と削除した者）と感度の書き換えを通す。
THE SYSTEM SHALL 主張の本文の消去を、原文と解析済みを空にし出来事の時刻と内容の鍵を変えない形で、かつ同じまとまりに**その主張の**消去の台帳の行があるときだけ通す。
THE SYSTEM SHALL これらの制限を、取り込み口の外から加えられた操作にも適用する。
THE SYSTEM SHALL 主張以外の「本人が書いた」記録に、この制限を広げない。

導出元: FR-44, FR-30, FR-50, FR-51, PERM-2。深掘り Q1 / C1。
凍結をアプリ層に置くと、同じ PC で動く psql やプラグインが素通りする（FR-30 と同じ理由）。
**主張も記録なので、消したことにする（FR-50）と本文の消去（FR-51）は及ぶ**（本人の決定）——「書き換えない」は「消せない」ではない。
台帳の行が「その主張のもの」でなくても通すと、台帳を 1 行書いたまとまりで何件でも消去でき、消去の形を問わないと台帳 1 行で値を植え替えられる（ST03 が実測した穴と同じ形）。

#### Scenario: 主張の値を書き換える文は拒まれる

- **WHEN** DB に直接つないで、格納された主張の値を別の値にする更新を実行する
- **THEN** その更新は失敗し、主張の値は変わらない

#### Scenario: 主張のいつからは書き換えられない

- **THEN** その更新は失敗する

#### Scenario: 主張の取り消し先は書き換えられない

- **THEN** その更新は失敗する

#### Scenario: 主張した日時は書き換えられない

- **THEN** その更新は失敗する

#### Scenario: 主張の行は削除できない

- **WHEN** DB に直接つないで、主張の行を削除する文を実行する
- **THEN** その文は失敗し、行は残る

#### Scenario: 他の記録を主張へ付け替えられない

- **WHEN** DB に直接つないで、「本人が書いた」別の記録の論理ソースを主張の論理ソースへ変える更新を実行する
- **THEN** その更新は失敗する

#### Scenario: 主張に削除の印を付けられる

- **WHEN** DB に直接つないで、主張に削除時刻と削除した者を付ける更新を実行する
- **THEN** その更新は成功する

#### Scenario: 主張の感度を変えられる

- **WHEN** DB に直接つないで、主張の感度を変える更新を実行する
- **THEN** その更新は成功する

#### Scenario: 台帳のある主張の消去は通る

- **WHEN** 同じまとまりで消去の台帳にその主張の行を書き、主張の原文と解析済みを空にする
- **THEN** 消去は成功する

- **THEN** 消去は失敗し、原文は残る

- **THEN** その更新は成功する

### Requirement: 消去した主張の値は、残った列から当てられない

THE SYSTEM SHALL 各主張の原文に 128 bit 以上の乱数を持たせ、その乱数を解析済みにも他の列にも写さない。
THE SYSTEM SHALL 主張の乱数を、同じ主張の識別子・出来事の時刻・値から導かない。

導出元: FR-51, FR-44。深掘り Q1 / C12。design D4。
内容の鍵は SHA-256(ソース, 出来事の時刻, 原文) で、消去の後も識別子・出来事の時刻・内容の鍵が残る。
原文の中に残らない乱数が無いと、住所のように候補の少ない値は、残った列から原文を組み直して鍵と照らせば確かめられる。

#### Scenario: 乱数は解析済みに写らない

- **WHEN** 主張を書き、格納された解析済みと、読み出した主張を見る
- **THEN** どちらにも原文の乱数の文字列が含まれない

#### Scenario: 同じ内容の 2 つの主張は別々の乱数を持つ

- **WHEN** 画面の組み立てで、識別子と主張した日時と値と「いつから」が同じ主張の原文を 2 回組む
- **THEN** 2 つの原文の乱数は異なり、どちらの乱数も識別子の文字列と一致しない

#### Scenario: 消去後に残る列と正しい値から鍵を作り直せない

- **WHEN** 主張を格納し、その主張の本文を台帳つきで消去したあと、残った識別子と出来事の時刻と、消去の前と同じ種類・値・「いつから」から、乱数を知らないまま原文を組んで内容の鍵を計算する
- **THEN** 計算した鍵は、残っている内容の鍵と一致しない

### Requirement: 属性の種類を足し、名前を変えても識別子を変えない

THE SYSTEM SHALL 利用者が属性の種類を足せるようにし、各種類に識別子を振る。
THE SYSTEM SHALL 種類の名前を変えても、その種類の識別子とそれを指す主張を変えない。
THE SYSTEM SHALL 種類の名前の変更を、前の名前を残したまま追記する。
THE SYSTEM SHALL 種類と名前の台帳の書き換え・行の削除・表の切り詰めを、DB の側で拒む。
THE SYSTEM SHALL 種類を 1 つも持たない利用者が個人属性の読み出しか種類を足す操作を初めて行ったとき、その操作の前に種類「住所」と「職業」を置く。
THE SYSTEM SHALL 住所と職業を置く操作が同時に何度走っても、種類と名前の行をそれぞれ 1 つずつにする。
THE SYSTEM SHALL 名前を NFC にしてから、空の名前と、その利用者のいまの名前と重なる名前を、足すときも変えるときも受け付けない。
THE SYSTEM SHALL 名前を変える要求が、その利用者の種類でない種類を指すとき、無い種類と同じに受け付けない。

導出元: FR-44, FR-29, FR-27。扉 #17 と同じ型。深掘り C7。design D7（仮）。
名前で種類を指すと、名前を直した日に過去の主張が別の種類に割れる。

- **THEN** 読み出すと種類「住所」「職業」「副業」の 3 つが現れる

#### Scenario: 空の名前の種類は足せない

- **WHEN** 空白だけの名前の種類を足す
- **THEN** 要求は受け付けられず、種類は増えない

- **WHEN** いまある種類と同じ名前（NFC にして同じになるものを含む）の種類を足す
- **THEN** 要求は受け付けられず、種類は増えない

- **THEN** 要求は受け付けられず、「副業」の名前は変わらない

- **THEN** 要求は受け付けられず、利用者 B のその種類の名前は変わらない

- **THEN** その文は失敗する

- **THEN** どの文も失敗する

### Requirement: 種類ごとのいまの値と履歴を読める

THE SYSTEM SHALL 利用者ごとに、種類を作った順に、種類ごとの「いまの値」・予定・積んだ主張・訂正で取り消された主張を読み出せるようにする。
THE SYSTEM SHALL 削除の印の付いた主張と、本文を消去した主張を、いまの値・予定・積んだ主張・取り消された主張のどれにも出さず、その主張による取り消しも効かせない。
THE SYSTEM SHALL 残った主張が指す取り消し先を「取り消された主張」とし、積んだ主張とは分けて、どの主張で取り消されたかを添えて返す。取り消された主張がした取り消しも効かせる。
THE SYSTEM SHALL 「いまの値」を、積んだ主張のうち「いつから」が今日以前で最も新しいものとし、「いつから」が同じなら主張した日時が後の主張、それも同じなら D-01 に入った時刻が後の主張とする。
THE SYSTEM SHALL 「いつから」の比較で、精度が年の主張をその年の 1 月 1 日から、年月の主張をその月の 1 日から有効とみなし、精度「分からない」の主張を最も古い側に置く。
THE SYSTEM SHALL 今日を `Asia/Tokyo` の日付で決める。
THE SYSTEM SHALL 「いつから」が今日より後の主張を「いまの値」にせず、予定として「いつから」の古い順に返す。
THE SYSTEM SHALL 積んだ主張に、いまの値と予定を含めた取り消されていない主張の全部を、「いつから」の新しい順（同じ「いつから」は主張した日時が後のものを先。精度「分からない」は最後）に並べて返す。
THE SYSTEM SHALL 各主張の主張した日時・D-01 に入った時刻・「いつから」・補足を別々の欄で返す。
THE SYSTEM SHALL 感度で主張を絞らずに返す。
THE SYSTEM SHALL 別の利用者の種類と主張を返さない。

導出元: FR-44, FR-45, FR-50, FR-51。深掘り Q4 / C5 / C6。design D6（仮）。
主張そのものは変わらないので、読み方（1 種類 1 値・比較の規則・日の区切り）は後から計算し直せる。
「後に書いた」を主張した日時で決めるのは、本人が書いた順（FR-45 の「主張した日時」）がこの規則の意味だから。
感度で絞るのは AI への経路（ST27）で、本人の画面ではない。

- **THEN** いまの値は 2023/3/18 からの主張である

- **THEN** いまの値は主張した日時が後の主張である

#### Scenario: 未来のいつからは予定に出ていまの値にならない

- **WHEN** 今日より後の「いつから」を持つ主張を書く
- **THEN** その主張は予定として返り、いまの値は変わらない

#### Scenario: 積んだ主張はいまの値と予定を含む

- **THEN** 積んだ主張にその 3 件がすべてあり、「いつから」の新しい順に並ぶ

#### Scenario: いつからを直す訂正で古い開始が残らない

- **THEN** 積んだ主張に 2019 年 4 月からの主張は無く、取り消された主張として、取り消した主張の識別子とともに返る

- **THEN** いまの値は精度「年」・2026 の主張である

#### Scenario: いつからが分からない主張は最も古い側に置く

- **THEN** いまの値は 2013 年 4 月からの主張で、積んだ主張の並びの最後が精度「分からない」の主張である

- **THEN** いまの値は「なし」の主張である

- **THEN** その主張は積んだ主張にある

- **THEN** 利用者 B の種類と主張は含まれない

### Requirement: 個人属性の画面は、種類ごとに積んだ主張を全部見せる

THE SYSTEM SHALL マスタ管理の画面に「個人属性」のタブを置き、まだ中身の無いタブ（人物・場所）を置かない。
THE SYSTEM SHALL 種類ごとに 1 枚のカードを、読み出した種類の順に出す。
THE SYSTEM SHALL 各カードに、種類の名前・いまの値と「いつから」を出し、いまの値が無ければ「まだ書いていない」、いまの値が「なし」なら「なし」と出す。
THE SYSTEM SHALL 予定の主張を、「予定」の文字を添えて出す。
THE SYSTEM SHALL 各カードに、積んだ主張を常に全部、読み出した順に、値・「いつから」・補足とともに出す。
THE SYSTEM SHALL 主張した日時を、その主張を押したときにだけ出す。
THE SYSTEM SHALL 訂正で取り消された主張を「訂正で取り消した N 件」に畳み、押したときに出す。
THE SYSTEM SHALL 主張の値を書き換える入力欄と、書き換えの要求を送る操作を置かない。
THE SYSTEM SHALL 画面の色を `docs/ui-direction.md` の確定値からだけ引く。
THE SYSTEM SHALL 稼働状況の画面からマスタ管理の画面へ行けるようにする。

### Requirement: 個人属性の画面から主張を書く

THE SYSTEM SHALL 各カードに「書く」を 1 つ置き、開いた中で「変わった」と「前の書き込みが間違っていた」を選ばせる。
THE SYSTEM SHALL 「前の書き込みが間違っていた」を選んだとき、その種類の積んだ主張から取り消す主張を選ばせ、主張した日時が最も新しい主張を最初に選んだ状態にする。
THE SYSTEM SHALL 「いつから」を、精度（年・年月・年月日・分からない）を先に選び、選んだ精度の欄だけに入れさせる。
THE SYSTEM SHALL 値の代わりに「なし」を選べるようにし、補足を任意で入れさせる。
THE SYSTEM SHALL 主張した日時を入力させず、その主張の原文を最初に組んだ「積む」の押下の時刻を送る。
THE SYSTEM SHALL 入力を変えずに「積む」を押し直したとき、同じ原文を送る。
THE SYSTEM SHALL 送っている間は「積む」を押せなくする。
THE SYSTEM SHALL 主張を積めたとき、フォームを閉じて画面の主張を読み直す。
THE SYSTEM SHALL 主張を積めなかったとき、入力を消さずに、理由の種別ごとに異なる文で積めなかったことを出し、サーバに届かなかったときはそれと分かる別の文を出す。
THE SYSTEM SHALL 種類を足す操作と、種類の名前を変える操作を置く。

導出元: FR-44, FR-45。深掘り Q2 / C4 / C5 / C7 / C10。design D9。

### Requirement: 個人属性の画面の読み出しの失敗と下限
