## D24

- 根拠: 条件 1（失わない側を選んでも `exported` が起きうる）に当たる。D24 は印を立てる時を「画面が前に出て（`onResume`）その行が見えた時」としている（design.md:190）。spec は「その行が見えた時」（specs/distribution/spec.md:195）、tasks は「見えた時（と `SetupActivity` を開いた時）」（tasks.md:112）で、3 か所の書き方が揃っていない。既存の `MainActivity` では、`onResume` が来ても行が画面に出るとは限らない。`onResume`（MainActivity.kt:128-131）は `proceed()` を呼ぶ。まだ求めていない権限があれば、`proceed()` はそれを求めて戻り（MainActivity.kt:197-210 の `next != null -> ask(next)`）、行を組む `showStatus`（`start()` の中。MainActivity.kt:400-423）まで進まない。求めたかどうかの `asked` は、Activity ごとにメモリに持つだけである（MainActivity.kt:71 `mutableSetOf`）。このため Android 13 以降で `POST_NOTIFICATIONS` を許していない人では、画面を開くたびに `onResume` で先に許可を求め、その間は行が画面に無い。この人たちはまさに、通知で示せないので D24 の画面に頼る人たちである。また通知を押して開いた時は `ACTION_MAIN` ではない。そのため `setupRow` が false になり、他の行が無ければ `finish()`（MainActivity.kt:415-423）で画面を閉じ、行は出ない。印を `onResume` に結び付けて作ると、行を見ないまま印が立ち、その後の機会に元の IP と時刻が配布元に出る。印は「行を `column` に足して `setContentView` した時」（と、`finish()` の分かれ目に入れ替えの行を足すこと）に結び付けないと、`keeps` の「目に入った時だけ印を立てる」は成り立たない。設定の画面も同じで、design と tasks は「開いた時」としているが、spec は「スイッチが見えた時」としている。今の `SetupActivity` は `ScrollView` の無い `LinearLayout` で、3 行の `EditText`・ボタン 2 つ・結果の行が先に並ぶ（SetupActivity.kt:33-67）。スイッチを置く場所は決まっていない
