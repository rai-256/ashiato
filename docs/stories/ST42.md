# ST42 — 衛星向けの API に版が付き、壊す変更を機械が止める

## 価値

本人として、本体を更新しても衛星が黙って壊れないようにしたい。なぜなら、衛星が壊れている間に書くはずだった記録は取れず、衛星は本体と別に作られて別に更新されるから。

## 満たす要件（requirements.md から逐語）

> - **FR-89**: THE SYSTEM SHALL 衛星が使う API に版を付け、同じ版の中では既存の衛星を壊す変更をしない。
>   ★ 2026-10-11 追加。衛星の基盤の監査（`docs/audit/2026-10-09-satellite-foundation.md`）§3。衛星は本体と別に作られて別に更新されるので、
>   本体の更新で衛星が黙って壊れると、衛星が書くはずだった記録が取れない。
>   壊す変更かどうかは、版ごとの API 契約（`openapi.json`）の差分を機械で見て判定する。

> - **FR-95**: WHEN API の壊す変更を新しい版として出す THE SYSTEM SHALL 前の版を 6 か月以上並べて動かす。
>   ★ 2026-10-11 追加。6 か月は推奨を採った仮の値（変えても失うものは無い。並べる期間を延ばすだけ）。

## 壊してはいけないもの

- ST01 の API 契約（docs/openapi.json）と、それを見る検査

## 完了の判定

- API の契約に版が付き、同じ版の中で既存の衛星を壊す変更を入れると CI が落ちる
- 壊す変更を新しい版として出すと、前の版も並んで動く
