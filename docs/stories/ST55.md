# ST55 — サーバを入れて、そのまま使い始められる

## 価値

本人（と、いずれ渡す相手）として、Windows でサーバのインストールを走らせるだけで、ほかのアプリ（Docker Desktop や WSL）を入れずに、データベースごと PC の起動時から動き、合言葉を決めて使い始めたい。なぜなら、いまは開発の台本と Docker でしか動かず、画面の合言葉を設定する口もどの Story も持っていないから（2026-11-03 の配布の方針の改訂）。

> - **FR-108**: WHEN 利用者が S-01 のインストールを始める THE SYSTEM SHALL 配布物に同梱した PostgreSQL（D-01）と S-01 を OS のサービスとして登録し、PC の起動時から動かす。
>   ★ 2026-11-03 訂正。配布の方針の改訂（`docs/briefs/req-native-postgres-r1.html` の Q1・Q2、`-r2.html` の Q1）。**コンテナの実行環境（Docker Desktop）を前提にするのをやめる。**

## 壊してはいけないもの

- 開発と試験の DB（`docker-compose.yml` の `postgres:17-alpine`）と、worktree ごとの DB（配る形と別のまま残す）
- 待ち受けと DB の接続先を loopback に限る守り（`net_guard.rs`）と、DB のログの 3 つの設定（`docs/production-prep.md` の既定値の棚卸し）
- 画面のログイン（ST28）と、Takeout をダウンロードするだけで入る取り込み待ち（正典 external-ingestion）

## 完了の判定

- Docker も WSL も無い Windows でサーバのインストールを走らせると、管理者の確認が 1 回出て、同梱の PostgreSQL 17 とサーバがサービスとして入り、PC を再起動するとログオンしなくても動いている
- DB・写真の原本・退避・バックアップ・書き出し・合言葉・設定がすべて PC 全体の置き場にあり、ほかのアカウントからは読めず、ダウンロードのフォルダに落とした Takeout は取り込まれる
- インストールの最後に画面の合言葉を決めると、そのまま画面にログインできる（DB の合言葉は自動で作られ、人は見ない）。Windows の CI で、配る形に移行を当ててサーバが起きる
