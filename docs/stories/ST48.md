# ST48 — 古い版が新しい DB を書き換えない

## 価値

本人として、ベータ版から正式版へ移ったり古い版に戻したりしても、新しい版で育った DB を古い版に書き換えさせたくない。なぜなら、いまの移行は全部の版を毎回当て直し、門の関数を古い定義に戻しうるうえ、どの版まで当たっているかを数えていないから（docs/audit/2026-10-25-consistency.md の C4）。最初に配る版に入っていないと、その版へ戻したときに止める仕組みそのものが無い。

## 満たす要件（requirements.md から逐語）

> - **FR-117**: IF S-01 が、自分の知る版より新しい移行の当たった D-01 に繋がる THEN THE SYSTEM SHALL 起動せず、どちらの版かを示す。
>   ベータ版から正式版へ移った・古い版に戻したときに、新しい DB を古い S-01 が書き換えるのを止める（FR-105）。移行を当てる側は FR-129。
>   ★ 2026-10-25 補足。整合の確認（`docs/audit/2026-10-25-consistency.md`）の C4。起動だけを止めても、起動の前に走る移行が門を古い定義に戻すので、移行の側を FR-129 で止める

> - **FR-118**: THE SYSTEM SHALL D-01 に当てた移行の版を、D-01 の中に記録する。
>   ★ いまの `ashiato-server migrate` は全部の移行を毎回当て直し、当てた版を数えていない（`crates/server/src/migrate_backup.rs`）。FR-117 の前提。

> - **FR-129**: IF 移行（`ashiato-server migrate`）が、自分の知る版より新しい移行の当たった D-01 に当たる THEN THE SYSTEM SHALL 1 つも当てずに止める。
>   ★ 2026-10-25 追加。整合の確認（`docs/audit/2026-10-25-consistency.md`）の C4。起動の台本は S-01 の起動の前に移行を当て、移行は全部の版を当て直す。
>   門の関数（`core.reject_collected_rewrite`）は複数の版で `CREATE OR REPLACE` されているので、古い版の移行が新しい D-01 に当たると、門が古い定義に戻る。FR-117 の拒否は起動の時にしか効かない

## 壊してはいけないもの

- 起動のたびに全版を当て直せる形で書いた既存の移行（ST29 / ST23 / ST41 / CH04 の design が前提にしている）が、版を数える形に変えた後も当たること
- 移行の前の自動の退避（`ashiato-server migrate` が当てる前に毎回取る）
- 縦串（`tools/smoke.sh`）と確認バッチの `MIGRATE_BACKUP=off` の使い捨ての DB

## 完了の判定

- 新しい版で移行を当てた DB に、古い版の `ashiato-server migrate` を走らせると、1 つも当てずに止まり、DB の版と自分の版が示される
- 同じ DB に古い版のサーバを起動すると、起動せずに版の食い違いが示される
- 同じ版で当て直しても、何も変わらずに通る
