# ST40 — 衛星が持ち込むモノを汎用の台帳に入れられる

## 価値

本人として、本や旅程のような衛星が扱うモノも手元に残したい。なぜなら、衛星が無くなっても自分のデータは残したく、モノの種類ごとに本体の表を足すと衛星のたびに本体が変わるから。

## 満たす要件（requirements.md から逐語）

> - **FR-86**: THE SYSTEM SHALL 衛星が持ち込むモノ（本・旅程・費目など）を、モノの型・識別子・名前と、
>   モノの型ごとに衛星が登録した形の中身で、1 つの汎用の台帳に保持する。
>   ★ 2026-10-11 追加。衛星の基盤の監査（`docs/audit/2026-10-09-satellite-foundation.md`）の問い 7 と §4 の机上の試験。読書ログ・家計簿・睡眠を想定すると、
>   記録（出来事）は今の表にそのまま入ったが、**本・旅程・費目のような「モノ」を入れる場所が無かった**。
>   モノの種類ごとに表を足すと、衛星のたびに本体の表が変わる（成功条件 3）。
>   弱いところ（本人が読んだ上で採った）: DB の制約で形を縛れない（サーバの検査で縛る）、衛星をまたいだ重複
> …（続きは requirements.md）

> - **FR-93**: IF 衛星が送ったモノの中身が、そのモノの型に登録された形に合わない THEN THE SYSTEM SHALL 400 で断る。
>   ★ 2026-10-11 独立レビューの指摘で FR-86 から割った。DB の制約で形を縛れないので、縛るのはサーバの検査だけになる。

## 壊してはいけないもの

- ST33 の書き出し（モノの台帳も対象になる）

## 完了の判定

- 衛星がモノの型と中身の形を登録してモノを書け、形に合わない中身は断られる
- モノの型を足しても本体の表と列が変わらない
