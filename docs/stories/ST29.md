# ST29 — プラグインを登録し、承認して初めて読ませる

## 価値

本人として、データの入口と出口を後から気軽に足したい。なぜなら、映画の記録のような思いつきを、その都度 API を直して足すのは続かないから。

## 満たす要件（requirements.md から逐語）

> - **FR-62**: WHEN プラグインが登録される THE SYSTEM SHALL
>   そのプラグインが読める感度の上限と対象ソースの宣言を要求する。

> - **FR-63**: WHILE 利用者がプラグインの宣言を承認していない THE SYSTEM SHALL
>   そのプラグインに記録を返さない。

> - **FR-64**: THE SYSTEM SHALL プラグインの書き込みを、そのプラグインが登録したソースに限定する。

> - **FR-65**: WHEN プラグインを追加する THE SYSTEM SHALL S-01 の再起動のみで有効化する。
>   有効化は登録簿への 1 行と再起動で完結し、**本体のプロセスにコードを読み込まない**（FR-77）。
>   API を変えずにソースを足せることは FR-61 が受ける（本人の言葉:「スマホアプリ導入&再起動程度
>   だったら許容範囲」）。

> - **FR-77**: THE SYSTEM SHALL プラグインおよび衛星アプリとのやり取りを、
>   別プロセスからの HTTP API 経由に限定する。
>   **これはライセンスの境界そのもの** —— 同一プロセスに読み込む形にすると、
>   プラグインが本体（AGPL-3.0）の派生物とみなされ、有料のまま配れなくなる。
>   後から締めると、それまでに書かれたプラグインが全部作り直しになる。

> - **PERM-8**: THE SYSTEM SHALL プラグインの既定の感度上限を「公開可」とする。

## 壊してはいけないもの

- ST24 の感度（プラグインが宣言を超えて読めないこと）
- ST01 の API 契約

## 完了の判定

- プラグインを登録すると、読める感度の上限と対象ソースの宣言を求められる
- 承認するまで 1 件も記録が返らない
- 有効化に必要なのは S-01 の再起動だけで、コードを直さなくてよい
- プラグインは別プロセスで動き、本体のプロセスにコードが読み込まれない（AGPL-3.0 の境界）
