# ST44 — 収集アプリと画面の資格情報が読める範囲を締める

## 価値

本人として、落とした電話や古い APK の合言葉で全記録を読まれないようにしたい。なぜなら、収集アプリの合言葉はいま全部を読めて、読まれた記録は戻らないから。

## 満たす要件（requirements.md から逐語）

> - **PERM-10**: THE SYSTEM SHALL 生存確認・ログイン・ログアウトの口を除くすべての API 要求に、呼び出し元を識別できる資格情報を要求する。
>   ★ 2026-09-08 追加。`/production-prep` のブロック B に対する自動セキュリティレビューが
>   「認証が無い」ことを指摘して見つけた**要件の抜け**。
>   PERM-7（外部からの到達を利用者が許可した私設網の内側に限る）は**網の外を止めるだけ**で、
>   **同じ PC の中から呼ぶものを何も止めない**。第三者製のプラグインは同じ PC で動き、
>   PERM-8 は既定を最も厳しい側に置いているので、素通しでは PERM-8 が空文になる。
> …（続きは requirements.md）

## 触れる扉（requirements.md §5 から逐語）

> 13. **provenance（どのソース・端末・衛星が書いたか）を持つか** — 決めるもの: 記録の有無
>     決着状態: 決定済（持つ。書き手はサーバが資格情報から決める）
>     ★ 2026-10-11 補足。衛星の基盤の監査（`docs/audit/2026-10-09-satellite-foundation.md`）の U1。**決定済なのに列が無かった**（ソースと、送り手が申告した端末だけ）。
>     衛星が書き始めてから足すと、それまでに衛星が書いた記録の書き手が分からない。期限は衛星が書き始める日
> …（続きは requirements.md）

## 壊してはいけないもの

- 収集アプリ（C-01 / C-02）の送信と合言葉
- ST28 の画面のログイン

## 完了の判定

- 収集アプリの資格情報では、送ることだけができて記録は読めない（配り方は深掘りで決める。handoff/ST29.md の Q4）
- 資格情報を求めない口は生存確認・ログイン・ログアウトだけで、正典の「すべての API 要求」に例外として書かれている
