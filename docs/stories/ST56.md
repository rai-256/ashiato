# ST56 — 収集アプリを入れた後に、繋ぎ先と資格情報を設定できる

## 価値

本人（と、いずれ渡す相手）として、配布元から落とした同じ APK と PC の収集アプリを入れて、自分のサーバに繋ぎたい。なぜなら、いまは繋ぎ先と資格情報を APK に焼き込み、PC は自動起動の台本に平文で書いているので、1 つの APK を全員に配ると送信が始まらないから（docs/audit/2026-10-25-consistency.md の C3）。

## 満たす要件（requirements.md から逐語）

> - **FR-128**: WHEN 収集アプリ（C-01 / C-02）を入れた後に初めて起動する THE SYSTEM SHALL 接続先（S-01）と資格情報を利用者に設定させる。
>   ★ 2026-10-25 追加。整合の確認（`docs/audit/2026-10-25-consistency.md`）の C3。いまの C-01 は接続先・資格情報・利用者識別子を組み立ての時に APK へ焼き込み（`build.gradle.kts` の `buildConfigField`）、
>   C-02 は環境変数を自動起動の `.cmd` に平文で書く。1 つの APK を全員に配る（FR-104）と、配った APK は送信を始めない。
>   設定のしかた（V-01 が示す符号を読み取る等）と資格情報の配り方は、ST29 / ST44 の深掘り（`docs/handoff/ST29.md` の Q4）で決める

## 壊してはいけないもの

- 収集アプリの資格情報では送ることだけができて記録は読めないこと（ST44）
- 未送信の保持と再送（ST04）
- いまの開発の組み立て（`-P` で焼き込む形）を使う試験とエミュレータの計測テスト

## 完了の判定

- 配布元の APK を入れて初めて起動すると、繋ぎ先と資格情報を設定する画面が出て、設定すると送信が始まる
- PC の収集アプリも、入れた後に繋ぎ先と資格情報を設定でき、合言葉が平文の台本に残らない
- 設定を間違えた・資格情報が取り消されたときに、記録を捨てずに設定し直しを促す
