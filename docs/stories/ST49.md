# ST49 — 記録ごとに、作った部品の版が残る

## 価値

本人として、配った後に「この版の収集だけ取り違えていた」と分かったとき、その版で作られた記録だけを選び出したい。なぜなら、いまの記録はスキーマ版と端末しか持たず、残し始める前の記録は後から版を知る手段が無いから（扉 32）。

## 満たす要件（requirements.md から逐語）

> - **FR-122**: THE SYSTEM SHALL C-01 / C-02 が作る記録 1 件ごとに、その記録を作った時の収集アプリの版を持たせる。
>   ★ Q1。配った後に「この版の収集だけ取り違えていた」と分かったとき、版が無いとどの記録がそれかを後から知れない。
>   いまの記録はスキーマ版（FR-26）と端末を持つが、アプリの版を持っていない。
>   ★ 2026-10-25 訂正。整合の確認（`docs/audit/2026-10-25-consistency.md`）の C7（従来は「送った収集アプリの版」）。未送信は更新の後に送られるので、送った時の版では、取り違えた版が作った記録に直した版が付く

> - **FR-123**: THE SYSTEM SHALL C-03 と派生が書く記録と、V-01 から本人が書く記録の 1 件ごとに、書いた時点の S-01 の版を持たせる。
>   ★ Q13。衛星の記録は対象にしない（衛星の版はサーバが確かめられない。衛星との契約は API の版（FR-89）が持つ）。
>   派生は作り直せるが、作り直したときに新しい版が入るだけで困らない。
>   ★ 2026-10-25 訂正。整合の確認（`docs/audit/2026-10-25-consistency.md`）の C8。V-01 から本人が書く記録（主観・個人属性の主張・場所・人物）も S-01 が書くので、同じく S-01 の版を持たせる

## 触れる扉（requirements.md §5 から逐語）

> 32. **記録ごとに、書いた本体の部品の版を持つか** — 決めるもの: 記録の有無
>     決着状態: 決定済（2026-10-25。配布と更新の深掘り Q1 / Q13。持つ —— C-01 / C-02 の記録は作った時の収集アプリの版、C-03・派生・V-01 から本人が書く記録は S-01 の版。衛星の記録は対象にしない）——
>     ★ 2026-10-25 訂正。整合の確認（`docs/audit/2026-10-25-consistency.md`）の C7 / C8（「送った」版を「作った時」の版に。本人が書く記録を足した）。
>     持たなかった期間の記録は、どの版で書かれたかを後から知れない。期限は本人の環境を配布の経路に切り替える日（以後、配った版の不具合を追うのに要る）

## 壊してはいけないもの

- 送信契約の既存の欄と重複判定（同じ記録を何度送っても増えない。ST03）
- 収集した記録を書き換えない門（FR-30）
- 書き出しの列の一覧（ST33）

## 完了の判定

- 携帯と PC の収集アプリが作った記録に、その記録を作った時の収集アプリの版が残る（未送信を更新の後に送っても、作った時の版のまま）
- 書庫の取り込み・滞在の派生・画面から本人が書いた記録に、書いた時点のサーバの版が残る
- 衛星が書いた記録には版を付けない
