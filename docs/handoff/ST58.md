# ST58 への申し送り

## st48-db-version-guard R21 — 終了コード 3 は「移行の失敗」ではない（この回の退避は無い）

- ST48 の `ashiato-server migrate` は、DB に自分の知らない版が当たっている（`kind=db_ahead`）・版の記録を読めない（`kind=ledger_unreadable`）とき、
  **退避を取らず・DB に何も書かずに終了コード 3** で止まる（`openspec/changes/st48-db-version-guard/design.md` D4・D6。試験 `st48_migrate_refusal_takes_no_backup`）。
  標準エラーの 1 行目は `error: kind=<種別>`、続く `  db: <名前> (<版番号> <commit>)` は 1 版 1 行（20 件を超えた分は `  more: <N>`）、`  self: <版番号> <commit>`
- 終了コード 1 は移行の失敗（版の中身が当たらない・退避の失敗・接続できない）。こちらはその回の退避がある（退避の失敗なら当てていない）
- **rc≠0 を一律に「移行の失敗」と扱って退避から戻すと、終了コード 3 の回は退避が無いので、前の回の退避（それ以後の記録を含まない）を戻しうる** ——
  捨てたものは復元できない。FR-119 の戻しは終了コード 1 の回だけにし、終了コード 3 の回は**退避から戻さず**、前の版のまま起動し直す
- ST48 の起動の検査は起動のときだけ（`startup_refusal`）。動いている古い S-01 は、別の組み立てが DB を新しくしても止まらない。
  **更新の手順は、新しい版の migrate の前に古い S-01 を止める**
- 出所: `openspec/changes/st48-db-version-guard/review/code.md` R21（code-verify の手 6）

## st51-update-history R1 — 戻した後に、落ちた試みの結果と戻したことを更新の履歴に書き直す

- ST51 は、migrate が版の検査を通った後・**当てる前の退避より前**に、移行の結果 `attempted`（試み）の 1 行を `core.update_history` に書いて commit する（深掘り Q6。退避に入る）。
  試みの行は版が変わる回（直前の通った行の版と自分の版が違う回）だけに書き、その後に同じ migrate の結果の行（`applied` / `nothing_to_apply` / `failed` / `backup_failed`）を足す（ST51 design D16（仮））
- 結果の行（`failed` / `backup_failed`、落ちた版の名前・SQLSTATE）は **D-01 の中だけ**に書く（深掘り Q2）。退避より後に書くので、FR-119 で退避から D-01 を戻すとちょうど消え、
  **戻した D-01 には試みの行だけが残る**（試みの後に、次の試みより前に `via = migrate` の結果の行が無い = 結果を書く前に終わった回）
- ST58 は戻した後に、知らせ（FR-120）の材料（落ちた版・理由）を持っている。戻して前の版で起動し直す前に、`core.update_history` へ
  「落ちた試みの結果」（`outcome` = `failed` / `backup_failed`。消えた結果の行と同じ中身 —— 落ちた版の名前・SQLSTATE）と「戻した」の 2 行を書き直す。試みの行は書き直さない（残っている）。
  「戻した」を表す値は `outcome` の今の 5 つに無いので、ST58 が列か値を**足す**（今の列の名前・型・NULL の可否は変えない —— `specs/distribution` の「更新の履歴は、決めた置き場と列の形で持つ」）
- ST58 より前に手で戻した回・ST58 が書き直す前に止まった回は、試みの行だけが残る（通らなかったことは分かり、落ちた版の名前と SQLSTATE は分からない）
- 起動の行（`via` = `startup`）は、前の版で起動し直したときに「直前の通った行の版と違えば」書かれる。戻した D-01 の最後の通った行は前の版なので（試みの行は通った行に数えない）、前の版で起動し直しても行は増えない
- 実装との照合（ST51 Task 10）: 列は `seq`（書いた順）・`at`・`component`・`via`・`from_version`・`to_version`・`outcome`・`applied_versions`・`failed_version`・`sqlstate`。`outcome` と `component`・`via` は CHECK で値を縛っているので、
  「戻した」の値を足すときは CHECK も作り替える（表は追記のみの門つき）。表がまだ無い回（ST51 の移行を初めて当てる migrate）は、試みの行を書かず警告（`update_history_unwritten`）を出す。
  その回の移行が表を作った後は、結果の行を 1 行書く（通れば `applied`、表を作った後の版で落ちれば `failed`。前の版は無いので `from_version` は空。
  表を作る前の版で落ちた・退避に失敗した回は、表が無いままなので結果も書かず警告だけ —— `migration_ledger::record_result` → `update_history::record_migrate` の `Attempt::Unwritten`）。
  その回の退避は表ができる前に取ったので表を含まず、退避から戻すと結果の行も表ごと消える（試みの行も無いので、戻した D-01 には跡が残らない）
- 出所: `openspec/changes/st51-update-history/review/deep.md` R1・深掘り Q2・Q6（`deep-answers-3.txt`）

## st51-update-history R10 — C-01 は更新の後に自分で起き直さない

- C-01 には `MY_PACKAGE_REPLACED` の受け手が無く、`LocationService` を起こすのは画面（`MainActivity.kt:183`）だけ。携帯の収集アプリを更新すると、
  本人がアプリを開くまで生存信号も記録も止まる。ST51 の版の変化の時刻は「開いた時」になり、「更新で止めた時間」は開くまで続く
- 更新を入れる ST58（FR-114）で、更新の後に収集を起き直させるか（`MY_PACKAGE_REPLACED` の受け手）を決める
