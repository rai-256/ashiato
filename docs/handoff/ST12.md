# ST12 への申し送り

ST12（書庫を置くだけで過去のデータが入る）は、この申し送りを書いた時点（2026-09-15）では `tasks.md` が無い（上流が走っている）。
**差し戻しではない** —— ST22（記録を消したことにできる）の深掘りのレビューが見つけた、**外部識別子を持つソースで初めて起きる**失われ方を、
最初に外部ソースを入れる ST12 の上流が深掘りの前に読めるように置いておく。ST22 の操作（滞在と、その時間の位置を消す）からは届かない。

## st22-record-deletion R3 — 削除済みの判定は、消した記録の前の版の内容を見ない

- 何を: 取り込みの削除済みの判定（`crates/server/src/lib.rs` の `ingest_one`）は、削除済みの行の**現在の**内容ハッシュだけを見る。
  外部の更新で版が進んだ後に消すと、**前の版と同じ内容が別の外部識別子で届いたとき、生きた記録として入る**（レビューの実測: `rows=2 live=1`）。
  前の版にも判定を当てると、届いた記録と新しい外部識別子を捨てる範囲が広がる（loss: discarded）。「印を付けて入れる」なら `record-envelope` の改訂が要る
- なぜ: 外部識別子で畳むソース（`external_id_kind='record'`）は、いま派生の `s01-stay` しか無い。ST12 が最初に入れる
- 根拠: openspec/changes/st22-record-deletion/review/deep.md R3

## st22-record-deletion R4 — 消していた間に届いた外部の更新は、どこにも残らない

- 何を: 削除済みの記録に同じ外部識別子で更新が届くと `SkippedDeleted` で返り、**本表にも履歴にも書かれない**（loss: discarded）。
  正典 `record-envelope` は「本人が自分で行う論理削除の取り消しは残る」と書くので、消した記録を戻すとその更新が欠ける
- なぜ: FR-50「外部サービスからの更新も取り込まない」は、生きた記録に反映しないのか、どこにも置かないのかに幅がある
- 根拠: openspec/changes/st22-record-deletion/review/deep.md R4

## st22-record-deletion R6 — 書庫から入る同じ場面は、ST22 の削除に当たらない

- 何を: ST22 で本人が滞在を消すと、その時間の位置（`c01-location`）に削除の印が付く（深掘り Q1 の推奨。答え待ち）。
  ST12 がマップのタイムラインを別の論理ソース（`c03-timeline-*` の案）として入れると、内容の鍵は論理ソースを含む（`ingest.rs` の `content_hash`）ので、
  **消した場面の位置が別のソースから生きた記録として入る**
- なぜ: 「消した時間帯に後から届いた記録にも印を付ける」（ST22 の Q2）は、ST22 が一緒に消すと決めたソースにしか掛からない
- 根拠: openspec/changes/st22-record-deletion/review/deep.md R6
