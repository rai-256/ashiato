# CH06 への申し送り

## ch07-declare-verify-reset R5・R10 — コンテナが外で消され volume が残った木では、前の DB の中身を持った volume が残り続ける

- `tools/verify-env.sh` の `reset_db` は、DB のコンテナが無いと「切った接続: 0（DB のコンテナが無い）」を出して立て直すだけで、volume を探さない
  （コンテナから控えた volume だけを消す。CH06 design D1 の「`-v` を使わず、名前で控えた volume だけを消す」）
- `docker compose rm -s -f db`（`-v` なし）でコンテナだけを消した後に印つきの準備を呼ぶと、rc=0・`HARNESS_RESET: testdb`・新しい DB は空
  （宣言は事実どおり）。ただ前の匿名 volume は `docker volume inspect` で残っていた（ch07 code_verify の手 6 で実測。確かめた後に手で消した）
- 溜まるのはディスクと、消したつもりの私的データの写し。CH06・CH07 のどちらの Scenario も「コンテナが無く、volume はある」を扱わない
  （CH06 の 7. はコンテナと volume の両方を消してから呼ぶ）
- 決めること: コンテナが無いときに、その compose project のラベルを持つ宙に浮いた volume を片付けるか（他の project・compose の外のものには触らない D1 を崩さない形で）。
  CH06 の後続の change で拾う。CH07 では直さない（CH07 の主張「宣言が事実どおり」は破っていない）
