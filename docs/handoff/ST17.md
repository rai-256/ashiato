# ST17 への申し送り

ST17（毎日 30 秒で「その日どう感じたか」を残す）は、この申し送りを書いた時点（2026-10-11）では上流（深掘り）にいる。
**差し戻しではない** —— 要件の改訂（2026-10-11。衛星の基盤）で、ST17 が決めた主観の感度の扱いがどう変わるかを、上流が読めるように置いておく。

## 2026-10-11 の要件の改訂 — 主観の「ローカル AI まで」は、記録の値ではなく承認になる

- 何を: ST17 の深掘り（C6 と tasks の「主観の感度を変えられる」）が主観に付ける「ローカル AI まで」は、改訂後の要件では
  **記録の値ではなく、「ローカル AI」の衛星にだけ主観の種類を承認すること**（PERM-4 / FR-88）になる。記録ごとに持つのは「出さない」の印だけ（PERM-2）。
  ST17 の tasks は凍結しているので変えなくてよい。書いた値は ST24 が読み替える（印ではないと読む）
- なぜ: ST17 が archive されると、`subjective-log` の正典に 4 段階の値が Scenario として残る。ST24 はそれを MODIFIED する
  （INDEX の 2026-10-11 の訂正で ST24 の capability に `subjective-log` を足した）
- 気をつけること:
  - 「主観の感度を変える操作」は、改訂後の要件には無い（PERM-2★「感度を変える操作はまだ無い」）。ST17 の下流で作るなら、
    それは ST24 の「出さない」の印か ST38 の承認と重なる。**失われるもの（A）は無い**（外へ出す経路がまだ無い）ので、深掘りの問いには立てない
- 根拠: docs/requirements.md PERM-2 / PERM-4 / FR-88、docs/stories/INDEX.md の 2026-10-11 の訂正、docs/audit/2026-10-11-consistency.md

## docs/audit/2026-10-12-st33-consistency.md C1 — 書き出し（ST33）の分類に `s01-feeling` を置く

- 何を: ST33 の書き出しは、緯度経度を持たないと決まったソースの一覧（`export::NO_COORD_SOURCES`）と幅の読み方（`SPAN_RULES`）に無いソースを
  「緯度経度を持つ・次の記録まで」とみなし、本人が消した滞在の時間と重なれば除く。`s01-feeling` はどちらにも無いので、消した滞在に付けた気分と
  その日の「日」の記録が書き出しから除かれ、ST17 の spec の「書き出しからは見える（Q10）」と合わない
- どうする: ST33 が先に archive されていれば、ST17 の下流が `s01-feeling` を `NO_COORD_SOURCES` に足し、幅は紐づけ先（`target`）で読む。ST17 が先なら ST33 の下流が足す（`docs/handoff/ST33.md` の C1）
- 失われるもの: 無い（除き過ぎの側）

## st17-daily-feeling R19 — `check-log-private.sh` は許した欄の名前しか見ず、値に何を入れても通す（ST17 の merge 後に `fix/` で拾う）

- 何を: `tools/check-log-private.sh` の Rust の検査は、構造化フィールドの**名前**が `ALLOWED` にあるかだけを見る。
  `tracing::info!(count = note.as_deref().unwrap_or(""), …)` のように、許した名前に主観のひとことを入れた行が rc=0 で通る
  （code-verify の実測。同じ値をメッセージに `{}` で埋め込むと rc=1 で止まる）
- なぜ ST17 で直さないか: いまの木の ST17 のコードに該当の行は無い（`feelings.rs` の tracing は `dropped` の件数 1 か所だけ）。
  検査は製造準備の道具で、値の側を絞ると全体の約 60 か所（`error = %error`・`logical_source = %req.logical_source`・`took_ms = took_ms(…)` など）の書き方の線引きを決め直すことになり、ST17 の範囲を越える
- 案: 許した欄の値を「名前と同じ識別子（省略形）・数値と文字列のリテラル・`.len()` / `.count()` などの件数の式・名指しした関数（`took_ms()`・`failure_kind()`）」に限り、
  外れるものは `// log-ok:` で理由を書かせる。`--self-test` に「許した名前に任意の値」の断片を足す
- 失われるもの: いまは無い（該当の行が無い）。一度出たログは消せないので、検査の穴が残る間に新しい行が入ると `exported`
