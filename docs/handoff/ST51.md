- **何を**: `crates/server/build.rs` は `.git/HEAD` の変化で作り直さない（ST48 design D8）ので、差分のビルドでは `BUILD_COMMIT` が古いまま残る。
  ST51 が「前と違う版か」を commit まで含めて比べても（FR-121 の ★ 2026-10-29。C3）、印そのものが古ければ論理だけを直した版が同じ版に見える

- **ST51 がやること**: 着手の時に ST49 の C10 が入ったかを確かめる。完了の判定の「版番号が同じで commit が違うサーバに入れ替えても 1 行残る」を、
  組み立て直した 2 つの実行ファイルで固定する試験にする
- **根拠**: `docs/audit/2026-10-29-fr121-consistency.md` K1・C3

## 2026-10-29-fr121-consistency.md C2 — 移行が通らなかった更新を、どこで・いつ書くか

- **何を**: FR-121 の「移行が通ったか」の欄は、起動のときに前回の起動と比べるだけでは常に「通った」になる。
  移行が落ちた版は起動まで進まず（FR-117）、FR-119 は退避から D-01 を戻して前の版で起動し直すので、変化が見えない
- **要件が決めたこと**: 通らなかった更新も「通らなかった」として 1 行残し、退避からの戻しで消えない置き場に書く（FR-121 の ★ 2026-10-29）
- **深掘りで決めること**: 書く主体（`ashiato-server migrate` の側か、戻した後に起動した前の版か）と置き場。
  戻しの経路を作るのは ST58（requires に ST51）なので、ST51 が書き方の口を用意し、ST58 がそれを呼ぶ形が候補
- **根拠**: `docs/audit/2026-10-29-fr121-consistency.md` C2
