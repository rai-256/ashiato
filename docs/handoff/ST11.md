# ST11 への申し送り

## 権限を拒否したときの振る舞いを、正典の Scenario にする

- **何を**: 位置の権限を**拒否**したときの振る舞いが、`openspec/specs/device-collection/spec.md` に
  Scenario として書かれていない。ST11 は「初回起動で権限を要求する」Story なので、ここで畳む
- **いまどうなっているか**: 振る舞いは**機械が守っている**（`collector-android/app/src/androidTest/
  kotlin/dev/ashiato/collector/PermissionDeniedInstrumentedTest.kt`。CI の `android-instrumented` で緑）。
  ただし `// Scenario:` の印は**付けていない** —— 対応する Scenario が正典に無く、付けると
  `check_scenarios.py` が「spec に無い Scenario を指す印」で warn を出すため。
  **つまり穴は塞がっているが、仕様としては書かれていない**
- **テストが実際に見ている 4 点**（Scenario の文面を書くときの材料。`MainActivity` の design D27 / tasks 6.2）:
  1. 拒否の後に `kind=permission_denied` が logcat に残る（結果コードではなく**実際の権限状態**を見た証拠）
  2. ~~前景サービスの通知が出ない（収集を始めない）~~ →
     **★ 2026-09-18 に反転（st06-app-usage の Q3 / Q7）。前景サービスの通知は出る**（収集は始まる）
  3. crash バッファにアプリが出ない（**落とさない**）
  4. 権限は拒否のまま
- **文面の叩き台**（**本人が deep で決めるもの**。そのまま使わない）:

  ```markdown
  #### Scenario: 位置の権限を拒否しても収集は始まり、拒否したことが残る

  - **WHEN** 位置の権限を求められて拒否する
  - **THEN** アプリは落ちず、収集は始まり、位置は「取得できない状態」として生存信号に載る
  ```

  > **★ 2026-09-18 に書き直した（st06-app-usage の spec レビュー R9）。**
  > 元の叩き台は「アプリは終了し、**収集は始まらず**」だった。ST06 が
  > `### Requirement: ソースごとに独立して収集する` で
  > 「収集の開始を、**ソースの取得条件が満たされているかに依らず**行う」を正典に入れるので、
  > 元の文面を ST11 が採ると**正典の中で 2 つの Requirement が食い違う**。
  > 言い方は ST06 の Scenario `位置の取得条件が欠けても位置の生存信号は届く` に揃えてある。
  > 出所: `openspec/changes/st06-app-usage/review/spec.md` R9

- **仕掛けはもう在る**（ST11 の「初回起動で権限ダイアログが出る」もこれで確かめられる）:
  - UI Automator（`androidx.test.uiautomator:2.3.0`）。権限ダイアログは `permissioncontroller` の
    ものなので **Espresso では触れない**
  - `@NeedsPristinePermissions` の印と **2 段実行** —— 自分の権限を自分で外すと
    計測テストのプロセスが死ぬ（実測 2026-09-18: `pm revoke` / `am force-stop` で `Process crashed`。
    9 本中 6 本しか走らなかった）。前提を作るのは**テストの外**の仕事で、
    `am force-stop` → `pm reset-permissions`（`pm clear` は前景サービスが残っていると `Failed`）
  - 走らせ方は `tools/android-emulator.sh`（2 段になっている）と CI の `android-instrumented`
- **出所**: 2026-09-18 の判断。**change のレビューから出たものではない** ——
  PR #62 で「拒否したときの振る舞い」を機械化したとき、正典に Scenario が無いことが分かり、
  単独の change を切るより ST11 に畳むほうが安いと決めた（ST11 は同じ capability・同じ仕掛けが要る）
- **いつ**: ST11 の上流。`device-collection` の `MODIFIED` に足す
