# ST22 への申し送り

ST22（記録を消したことにできる）は、この申し送りを書いた時点（2026-09-13）では上流が始まっていない（`tasks.md` が無い）。
**差し戻しではない** —— ST16 が先に作る滞在の側の約束を、ST22 の上流が深掘りの前に読めるように置いておく。

## st16-stay-derivation R14 — 滞在を消すときに `deleted_by` に書く値

- 何を: ST22 が滞在（`logical_source = 's01-stay'`）に削除の印を付けるとき、**`deleted_by` に `rebuild:` で始まる値を書かない**。
  `rebuild:absorbed` と `rebuild:erased-range` は ST16 の作り直しが付ける印で、それ以外（`NULL` を含む）はすべて「本人が消した」と読まれる
- なぜ: ST16 の作り直しは、本人が消した滞在の時間帯に滞在を戻さない（FR-50 ★ 2026-09-13）。`rebuild:` で始まる値を書くと、
  本人が消した滞在が作り直しの印と区別できず、**次の作り直しで消した滞在が戻る**
- 根拠: openspec/changes/st16-stay-derivation/review/spec.md R14 / design.md D4

## st16-stay-derivation R19 — 消した時間帯に一部だけ重なる滞在の扱いと、FR-50 の文面

- 何を: ST16 は、本人が消した滞在の時間帯と**少しでも**重なる滞在を**丸ごと**削除済みとして作る（**本人の決定**。深掘り第 2 回 Q12。FR-50 ★ 2026-09-13）。
  消していない時間まで隠れることがある。**（仮）なのは印を時刻の範囲に掛ける形**（design D4）で、ST22 の深掘りで本人が
  掛け方を変えたいと望むなら、**滞在を消す操作ができる前に** D4 と FR-50 の ★ の文面を改訂する
- なぜ: 消した滞在が 1 件でもできた後に掛け方を変えると、隠れる範囲が変わる
- 「消したものを戻す」操作を作るなら、戻した滞在の時間帯に `rebuild:erased-range` の印を持つ滞在があるので、それも外す必要がある
- 根拠: openspec/changes/st16-stay-derivation/review/spec.md R19 / design.md D4

## st16-stay-derivation R37 — 位置の記録を消したら、その日の滞在を作り直す

- 何を: ST22 が位置の記録（滞在の基準の `sources`。既定は `c01-location`）に削除の印を付けたら、**その記録の日（Asia/Tokyo）の滞在を作り直す**
  （`stay_store::rebuild_day(pool, user, day)`。日ごとに 1 回）。作り直しは消した位置を読まないので、その位置から作った滞在は吸収されて読み出しから外れる
- なぜ: ST16 の作り直しの契機は `/ingest` の受け入れと `POST /stays/rebuild` だけ。過ぎた日にはもう位置が届かないので、
  **消した位置の緯度経度を持った滞在が、手で作り直すまで一覧に残る**（code-verify の実測: 位置をすべて消した利用者の滞在 6 行が読み出しに出たまま）
- 根拠: openspec/changes/st16-stay-derivation/review/code.md R37

## st16-stay-derivation R44 — 滞在の削除の印を書くときは、作り直しと同じ錠を取る

- 何を: ST22 が滞在に削除の印を付ける（または外す）トランザクションでは、先頭で
  `SELECT pg_advisory_xact_lock(4816016, hashtext(<user_id>::text))`（`stay_store::LOCK_KEY` と同じ鍵）を取る
- なぜ: ST16 の作り直しは「読んだときと削除の印が同じ行だけを書き換える」ようにしてある（読んだ後に印が変わっていたら作り直しごと巻き戻す）。
  **錠を取れば巻き戻しも起きず**、取らなければ作り直しが 1 回無駄になる（取り消しは起きない）
- 根拠: openspec/changes/st16-stay-derivation/review/code.md R44 / design.md D5

## st16-stay-derivation R35 — 消した滞在の時間は、1 日の一覧で空白になる

- 何を: ST16 の 1 日の一覧は、本人が消した滞在（と、消した時間帯で隠した滞在）の時間を**移動とも記録なしとも出さず、空白にする**（design D8（仮））。
  ST22 の深掘りで「消した時間」をどう見せるか（行を出す / 空白のまま）を本人に問うなら、ここを変える
- なぜ: 空白を埋める規則（滞在にも記録なしにも入らない時間を移動にする）のままだと、とどまっていた時間が「移動 1 時間 1 分」と出た（code-verify の実測）
- 根拠: openspec/changes/st16-stay-derivation/review/code.md R35
