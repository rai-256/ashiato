# ST23 への申し送り

ST23 は、この申し送りを書いた時点（2026-09-14）では上流が始まっていない（`tasks.md` が無い）。
**差し戻しではない** —— ST16 が作った滞在（派生）の側の事実を、ST23 の上流が深掘りの前に読めるように置いておく。

## st16-stay-derivation R38 — 位置の本文を消去するとき、滞在と滞在の前の版にも座標が残っている

- 何を: 位置の記録（`c01-location`）の本文を消去する（FR-51）とき、**その時間と重なる滞在（`logical_source = 's01-stay'`、`origin = 'derived'`）の行と、
  その滞在の `core.event_version` の前の版も消去の対象に含めるか**を、ST23 の深掘りで決める。
  滞在の `raw` / `payload` は重心の緯度経度（小数 6 桁）を持ち、作り直しで吸収された滞在も行を残す（design D3）。
  いま居る滞在は作り直しのたびに前の版を積む（design Risks: 1 日 288 回）ので、座標を持つ前の版は多い（code-verify の実測: テスト 1 周で 1,443 行）
- なぜ今入れないか: 消去の操作は ST23 まで存在しない。ST16 が消去の範囲を先に決めると、ST23 の判断を先取りする
- 手がかり: 消去の後に `stay_store::rebuild_day` を呼ぶと、消去した位置（`payload = '{}'`）は判定に使われず、その位置から作った滞在は吸収される。
  **ただし吸収は行を消さず、前の版も残る**ので、作り直しだけでは座標は消えない。消去には台帳の行が要る（ST03 の門）
- 根拠: openspec/changes/st16-stay-derivation/review/code.md R38

## st19-personal-attributes Q1 — 個人属性の主張の本文も消去できる。消去の後に値を当てられない形で入っている

- 何を: 個人属性の主張（`logical_source = 's01-attribute'`）の本文の消去（FR-51）は、**ST03 と同じ消去の形**（`raw = ''` / `payload = '{}'` / `event_time` と `content_hash` は不変）かつ
  **同じまとまりに、その主張の `core.erasure_ledger` の行（`event_id = NEW.id` かつ `scope = 'event'`）**があるときだけ通る（ST19 の `core.require_claim_erasure_ledger()`。design D2）。
  台帳の行があっても消去の形でない書き換えは拒む。主張には前の版（`core.event_version`）は無い
- 主張の原文には**他の列へ写さない乱数（`nonce`）**が入っている（design D4）ので、消去の後に残る `id` / `event_time` / `content_hash` と値の候補から鍵を作り直せない。
  **位置など他のソースの記録には同じ守りが無い**（鍵は SHA-256(ソース, 出来事の時刻, 原文) で塩が無い）—— ST23 の深掘りで、消去で鍵も消すか・他のソースにも同じ守りを掛けるかを問うなら、ここが手がかり
- **ST19 の読み出し（`GET /attributes`）は、本文を消去した主張（削除の印が無く `raw = ''`）を出さず、その主張による取り消しも効かせない**（design D6 の手順 1。spec「本文を消去した主張は出ず、その取り消しも効かない」）。
  消した主張が取り消していた主張は積んだ主張に戻る（削除の印と同じ。`docs/handoff/ST22.md` の ST19 の項）
- 根拠: openspec/changes/st19-personal-attributes/deep.md Q1 / C12、review/deep.md R3、review/spec.md R7 / R18、design.md D2 / D4 / D6

## st12-archive-ingestion R23 — 残さない設定でも、読み直し後に写しを消すコードが無い

- **何を**: spec `external-ingestion` の「残さない設定では、印を置いて読み直し終えたらその写しを消す」に対して、
  `crates/server/src/archive/` に写しを消す経路が 1 つも無い（`grep -rn "remove_file\|fs::remove" crates/server/src`
  が出すのは試験の後始末だけ）。Scenario `確認待ちのために作った写しは読み直した後に消える` の担保に
  付いている試験は、DB の待ち行列の行数だけを見ていてディスク上の写しを見ていない
- **なぜ ST12 で直さないか**: 写しの削除は、**この handoff の既存項目（物理削除 FR-51 が写しに届かない）と
  同じ削除経路**を触る。2 つの Story が別々に作ると食い違うので、ST23 で 1 本にまとめる
- **根拠**: `openspec/changes/st12-archive-ingestion/review/code.md` R23
