# ST55 への申し送り

## 配布の方針の改訂（2026-11-03）— 同梱の PostgreSQL とサービスの形で、コードと正典が持ち越していること

出所: `docs/audit/2026-11-03-native-postgres-consistency.md`、`docs/requirements.md` の FR-108 / FR-109 / FR-133 の ★ 2026-11-03。
ST55 の上流（枝 `docs/st55-upstream`、commit `4f068c66`）は Docker Desktop の前提で問いを立てていた。改訂後の要件で深掘りからやり直す（C2）。
サービスに関わらない下調べ（`premises.md` の P1・P2・P6〜P8・P10・P13・P14・P16）は使い回せる。

- **K1 移行の前の退避の既定**: `crates/server/src/migrate_backup.rs:30-33` は `MIGRATE_BACKUP_DIR` が無ければ相対の `backups/pre-migrate`、`PG_DUMP` が無ければ PATH の `pg_dump`。
  サービスの作業ディレクトリは `C:\Windows\System32` で、同梱の `pg_dump` は PATH に無い。既定を FR-109 の置き場と同梱の `pg_dump` にするか、インストーラが渡すと決めて試験で固定する
  （FR-108 の Windows の CI の試験で、`MIGRATE_BACKUP_DIR` を渡さずに migrate を当てる）
- **K2 Windows の権限**: 置き場の権限を付けるのは `#[cfg(unix)]` だけ（`media.rs:41-43`・`migrate_backup.rs:141-163`）。FR-109 の「サービスのアカウントだけが書け、それと本人だけが読める」を ACL で付け、試験で ACL を読む（`Users` / `Authenticated Users` の読みが無いこと。C4）
- **C5 / K3 取り込み待ち**: `archive/config.rs:36-64` は既定の置き場を、動いているアカウントの `USERPROFILE` / `LOCALAPPDATA` から作る。サービスでは、インストールした本人のダウンロードと取り込み待ちのフォルダを明示して渡し、
  そのフォルダにサービスのアカウントの読み（取り込み待ちは読み書き）を足す（FR-108 の ★ 2026-11-03 補足・r3 Q1）。`docs/archive-inbox.md:14-16` もサービスでの渡し方に書き直す
- **C6 正典の既定の置き場**: `openspec/specs/data-durability/spec.md:26`・`:114`（書き出しの `%LOCALAPPDATA%\ashiato\export`）と `openspec/specs/device-collection/spec.md:1867`・`:1896`（原本の `%LOCALAPPDATA%\ashiato\media`）を MODIFIED で FR-109 の置き場へ。印つきの試験 `export_tests.rs:73`・`media_tests.rs:211` も一緒に
- **C7 配る D-01 の設定**: `docker-compose.yml:9-15` にしか無い 3 つのログの設定と `127.0.0.1` の待ち受けを、配る D-01 にも持たせる。`initdb` は `-A` を渡さなければ手元の接続を `trust` で通す（未確認）ので、合言葉の認証にする。
  Windows の CI の試験で `SHOW log_statement` などと `pg_hba.conf` に `trust` が無いことを見る
- **C12 許諾**: 同梱する PostgreSQL と zip に入るほかの部品（DLL）の許諾を、FR-127 の一覧（ST53 の `tools/release/notices.sh server`）と NFR-26 の検査（`tools/check-licenses.sh` は同梱のバイナリを見ない）に足す。
  `tools/release/check-artifacts.sh` で、サーバの配布物に PostgreSQL があるなら `THIRD-PARTY-NOTICES.txt` に PostgreSQL の見出しがあることを見る
- **C13 `WEB_SESSION_KEY`**: ST44 の design D8（仮）は、画面のセッションの印の鍵を環境変数 `WEB_SESSION_KEY` で渡し、無い・短いと起動しない。インストーラが作る秘密（FR-110 の DB の合言葉・FR-111 の画面の合言葉）にこの鍵も入れる
- **C8 更新**: サーバの更新と移行の失敗の戻しは、更新のたびに UAC を 1 回出して行う（FR-108 の補足・r3 Q2）。更新係は別のサービスのアカウントで動き、結果を自分の置き場に書く（FR-112 の ★ 2026-11-03）。ST55 はサービスの名前と置き場をこの形に合わせて決める（ST57 / ST58 が乗る）
- **C11 開発版**: 開発版の S-01 / D-01 は別のサービスの名前・別の置き場・別の待ち受け（FR-106 の ★ 2026-11-03）。ST54 の D8（仮）の `docker compose` の手順書はつなぎ

## ST53 の rebase の整合の確認（`docs/audit/2026-11-03-st53-rebase-consistency.md`）

- **C3 ST53 の道具が先に要る**: 上の C12 が足す先（`tools/release/notices.sh server`・`tools/release/check-artifacts.sh` の許諾の 3 点・`tools/check-licenses.sh` の許可の一覧）は ST53 が作る。
  ST55 の requires は `[ST52, ST28]` で ST53 を含まない。ST55 の下流が許諾に手を付けるときに ST53 が main に入っていなければ、ST53 を依存として取り込む（`story_deps.py take`）か、ST53 の後へ回す
- **C4 ST53 の Requirement を MODIFIED する**: ST53 が正典の distribution に入れる 2 つの Requirement —— 依存の許諾の検査（許可の一覧を「17 の値とちょうど同じ」と固定する Scenario）と
  配布物の 3 点（サーバの `THIRD-PARTY-NOTICES.txt` に入れる部品の一覧・「tar / zip では根に」）—— を MODIFIED し、許可の一覧に `PostgreSQL` ほか zip の部品の許諾を足す。
  足すと ST53 の自己試験（17 の値とちょうど同じ）が落ちるので、Scenario と一緒に直す
