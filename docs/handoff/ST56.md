# ST56 への申し送り

## 送り先の系統の取り違え（2026-11-03）— 資格情報が違うと FR-106 の知らせに届かない

出所: `docs/audit/2026-11-03-st54-q12-consistency.md` の C2、`docs/requirements.md` の FR-106 の ★ 2026-11-03（ST54 の深掘り第 2 回 Q12・Q13）。

- 収集アプリは系統（開発版 / それ以外）の違う S-01 へは送らず手元に残し、「送り先が開発版／正式版のサーバです。送り先を確かめてください」と知らせる。系統は契約の版を読めた答え（`GET /contract`）からだけ読む
- `GET /contract` には収集アプリの資格情報が要り、401 は一時的な失敗として扱われる（`crates/server/src/contract_version.rs:52`・`collector-android/.../ContractGate.kt:27`・`crates/collector-windows/src/runtime.rs:819`）。開発版の S-01 が自分の資格情報を持つなら、送り先の取り違えの多くは 401 で現れ、FR-106 の知らせは出ない
- これを受けられるのは ST56 の「設定し直しを促す」（FR-128）だけ。ST56 の深掘りで次を決める: 繋ぎ先を設定する時点で系統を確かめるか・401 が続くときの文に「送り先の取り違え」を含めるか・利用者に見せる呼び名（FR-106 の文は「送り先」、FR-128 は「接続先」、ST56 は「繋ぎ先」）をどれに揃えるか
- 携帯の未送信は上限（FR-8 / FR-9。`Retention.kt`）で送れない理由を見ずに捨てるので、気づかないまま 90 日を過ぎると失う（`loss: discarded` の型。問いにするなら A）
