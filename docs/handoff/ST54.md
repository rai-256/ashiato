# ST54 への申し送り

## st51-update-history premises 9 — 同じ PC に並べた C-02 の端末識別子を分ける

- C-02 の端末識別子は環境変数 `ASHIATO_DEVICE_ID`（設定の値。`crates/collector-windows/src/config.rs:123`）。正式版と開発版を同じ PC に並べたとき、同じ値になりうる
- ST51 は収集アプリの版の変化を、端末・部品ごとに生存信号の版を並べて導く（`core.collector_version_change`）。並べた 2 つの C-02 が同じ端末識別子で交互に信号を送ると、
  版が行き来したように見える（生存信号の行と版は残るので、識別子を分ければ読み口は出し直せる）
- 並べる仕組みを作る ST54 で、並べた C-02 が別の端末識別子を持つようにする
- 出所: `openspec/changes/st51-update-history/premises.md` の 9・C10

## ST52 Q4・Q11 — 開発版に携帯の APK を足し、開発版の鍵を作る（整合の確認 `docs/audit/2026-11-01-st52-door34-consistency.md` の C1）

- ST52 の深掘りで、開発版（`nightly`）に携帯の APK を入れ始めるのは **ST54 から**になった（Q4。本人が推奨と違う側を選んだ）。ST52 の開発版のリリースには S-01 と C-02 だけが並ぶ
- 開発版の C-01 は識別子 `dev.ashiato.collector.dev`（扉 34）で、**正式版と別の鍵**で署名する（Q11）。鍵は開発版の Environment に置き、控えは USB に 1 部（扉 34 ★ 2026-11-01・`docs/production-prep.md` の A-3）
- 開発版の鍵は一度配ると替えられない（替えると開発版を入れた携帯は消して入れ直し、手元の未送信が消える）。ST54 で鍵を作る前に、形（ST52 の design D3（仮）の RSA 4096・25 年以上）と作る手順（ST52 の `docs/release.md`）を確かめる
- ST54 の完了の判定には、いまは開発版のリリースに携帯の APK が並ぶこと・開発版の鍵で署名されていることが無い。足すかは ST54 の上流で決める
- 出所: `openspec/changes/st52-release-channels/deep.md` の Q4・Q11、`docs/requirements.md` の扉 34・FR-104 の ★ 2026-11-01
