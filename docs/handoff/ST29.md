# ST29 への申し送り

## st28-private-network-only Q4 — 収集側の合言葉が全記録を読める範囲を、ST29 で絞る
- 何を: 収集アプリの APK（BuildConfig に埋め込み）と C-02 が持つ合言葉（`.env` の `API_TOKEN`）は、送る経路だけでなく
  `/events` などの読み出しにも通る（`crates/server/src/lib.rs` の `authorize`）。PERM-10 の資格情報の配り方を決めるときに、
  **収集側の資格情報が読める範囲**を一緒に決める
- なぜ今入れないか: ST28 の深掘り Q4（2026-09-29）で本人が「ST29 まで全読みのまま置く」を選んだ（推奨は「ST28 で送る経路だけに絞る」）。
  ST28 は画面（V-01）の資格情報だけを合言葉のログインに分け、収集側の合言葉は変えない
- それまでの間に失われうるもの: 落とした電話・入れ直す前の古い APK の合言葉で読まれた記録（loss: exported）。
  ST28 は電話を落としたときの手順（網からノードを外す・合言葉を変えて APK と C-02 を入れ直す）を手順書に置く
- いつ・どこで: ST29 の深掘りで（PERM-10 の配り方の問いと一緒に）
- 根拠: openspec/changes/st28-private-network-only/deep.md Q4 / deep-answers-1.txt

## st17-daily-feeling R5 — 収集側の合言葉で読める主観の口（`/feelings` と `/feelings/reminder`）

- **何を**: ST17 は主観の読み出し `GET /feelings`（尺度・ひとこと・記入の日時を返す）と、携帯の通知の判断 `GET /feelings/reminder`（通知の時刻と「その日に記録があるか」の真偽だけ）を足す。
  どちらも `authorize()` を通るので、ST29 までは収集側の合言葉で両方読める（`/events` も主観の原文を返す）
- **ST29 で範囲を絞るとき**: 携帯の収集アプリが要るのは `/feelings/reminder` だけ。`/feelings` は画面（session）だけでよい
- **根拠**: openspec/changes/st17-daily-feeling/review/spec.md R5 / design.md D9

> ★ 2026-10-12（docs/audit/2026-10-12-st17-consistency.md C1）: 上の R5 の「ST29 で範囲を絞るとき」は、収集アプリの資格情報が ST44 に移ったので `docs/handoff/ST44.md` に写した。
> 衛星の資格情報で ST17 の 2 つの口が主観を返さないことは C2（`docs/handoff/ST45.md`）。

## docs/audit/2026-10-12-st17-consistency.md C2 — 衛星の資格情報では、ST17 の主観の口（`/feelings` `/feelings/reminder`）も返さない

- **何を**: ST17 の spec は 2 つの口を「資格情報を持つ呼び出し元」に返すと書いている（2026-10-07。衛星の資格情報が無かった時点の文）。
  ST29 の完了の判定「衛星の資格情報では、まだどの口も記録を返さず受け取らない」は、route ごとでなく **router の全 route を衛星の資格情報で呼んで、記録を返す口が 0** で試験すると、後から足した `/feelings` も拾える
- **根拠**: docs/audit/2026-10-12-st17-consistency.md C2 / openspec/changes/st17-daily-feeling/specs/subjective-log/spec.md（主観を読み出す・通知の判断）

## docs/audit/2026-10-12-st33-consistency.md C4 — 衛星の資格情報では、書き出しの口（ST33）も断る

- 何を: ST33 の書き出しの 3 本の口（書き出しを始める・件数と見込み・状態）は「記録の読み出しの口と同じ資格情報」で通す（ST33 の spec:23、design D1）。
  記録そのものは返さないが、全ソースの件数と期間（主観・人物など承認していない種類を含む）と、書き出しの置き場の絶対パスを返し、書き出しを始められる
- どうする: 衛星の資格情報では 3 本とも断る（画面のログインと本人の合言葉だけが通る）。上の C2 の全 route の試験の判定を「記録を返す口が 0」から
  「**衛星の資格情報で 2xx を返す口が、衛星向けに作った口だけ**」に広げれば、書き出しの口も、後から足した口も拾う
- なぜ ST29 か: 衛星の資格情報を作るのが ST29。それより前に衛星の資格情報は無く、失われるものは無い。ST33 の deep.md の C11「呼び出し元ごとの本決めは ST29」の宛先は、
  2026-10-11 の改訂で収集アプリと画面の資格情報（ST44）・衛星の資格情報（ST29）・衛星の読み出しの門（ST45）に分かれた
