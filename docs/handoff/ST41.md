# ST41 への申し送り

ST41（幅のある出来事に終わりの時刻を持たせる）は、この申し送りを書いた時点（2026-10-12）では上流が始まっていない。
**差し戻しではない** —— 書き出し（ST33）が「消した場面」を除くときに終わりの時刻を読む場所を、ST41 の上流が深掘りの前に読めるように置いておく。

## docs/audit/2026-10-12-st33-consistency.md C7 — 終わりの列を足すとき、書き出しの除く判定と `core.stay_erased` にも読ませる

- 何を: ST33 の書き出しは、本人が消した滞在の時間と幅で重なる緯度経度つきの行を除く（NFR-16 ★ 2026-09-29、ST33 の Q5 / Q6）。幅は内容（`payload`）の鍵
  （`export::END_KEYS` = `end` / `end_time` / … ）で読み、消した時間も `core.stay_erased` の `coalesce(core.try_timestamptz(payload->>'end'), …)`
  （`migrations/202609271716_deletion_ledger.sql:60`）で読む。FR-91 は終わりを**列**に置くので、列だけを持つ記録は (c)「次の記録まで」に落ちる
- どうする: 終わりの列を足すときに、ST33 の幅の読み方（design D5b の (a)）と `core.stay_erased` が**列を先に、無ければ内容の鍵**を読むようにする。
  `export_tests.rs` に「終わりを列に持つ緯度経度つきの記録が消した時間と重なれば除かれる」を 1 本置く
- 失われるもの: 滞在の終わりを列へ移したのに読ませないと、前の版の広い時間（ST33 の C19）が点に縮み、消した場面の緯度経度が書き出しから外へ出て戻らない（`loss: exported`）。
  列を足すこと自体は問わない —— 読ませ方は機械で決まる
