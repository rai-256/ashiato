# ST08 への申し送り

ST08 自身の whole-branch review（`/story ST08 final`）で残した Minor。失うものは無い（A ではない）ので、merge の後に `fix/` の小さな change で拾う。

## st08-browser-history R65 — Firefox の帳面が、ini の絶対パスのプロファイルと `Profiles\` 直下の同名ディレクトリで衝突する

`history/locate.rs` の `scan_ini` が `directory` = `file_name` にするので、2 つが同じ `(browser, directory)` の帳面を共有し、互いの訪問を毎回「消えた」と記録する。
帳面のファイル名だけ別の鍵にすれば `profile_dir` も D6 も変えずに止められる。本文の `profile_dir` で 2 つを見分けるのは設計の判断（D4 / D6）。

## st08-browser-history R66 — URL の行を失った訪問が URL 無しの識別子で 2 件目として送られる

URL 付きで送った訪問が後から URL の行を失うと、取り込み口に同じ訪問の行が 2 つ残る（URL ありと URL 無し）。D6 に「同じ `slot` がすでに送られていれば送らない」を足すか、件数を数える Story で畳む。

## st08-browser-history R67 — `CLEANUP_FAILURES` の static と `collect_rows` の飛ばし方

`history/read.rs` の `CLEANUP_FAILURES` をプロセス全体の static から呼び手ごとの値にする。`collect_rows` は値の型の不正だけを飛ばし、`InvalidColumnIndex` などのコードの誤りは失敗にする。

## st08-browser-history R74 — 積み込みの途中で落ちた取得の積み直しと、`add_many` の書きかけ

深掘り第 5 回 Q9 の実装（990cc9b）の scoped re-review で残した Minor。途中のまとまりで落ちると、試し直しのたびに前のまとまりを重ねて積む
（取り込み口が `external_id` で畳むので失われない）。大きな `write_all` の書きかけには次の追記が連結されうるので、追記の前に末尾の改行を確かめる。

## st08-browser-history R75 — 消えたプロファイルの帳面の書き直しと、除外の登録を読む時点

`Plan::save` が開いた帳面をすべて書く（旧版は変えたものだけ）。除外の登録は読み終えた直後に読むので、積み終えるまでに足した除外はその回に効かない。変えた帳面だけを書く印を持てば前者は戻る。

## st08-browser-history R76 — 積み込みの途中・帳面の保存の失敗のテスト

2,001 件以上で 2 回目の積み込みを失敗させても帳面が無いこと、帳面を書けないときに生存信号へ `queued=false` が渡ることをテストで固定する。

## st08-browser-history R83 — 印がある起動で、起動直後の信号が 1 区間遅れて正しくなる

`runtime.rs:668-673`。起動直後の確かめが取得より先に終わるので、原因を直した後の最初の信号も「取得できない」になる。`is_reading()` の間は信号を待つ選択肢を D12 に書く。

## st08-browser-history R84 — panic のテストが stderr に出す

`history_heartbeat_counts_panicked_read_as_not_queued` の中だけ panic の hook を黙らせる。

## st08-browser-history R85 — Task 10 の F2〜F4

`tests/runtime_windows.rs`: 取得のときにブラウザが動いていることを `try_wait().is_none()` で固定する / ブラウザの stderr を継がない / Chrome を `%LOCALAPPDATA%\Google\Chrome\Application` でも探す。

## st08-browser-history R87 — spec の SHALL の「読んだ時刻を載せ」と、印を書く側の無言の失敗

`specs/desktop-collection/spec.md:169-172` と導出の段落を「読んだ時刻を基に、ただし前に送った版より前にしない（前に送った版の記録がどちらも失われた（無い・読めない）後は除く。保存場所ごと消えた・入れ直した場合を含む —— 第 7 回 Q12 / 第 8 回 Q13）」の 1 文にまとめる。例外の括弧は落とさず、いまの SHALL の括弧の範囲のまま写す（review/code.md R89・整合の確認 2026-10-14 の C5 / Q13 の確認の C6）。`remember_queued` の印を書く `write(...).ok()` の失敗も数える。

## st08-browser-history R93〜R97 — 読めない送った版の最大値の退避（深掘り第 8 回 Q13）の Minor

`history/collect.rs` の `read_sent_version`: 退避はパース失敗に限り、NotFound 以外の io エラーは送る準備の失敗にして次の取得でやり直す（R93）/
退避先は直近 1 つと design D16 に書くか時刻つきにする（R94）/ 読みの thread の panic で種別が落ちることをコメントに書くか印を共有する（R95）。
`runtime.rs` の `history_heartbeat_reports_unreadable_sent_version` のコメントを「書き直されたファイルを読める」に直す（R96）。
退避できない（退避先に空でないディレクトリ）ときに積まず両方の種別が載り本体が残ることのテストを 1 本足す（R97）。
