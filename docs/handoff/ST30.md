# ST30 への申し送り

ST30（バックアップ）は、この申し送りを書いた時点（2026-10-15）では change が無い（上流の前）。**差し戻しではない** —— ST33 の独立検証で見つかった、戻した後の書き出しの置き場の扱いを、ST30 の上流が読めるように置いておく。

## st33-data-export R23 — D-01 を戻した後、台帳に無い前の書き出しが置き場に残り続ける

- 何を: ST33 の書き出しは、置き場（`ASHIATO_EXPORT_DIR`）の前のファイルを**台帳（`core.export_ledger`）の `done` の行にあるものだけ**消す（ST33 design D16。本人の置いたファイルを守るため、台帳に無いパスには触らない）。
  D-01 をバックアップから戻す（ST32 の復元テストを含む）と、戻した時点より後の書き出しは台帳から消え、置き場の `ashiato-export-*.zip` は「このシステムが書いていないもの」になる。それらは二度と消えず、状態の `leftover` にも出ず、その後に本人が消した場面を含んだまま積み上がる（中身は合言葉で暗号化されている）
- どうする（案）: 戻す手順の中で、置き場の `ashiato-export-*.zip` / `.partial-ashiato-export-*.zip` のうち台帳に無いものを本人に見せる（消すかは本人が決める）。
  ST33 の側でできるのは、台帳に無い書き出しの名前のファイルを状態に「見覚えの無い書き出しのファイル」として出すこと（消さない）で、扉は開いたまま残る
- 失われるもの: 無い（消さない側。残り続けるのは本人の手元の暗号化されたファイル）
- 根拠: openspec/changes/st33-data-export/review/code.md R23（code-verify の実測: 台帳を作り直した worktree の置き場に、台帳に無い書き出しが 11 個残っていた）。`docs/stories/ST30.md` / `ST32.md` に「書き出し」の語は無い
