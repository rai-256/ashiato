# ST49 への申し送り

## st50-contract-version R1 — D3（仮）の反転条件は ST50 で条件の形が立つが、欄を落とさなくてよい
- 何を: ST49 design D3（仮）の反転条件「知らない欄を送り返したことで S-01 が要求を断る事例（`deny_unknown_fields` を足した型など）が出たら、送る前に S-01 の契約の版で欄を落とす」について。
  ST50（深掘り Q2 の推奨）は、S-01 が知らない最上位の欄を持つ 1 件を `unknown_field`（収集アプリが捨てない断り）で断る。断られるのは S-01 が古いときだけで、そのとき行は収集アプリの手元に残り、
  S-01 を更新すれば入る（FR-125 のとおり）。**送る前に欄を落とすと、その欄が失われる**ので、反転条件が立っても欄を落とす実装はしない。D3（仮）の反転条件の文を「ST50 の `unknown_field` は該当しない（行は残り、S-01 の更新で入る）」に直す
- なぜ今入れないか: ST49 は下流が走っている（tasks.md あり）。走っている Story へ差し戻さない
- いつ・どこで: ST49 と ST50 の後に main に入る側が rebase のときに design の 1 文を直す。`client_version` は版 1 の欄（ST50 design D8）なので、ST50 の知らない欄の一覧（型から作る）に入っていれば `unknown_field` にならない —— 後から入る側が、ST50 の `st50_released_v1_accepted` の例に `client_version` を足して確かめる
- 根拠: openspec/changes/st50-contract-version/review/spec.md R1・design.md D2・D8、openspec/changes/st49-record-component-version/design.md D3（仮）

## st50-contract-version R1（続き）— 後から main に入る側が直すもの 2 つ
- 何を: (1) ST50 が先に main に入ったら、ST49 が収集アプリ 2 本と S-01 の型に足す `client_version` で封筒の形の写し（`docs/contract/envelope.json`）が古くなり、ST49 の PR の CI（`St50EnvelopeShapeTest`・`st50_envelope_shape`・`tools/check-contract-version.sh`）が落ちる。

- なぜ今入れないか: 同上（ST49 は下流が走っている）
