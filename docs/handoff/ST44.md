# ST44 への申し送り

## docs/audit/2026-10-12-st17-consistency.md C1 — 収集アプリの資格情報でも、通知の判断の口（`GET /feelings/reminder`）だけは読める

- **何を**: ST44 の完了の判定は「収集アプリの資格情報では、送ることだけができて記録は読めない」。ST17 の携帯の通知（FR-43）は、
  通知を出す前に収集アプリの資格情報で `GET /feelings/reminder`（通知の時刻と「その日に紐づく記録があるか」の真偽だけ。本文は返さない）を聞く。
  ST17 の design D10 は、答えが得られない（401 を含む）なら**通知を出す**側に倒すので、この口まで塞ぐと書いた日にも毎日鳴る
  （FR-43 ★ 2026-10-07 が避けた「鳴りすぎる通知は切られる」に黙って戻る）
- **ST44 で範囲を絞るとき**: 収集アプリの資格情報に残すのは `/feelings/reminder` の読みだけ。`/feelings`（尺度・ひとこと）は画面（session）だけでよい。
  `GET /feelings/reminder` を収集アプリの資格情報で呼んで 200 を見る試験を ST44 の側に置く
- **宛先が移った経緯**: ST17 はこれを `docs/handoff/ST29.md` の R5 として ST29 に宛てたが、2026-10-11 の改訂で収集アプリの資格情報は ST44 に移った（INDEX の 2026-10-11 の訂正）
- **失われるもの（A）は無い**: 鳴りすぎは設定と資格情報の範囲を直せば戻る
- **根拠**: docs/audit/2026-10-12-st17-consistency.md C1 / openspec/changes/st17-daily-feeling/design.md D9 / D10 / docs/handoff/ST29.md R5

## docs/audit/2026-10-13-st14-consistency.md C1 — 収集アプリの資格情報でも、途絶の判定の口は読める

- **何を**: 改訂後の FR-35（★ 2026-10-13。ST14 の深掘り Q1）では、携帯と PC の収集アプリが**収集アプリの資格情報でサーバの途絶の判定を問い合わせ**、
  OS の通知を出す。返すのは途切れたソースの表示名と最後に届いた日時だけ（ST14 の deep C5。記録の中身は返さない）。
  上の C1 の「残すのは `/feelings/reminder` の読みだけ」で締めると、この問い合わせが 401 になり、**携帯からも PC からも途絶の通知が黙って出なくなる**
- **ST44 で範囲を絞るとき**: 例外を「`/feelings/reminder` と途絶の判定の口」の 2 つにする（口の名前は ST14 の design が決める）。
  途絶の判定の口を収集アプリの資格情報で呼んで 200 を見る試験を ST44 の側にも置く（ST14 の側にも置く）
- **失われるもの（A）は無い**: 鳴らない間に途切れが続くことはあるが、格子の⑥には残り、資格情報の範囲を直せば戻る
- **根拠**: docs/audit/2026-10-13-st14-consistency.md C1 / docs/requirements.md FR-35 ★ 2026-10-13 / openspec/changes/st14-outage-alert/deep.md Q1・C4・C5
