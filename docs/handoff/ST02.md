## st03-idempotent-ingest R-e — 更新だけが届いた日を稼働記録でどう数えるか

- **何を**: ST03 が外部サービス由来の更新の経路を開けたので、稼働記録の正典
  「**新しく入った記録だけを数える**」に穴が開く —— 更新だけが届いた日は
  `core.coverage.event_count` が 0 のまま増えない
- **ST03 側でどうしたか**: 正典どおり**更新は 0 件として数える**。ただし
  **その日の行そのものは立てる**（「その日は収集が動いていた」は更新の到着でも真）。
  `crates/server/src/lib.rs` の `ingest_one`（`i32::from(row.is_some())`）
- **いまどう見えるか**: `coverage.rs:568-578` が「① 記録あり」を `core.event` から
  `count(*)` で引いているので、**更新だけが届いた日も「① 記録あり」になる**
  （出来事の時刻がその日にある限り）。画面は倒れない
- **なぜ今入れないか**: 数え方の正典は `collection-coverage`（ST02）が持つ。
  ST03 が変えると **NFR-13 の分子が動く**（成功条件 1 の合否に触る）
- **いつ・どこで**: ST02 の merge 後、必要なら `fix/coverage-count-updates` で。
  **数え方を変えるなら本人に問う** —— 達成日数が動くので `premise` の型
- **根拠**: `openspec/changes/st03-idempotent-ingest/tasks.md` 13.2 (e) /
  `openspec/changes/st03-idempotent-ingest/deep.md`「あわせて、`lib.rs:224` は稼働記録の件数に
  『新しく入った行だけ』を足すので、Q1 の更新で入った再取得は 0 件として数えられる」
