# 収集アプリの設定手順

この手順は、サーバを移した後、初めて収集アプリを使うとき、または送り先・資格情報を変更したときに使う。設定の文字列には収集アプリ用の資格情報が含まれるため、画面に表示したり貼り付けたりする場面以外では、ログ・標準出力・通知・スクリーンショット・台本に残さない。

## 1. サーバで設定の文字列を作る

1. サーバの画面を、携帯または PC から Tailscale のアドレスで開く。
2. 画面のログインで、画面の合言葉を入れ直す。
3. 「収集アプリの設定」を開き、表示された設定の文字列をコピーする。

設定の文字列は、合言葉を入れ直した本人だけが取得できる。送り先や資格情報を別々に編集せず、毎回この画面で作った一行を使う。

## 2. 携帯に貼る

1. 携帯の収集アプリを開き、最初に表示される設定の画面で設定の文字列を貼る。
2. 保存時の確認結果を見て、送り先へ接続できることを確認する。接続できなくても設定は保存されるので、表示された案内に従って直す。
3. 未送信の記録がある状態で送り先を変えた場合は、内容を確認するまで送信しない。保留にした場合は、後で「この送り先へ送る」を押して送信を再開する。

初回の設定を後回しにした場合も、アプリのメインの画面の「送り先の設定」から同じ手順で設定できる。設定の画面には「設定済み」と送り先だけが出て、資格情報は出ない。

## 3. PC に貼る

PC では黒い窓（コマンドプロンプト）を開き、設定の文字列を標準入力へ貼る。実行ファイルのある場所で次を実行する。

```text
ashiato-collector-windows.exe setup
```

表示された入力待ちに、携帯と同じ設定の文字列を貼って Enter を押す。保存すると確認の結果（「繋がりました」など）が出る。未送信の記録があるまま送り先を変えたときは、未送信の件数と期間を示して「この送り先へ送りますか [y/N]」と聞くので、送るなら `y` を入れる（`N` か答えずに閉じると保留になる。§5）。設定の無い PC で収集アプリを窓のまま起動したときも、同じ入力待ちがその窓に出る。資格情報は Windows の保護された保存場所へ保存され、台本や自動起動の引数には書かれない。既定の置き場は `%LOCALAPPDATA%\ashiato\collector` で、端末の識別子は最初の起動時に作られて保存される。

開発や録画で、環境変数から設定を渡して起動する必要がある場合だけ、次の印を付ける。5 つの設定値を台本へ書く用途ではなく、開発・試験専用の起動方法である。

コマンドプロンプト（cmd）:

```bat
set "ASHIATO_BASE_URL=http://127.0.0.1:18787"
set "ASHIATO_API_TOKEN=<開発用の資格情報>"
set "ASHIATO_USER_ID=00000000-0000-0000-0000-000000000000"
set "ASHIATO_DEVICE_ID=pc-01-dev"
set "ASHIATO_STATE_DIR=C:\dev\ashiato-state"
ashiato-collector-windows.exe --config-from-env
```

PowerShell:

```powershell
$env:ASHIATO_BASE_URL = "http://127.0.0.1:18787"
$env:ASHIATO_API_TOKEN = "<開発用の資格情報>"
$env:ASHIATO_USER_ID = "00000000-0000-0000-0000-000000000000"
$env:ASHIATO_DEVICE_ID = "pc-01-dev"
$env:ASHIATO_STATE_DIR = "C:\dev\ashiato-state"
.\ashiato-collector-windows.exe --config-from-env
```

引数 `--config-from-env` の代わりに環境変数 `ASHIATO_CONFIG_FROM_ENV=1` を置いてもよい。印で渡した送り先は承認したものとして扱い、置き場の設定のファイルは読まない。

自動起動を使う場合も、台本に書くのは実行ファイルの場所、既定でない置き場、端末の識別子だけにする。前の形の台本から移るときは、環境変数の印が無くても `ASHIATO_STATE_DIR` と `ASHIATO_DEVICE_ID` の値を引き継ぐ。送り先・資格情報・利用者は、印の無い環境変数から読み直さない。

## 4. 更新の確認を切り替える

携帯の更新の確認は、収集アプリの設定画面の「新しい版を確かめる」スイッチで端末ごとに切り替えます。切った端末では更新の確認や新しい版の知らせを行いません。戻すときは同じスイッチを有効にします。

PC の更新の確認は、管理者のコマンドプロンプトで次を実行して切り替えます。

```text
ashiato-collector-windows.exe update-check off
ashiato-collector-windows.exe update-check on
```

携帯と PC の設定はそれぞれの端末に保存されます。サーバのインストーラにある `ashiato-setup.exe update-check off|on` はサーバの更新係を切り替えるもので、収集アプリのスイッチとは別です。

## 5. 知らせが出たとき

収集アプリがサーバから 401 を受け続けると、1 時間後に「サーバに断られています。資格情報か送り先が違います。設定し直してください」という知らせが出る。記録は捨てずに保持されるので、「設定し直してください」の案内に従い、サーバで新しい設定の文字列を作って携帯と PC に貼り直す。

設定を保存してから 24 時間、送り先から答えが 1 度も返らないと「送り先に届きません。設定を確かめてください」が出る。設定していない間は「送り先が設定されていません」が出る。未送信を残したまま送り先を変えて保留にしている間は「送り先の確認を待っています」が出る。どの知らせも、続く間は 24 時間ごとに出し直し、押すと携帯は設定の画面、PC は `setup` の窓が開く。

## 6. サーバの `repair` や資格情報を変えた後

サーバの `repair` を実行した後、または収集アプリの共有の資格情報を変更した後は、古い設定のまま送信を続けない。サーバの画面にログインし、画面の合言葉を入れ直して「収集アプリの設定」から新しい文字列を作る。その文字列を、使っているすべての携帯と PC に貼り直す。

未送信の記録があるときは、送り先を変更した後に自動で送られない。送り先を確認してから、携帯では設定の画面の「この送り先へ送る」を押す。

PC で保留を解くには、`ashiato-collector-windows.exe setup` を走らせ（「送り先の確認を待っています」の知らせを押しても開く）、設定の文字列を貼らずにそのまま Enter を押す。今の設定のまま未送信の件数と期間が出て「この送り先へ送りますか [y/N]」と聞かれるので、`y` を入れる。次の送信の契機から、新しい送り先へ送り始める。

## 7. 前の形の台本から移る

前の形で `ASHIATO_STATE_DIR` を渡していた PC は、新しい実行ファイルへ置き換える前に、その台本の置き場と端末識別子を確認する。`setup` で設定を更新するときも、その 2 つの行は残す（置き場が既定と同じなら省略できる）。除外設定など既存の置き場にある記録を引き継ぐためである。

移行後の確認は次の順で行う。

1. 環境に `ASHIATO_STATE_DIR` または `ASHIATO_DEVICE_ID` がある場合は、その値を確認する。
2. 無い場合は、自動起動の台本にある同名の行を確認する。
3. 端末識別子が台本にも無い場合は、既存の `%LOCALAPPDATA%\ashiato\collector\settings.json` の値を使う。
4. それでも無ければ、新しい実行ファイルが最初の起動時に識別子を作る。

送り先・資格情報・利用者を旧台本から平文で引き継がない。設定の文字列を画面で作り、携帯と PC に貼る。
