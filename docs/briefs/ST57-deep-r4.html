新しい版が出たら知らせる —— 切り方の通知を更新ありの通知が上書きしてよいか

止める 1 問 —— 答えが要る。後から変えると失われるものがある

第 2 回の Q11 で、入れ替えた収集アプリは切り方を示すまで問い合わせないと決めていただきました。ところが AI が仮で決めた D30 の通知 ID の割り当てでは、切り方を示す通知が数分後に更新ありの通知で上書きされます。

Q11 の答え（切り方を示してから問い合わせる）は変えません。この問いは、通知の欄に切り方をどこまで残すかだけです。選んだら一番下の「回答をコピー」を押して、セッションに貼り戻してください。

Q14止める一方通行

前の版から入れ替えた携帯は、「更新の確認: 有効（切るには設定の画面）」の通知を出せた時に、切り方を示した印を立てます。その直後に新しい版が見つかると、今の実装は同じ通知 ID 10 で「新しい版 0.5.0 が出ています」を出し、切り方の通知を上書きします。切り方の通知を残すために別の通知 ID を使いますか。それとも更新ありの通知で置き換えてよいですか。

同じ ID で置き換えると、通知の欄を数分の間に見なかった人は切り方を見ないまま次の毎日の問い合わせが出て、元の IP と時刻が配布元に残り得ます。外へ出た IP と時刻は後から取り消せません。

失われるもの: 外に出たデータは戻らない

通知の ID は今、切り方と更新ありが 10、確かめられていないが 11、既存のサーバ更新通知が 5 です。D30 は「専用の通知 ID」と書きましたが、どの通知をどの ID に残すかを決め切れていませんでした。

同じ族（切り方を示した印を立てた後も、本人が切り方を読める状態を保つ）の場合
  • 入れ替えた携帯で通知を出せない、または画面を開かない —— 決めた（Q11: 示せない間は問い合わせない）
  • 入れ替えた携帯で画面の行が見えないまま印が立つ —— 決めた（Q12: 行を組んで画面に出した時だけ印を立てる）
  • 入れ替えた PC で離席中のトーストが成功する —— 決めた（Q13: 定期の時はロックしておらず直前に入力があった時だけ）
  • 入れ替えた携帯で切り方の通知を出した直後に更新ありの通知が同じ ID で上書きする —— 未決 Q14
  • 既存のサーバ更新通知（チャンネル contract・ID 5） —— 決めた（D30: 置き換えない）

切り方の通知に別の ID を割り当て、更新ありの通知と並べて残す推奨

切り方を示した通知を更新ありで上書きしない。既存のサーバ更新通知（ID 5）も置き換えない。通知が 2 件並ぶ間はあるが、切り方を後から読める。

更新ありの通知で切り方の通知を置き換えてよい

通知は 1 件のままにする。更新ありの通知には切り方を書かない。

戻せないもの: 切り方を見なかった人でも、示した印が残るため、次の機会に問い合わせの元の IP と時刻が配布元に残り得る
