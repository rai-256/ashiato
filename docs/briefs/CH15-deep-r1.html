Q-L2止める前提が崩れた

最後の段の指摘（review/code.md R1）を受けて、crates/server/src/web_session.rs の 2 つの口、ログインの口（POST /session）と資格情報を返す口（POST /collector-setup）の「照合 → 読み出しの記録の行 → 答え」を run_to_completion（tokio::spawn した task）で走らせるようにしました。接続が切れて求めが取り消されても照合は最後まで走り、失敗なら失敗に数え、記録の行が 1 行残ります。これまでは、取り消された求めでは行が残らず、印を待っている間に取り消されると失敗にも数えられませんでした。CH15 の「壊してはいけないもの」4（ログインの口の振る舞い）に触れる変化です。これを受け入れますか。

取り消された求めの記録の行は、その時に書かなければ後から作れません。逆に、行を残すと読み出しの記録の行数と失敗の数え方が変わります。依頼（照合の差し替え）の外で、ログインの口にも及んでいるので、人が決めます。

失われるもの: 取っていなかったデータは後から作れない

応答の形と状態の番号は変わりません（1.2 の st55_・st56_・web_session と ch15_ が PASS）。取り消しの試験は、照合の印を試験が握り、照合が印を待ち始めた合図で求めを取り消す形で、時刻に依らずに固定しています（fix の commit 82884331e・0b229b92e・698e27208）。正典 data-sensitivity の「1 件ごとに 1 行」を根拠に足しました（design D1 の「最後の段の処置で足したこと」）。task の join が失敗したとき（task の panic）は 500 を返します。

同じ族（2 つの口の照合を 1 つの道にしたことで、依頼の外で変わる振る舞い）の場合
  • 取り消された求めでも照合を走り切り、行を残し、失敗に数える（2 つの口） —— 未決 Q-L2
  • 断る数を超えている間は、1 つずつの印を待たず本文も読まずに 429（2 つの口。印を取った後にも数え直す） —— design D1（R4・R5）。応答と数えは base と同じで、変わるのは 429 を返すまでの待ち時間だけ。失うものが無いので問わない
  • 空の合言葉は Argon2id を回さず失敗に数える（照らす形のログインの口） —— design D1。base でも照合は失敗して数えられ、401 も同じ。変わるのは CPU の使い方だけ
  • ログインの口の、印が取れないときの 503 の道を外した —— design D1（R9）。印は static で閉じないので、base でも起きない道
  • 資格情報の口がログインの口と同じ印で 1 つずつ並ぶ（同時のログインと資格情報の求めが順に待つ） —— design D1（正典「ログインの口と同じ失敗の遅れと回数の制限を当て、失敗の数えを共有する」）
  • 試験のための App の組み方を testdb::verifier_app に寄せ、tasks の制約の外の st55_tests.rs・testdb.rs に触れた（review/code.md R8） —— 振る舞いは変わらない（試験の置き場だけ）。軽い路の判定はこれを外れた理由にしていない

受け入れる（2 つの口とも、取り消されても走り切って行を残し、失敗に数える）推奨

読み出しの記録は「1 件ごとに 1 行」を、接続が切れた求めでも満たします。取り消しを使って失敗の数えから逃げることもできなくなります。
