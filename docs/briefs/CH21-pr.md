# CH21 確認バッチの前に、その回で足した機能を使ってみる席（/tsukau）で確かめ、違和感を直すか人間に回す

change: `openspec/changes/ch21-trial-use-before-verify/`（capability `verify-environment`。ADDED の Requirement 12・Scenario 69 本）。
依頼と完了の判定は `docs/changes/CH21.md`。第 3 版（依頼に「見つけた後の処置」が足され、深掘りから立て直した）。

確認バッチを作るたびに、その回に入った Story / change が変えたファイルで相手（画面・PC）を決め、AI が配る形で 10 分・20 万 token ずつ使ってみる（harness2 の `/tsukau`）。
ashiato2 は、席が本物を立てる差し込み口（`tools/tsukau/`。画面は専用の環境、PC は網を切った Windows Sandbox）・確認バッチの準備からの呼び出し・処置へ渡す手元の目録・公開に出す題を伏せる台本・直した後の確かめ直しの口を持つ。
見つけた違和感の処置（別の席の選別 → 本人が見る前に Story のブランチで直す／本人に聞く／違和感の issue）は harness2 の確認バッチへの依頼にし、それが入った後に、公開の repo に何も出さない使い捨ての木で処置まで本物で通して終える。

## 仮決め（B）

台帳（`provisional.jsonl`）に載せたもの: D1・D3・D5・D7・D9・D10・D12・D15・D16・D18・D19・D20。

- D1（仮）置き場を `~/.local/state/ashiato2/tsukau` に明示し、`--label verify-<tag>` で走らせる
- D3（仮）PC は Sandbox を 1 つだけ起こし（動いていれば待たずに断る）、自分の id だけを、中のログを写してから止める
- D5（仮）配る zip は席を呼ぶ前に手元で組み（上限 2,400 秒。未測）、立てる時間に数えない
- D7（仮）画面の相手は専用の project・乱数の合言葉・偽データで立て、本人の `.env` と確認バッチの DB を使わない
- D9（仮）席は使い捨ての作業ツリーで走らせる
- D10（仮）同じ中身の鍵は、merge のコミットでなく確認バッチの木で比べる（作り直すと merge のコミットは毎回変わる）
- D12（仮）公開に出す題は `tools/tsukau/public-title.sh` 1 か所で伏せ、処置も同じものを通す
- D15（仮）harness2 への依頼の中身（`harness2-request.json`。合意の後に Task 9.3 が受け皿へ置く）
- D16（仮）直した後の確かめ直しは、直した候補だけを範囲に 5 分・10 万で呼ぶ
- D18（仮）完了は、harness2 の処置が入った後に使い捨ての木で処置まで本物で通す（push 先は一時の bare repo、`gh` は偽物、用意した候補 2 つ）
- D19（仮）公開の題の網は厳しい側（検査できなければ全部伏せる・写した題も通し直す）
- D20（仮）処置が書く試験の名前と中の文字列にも題と番号だけ
