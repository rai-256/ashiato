# CH15 — 配った形のサーバで、収集アプリの設定が正しい合言葉を断る

## 価値

インストーラで入れたサーバでも、画面の「収集アプリの設定」で正しい合言葉を入れると設定の文字列が出るようにする。
いまは、合言葉そのものを持たず照らすための値で起動する配った形のサーバで、資格情報を返す口が正しい合言葉も断る（ログインは通る）。
正典の Scenario「合言葉を入れ直すと、設定の文字列とコピーのボタンが出る」（`openspec/specs/data-sensitivity/spec.md`）どおりに動かすのが目的で、振る舞いの決まりは変えない。

## 依頼（逐語）

> 正典の Scenario「合言葉を入れ直すと、設定の文字列とコピーのボタンが出る」（openspec/specs/data-sensitivity/spec.md）が、インストーラで入れたサーバ（照らすための値 verifier で起動する WebLogin::new_with_verifier）で落ちる。collector_setup_post（crates/server/src/web_session.rs:598）が token_matches(&given, &app.login.password) で比べており、verifier の形では password が空なので常に 403。ログインと同じ WebLogin::accepts で照らす。試験は verifier で起動したサーバで、直す前に落ち、直した後に通ること。2026-11-09 本人の実地で発生（ログインは通るが、収集アプリの設定で正しい合言葉が「合言葉が違います」になる）

## 壊してはいけないもの

1. 資格情報を返す口（`POST /collector-setup`）の応答の形と状態の番号: 正しい合言葉は 200 `{"token": …}`、違う合言葉と空の合言葉は 403 `{"error": "wrong_password"}`（ログインは保たれる）、ログインの印が無ければ 401、収集アプリの資格情報では 403、JSON でない本文は 415、失敗の数えを超えたら正しい合言葉でも空の合言葉でも 429。どれも `Cache-Control: no-store`
2. 失敗の遅れと、ログインの口と共有する失敗の数え（どちらの口で失敗しても同じ窓で数える）
3. 読み出しの記録にこの口の行が成功も失敗も 1 行ずつ残り、記録とログに資格情報の値と入れた合言葉が出ない
4. ログインの口（`POST /session`）の振る舞い（合言葉そのものの形でも、照らすための値の形でも）
5. 合言葉そのもので起動する開発の形での、この口の振る舞い（いまの試験 `st56_` と画面の e2e が通るまま）
6. API の契約（`docs/openapi.json`）

## 完了の判定

- `cargo test -p ashiato-server ch15_` が rc=0（tasks 1.1）で、`-- --list` で 3 本以上（tasks 1.2）。照らすための値で起動したサーバで、正しい合言葉なら 200 で資格情報が返り、違う・空の合言葉は 403、失敗の数えを超えたら正しい合言葉も空の合言葉も 429
- 1.1 の検証が、本番のコードを直す前の木で FAIL、直した後で PASS の証跡を持つ（`scripts/verify-run 1.1`。軽い路の判定が見る）
- 「壊してはいけないもの」が残る: `cargo test -p ashiato-server st56_`（7 本以上）・`st55_`・`web_session` が rc=0、`./tools/check-openapi.sh` が rc=0、画面の e2e `web/e2e/st56-collector-setup.spec.ts` が rc=0、`web_session.rs` に `login.password` を比べる式が無く、照合が `LOGIN_CHECK` の印の中の 1 か所にある（tasks 1.2）
- 確認バッチ: この change を含む組み立ての配る道具で上げた本人の PC のサーバで、画面の「収集アプリの設定」に正しい合言葉を入れると設定の文字列とコピーのボタンが出て、違う合言葉では「合言葉が違います」と出る（tasks 9.1）

archive の判定: 上の検査が揃い、`openspec validate ch15-collector-setup-verifier-password --strict` が rc=0。正典（`openspec/specs/`）は変わらない。
