# CH11 — 依存の脆弱性を CI で検査する

## 価値

依存の脆弱性を CI で検査する。いまは許諾（tools/check-licenses.sh）と秘密（tools/check-secrets.sh）の検査はあるが、
脆弱性の検査（cargo-audit / cargo-deny / npm audit / Dependabot）はどれも無い。リポジトリは public。

本人と合意した中身（2026-11-08、ハーネス改善の資料 2 節）:

1. osv-scanner 1 本で Rust（Cargo.lock）・web（web/package-lock.json）・Android（gradle.lockfile）を見る。
   cargo-deny と npm audit を個別には入れない（例外の表がエコシステムごとに散らばるため）。
2. collector-android に gradle の依存の固定（dependency locking）を入れ、gradle.lockfile を commit する。
   ロックファイルと解決結果がずれたら落ちる。依存を変えた PR がロックファイルも更新する。
3. CI: PR ではロックファイルが変わったときだけ走らせ、その PR が新しく持ち込んだ脆弱性で落とす
   （Actions の予算切れが過去にあったので、毎回は走らせない）。nightly は main 全体を見て、例外の表に無いもので落とす。
4. 例外の表（osv-scanner.toml）の各行には理由と期限が要る。期限が過ぎた行・理由の無い行を CI が落とす（機械の検査）。
5. GitHub の dependency-review-action を PR に入れる（重大度 high 以上で落とす）。Dependabot alerts は有効にする（通知だけ）。
   Dependabot の自動の更新 PR は入れない（グラフの外から PR が立つため。更新は hx change から流す）。
6. 同梱する PostgreSQL の minor 版が最新の minor から遅れていないかを nightly で見る（tools/check-pg-major.sh の隣）。
7. nightly で落ちたときの行き先: 該当する依存と重大度を本文にした issue を立てる（change の候補）。

入れないもの: OWASP dependency-check（重く NVD の API キーが要る）、Dependabot の自動の更新 PR。

完了の判定: 既知の脆弱な版をわざと入れた枝で PR の検査が落ちること・期限切れの例外の行で落ちることを、
自己試験（tools/check-*.sh の --self-test の流儀）で確かめる。

（`hx change` の依頼の逐語。上流の深掘りの後に、何のために変えるかを 1〜3 文に整える）
