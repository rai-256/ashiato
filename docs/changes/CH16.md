# CH16 — CI の Windows の試験の判定が落ちたら、何が起きていたかを必ずログに出す

## 価値

CI の Windows のインストールの試験で判定が落ちたとき、`NG:` の 1 行だけでなく、その判定が見た観測（サービスの状態・設定のキー・healthz・
命令の記録の末尾・判定が読んだ命令の生の出力）を同じログに出す。観測を足すためだけに CI をもう 1 周（約 1 時間）回さずに、
製品の誤りか判定の誤りかを 1 回のログで切り分けられるようにする。出さない判定は自己試験が機械で落とす。

受け皿の依頼 #307（https://github.com/rai-256/ashiato/issues/307）から。

## 本人の言葉

> （ST58 の関門で）判定が落ちたら観測を必ずログに出す、は入れて良いと思います

## 議論で決めたこと（本人の決定。深掘りで聞き直さない）

- **何を**: Windows のインストールの試験（tools/release の install 系の台本）の判定が NG になったとき、NG の 1 行だけでなく、その判定が見た観測（サービスの状態・設定・healthz・trace の該当部分）を必ず CI のログに出す。出さない判定を検査で落とす
- **なぜ**: ST58 の関門で、判定が落ちても何が起きていたかがログに出ず、観測を足すためだけに CI を 1 周（約 1 時間）使った。さらにその観測で、製品ではなく判定のほうの誤り（sc query の 4 行目を読めていない）だと分かった。最初から観測が出ていれば 2 周短くできた
- **どこまで**: Windows のインストールの試験の台本の判定と、その自己試験。CI の他の job と、製品のコードは変えない

## そのとき考えたこと

手元の Windows を直に触らせる案は、並列とコンテナ化の利点を削るので取らなかった（別の話として、CI の 1 周を縮める案を検討）

## 壊してはいけないもの

1. 2 つの台本（`tools/release/install-check.sh`・`tools/release/update-check-install.sh`）の判定が OK / NG を出す条件。今 OK の入力は OK、今 NG の入力は NG のまま
2. NG の 1 行目の文（`NG: <理由>`）と終了コード 1。観測は標準エラーに、その行の後に足すだけ
3. 標準出力（CI の `install-windows` が数える `== Scenario:` の行）と `--list` の出力
4. CI のログに秘密を出さないこと（設定の秘密・試験の画面の合言葉・ログインの印の値）。観測を足しても出さない
5. CI の job の形（`.github/workflows/ci.yml`）と、ほかの job・ほかの台本・製品のコード
6. 今の自己試験の確かめ（合う出力と外れた出力の試し・Scenario の印の置き場の検査）

## 完了の判定

- `tools/release/check-ng-observations.sh --self-test`・`tools/release/install-check.sh --self-test`・`tools/release/update-check-install.sh --self-test` が rc=0（tasks 1.1・2.1・3.1）。
  自己試験の中で、偽の `sc.exe` の出力（4 行目に状態を持つ ST58 の形）で落とした判定が `NG:` の行の後にその出力を出し、秘密の値を出さないことを確かめている
- `tools/release/check-ng-observations.sh tools/release/install-check.sh tools/release/update-check-install.sh` が rc=0 で、`die` を通さない NG・記録しない観測の命令を持つ写しは rc=1（tasks 1.1・3.1）
- 2 つの台本の `--list` が変更の前と 1 行も変わらない（tasks 2.1・3.1）
- `.github/workflows/ci.yml` が変わっていない・`docs/testing.md` に検査の名前がある（tasks 3.1）
- PR の CI の `chain`（2 つの `--self-test`）と `install-windows` が緑（実地の確かめが今の判定のまま通り、始めに観測の塊を本物の命令で一度出せている）
- 確認バッチ: 画面も操作も変わらないので、人間の確認は置かない。観測の塊が本物の Windows で出せることは、`install-windows` の実地の確かめの始めで機械が見る（design D7）
