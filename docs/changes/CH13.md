harness2 の作業箱（検証と agent を thread ごとのコンテナで走らせる。harness2 #152 で 2026-11-08 に main へ merge 済み）を ashiato2 で有効にできるように、

上流の調べで、依頼の中身のままでは箱を有効にした日に落ちる・当たりすぎる検証が見つかった。本人は依頼の「書き換えない」を外し（Q1）、見つけた不足を 3 つに分けた:

1. **JSON で直せるものは CH13 の中で直す**: docker の正規表現に錨を置く（台本の名前を grep するだけの検証に docker を渡さない）・`prep_files` に `tools/db-roles.sql` と `docker-compose.override.yml` を足す・
   docker の欄に画面の e2e・`cargo test --workspace`（と `server_startup`）・actionlint の検査・中で docker を使う台本を呼ぶ台本を足す・`host_only` に Windows とエミュレータを使う台本を足す
2. **根本は harness2 の issue にする**: docker を渡すかを検証コマンドの字面で決める設計・知らない鍵を黙って無視すること・古いイメージの掃除（後の Story に箱の制約を知らせる文書は置かない。Q2）
3. **測るものだけを有効にする前の宿題に残す**（`openspec/changes/ch13-workbox-config/enable-before.md` と ashiato2 の issue）: e2e と agent の cargo がメモリの上限に収まるか・5 本のときの空き

pgrep の確かめ（`workbox.py run . -- bash -c 'pgrep -fc /'` が 10 未満）と、直した正規表現が harness2 と同じ判定で当たる・当たらないことの確かめは、この change の tasks に置く（Q3）。
触るのは `tools/workbox.json` と change の中の文書だけで、正典の仕様にも文書にも手を入れない（Q4）。

## 依頼（逐語）

> harness2 に入れる「作業箱」（検証と agent を thread ごとのコンテナで走らせる。harness2 の PR feat/workbox）を、
> ashiato2 で使えるようにする設定を置く。ハーネスは repo に `tools/workbox.json` があり、環境変数
> `HARNESS_WORKBOX` が tests か all のときだけ箱を使う（既定 off。このファイルを置いただけでは何も変わらない）。
>
> 本人の依頼（2026-11-08）: 走らせている Story を検証環境としてコンテナで隔離する。Story 5 本くらいの並列に耐えたい。
> なぜ: 共有の /tmp を試験の漏れが埋めた（10-23）・メモリ不足で langgraph が OOM kill（10-25）・試験の pgrep -f "/" が

>
> 置くもの: `tools/workbox.json` を下の中身のとおりに（2026-11-08 に手元で確かめた版。書き換えない。足りないものに気付いたら PR 本文に挙げる）:
>
> ```json
> {
>   "apt": [
>     "postgresql-client",
>     "libnss3",
>     "libatk1.0-0t64",
>     "libatk-bridge2.0-0t64",
>     "libcups2t64",

>   "docker": [
>     "tools/(smoke|seed|db|dev|stack|env-init|verify-env|docker-tidy|db-roles|pg_dump-docker|archive-shape|record-env)\\.sh",
>     "tools/check-(db-secret|exposure|pg-major|db-version-stop|panic-log|verify-env-reset|immutable|test-db-growth|test-db-killed)\\.sh",

>     "tools/docker-tidy.sh",
>     "docker-compose.yml"
>   ]
> }
> ```
>
> 各欄の意味（正本は harness2 の scripts/workbox.py の冒頭）:
> - apt: イメージに足す包み（psql、playwright の Chromium が要るライブラリ、日本語のフォント）
> - memory / tmp_size: 検証の箱 1 つのメモリと /tmp の上限。agent_memory: agent の箱の上限
> - parallel_verify: 同時に走る検証の箱の数（同じ repo の worktree どうしで数える。空くまで待つ）
> - docker: この正規表現に当たる検証にだけ docker を渡す（DB や compose を自分で扱う台本）
> - host_only: 箱に入れずホストで走らせる検証（Windows 側の cmd.exe・エミュレータ）
> - prep_files: 検証の準備（tools/verify-env.sh）が読む台本。箱の中の agent から来た依頼では、main の版と違えば断る
> - env: 箱の中だけの環境変数（並走する cargo のビルドが CPU を取り合わないように）
>
> 確かめたこと（2026-11-08、HARNESS_WORKBOX=tests、harness2 feat/workbox）:
> - 箱の中で cargo・node・JDK・psql・claude・codex が動き、`.aws` `.config/gh` は見えない。pgrep で見えるのは箱の中だけ。/tmp は 4GB
> - `cargo test -p ashiato-server --lib access_log_tests`（DB を使う）・`tools/check-migrations.sh`・`tools/check-pg-major.sh`（docker を使う）が PASS
> - worktree 5 本で同時に cargo test を新しいビルドから: 席 2 つで順に流れ、空きメモリの最低は 12GB。全部 PASS
>
> 完了の判定: `tools/workbox.json` が上の中身であり、`python3 -c 'import json; json.load(open("tools/workbox.json"))'` が rc=0。
> docker のある環境では、harness2 の `scripts/workbox.py run . -- bash -c 'pgrep -fc /'` が 10 未満を出す（harness2 の main に
> feat/workbox が入っていなければ、この確かめは「人間の確認待ち」でなく BLOCKED として残す）。
