# CH19 — エミュレータの計測テストを 1 クラスだけ走らせる口を足す

## 価値

計測テストの 1 クラスを直している間は、そのクラスだけを `ONLY=` でエミュレータに走らせ（全体の 17 分を待たない）、通ったら最後に全体を走らせる、という回し方をできるようにする。
ST56 Task 5 では 1 クラスを直すのに全体を 27 回まわし、implement が 485 分かかった。ハーネスの「絞った検証」（harness2 #271）もこの口を使う。
受け皿の依頼 #328（https://github.com/rai-256/ashiato/issues/328）から。

## 本人の言葉

> テストで落ちる→直す→直したところだけ走らせる→ngならまた直すところから、okなら全体を走らせる みたいなのがいいかなって思ってます

## 議論で決めたこと（本人の決定。深掘りで聞き直さない）

- **何を**: tools/android-emulator.sh に、指定したクラス（例: ONLY=dev.ashiato.collector.St56BackupTest）だけを 1 段で走らせる口を足す。指定が無ければ今の 8 段のまま。AGENTS.md の「長いコマンド」に、直している途中は絞って走らせ最後に全体を verify-run で走らせることと、絞り方（エミュレータは ONLY=、cargo test は名前の絞り）を書く
- **なぜ**: ST56 Task 5 で 1 クラスを直すのに全段（1 回 17 分。gradle は 20 秒で落ちている）を 27 回まわし、implement が 485 分かかった。いまの台本には 1 クラスだけを走らせる口が無く、絞りたくても絞れない。ハーネス側の「絞った検証」（harness2 #271）が使う口になる
- **どこまで**: tools/android-emulator.sh の絞る口と AGENTS.md の記述だけ。全体のときの段の構成と、既存の tasks.md の検証コマンドは変えない

## そのとき考えたこと

gradle には -Pandroid.testInstrumentationRunnerArguments.class がすでにあるので、台本から渡すだけ。APK の入れ替えなど別の台本（tools/android-st58-replace.sh）の段は今回は対象外

## 壊してはいけないもの

1. `ONLY` を渡さない（か空の）ときの `tools/android-emulator.sh` の全体の振る舞い: 今と同じ命令を同じ順に送り、今と同じ 8 段の結果の XML を残し、入れ替えの台本を最後に走らせる。全体の経路の行は字下げも含めて変えない
2. CH10 で固めた起動と止まり方（/dev/kvm・待ちの上限・同じ AVD・KEEP・後片付け）と、その試験 `tools/test-android-emulator.sh` の既存の場合と `--self-test`
3. `tools/test-usage-volume.sh` の行の形の検査（採寸の試験を通常の段から除く行・1 段目の gradle の前にアプリを外す行）が、ファイルを変えずに通ること
4. 既存の Story / change の `tasks.md` の検証コマンド（全体を走らせる `tools/android-emulator.sh` のまま。書き換えない）
5. 製品（収集アプリ・サーバ・画面）のコードと計測テストの中身、`tools/android-st58-replace.sh`・`tools/usage-volume.sh`・`tools/android-backup-roundtrip.sh`・`tools/emulator-start.sh`

## 完了の判定

1. `ONLY=dev.ashiato.collector.<クラス>` で、そのクラスだけに絞った計測テストが 1 段で走り、渡したクラスの結果が無ければ 0 本として止まる。`St56BackupTest` は全体と同じ準備・往復・確かめの手順だけが走る。専用の台本のクラスと形の違う値は、エミュレータを起こさずに rc=1 で止まる（偽の SDK の試験 `tools/test-android-emulator.sh` の場合 `only-*` が rc=0。tasks 2.2・3.1）
2. `ONLY` が無いか空なら、命令の列が base の台本と同じ（比べる元の版を渡した `only-base` が飛ばさずに rc=0。tasks 1.1・3.1）で、`tools/test-usage-volume.sh` が rc=0
3. 本物のエミュレータで、`ONLY` に `MediaPremisesInstrumentedTest` と `St56BackupTest` を渡した実行と、全体の実行がどれも rc=0（tasks 4.1・4.2）
4. `AGENTS.md` の「長いコマンド」に、直している途中は絞って走らせ（エミュレータは `ONLY=`、`cargo test` は名前の絞り）、最後に全体を `scripts/verify-run` で走らせることが書いてある（tasks 3.2）
5. 触ったファイルが予定のパス（`tools/android-emulator.sh`・`tools/test-android-emulator.sh`・`AGENTS.md`・`docs/changes/CH19.md`・この change の中）だけ（tasks 4.3）
6. 確認バッチの問い: 「CH19 の PR の証跡で、4.1 の `ONLY` の 2 回が全体より短い時間で rc=0 になり、4.2 の全体も rc=0 か」。画面や製品の操作は変わらないので、人間が触って確かめるものは無い
