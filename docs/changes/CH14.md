# CH14 — インストーラの合言葉の問いが文字化けする

## 価値

ashiato-setup.exe を日本語の Windows（cp932 のコンソール）で開くと、rpassword::prompt_password の問い（「画面の合言葉: 」「画面の合言葉（もう一度）: 」、crates/installer/src/main.rs:291 付近）が UTF-8 のバイト列のまま書かれ、『逕ｻ髱｢縺ｮ蜷郁ｨ闡』のように化ける（2026-11-09 本人の実地で発生。昇格して開き直した窓）。ほかの行は Rust の標準出力を通るので化けない。問いを標準出力（WriteConsoleW を通る経路）で出し、rpassword は読みだけにする。password / repair など合言葉を聞く他の口も同じ。本物の Windows のコンソールで化けないことを試験で確かめる（CI は入力を流し込むので今は見えていない）。あわせて、合言葉の要件（16 文字以上・change-me で始めない・API の合言葉とログインの印の鍵と違う。crates/installer/src/password.rs の MIN_LEN ほか）を最初の問いの前に示す（本人が『短い』とだけ言われて要件が分からなかった。2026-11-09 訂正: 登録時の「12 文字」は誤り）

日本語の Windows（cp932 の窓）で `ashiato-setup.exe` を使う本人が、合言葉の問いと条件を化けずに読み、条件を知ったうえで 1 回で通る合言葉を決められるようにする。あわせて、子の命令（`sc.exe`・`icacls`・`whoami`・`reg.exe`・`tasklist` など）の出力を窓のコード頁で正しく読み、失敗の理由が読めること・日本語の利用者名やフォルダ名でも repair とインストールが止まらないことを、この change で直す（第 1 回の深掘り Q2 で本人が「表示も値の口も含める」を選んだ。2026-11-10）。

## 壊してはいけないもの

（第 1 回の深掘り Q1〜Q5 の推奨の答えで先に書き、2026-11-10 の本人の答えで確かめた。Q1・Q3・Q4・Q5 は推奨どおりで 1〜6 は変わらない。Q2 の答えで 7 を足した）

1. 合言葉の検査の中身: 16 文字より短い・`change-me` で始まる・API の合言葉と同じ・ログインの印の鍵と同じ・2 回が一致しない、のどれかなら断って入れ直させる（今の install-check の「短い・既定の雛形・一致しない合言葉は受け付けない」「API の合言葉やログインの印の鍵と同じ値は受け付けない」がそのまま通る）
2. 断りの行の形 `合言葉を受け付けない: <理由>。入れ直してください` と、理由の語（短い・雛形・API の合言葉と同じ・ログインの印の鍵と同じ・一致しない）が行に残る
3. 端末でないとき（標準入力が管）は、標準入力の 2 行を 2 回入れた合言葉として読む（Windows の CI のインストールの試験の道）
4. 入れた合言葉を窓に表示せず、元の値を設定にもログにも端末の出力にも残さない（「合言葉の元の値は、どこにも残らない」）
5. install の最後・`password`・`repair` の 3 つの口が、同じ問い方・同じ検査で合言葉を聞く
6. 標準出力・標準エラーを向け替えても、問いは窓に出る（今も rpassword が窓へ直に書くので見える）
7. 子の命令の出力を読み替えても、英字だけの出力（いまの本人の PC の利用者名 `<PC 名>\<利用者名>`・英字のダウンロードの場所）は、いまと同じ値として読まれ、repair の DB の認証の対応表とインストールの道がそのまま通る（Q2）
