# CH18 — 作業箱の設定に圧縮ライブラリと CPU の上限を足す

## 価値

作業箱（`HARNESS_WORKBOX=tests`）を有効にした日に、箱の中でサーバの試験が組み立てで落ちないようにし（圧縮ライブラリ 2 つ）、
同時に走る 2 つの箱が機械の CPU を食い尽くさないようにする（箱 1 つ 6 本）。有効にする前の最後の設定の直しで、有効にするのは merge の後に人間が行う。

## 何を
1. `apt` に `liblzma-dev` と `libbz2-dev` を足す
2. `cpus` を 6 にする（箱 1 つの CPU の上限）。`parallel_verify` は既定の 2 のまま

## なぜ
- 1: 2026-11-17 に箱の中で `cargo test -p ashiato-server` を組み立てると `rust-lld: error: unable to find library -llzma` / `-lbz2` で止まった（圧縮の依存が動的にリンクする）。このままでは有効にした瞬間にサーバの試験が全部落ちる
- 2: 全体テストは、ほかの Story が同時に重いコマンドを走らせていると遅くなっていた（30 分を超えた回は同時に平均 0.83 本、10 分以内の回は 0.01 本）。機械は 16 コアで、箱 2 つ × 6 にしてホスト側（agent・langgraph）に残す

## どこまで
- 変えるのは `tools/workbox.json` だけ。`HARNESS_WORKBOX=tests` を hx-dev.service に足すのは merge の後に人間側で行う（この change では行わない）

## 確かめ方（実測済みの手順）
`tools/workbox.json` を直した木で、次がどれも rc=0 になること:
`HARNESS_WORKBOX=tests python3 .harness2/scripts/workbox.py run . bash -c 'export TMPDIR=$(mktemp -d); . ./tools/agent-env.sh; tools/verify-env.sh && cargo test --workspace --no-fail-fast && tools/smoke.sh && (cd web && npm run test:e2e) && ./collector-android/gradlew -p collector-android :app:testDebugUnitTest'`
2026-11-17 に、上の 2 パッケージを足した写しでこの全部が通った（workspace 約 5 分・e2e 262 本 6.4 分・携帯の単体 2 分 18 秒）。
