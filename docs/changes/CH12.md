# worktree の待ち受けのポートは、どの worktree でも被らないよう機械が割り当てる

- 日付: 2026-10-03
- 状態: 採用
- 出所: メモリ worktree-port-allocation-followup.md・prefer-collision-free-allocation-over-checks.md・`tools/ports.sh`

## 背景

2026-10-03、worktree をまたいで DB を取り違えた。ST08 の再検証が ST22 の DB に書いた。
ST05 の `tools/ports.sh` は「名前が `-st<NN>` で終われば DB を 55500+NN、それ以外は 55432」だった。
録画の `-rec-st22` と下流の `-st22` は同じ番号になった。`-integ`・`-recording` など `-stNN` で終わらない worktree は、すべて 55432 で main とも被った。

## 決定

規則で直す。運用で手で分けない。

- 下流の `<repo>-stNN` は従来どおり 55500+NN。
- main の checkout は 55432。
- それ以外の worktree は、git の共通ディレクトリに置く台帳（worktree のパス → 番号）で、空いている番号を機械が割り当てて記録する。
- 名前のハッシュは衝突しうるので使わない。
- Rust のテスト用 DB（`testdb.rs`）も同じ規則を読む。

実施は ST05 が確認バッチを経て main に入った後の小さな fix とした。

## 退けた案

- 繋ぎ先が自分の DB かを、検証の前に確かめる検査。被らない割り当てがあれば二重持ちになる（本人の判断）。
- 名前のハッシュで番号を決める。衝突しうる。
- 運用で手で分ける。

## 反転の条件

記録なし。

## 影響

- いまの `tools/ports.sh` はこの規則で動き、規則はここだけに置く。Rust のテストもこの台本を呼んでポートを得る。
  確認バッチの作業ツリー（`-verify`）にも専用の番号がある。
- 割り当てられなければ非 0 を返し、55432 には落とさない。落とすと main の DB と取り合う。
- 2026-10-21 には `-ch01` と `-ch02` が 55432 に落ち、残っていた確認バッチの DB と取り合って両方止まった（`tools/ports.sh` の注記）。
- ハーネス側の原則は harness2 の ADR「取り違えは、被らない割り当てを機械が決めて防ぐ」。

- 日付: 2026-10-08

## 背景

## 退けた案

- 「AI に読ませる」を目的とし、衛星を範囲外とする（当時の要件の形）。

記録なし。

- 検査スクリプトで純粋さを見る。

## 反転の条件

記録なし。

## 影響

- 計画（分類・順番・見積もり）は `docs/audit/2026-10-11-pure-crate-plan.md` にある。
  計画の「先に決めること」（crate の名前・tracing の扱いなど）は提案で、本人の決定ではない。行番号は調べた時点のもの。

> # lint を一段厳しくする（Rust は pedantic、Web は strictTypeChecked、Kotlin は baseline）
>
> - 日付: 2026-10-11
> - 状態: 採用
> - 出所: メモリ lint-purity-ui-refresh-plan.md・`Cargo.toml`・`web/eslint.config.js`
>
> ## 背景
>
> 本人が「lint を厳しく」と求めた。main（4f170499）で測ると、Rust の pedantic で 551 件、Web の strict で 235 件の違反があった。
> 走っている ST12・ST21 がサーバと画面を広く触っていた。全体の違反を今直すと衝突する。
>
> ## 決定
>
> - Rust: clippy の pedantic を止める。他人に配るライブラリ向けの文書の催促の 4 種は外す。
> - Web: typescript-eslint の strictTypeChecked にする。
> - Kotlin: detekt と ktlint を baseline 付きで入れる。
> - 全体の違反の修正は、ST12・ST21 の merge 後に crate の分割と同じ fix で行う。Kotlin の baseline はいま進めてよい。
>
> ## 退けた案
>
> 記録なし。
>
> ## 反転の条件
>
> 記録なし。
>
> ## 影響
>
> - `Cargo.toml` と `web/eslint.config.js` には、「まだ直していないだけ」の規則を許す表がある。全体の修正でこれを空にする。
> - 全体の修正も change として流す（harness2 の ADR「要件から来ない作業は change として Story と同じグラフに流す」）。
> - CI の Rust は stable を追うので、版が上がると pedantic の規則が増えて落ちうる。2026-10-12 に 1.99 で増えた 1 つを表に足した。
