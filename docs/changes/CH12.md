> # worktree の待ち受けのポートは、どの worktree でも被らないよう機械が割り当てる
>
> - 日付: 2026-10-03
> - 状態: 採用
> - 出所: メモリ worktree-port-allocation-followup.md・prefer-collision-free-allocation-over-checks.md・`tools/ports.sh`
>
> ## 背景
>
> 2026-10-03、worktree をまたいで DB を取り違えた。ST08 の再検証が ST22 の DB に書いた。
> ST05 の `tools/ports.sh` は「名前が `-st<NN>` で終われば DB を 55500+NN、それ以外は 55432」だった。
> 録画の `-rec-st22` と下流の `-st22` は同じ番号になった。`-integ`・`-recording` など `-stNN` で終わらない worktree は、すべて 55432 で main とも被った。
>
> ## 決定
>
> 規則で直す。運用で手で分けない。
>
> - 下流の `<repo>-stNN` は従来どおり 55500+NN。
> - main の checkout は 55432。
> - それ以外の worktree は、git の共通ディレクトリに置く台帳（worktree のパス → 番号）で、空いている番号を機械が割り当てて記録する。
> - 名前のハッシュは衝突しうるので使わない。
> - Rust のテスト用 DB（`testdb.rs`）も同じ規則を読む。
>
> 実施は ST05 が確認バッチを経て main に入った後の小さな fix とした。
>
> ## 退けた案
>
> - 繋ぎ先が自分の DB かを、検証の前に確かめる検査。被らない割り当てがあれば二重持ちになる（本人の判断）。
> - 名前のハッシュで番号を決める。衝突しうる。
> - 運用で手で分ける。
>
> ## 反転の条件
>
> 記録なし。
>
> ## 影響
>
> - いまの `tools/ports.sh` はこの規則で動き、規則はここだけに置く。Rust のテストもこの台本を呼んでポートを得る。
>   確認バッチの作業ツリー（`-verify`）にも専用の番号がある。
> - 割り当てられなければ非 0 を返し、55432 には落とさない。落とすと main の DB と取り合う。
> - 2026-10-21 には `-ch01` と `-ch02` が 55432 に落ち、残っていた確認バッチの DB と取り合って両方止まった（`tools/ports.sh` の注記）。
> - ハーネス側の原則は harness2 の ADR「取り違えは、被らない割り当てを機械が決めて防ぐ」。
