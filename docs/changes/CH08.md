# CH08 — 消した記録の一覧に包まれた滞在を残し、作り直しで隠れた滞在の本文も消す（ST23 Q7・Q8）

## 価値

## 依頼

ST23（`st23-record-erasure`、消した記録を本文ごと消せる）の深掘り第 2 回で本人が決めた Q7・Q8 を、仕様（Requirement と Scenario）から作る。
ST23 は Q7・Q8 を含まないまま merge する（深掘り第 3 回 Q9 の答え。2026-10-28 に「merge して新しい change で作る」へ変更）。

- **Q7** —— 本人が別に「消した」にした滞在 B が、本文ごと消した滞在 P の時間にすっぽり入るとき、1 日の一覧で差し引いて空になっても、
  B の行（時間・「戻す」「本文ごと消す」）を P の「本文ごと消した」の行の下に出す。design D2・D12 を本人の決定に書き直し、画面の Scenario と e2e を足す。
- **Q8 / FR-50 の ★ 2026-10-23** —— P を本文ごと消した後、作り直し（`rebuild_day`）で P の時間帯に重なる滞在 L が隠れたら、隠した同じまとまりで L の本文も消し、
  消去の台帳に「後から」（kind = late、元の操作 = P）として載せ、P の行の「後から届いた N 件も本文ごと消した」に数える。一覧に出ている間の L は消さない（design D17）。
- **merge から作るまでの手当て** —— この change が入る前に作り直しで隠れた L（本文ごと消した P と重なり、`rebuild:absorbed` で隠れて本文が残っているもの）を探し、同じ扱いで消す。

## なぜ

- ST23 の code-verify（`openspec/changes/st23-record-erasure/review/code.md` R15）が、Q7・Q8 が spec・design・tasks・コードのどこにも入っておらず、
  決めた振る舞いが起きないことを使い捨ての DB で確かめた（Q7: B に届く行が 1 日の並びに無い / Q8: 隠れた L の本文が残り、どの口からも消せない）。
- 第 2 回の答えを deep.md に書いた後、spec の段が走らないまま合意と下流へ進んだ（`docs/audit/2026-10-24-st23-q8-consistency.md` C1）。
- ST23 の残りは検証と review を通っている。足し算の Q7・Q8 のために ST23 全体を上流から回し直すより、merge して別に作るほうが安い。

## 完了の判定

- Q7: P にすっぽり入る B があるとき、P を本文ごと消した後の 1 日の一覧に B の行が P の行の下に出て、そこから B を戻す・本文ごと消すができる（e2e）。
- Q8: P を本文ごと消した後に作り直しで隠れた重なる滞在 L の本文が、同じまとまりで消え、台帳に kind = late・元の操作 = P で載る（server の試験）。一覧に出ている L は消えない。
- 手当て: この change の前に隠れて本文が残った L が、移行か作り直しの経路で消え、台帳に載る（試験で前の状態を作って確かめる）。
- ST23 の既存の Scenario と試験はそのまま通る。
