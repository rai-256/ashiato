# CH10 — エミュレータが起動できないとき android-emulator.sh が無期限に待たない

## 価値

手元でエミュレータを起こす台本が、起こせないときに来ない端末を待ち続けず、早く・理由つきで止まるようにする（2026-11-05、ST54 の ci_fix が約 20 分止まり、人間が kill した）。
/dev/kvm を開けない・起動の途中で終わる・端末が現れない・同じ AVD が既に動いている、のどれでも、何が起きたかとエミュレータの出力の末尾が残り、/dev/kvm のときは verify-run が環境の欠落と読める文言で落ちる。
正常にエミュレータが立つときの振る舞いは変えず、それを偽の SDK の試験で固定する。同じ形で起こしている利用状況の採寸の台本も同じ部品で直す（第 1 回の深掘り Q1。本人の選択）。
端末が adb に現れるまでの上限は 120 秒（Q2）。同じ AVD のエミュレータが既に動いていれば、起こす前に理由つきで失敗する（Q3）。待つ端末が自分の起こしたものかの取り違えはこの change では直さない（Q4。やらないこと）。

## 依頼（逐語）

> ## 何が起きたか（2026-11-05、ST54 の ci_fix）
>
> Codex が sandbox の中で `scripts/quiet-run st54-android-instrumented-before -- ./tools/android-emulator.sh` を走らせた。
> sandbox の中では /dev/kvm を開けないため、エミュレータ（qemu）は起動直後に落ちた。ところが
> `tools/android-emulator.sh:35` の `adb wait-for-device` に上限が無く、来ない端末を約 20 分待ち続けた。
> 人間が `adb wait-for-device` を kill して、ようやく ci_fix が先へ進んだ。エミュレータの出力は `>/dev/null 2>&1`
> に捨てているので、落ちた理由もログに残っていない。
>
> ## 依頼
>
> `tools/android-emulator.sh` が、エミュレータを起動できないときに **無期限に待たず、早く・理由つきで失敗する**ようにする。
>
> - `adb wait-for-device` に上限を付ける（例: `timeout`）。上限を超えたら理由つきで非 0 で終える
> - 待っている間に、バックグラウンドのエミュレータのプロセスが死んだら、すぐ失敗で返る
> - エミュレータの stdout/stderr をファイルに残し、失敗したときに末尾を表示する（/dev/kvm を開けない等の理由が見えるように）
> - /dev/kvm を開けないときは、`scripts/verify-run` が BLOCKED_INFRA（「/dev/kvm を開けない」）と判定できる文言で落ちる
>   （AGENTS.md の「/dev/kvm（Codex のとき）」の手順に乗るように）。既存の判定の文言に合わせる
> - 正常にエミュレータが立つ場合（手元の kvm あり・CI）の振る舞いは変えない
>
> ## 検証
>
> - エミュレータが起動直後に死ぬ状況（例: emulator を即 exit する偽物に PATH で差し替える）で、スクリプトが短時間で非 0 になり、理由が出ることをテストで確かめる
> - /dev/kvm を開けない状況の文言が verify-run の BLOCKED_INFRA 判定に掛かることを確かめる

## 壊してはいけないもの

（第 1 回の深掘り Q5 で本人が「この一覧のとおり」と答えた。2026-11-07）

1. kvm があり正常に立つとき、今と同じ引数（`-avd <AVD> -no-window -gpu swiftshader_indirect -noaudio -no-boot-anim -camera-back none -no-snapshot`）でエミュレータを起こし、起動の完了を待って、計測テストを 6 段で走らせ、段ごとの XML を `androidTest-results-stage1`〜`stage6` に残す（偽の SDK の試験と、手元の本物の 1 回。tasks Task 1.1・6.1）
2. `KEEP=1` なら、通った後にエミュレータを止めない。`KEEP` が無ければ、通った後に `emulator-5554` を止める（Task 1.1）
3. emulator・システムイメージが無いときは今の文言で rc=1（Task 1.1）
4. AVD が無ければ作る（Task 1.1）
5. CI の計測テスト（`android-emulator-runner`）は変わらない（この台本を使っていない）
6. `tools/test-usage-volume.sh` が確かめている形（採寸の試験を通常の段から除く・1 段目の前にアプリを外す・`tools/wait-android-boot.sh` の有限の待ち）がそのまま通る。`tools/wait-android-boot.sh` の呼び出し方は変えない（Task 1.1・4.1）
7. 利用状況の採寸の台本の約束: 測れなかったら rc=2、adb に見えているエミュレータがあれば起こさずに使う、起こすときの引数（`-wipe-data` を含む）は今のまま（Q1。Task 4.1）

変わるもの（1 つ）: 同じ AVD のエミュレータが既に動いているとき、今はその端末で計測テストが走るが、この後は起こさずに理由つきで rc=1 になる（Q3）。`KEEP=1` の後に続けて走らせるには、先に `adb -s <serial> emu kill` で止める。
