# CH23 — 毎晩の脆弱性の検査が issue を立てられず、9 晩赤のまま誰にも届かなかったのを直す

## 価値

毎晩の脆弱性の検査で見つかった当たりが、ラベル `脆弱性` が無くても issue として本人に届くようにする（gh の空の応答を読めずに 9 晩 issue を立てられなかった不具合を直し、
自己試験の偽の gh を本物の返し方に合わせる）。issue を立てる段そのものが落ちた夜も、決まった題の issue 1 件で知らせ、赤のまま誰にも届かない夜を減らす。

受け皿の依頼 #333（https://github.com/rai-256/ashiato/issues/333）から。

## 本人の言葉

> 理解しました、そうしてください（2026-11-19。毎晩の検査の知らせが壊れていると説明した後の答え）

## 議論で決めたこと（本人の決定。深掘りで聞き直さない）

- **何を**: tools/check-vulns-issues.py が、gh が当てはまるものが無いときに返す空の文字を空の一覧とみなすようにする。自己試験の偽の gh を、本物の返し方（当てはまらないと空の文字）に合わせる。毎晩の検査の赤が 9 晩気づかれなかった理由（知らせがどこに届くか）を調べ、届く形にする
- **なぜ**: vulns-nightly.yml は 2026-11-10 から 9 晩すべて赤で、毎晩 issue を立てる段が「gh の応答: Expecting value」で落ちていた。ラベル「脆弱性」が無いと gh label list --search は [] でなく空の文字を返し、台本がそれを読めずにラベルも issue も作らなかった。偽の gh は [] を返すので自己試験は通っていた。その間、例外の表に無い当たり（PostgreSQL 17.6 → 17.12・libsqlite3-sys・chrono・rustix）が誰にも届かなかった
- **どこまで**: 知らせの段の直しと、偽の gh を本物に合わせることと、赤に気づける形にすること。見つかった当たりそのものの処置（版を上げる・例外にする）は、立った issue から別に扱う。2026-11-19 にラベル「脆弱性」は手で作った（一時しのぎ）。直しはラベルが無い状態でも動くことを試験で確かめる

## そのとき考えたこと

偽物とだけ試して本物で動かない、という #332・harness2 #272 と同じ形の取りこぼし。赤が届かなかった件は、GitHub の既定の知らせ（cron を最後に変えた人へのメール）が本人に届いていないか、届いても埋もれている見込み。調べてから決める

## 壊してはいけないもの

- 正典 `dependency-vulnerability-scan` の毎晩の約束: 依存ごとに 1 件の issue（題 `脆弱性: <エコシステム> <依存の名前>`・ラベル `脆弱性`）・開いていれば立て直さず無い勧告の ID だけ追記・本文は決まった項目だけ・閉じない・例外の表と PostgreSQL の遅れはそれぞれ 1 件。自己試験の既存の Scenario は消さず・緩めない
- 検査できなかった夜（rc=2）は issue を立てない（正典のとおり。この change は変えない。design D3）
- `issues: write` を持つ job は `issues` の 1 つだけ・検査の job は読むだけの権限・`nightly.yml` に脆弱性の検査が混ざらない
- 勧告が残る夜に `vulns`・`pg-minor` の job が赤になる付き方（design D4）
- 見つかった当たりの処置（版を上げる・例外の表に足す）はしない（#334〜#337 から別に扱う）

## 完了の判定

1. 自己試験の偽の gh が、ラベルが無いとき本物と同じく空の文字を返し、その偽の gh で Scenario「落ちた夜に、依存ごとに 1 件の issue が立つ」が、直す前の台本では落ち、直した後に通る（tasks 1.1。証跡に FAIL と PASS が残る）
2. ラベルの一覧に空の文字で答える gh でもラベルを作ってから issue を立て、知らせの段が落ちた夜に題 `脆弱性: 毎晩の知らせを issue にできなかった` の issue がラベル無しで 1 件立ち、開いていれば追記になる（tasks 1.2・2.1 の自己試験）
3. `vulns-nightly.yml` の `issues` の job が、`file-issues` の段が落ちたときだけ `report-unfiled` を走らせ、材料の無い夜は `file-issues` を呼ばず、配線の検査と自己試験がそれを見る。`issues` の外の job は base のまま（tasks 2.2）
4. 触ったファイルが予定のパス（`lane.json`）とこの change の中だけ（tasks 3.2）
5. 確認バッチの問い（tasks 4.1）: 「2026-11-19 に毎晩の検査が立てた #334〜#337 の知らせは、メールか GitHub の通知で届いていたか」（届いていなければ、知らせの経路を issue 以外にする change を別に立てる）・「11-10〜11-18 の失敗の知らせは届いていたか、届いていたならなぜ気づかなかったか」・「検査できなかった夜も issue で知りたいか」

## 残るもの

- 検査できなかった夜（osv.dev や PostgreSQL の版の一覧に届かない）は、正典のとおり Actions の赤だけで、本人に届かないことがある。issue で知らせるには正典を変える change（通常の路）が要る（design D3）
- `gh` そのもの・権限・GitHub の障害で知らせの段も落ちた夜は、赤だけが残る（design D2）
