# CH23 — 毎晩の脆弱性の検査が issue を立てられず、9 晩赤のまま誰にも届かなかったのを直す

## 価値

受け皿の依頼 #333（https://github.com/rai-256/ashiato/issues/333）から。

## 本人の言葉

> 理解しました、そうしてください（2026-11-19。毎晩の検査の知らせが壊れていると説明した後の答え）

## 議論で決めたこと（本人の決定。深掘りで聞き直さない）

- **何を**: tools/check-vulns-issues.py が、gh が当てはまるものが無いときに返す空の文字を空の一覧とみなすようにする。自己試験の偽の gh を、本物の返し方（当てはまらないと空の文字）に合わせる。毎晩の検査の赤が 9 晩気づかれなかった理由（知らせがどこに届くか）を調べ、届く形にする
- **なぜ**: vulns-nightly.yml は 2026-11-10 から 9 晩すべて赤で、毎晩 issue を立てる段が「gh の応答: Expecting value」で落ちていた。ラベル「脆弱性」が無いと gh label list --search は [] でなく空の文字を返し、台本がそれを読めずにラベルも issue も作らなかった。偽の gh は [] を返すので自己試験は通っていた。その間、例外の表に無い当たり（PostgreSQL 17.6 → 17.12・libsqlite3-sys・chrono・rustix）が誰にも届かなかった
- **どこまで**: 知らせの段の直しと、偽の gh を本物に合わせることと、赤に気づける形にすること。見つかった当たりそのものの処置（版を上げる・例外にする）は、立った issue から別に扱う。2026-11-19 にラベル「脆弱性」は手で作った（一時しのぎ）。直しはラベルが無い状態でも動くことを試験で確かめる

## そのとき考えたこと

偽物とだけ試して本物で動かない、という #332・harness2 #272 と同じ形の取りこぼし。赤が届かなかった件は、GitHub の既定の知らせ（cron を最後に変えた人へのメール）が本人に届いていないか、届いても埋もれている見込み。調べてから決める
