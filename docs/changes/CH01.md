# CH01 — ST17 の /code-review の 9 件を直す

## 価値

ST17（毎日 30 秒で「その日どう感じたか」を残す。archive 済み）の実装を、Claude Code の組み込みの `/code-review` で見直したら、
下流のレビュー（final・code-verify・fix、合わせて 21 件）が拾っていない指摘が 9 件出た。これを直す。

出所: 2026-10-17、PR #89 の head 09987c1（base c6109b7）に `claude -p "/code-review"` を走らせた結果（人間の依頼でなく、AI の指摘）。
1〜3 は main で事実と確かめた。4〜9 は未確認 —— 再現してから直し、再現しなければ直さずに理由を残す。
行番号は 09987c1 のもの。

1. `tools/check-immutable.sh` の本体（1155 行あたり）に、ST17 の錠の節（約 150 行）が書き足されている。AGENTS.md と
   `tools/check-immutable.d/README.md` は Story ごとの `tools/check-immutable.d/` に置けと言っている。途中への書き足しなので、
   末尾だけを見る `tools/check-shared-appends.sh` もすり抜けた（確認済み）
2. 同じ節の戻しの検査（1317 行あたり。main では 1336 行）が、直前の検査が NG を出しても「OK feeling 主観が残っていれば…」を
   無条件に出す。rc は正しく 1 になるが、記録には NG と OK が並ぶ（確認済み）
3. `tools/record-env.sh:166` は API トークンと利用者の id を、追跡されている `collector-android/gradle.properties` に足し、
   ビルドの後に戻す。trap が無いので、ビルドが途中で止まるとトークンが追跡ファイルに残る（確認済み。一時の worktree の中ではある）
4. `crates/server/src/feelings.rs:298` `target_state_error` が、本文を消した滞在（payload が `{}` で終わりが無い）を
   長さ 0 の区間として扱う。そのため始まりより後の時刻を持つ記録は、紐づけ先として断られる（コメントは「消した滞在も通す」と言っている）
5. `web/src/FeelView.tsx:306` `pressStay` は押した値を送る前に `stayPicks` に入れ、サーバに断られても届かなくても消さない。
   滞在の行に保存されていない値が押された印のまま残る
6. `web/src/FeelView.tsx:222` 前/後の判定が読み込んだときの `now` で決まる。開いたまま対象の日の終わりをまたぐと、画面とサーバで前と後が食い違う
7. `crates/server/src/lib.rs:993` 取り込みに、人が書いた記録の規則（origin・端末 id 無し・外部 id 無し・tz）の写しが 3 つ目として入った。
   すでに tz の扱いが食い違っている（主観は +540 固定、ほかは ±1439）
8. `web/src/FeelView.tsx:114` 同じ日について `/api/feelings` を 2 回取りに行く（その日だけと、その日を含む 30 日）。押すたびにも 2 回
9. `crates/server/src/feelings.rs:625` 読むたびに、利用者の主観の記録の全部を `min(event_time)` で走査して始まりの日を求める
