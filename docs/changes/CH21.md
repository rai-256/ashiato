# CH21 — 確認バッチの前に、その回で足した機能だけを使ってみる席（/tsukau）で軽く確かめる

## 価値

本人として、確認バッチを開く前に、その回で足した画面と PC の機能を AI が配る形で一度普通に使ってみた結果（違和感の件数と題）を手順書で見たい。
なぜなら、今の試験は spec の Scenario を 1 つずつ確かめるだけで、入れて普通に使えば気づく不具合（#329 の更新係の落ち続け）を本人が最初の利用者になって見つけているから。
（深掘り第 1 回は推奨の答えで先に書いている。答えを受けたら record が直す）

## 依頼（逐語）

> ## 何を
> ashiato2 に harness2 の「使ってみる席」（`/tsukau`・`scripts/tsukau.py`。harness2 #272 / PR #276 で入った）の差し込み口を置き、
> 確認バッチの準備（`tools/verify-prep.sh`）から、**その回のバッチで足した機能だけ**を範囲にして、小さい時間と token で毎回呼ぶ。
> 結果の件数と題を確認バッチの手順書に載せる。手で好きなときに呼ぶ（`/tsukau`）ときも同じ差し込み口を使う。
>
> ## なぜ
> 2026-11-19、本人が配る形を入れて普通に使ったら、違和感（更新の確認がエラーを出し続ける）がすぐ見つかった（#329）。
> 今の試験はどれも spec の Scenario を 1 つずつ確かめるだけで、「入れて普通に使うとどう見えるか」を見る席が無く、人間が最初の利用者になっている。
> 席そのものは harness2 に置いた（好きなときに範囲・時間・token を決めて呼べる）。本人の決定（2026-11-20）: 好きなときに回したいが、
> 毎回簡単な動作確認もしてほしい。毎回やるのは追加機能に限ってよい。
>
> ## どこまで
> - 差し込み口: `tools/tsukau/tsukau.json` と env_hook（`up` / `down`）。契約は harness2 の `scripts/tsukau.py` の冒頭と README の「使ってみる席」。
>   相手は少なくとも PC 側（Windows Sandbox に配る zip を入れる。PC の収集アプリの録画で実績あり）。画面（web）も入れられるなら入れる。携帯は外（後で足せる作り）
> - 確認バッチの前: `tools/verify-prep.sh` から、そのバッチに入る Story / change が足した機能を `--scope` にして `scripts/tsukau.py run` を呼ぶ。小さい時間と token
> - 手順書と PR 本文に写すのは件数・題・止まり方だけ（候補の本文・根拠・画像・ログは repo に入れない）。issue は作らない
> - 席が落ちても・時間切れでも、確認バッチの準備は止めない（警告として手順書に書く）
> - 席の中身（触り方・違和感の候補の書き方・止まり方）は harness2 側。ここでは変えない
> - 以前の CH21（ashiato2 だけで席を作り、数日分の使い方を毎回真似る形。Scenario 39 本）は捨てる。席は harness2 に移った

## 壊してはいけないもの

- 確認バッチの準備（`tools/verify-prep.sh`）が作る成果物: サーバ（`ashiato-server`）・画面（`web/`）・携帯の APK・`run.sh`・手順書（`manifest.md`）の既存の段落（席の段落は最後に足すだけ。深掘り Q8）
- 確認バッチの準備の成否: 席が落ちても・時間切れでも・呼べなくても、準備は rc=0 のまま（依頼）
- 確認バッチの作業ツリー: 席が何を書いても、作業ツリーに未コミットの変更を残さない（残すと次の確認バッチが止まる。design D9）
- 本人の合言葉・確認バッチの DB・本人の PC の配布版・本人が起こした Sandbox: 席の相手を立てるときに使わない・触らない（design D3・D7）
- 録画: 席は録画より先に終わり、自分が起こした Sandbox だけを止める（design D3）

## 完了の判定

- `tools/tsukau/verify-batch.sh --self-test` と `tools/tsukau/env-hook.sh --self-test` が CI の `rust` の job で緑（範囲の決め方・呼び方・写すもの・止めないこと・同じ中身の写し・PC と画面の相手の立て方と片付け）
- この PC で、本物の Sandbox を網ありで起こして塞いだ後、私設網と手元の網の宛先に届かない（`tools/tsukau/env-hook.sh probe-network`。届けば網を切る道が働く）
- 同じ差し込み口を本物で 1 回ずつ（画面と PC）呼び、どちらも席が `done`・`time`・`tokens` のどれかで終わり、片付けに残りが無い（`tools/tsukau/real-run.sh`。CH21 自身は道具だけを変えるので、CH21 だけの確認バッチでは席が回らない。design D14）
- `python3 scripts/tsukau.py check` が rc=0
- 確認バッチの問い: 手順書の冒頭に「使ってみる席」の段落が載り、相手ごとの行が読める（CH21 だけの回では「回さなかった」の 2 行）
- archive で、正典 verify-environment に 8 つの Requirement が足される
