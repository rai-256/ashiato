# CH21 — 確認バッチの前に Claude が配る形を入れて普通に使ってみる

## 価値

確認バッチの手順書が人間に渡る前に、Claude がまっさらな Windows に配る形を入れて普通に使い、気になったことを根拠つきで手元に残し、手順書の冒頭に件数と題を載せる。
人間が配る形の最初の利用者になって違和感を踏むのをやめ、Scenario を 1 つずつ確かめる試験では見えない「入れて使うとどう見えるか」を、確認のたびに先に見ておく。
（第 1 回の深掘りの推奨の答えで書いた。2026-11-19）

## 何を
確認バッチの手順書が人間に渡る**前に**、Claude が配る形（Windows の配る zip）を Windows Sandbox のまっさらな Windows に入れ、**筋書きなしで普通の利用者として**使ってみる席を足す。気になったことは、確認バッチの手順書に載せ、残すべきものは「違和感」の issue にする。

## なぜ
2026-11-19、本人が配る形を入れて普通に使ったら、違和感（更新の確認がエラーを出し続ける）がすぐ見つかった。今の試験（`install-check.sh` の約 80 項目・`web/e2e`・録画）は、どれも spec の Scenario を 1 つずつ確かめるだけ。e2e の相手は `stack.sh` の開発用の環境で、インストールした形ではない。**「入れて普通に使うとどう見えるか」を見る席がどこにも無い。** そのせいで、人間が最初の利用者になっている。

## どこまで
- 走らせるのは確認バッチの前（差し込み口の `tools/verify-prep.sh` から呼ぶ想定。手順書の冒頭には manifest が載る）
- 場所は Windows Sandbox（本人の作業中の画面は使わない。PC の収集アプリの録画で実績あり）
- 対象: インストール → 合言葉 → 画面にログイン → 数日分の使い方の真似（取り込み・画面の見て回り・設定・更新の確認の表示・アンインストール/入れ直し）。何を触るかは筋書きにしない（Scenario の写しにならないこと）
- 出すもの: 見たもの（画面の写し・ログ）と「違和感の候補」の一覧。誤検知で人間を疲れさせないよう、候補には根拠を添える
- 携帯の収集アプリはこの change の外（後で同じ形を足せる作りにはする）
- 落ちても確認バッチは止めない（警告として手順書に書く）

## 壊してはいけないもの

- 確認バッチの準備（`tools/verify-prep.sh`）のいまの成果物（サーバ・画面・携帯の APK・`run.sh`）と manifest の既存の段落。席が落ちても準備は rc=0 で終わり、これらは席の無いときと同じに残る
- 録画の順番: 録画（`record-run`）は準備の後に Sandbox を起こす。席は自分の Sandbox を必ず閉じ、他人の Sandbox が動いていれば起こさない・閉じない
- 手順書の Story ごとの「違和感」の問い・確認バッチの手順書の形・/iwakan・ラベル「違和感」の意味（人間が見て・触って感じたもの）。ハーネス（harness2）には手を入れない
- 公開の repo に出るもの: 手順書（`docs/verify/<tag>.json` と PR の本文）に足すのは件数・題 1 行ずつ・巡った目的の札・所要・終わり方・手元の報告の場所だけ。候補の本文・根拠・画像・ログは repo に入れない。issue は作らない
  （この行は第 1 回の Q7・Q8（A。本人は答えを省略できない）の推奨で書いた。答えが推奨と違えば `spec --answers` が書き直す）
- 製品のコード・移行・画面・収集アプリ・配る形の組み立て（`tools/release/`。呼ぶだけ）

## 完了の判定

- 席の約束（`openspec/changes/ch21-trial-use-before-verify/specs/trial-use/spec.md` の 39 本の Scenario）を、偽の Windows・偽の Claude・偽の gh で確かめる `tools/trial-use/check-trial-use.sh --self-test` が rc=0 で、CI の `chain` job で走る
- 手元の機械で本物の Sandbox と Claude で 1 回走り、段落が「使ってみた」で始まり、手元の置き場に報告の HTML が残る（tasks 11.1 の証跡）。
  インストーラが Sandbox で通るなら（tasks 1.1 の `install` が PASS）、インストールまで届き、画面の写しも残る。通らないなら、段落が「インストールまで届かなかった」の警告を書き、報告にそこまでのログが残る（Q13 の推奨「結果か警告が載ること」。spec-review R21）
  11-19 の違和感（更新の確認がエラーを出し続ける）を拾えたかは記録するが、判定には使わない（Q13）
- 確認バッチで 1 回実地に走り、手順書の冒頭の manifest に「使ってみた」の段落（件数と題か、0 件なら巡った目的、か、走らなかった・落ちた理由）が載る（確認バッチの「人間の確認待ち」1 件。0 件なら巡った目的の札。`> 物理: device`）
