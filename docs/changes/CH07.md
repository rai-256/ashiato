# CH07 — 検証の準備が作り直した DB を宣言する

## 価値

検証の準備（`tools/verify-env.sh`）が worktree のテスト用 DB を空から作り直したことを、harness2 #112 の約束の形（`HARNESS_RESET: testdb`）で宣言する。
`verify-run` の証跡に何を作り直したかが残り、作り直していない証跡（溜まった DB の上で取ったもの）にだけ「注意」が付く。`init.py --check` の人間の項目も消える。

## 依頼

`HARNESS_VERIFY=1` で `tools/verify-env.sh` がこの worktree のテスト用 DB を作り直したら、作り直したものを `HARNESS_RESET: testdb` の 1 行で標準出力に出す。

## なぜ

- harness2 PR #112（2026-10-25）で、検証の準備は作り直したものを `HARNESS_RESET: <何を>` の行で宣言する約束になった。
  `verify-run` はこの行を証跡の `reset` に残し、無ければ「注意」を出す。`init.py --check` も、宣言の無い `verify-env.sh` を人間の項目として出す。
- CH06 は作り直しそのものを入れたが、この宣言の形が決まる前に合意したので、宣言の行を出していない。
  いまの ashiato2 で `python3 .harness2/scripts/init.py --check` を流すと「tools/verify-env.sh が作り直したものを宣言していない」が出る。

## 完了の判定

- `HARNESS_VERIFY=1` で作り直したときだけ `HARNESS_RESET: testdb` を 1 行出す。作り直さない場合（印が無い・CI でない main の checkout・作り直せずに非 0 で終わる）は出さない。
- CH06 の `tools/check-verify-env-reset.sh` が、作り直したときにこの行が出ること・作り直さないときに出ないことを機械で確かめる（`--self-test` を含めて rc=0）。
- `python3 .harness2/scripts/init.py --check` が `tools/verify-env.sh` の項目を出さない（harness2 #112 の merge 後）。
- CH06 の振る舞い（作り直しの対象・切った接続の行・印が無いときの振る舞い）は変えない。
