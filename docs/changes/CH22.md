# CH22 — 配る形を外につながる状態で入れて置き、落ち続けや誤りの続きを PR の CI で捕まえる

## 価値

普通に入れて置いておけば気づける壊れ方（サービスの落ち続け・止まったまま・同じ誤りの続き・本物の配布元に聞けない）を、
PR の CI が配る形をそのまま外につながる状態で 5 分置いて機械で落とす。0.1.0 の「入れて放っておくだけで更新係が 10 秒ごとに落ちる」を、配る前に捕まえる。

受け皿の依頼 #332（https://github.com/rai-256/ashiato/issues/332）から。

## 本人の言葉

> 普通に使ってても問題よねみたいな、モンキーテスト？アドホックテスト？みたいなのをやらせたいんですよね。普通に使ってれば気がつけるよねみたいなものを見つけたいです／1の、その試験って普通にテストとして追加するって話ですか？

## 議論で決めたこと（本人の決定。深掘りで聞き直さない）

- **何を**: CI の install-windows で、配る形のサーバを入れた後に外向きの塞ぎを外して数分置き、サービスの再起動の繰り返し・panic・誤りの記録の連続・クラッシュを機械が判定する
- **なぜ**: 0.1.0 は入れて放っておくだけで更新係が 10 秒ごとに落ちた。CI は外向きを塞ぎ、偽の受け手だけで試すので素通りした（#329）
- **どこまで**: PR の CI（install-windows の後段。5 分ほど）。正典 distribution の「自動の試験は本物の配布元に問い合わせない」を、この段と #329 の握手の試験（tls_online_*）に合わせて改める。最初のインストールより前に外向きを塞ぐ D18 は残す。製品のコードは変えない。やらないこと: 長く置く毎晩の試験、本物の答えの形の比べ（CH20 の中身）

## そのとき考えたこと

2026-11-19 の議論。CH20（本物の配布元で毎晩確かめる）は重すぎ（台本の口 4 つ・流し直し・別の repo・3 晩の数え方）で、既知の食い違い 3 つで初日から赤が続き、今回の HTTPS の握手の不具合も捕まえない形だったのでやめ、これに置き換える。毎晩 30 分置く形は、長く置かないと出ない問題が要るようになったら足す。PC の収集アプリも配る形で置くかは深掘りで決める。AI が普通に使ってみる席は harness2 の依頼と CH21 で別に扱う

## 壊してはいけないもの

- 製品の振る舞い（サーバ・DB・更新係・PC の収集アプリ・携帯の収集アプリ・画面）。製品のコードは変えない
- ST57 D18: `install-windows` は最初のインストールより前に更新係の外向きを塞ぎ、置く段より前の全部の段（`install-check.sh`・`update-check-install.sh`・`update-apply-install.sh`）を塞いだまま走らせる。
  とくに正典 distribution の Scenario「配布元に届かなくてもインストールは終わる」（塞いだ状態で確かめる）は、置く段より前で今のとおり走る
- `install-windows` の今の 3 つの台本の `--list` と走った `== Scenario:` の突き合わせ（欠ければ落ちる）
- `collector-windows-runtime` の握手の試験 `tls_online_*`（本物の `api.github.com` との握手を 2 本走らせ、走った本数を確かめる）
- 正典 distribution の「更新を確かめる問い合わせは、版の一覧を取る決まった形だけを配布元へ送る」の、最後の SHALL のほかの約束と既存の 9 本の Scenario

## 完了の判定

- PR の CI の `install-windows` が、最後の置く段を含めて緑である（判定を緩めず、外れを許す一覧を持たない。置く段が今の不具合を見つけたら、直しの change の後に merge する。深掘り Q7）
- `rust` の job の `tools/release/soak-install.sh --self-test` が緑で、置く段の判定が落ちる入力（起こし直し・止まったまま・healthz・同じ誤り・サーバの panic・確かめた記録が無い・PC の収集アプリが終わる・消せない・塞ぎが外れない）でどれも落ちる
- 置く段が緑の回でも、起こし直しの回数・置く間の誤りの行・システムの記録を読めたか・PC の収集アプリの通知の登録の行・確かめた記録の行を CI のログに出す（最初の走りの観測が残る）
- archive で、正典 distribution に置く段の 5 つの Requirement が足され、「本物の配布元に問い合わせない」の約束が名指しの 2 つの例外の形に改まる
- 確認バッチの問い: なし（画面も本人の操作も変わらない。置く段は CI が機械で見る）
