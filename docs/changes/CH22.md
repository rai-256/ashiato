# CH22 — 配る形を外につながる状態で入れて置き、落ち続けや誤りの続きを PR の CI で捕まえる

## 価値

受け皿の依頼 #332（https://github.com/rai-256/ashiato/issues/332）から。

## 本人の言葉

> 普通に使ってても問題よねみたいな、モンキーテスト？アドホックテスト？みたいなのをやらせたいんですよね。普通に使ってれば気がつけるよねみたいなものを見つけたいです／1の、その試験って普通にテストとして追加するって話ですか？

## 議論で決めたこと（本人の決定。深掘りで聞き直さない）

- **何を**: CI の install-windows で、配る形のサーバを入れた後に外向きの塞ぎを外して数分置き、サービスの再起動の繰り返し・panic・誤りの記録の連続・クラッシュを機械が判定する
- **なぜ**: 0.1.0 は入れて放っておくだけで更新係が 10 秒ごとに落ちた。CI は外向きを塞ぎ、偽の受け手だけで試すので素通りした（#329）
- **どこまで**: PR の CI（install-windows の後段。5 分ほど）。正典 distribution の「自動の試験は本物の配布元に問い合わせない」を、この段と #329 の握手の試験（tls_online_*）に合わせて改める。最初のインストールより前に外向きを塞ぐ D18 は残す。製品のコードは変えない。やらないこと: 長く置く毎晩の試験、本物の答えの形の比べ（CH20 の中身）

## そのとき考えたこと

2026-11-19 の議論。CH20（本物の配布元で毎晩確かめる）は重すぎ（台本の口 4 つ・流し直し・別の repo・3 晩の数え方）で、既知の食い違い 3 つで初日から赤が続き、今回の HTTPS の握手の不具合も捕まえない形だったのでやめ、これに置き換える。毎晩 30 分置く形は、長く置かないと出ない問題が要るようになったら足す。PC の収集アプリも配る形で置くかは深掘りで決める。AI が普通に使ってみる席は harness2 の依頼と CH21 で別に扱う
